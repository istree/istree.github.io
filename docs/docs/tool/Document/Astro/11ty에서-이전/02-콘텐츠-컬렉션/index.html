11ty는 입력 디렉토리 아래 마크다운을 모두 페이지로 만든다.

Astro는 글을 콘텐츠 컬렉션으로 읽고, 페이지는 src/pages 에서 따로 만든다.

컬렉션은 src/content.config.ts 에 정의한다.

import { defineCollection } from "astro:content";
import { glob } from "astro/loaders";

const keepPath = ({ entry }) => entry.replace(/\.md$/, "");

export const collections = {
  posts: defineCollection({ loader: glob({ pattern: "**/*.md", base: "../../../page/dev/posts", generateId: keepPath }) }),
  docs: defineCollection({ loader: glob({ pattern: "**/*.md", base: "../../../page/dev/docs", generateId: keepPath }) }),
};

base 는 프로젝트 밖이어도 된다. 내 경우 원고를 저장소의 다른 곳에 두고 빌드 코드만 따로 두었다.

id 는 기본으로 소문자 slug 가 된다. 주소를 파일 경로로 만들어야 해서 generateId 로 경로를 그대로 쓴다.

원고가 프로젝트 밖이면 개발 서버가 그 안의 이미지를 읽지 못한다. vite 에 허용해준다.

vite: { server: { fs: { allow: [".", "../../../page"] } } },

글은 getCollection 으로 읽고 render 로 출력한다.

---
import { getCollection, render } from "astro:content";
const posts = await getCollection("posts");
const { Content } = await render(posts[0]);
---
