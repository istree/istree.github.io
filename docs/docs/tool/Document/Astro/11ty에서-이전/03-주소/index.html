11ty의 주소 규칙을 그대로 옮겨야 기존 링크가 깨지지 않는다.

  • 기록: 파일 이름에서 앞의 날짜를 뺀 /posts/이름/
  • 정리: 파일 경로 그대로 /docs/경로/
  • index.md 는 그 폴더 주소

11ty는 폴더 이름과 같은 파일(Vim/Vim.md)도 폴더 주소로 만들어 준다. 이런 파일이 하나뿐이라 index.md 로 바꾸고 이 규칙은 옮기지 않았다.

페이지는 동적 경로로 만든다. 정리처럼 깊이가 정해지지 않은 경로는 [...path] 를 쓴다.

---
// src/pages/docs/[...path].astro
export async function getStaticPaths() {
  return (await pagesOf("docs")).map((page) => ({
    params: { path: page.url.replace(/^\/docs\/|\/$/g, "") },
    props: { page },
  }));
}
---

/posts/글/ 과 /posts/연도/ 는 같은 한 단계 주소라서 한 파일([slug].astro)에서 둘 다 만든다.

자소분리는 11ty 때와 같다. 주소는 NFC 로 정규화한다.

끝 /

원고의 상대 링크가 [MFC](MFC) 처럼 끝 / 없이 적힌 것이 많았다.

GitHub Page는 /MFC 를 /MFC/ 로 넘겨줘서 몰랐는데, 개발 서버에서 trailingSlash 를 always 로 두면 404 가 난다.

넘겨주지 않는 서버에서는 그 페이지 안의 상대 링크도 한 단계 위로 풀린다. 그래서 원고의 링크 끝에 / 를 붙이고, 설정은 ignore 로 했다.

trailingSlash: "ignore",
