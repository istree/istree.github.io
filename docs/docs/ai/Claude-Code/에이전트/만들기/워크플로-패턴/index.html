에이전트를 만들 때는 가장 단순한 것부터 쓰고, 그것으로 모자랄 때만 한 단계씩 올린다. 정해진 길을 코드로 짜 두는 것이 워크플로, 길을 모델이 고르는 것이 에이전트다.

패턴 하는 일 쓸 때
프롬프트 체이닝 일을 단계로 나눠 앞 출력을 다음 입력으로 넘긴다. 중간에 검사(게이트) 를 둔다 단계가 정해져 있고, 느려도 정확해야 할 때. 개요 → 검사 → 본문
라우팅 입력을 분류해 알맞은 프롬프트 · 도구 · 모델로 보낸다 갈래가 뚜렷할 때. 쉬운 질문은 작은 모델, 어려운 것은 큰 모델
병렬화 나눠서 함께 돌리거나(sectioning), 같은 일을 여러 번 돌려 투표한다(voting) 빨라야 하거나, 여러 관점 · 여러 번 시도가 필요할 때. 취약점 리뷰를 여러 프롬프트로
오케스트레이터-워커 지휘하는 모델이 일을 그때그때 나눠 일꾼에게 맡기고 결과를 합친다 하위 작업을 미리 알 수 없을 때. 여러 파일을 고치는 코딩
평가자-최적화자 하나가 만들고 하나가 평가 · 피드백하기를 되풀이한다 평가 기준이 분명하고, 되풀이할수록 나아질 때. 번역 · 여러 번의 검색
  • 증강 LLM — 모든 패턴의 바탕은 검색 · 도구 · 메모리를 붙인 모델 하나다
  • 단순하게 · 드러나게 — 구조를 단순하게 두고, 에이전트의 계획 단계를 보이게 하며, 도구 문서와 시험에 공을 들인다
  • 프레임워크는 걷어 낸다 — 시작은 빨라지지만 안에서 무엇이 오가는지 가린다. 실제로 쓸 때는 API 를 바로 부르는 쪽으로 줄인다
