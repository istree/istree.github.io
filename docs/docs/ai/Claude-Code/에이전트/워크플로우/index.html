동적 워크플로우는 서브에이전트 여럿을 JavaScript 스크립트로 조율하는 기능이다. 할 일을 말하면 Claude 가 스크립트를 짜고, 런타임이 그것을 뒤에서 돌린다. 서브에이전트에게 그때그때 맡길 때는 Claude 가 다음 할 일을 정하고 결과가 모두 대화에 쌓이지만, 워크플로우는 반복 · 분기 · 중간 결과를 스크립트가 쥐고 대화에는 마지막 답만 돌아온다. 저장소 전체 점검, 파일 수백 개 옮기기, 출처끼리 대조하는 조사에 쓴다.

켜기

// ~/.claude/settings.json
{ "enableWorkflows": true }
  • 요금제에 따라 기본으로 꺼져 있다. /config 의 Dynamic workflows 로도 켠다
  • 켜지 않으면 "워크플로로 해 줘" 라고 해도 일반 서브에이전트로 나눠 돌린다
  • 끌 때는 "disableWorkflows": true 를 두거나 CLAUDE_CODE_DISABLE_WORKFLOWS=1 을 준다

시키기

use a workflow to audit every route handler under src/routes/ for missing auth checks
ultracode: audit every API endpoint under src/routes/ for missing auth checks
/deep-research Node.js 20 과 22 사이 권한 모델이 어떻게 바뀌었나
  • "use a workflow" 라고 하거나 프롬프트에 ultracode 를 넣으면 그 일 하나를 워크플로우로 돌린다
  • /effort ultracode 를 켜면 큰 일마다 Claude 가 알아서 워크플로우를 짠다
  • /deep-research 는 딸려 오는 워크플로우다. 여러 갈래로 웹을 찾고, 출처를 서로 대조해 통과한 주장만 인용과 함께 보고한다
  • 돌리기 전에 단계 목록을 보여 주고 묻는다. View raw script 로 스크립트를 먼저 볼 수 있다. 권한을 건너뛰는 모드 · claude -p 는 묻지 않는다

돌려 본 것

파일 넷의 줄 수를 에이전트 넷이 함께 센다.

$ claude -p 'use a workflow: for each of f1.txt f2.txt f3.txt f4.txt run one agent in parallel
  that counts the lines of that file (schema {file, lines}), then return a JSON array sorted by file.'
[{"file":"f1.txt","lines":3},{"file":"f2.txt","lines":6},{"file":"f3.txt","lines":9},{"file":"f4.txt","lines":12}]

Claude 가 짠 스크립트다 (에이전트 프롬프트만 줄였다).

export const meta = {
  name: 'count-lines',
  description: 'Count lines of f1-f4.txt in parallel, one agent per file',
  phases: [{ title: 'Count' }],
}
const FILES = ['f1.txt', 'f2.txt', 'f3.txt', 'f4.txt']
const SCHEMA = {
  type: 'object',
  properties: { file: { type: 'string' }, lines: { type: 'integer' } },
  required: ['file', 'lines'],
}
phase('Count')
const results = await parallel(FILES.map(f => () =>
  agent(`Count the number of lines in the file ${f} (use \`wc -l < ${f}\`).`,
        { label: `count:${f}`, phase: 'Count', schema: SCHEMA, effort: 'low' })))
return results.filter(Boolean).sort((a, b) => a.file.localeCompare(b.file))
함수 하는 일
agent(프롬프트, 옵션) 서브에이전트 하나를 띄운다. schema 를 주면 그 형식의 JSON 을 돌려받는다
parallel(작업들) 여러 에이전트를 함께 돌리고 다 끝날 때까지 기다린다
pipeline(목록, 함수) 목록의 항목마다 에이전트를 하나씩 돌린다
phase(제목) · log(글) 진행 보기에서 단계로 묶고, 메시지를 띄운다
args 저장한 워크플로우를 부를 때 넘긴 입력
  • 멈추거나 실패한 agent() 는 null 이 되므로 끝에서 filter(Boolean) 으로 거른다
  • 스크립트는 파일 · 셸에 직접 손대지 못한다. 읽고 쓰고 명령을 돌리는 것은 에이전트가 한다. import() 도 쓸 수 없다
  • 다시 이어 돌릴 수 있게 Date.now() · Math.random() 은 막혀 있다. 시각은 args 로 넘긴다

지켜보기 · 저장

/workflows      # 실행 목록 · 진행 보기
키 하는 일
Enter · Esc 단계 → 에이전트로 들어가고 나온다
p 멈추고 다시 잇는다
x 에이전트 하나 또는 실행 전체를 멈춘다
r 에이전트 하나를 다시 돌린다
s 스크립트를 명령으로 저장한다
  • 저장하면 .claude/workflows/<이름>.js (저장소와 함께) 나 ~/.claude/workflows/ (나만) 에 남고, 다음부터 /<이름> 으로 돈다. "/triage-issues 를 1024, 1025 이슈에 돌려" 처럼 입력을 함께 준다
  • 고칠 때는 /workflow-authoring 스킬을 먼저 불러 스크립트 작성 참조를 읽게 한다
  • 다시 이으면 끝난 에이전트는 저장된 결과를 돌려주고, 실패한 곳부터 다시 돈다

주의

  • 에이전트를 많이 띄우므로 같은 일을 대화로 할 때보다 토큰을 훨씬 많이 쓴다. 디렉터리 하나 · 좁은 질문으로 먼저 돌려 본다
  • 동시에 16 개, 한 실행에 1,000 개까지 띄운다. 25 개를 넘거나 150 만 토큰을 넘을 것 같으면 Large workflow 경고가 뜬다
  • 도는 중에는 내 입력을 받지 않는다. 단계마다 승인이 필요하면 단계를 워크플로우 하나씩으로 나눈다
  • 구독 사용 한도에 걸리면 실패하지 않고 풀릴 때까지 멈췄다가 잇는다 (대화형 세션, autoContinueAtUsageLimit 켜짐)
