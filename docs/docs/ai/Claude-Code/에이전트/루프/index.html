루프는 내가 다음 말을 하지 않아도 세션이 일을 이어 가게 하는 방법이다. 다음 턴을 언제 시작하는지에 따라 고른다. 조건을 채울 때까지 바로 이어 가는 /goal, 시간 간격마다 다시 도는 /loop, 응답이 끝날 때마다 내 스크립트가 판단하는 Stop 훅이 있다.

방법 다음 턴 멈출 때
/goal <조건> 앞 턴이 끝나면 바로 따로 도는 평가 모델이 조건을 채웠다고 보거나, 할 수 없다고 볼 때
/loop [간격] <지시> 간격이 지나면 내가 멈추거나, Claude 가 일이 끝났다고 볼 때
Stop 훅 앞 턴이 끝나면 바로 내 스크립트 · 프롬프트가 정할 때

/goal

끝난 상태를 조건으로 적으면, 턴마다 평가 모델이 조건을 따져 보고 아직이면 다음 턴을 시작한다. 일을 한 모델이 아니라 새 모델이 끝을 판정한다.

/goal test/auth 의 테스트가 모두 통과하고 lint 가 깨끗하다
/goal               # 상태 보기 (조건 · 걸린 시간 · 턴 수 · 토큰 · 마지막 판정 이유)
/goal clear         # 지우기
$ claude -p '/goal count.txt contains the numbers 1 to 5, one per line, and `cat count.txt` output is shown.
  Add only one number per turn. Or stop after 8 turns.'
count.txt now has the numbers 1 to 5, one per line. I added one number per turn, so it took 5 of the 8 allowed turns.

  • 평가 모델은 대화에 나온 것만 본다. 명령을 돌리거나 파일을 읽지 않으므로, 조건에 확인 방법을 적는다 ("npm test 가 0 으로 끝난다" · "git status 가 깨끗하다")
  • 바뀌면 안 되는 것도 조건에 적는다 ("다른 테스트 파일은 고치지 않는다")
  • 끝없이 돌지 않게 "or stop after 20 turns" 처럼 턴 · 시간 한도를 붙인다
  • 권한 모드는 바꾸지 않는다. 사람 없이 돌리려면 auto 모드에서 건다
  • 세션당 목표는 하나다. --resume 으로 다시 열면 이어진다
  • claude -p 에서는 한 번 부르면 끝날 때까지 돈다. 도는 동안 보려면 --output-format stream-json --verbose 를 붙인다

/loop

세션이 열려 있는 동안 같은 지시를 되풀이한다. 배포 · CI 처럼 바깥 상태를 기다릴 때 쓴다.

/loop 5m 배포가 끝났는지 보고 결과를 알려 줘     # 5 분마다
/loop CI 가 통과했는지 보고 리뷰 댓글을 처리해     # 간격은 Claude 가 1 분–1 시간 사이에서 고른다
/loop 20m /review-pr 1234                      # 스킬을 되풀이
/loop                                          # 기본 유지 보수 지시 (`.claude/loop.md` 로 바꾼다)
  • 간격을 주면 cron 으로 바꿔 예약한다. 단위는 s · m · h · d, cron 이라 1 분 단위로 올림한다
  • 간격을 빼면 Claude 가 지켜본 것에 따라 다음 간격을 고르고, 일이 끝나면 스스로 멈춘다
  • 간격 없는 루프는 기다리는 동안 Esc 로 멈춘다. 간격을 준 루프는 "배포 확인 루프를 취소해" 처럼 말로 멈춘다
  • 되풀이 작업은 7 일 뒤 저절로 지워진다
  • 세션이 닫히면 멈춘다. 닫혀 있어도 돌아야 하는 일은 데스크톱 · 클라우드 예약 작업으로 옮긴다

Stop 훅 · Ralph 루프

Stop 훅이 2 로 끝나면 Claude 는 멈추지 못하고 이어서 일한다. 이것을 쓰면 끝날 때까지 같은 지시를 다시 넣는 루프가 된다. ralph-loop 플러그인이 이렇게 만들어져 있다.

/ralph-loop "할 일 API 를 만든다. CRUD · 입력 검사 · 테스트. 다 되면 <promise>COMPLETE</promise> 를 출력한다" \
  --completion-promise "COMPLETE" --max-iterations 50
  • 지시는 매번 같고, 앞에서 한 일은 파일 · git 기록에 남아 다음 바퀴에 읽힌다
  • 약속한 낱말(COMPLETE) 이 나오거나 최대 횟수에 닿으면 멈춘다
  • 직접 훅을 짤 때는 입력의 stop_hook_active 를 보고, 검사를 통과하면 0 으로 끝내게 한다. 그렇지 않으면 끝나지 않는다

셸 반복문

세션 밖에서 claude -p 를 셸로 되풀이할 수도 있다. 바퀴마다 새 대화로 시작한다.

for i in $(seq 1 10); do
  claude -p "TODO.md 에서 맨 위 항목 하나를 끝내고 지운다. 남은 것이 없으면 DONE 만 출력한다" \
    --permission-mode acceptEdits --max-turns 30 | tee -a loop.log | grep -q '^DONE$' && break
done
  • --max-turns · --max-budget-usd 로 한 바퀴의 크기를 묶는다
  • 바퀴 사이에 남길 것은 파일(TODO.md · NOTES.md) 로 넘긴다
