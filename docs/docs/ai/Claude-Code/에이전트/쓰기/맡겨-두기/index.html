사람이 지켜보지 않으면 놓친 것을 잡아 줄 사람도 없다. 맡기기 전에 끝 · 확인 · 범위 · 멈춤 · 승인을 정하고, 알맞은 방법으로 돌린다.

물음 예
완료가 무엇인가 목표 조건 · 스펙 파일 · 통과시킬 실패 테스트
스스로 확인할 수 있는가 테스트 · Stop 훅 · 리뷰 단계
무엇에 손댈 수 있는가 권한 규칙 · dontAsk · 샌드박스 · 워크트리 · push 할 브랜치 하나
무엇이 멈추는가 --max-turns · --max-budget-usd · 지출 한도
결과는 어디로, 누가 승인하는가 PR · 댓글 · 요약, 병합 · 배포를 승인할 사람
  • 스크립트로 — claude -p 로 한 번 돌리고 끝낸다. CI · git 훅 · 셸 반복문에서 쓴다
  • 목표까지 — /goal <조건> 을 걸면 조건을 채울 때까지 여러 턴을 이어 간다. 끝날 때까지 같은 지시를 되풀이하는 Ralph 루프도 같은 생각이다
  • 일정 · 이벤트로 — 열린 세션에서는 /loop, 닫혀 있어도 돌릴 일은 예약 작업 · CI 로 시작시킨다
  • 큰 변경은 나눠서 — /batch 는 저장소 전체 변경을 독립된 단위로 나눠 워크트리마다 맡긴다
