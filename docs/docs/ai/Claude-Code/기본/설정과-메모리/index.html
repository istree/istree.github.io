Claude Code 의 동작은 settings.json 에, 일하는 규칙은 CLAUDE.md 에 적는다. 둘 다 전역(~/.claude) 과 프로젝트(.claude · 저장소 뿌리) 에 둘 수 있다. 여기에 Claude 가 스스로 적어 두는 자동 메모리가 더해진다.

settings.json

파일 적용 저장소에
~/.claude/settings.json 이 맥의 모든 프로젝트 —
.claude/settings.json 이 프로젝트 올린다
.claude/settings.local.json 이 프로젝트, 나만 .gitignore 에 넣는다

같은 키가 여러 곳에 있으면 local → 프로젝트 → 전역 순으로 앞의 것을 쓴다. permissions.allow 같은 목록은 고르지 않고 합친다. 띄울 때 --settings 로 준 값은 그 세션에서 파일보다 앞선다.

{
  "statusLine": { "type": "command", "command": "node ~/.claude/statusline-command.mjs" },
  "hooks": { "Stop": [ … ] },
  "enabledPlugins": { "telegram@claude-plugins-official": true },
  "skipDangerousModePermissionPrompt": true
}
  • 파일을 고치면 떠 있는 세션도 다시 읽는다. 권한 · 훅도 다시 띄우지 않고 바뀐다
  • /config · /model 에서 바꾼 것도 이 파일에 저장된다
  • 한 세션만 다르게 띄울 때는 claude --settings '{"model": "claude-opus-5-5"}' 처럼 준다

CLAUDE.md

대화를 시작할 때마다 읽는 지침이다. 작업 폴더와 그 위 폴더의 CLAUDE.md 를 모두 읽고, 아래 폴더의 것은 그 폴더 파일을 만질 때 읽는다.

파일 적용
~/.claude/CLAUDE.md 모든 프로젝트, 나만
./CLAUDE.md 또는 ./.claude/CLAUDE.md 이 프로젝트, 저장소에 올린다
./CLAUDE.local.md 이 프로젝트, 나만 (.gitignore) 
# life

## 응답 언어
- 사용자에게 출력하는 모든 텍스트는 한국어로 작성한다

## 디렉토리 구조
- `note/daily/YYYY/MM/YYYY-MM-DD.md` - 일일 기록
- `page/` - 블로그 원고 (정본). 여기서만 쓰고 고친다

## 커밋 규칙
- 커밋 메시지에 Co-Authored-By 줄을 추가하지 않는다
  • 코드를 읽어 알 수 있는 것보다, 읽어서는 모르는 것(폴더마다 쓰임 · 하지 말 것 · 절차) 을 적는다
  • 짧게 둔다. 파일 하나에 200 줄 안쪽을 권한다. 길어지면 따로 떼고 @docs/규칙.md 로 가져온다
  • /init 은 저장소를 읽어 CLAUDE.md 초안을 만든다

규칙 파일

.claude/rules/ 에 주제마다 .md 를 두면 CLAUDE.md 와 함께 읽는다. paths 를 주면 그 파일을 만질 때만 읽어 컨텍스트를 아낀다.

---
paths:
  - "page/**/*.md"
---
- 문장은 명사로 끊지 않고 서술어로 맺는다

자동 메모리

Claude 가 일하면서 고침 받은 것 · 알게 된 것을 스스로 적어 두는 노트다. 기본으로 켜져 있다.

~/.claude/projects/<프로젝트>/memory/
├── MEMORY.md            # 목록. 한 줄에 메모 하나. 대화마다 읽는다
├── page-doc-style.md    # 메모 하나
└── work-stages.md
---
name: page-doc-style
description: 블로그 정리 글은 실제 사용 패턴 · 스니펫 · 키워드 위주
metadata:
  type: feedback
---

원론은 공식 문서에 맡기고 짧게 쓴다.
**Why:** "너무 복잡하다" 는 피드백을 받음
**How to apply:** 소제목은 짧은 우리말, 예제는 몇 줄짜리
  • MEMORY.md 는 앞 200 줄(25 KB) 만 읽는다. 메모 본문은 필요할 때 연다
  • type 은 user(나에 대해) · feedback(고침 받은 것 · 확인받은 방식) · project(진행 중인 일 · 결정) · reference(바깥 자료 위치) 넷이다
  • 코드 · git 기록 · CLAUDE.md 로 알 수 있는 것은 적지 않는다
  • 저장소에 들어가지 않고 이 맥에만 있다. 같은 저장소의 하위 폴더 · 워크트리는 메모리를 함께 쓴다
  • /memory 에서 메모리를 끄고 켜거나, 저장된 것을 열어 고친다
  • 저장소 모두에게 맞는 규칙은 CLAUDE.md 로 옮긴다
