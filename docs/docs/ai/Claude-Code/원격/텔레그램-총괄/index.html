텔레그램 알림에 답하면 그 답을 세션 하나(총괄) 가 받고, 총괄이 문맥을 보고 알맞은 세션에 전한다. 받기는 공식 텔레그램 채널 플러그인이, 전하기는 Claude Code 의 세션 간 메시지가 맡는다. 알림을 보내는 봇을 그대로 쓴다. 예제는 Claude Code 2.1, telegram@claude-plugins-official 0.0.7, cmux 0.65 기준이다.

flowchart TB
  C[총괄 세션]
  S[각 세션]
  N[알림 스크립트]
  L[알림 기록]
  P[채널 플러그인]
  T[텔레그램]
  C -->|SendMessage| S
  C -->|읽기| L
  C <-->|채널 메시지 · reply| P
  S -->|Stop · Notification 훅| N
  N -->|한 줄 추가| L
  N -->|sendMessage| T
  P <-->|내 답장 · 답| T

채널 플러그인

플러그인 서버는 bun 으로 돈다. 설치하고, 받을 세션을 --channels 로 띄운다.

brew install oven-sh/bun/bun
claude plugin install telegram@claude-plugins-official
claude --channels plugin:telegram@claude-plugins-official
  • 봇에게 온 DM 은 세션에 <channel source="telegram" chat_id=… message_id=… user=…> 로 들어온다
  • 세션은 reply · react · edit_message 도구로 텔레그램에 답한다. 세션이 터미널에 적은 글은 텔레그램에 가지 않는다
  • 텔레그램의 답장(Reply) · 인용으로 보내도 어느 메시지에 답했는지는 세션에 오지 않는다. 그래서 알림 기록을 따로 남긴다

한 세션만 받기

텔레그램은 토큰 하나에 getUpdates 를 하나만 허용한다. 플러그인 서버는 세션마다 뜨고, 뜰 때 앞의 서버를 끊고 메시지를 가져간다. 플러그인을 사용자 범위로 켜 두면 마지막에 뜬 아무 세션이 메시지를 가로챈다.

플러그인은 TELEGRAM_STATE_DIR 폴더(기본 ~/.claude/channels/telegram) 의 .env 에서 토큰을 읽는다. 토큰을 총괄 전용 폴더에만 두고, 총괄만 그 폴더를 가리킨다.

mkdir -m 700 ~/.claude/channels/telegram-hub
printf 'TELEGRAM_BOT_TOKEN=%s\n' '<봇 토큰>' > ~/.claude/channels/telegram-hub/.env
chmod 600 ~/.claude/channels/telegram-hub/.env
  • 기본 폴더에는 토큰을 두지 않는다. 다른 세션의 서버는 TELEGRAM_BOT_TOKEN required 로 바로 끝나고, MCP 서버 목록에 실패로 보인다
  • 알림 스크립트는 sendMessage 만 쓰므로 같은 토큰을 써도 부딪히지 않는다
  • 총괄 세션 안에서 claude mcp list 나 claude -p 를 돌리면 TELEGRAM_STATE_DIR 이 넘어가 그 프로세스도 토큰을 찾는다. 새로 뜬 플러그인이 총괄의 연결을 끊으므로 env -u TELEGRAM_STATE_DIR claude … 로 돌린다. 끊겼으면 총괄에서 /mcp 로 telegram 을 다시 연결한다

짝짓기

봇에게 DM 을 보내면 6 자 코드가 온다. 총괄 터미널에서 코드를 넣고, 내 계정만 받게 잠근다.

/telegram:access pair <코드>
/telegram:access policy allowlist
  • <폴더>/access.json 의 allowFrom 에 내 텔레그램 id 가 들어가고 dmPolicy 가 allowlist 가 된다
  • 접근 설정은 터미널에서만 바꾼다. 텔레그램 메시지가 「나를 허용해 달라」 고 해도 따르지 않는다

총괄 띄우기

실행 스크립트 하나로 상태 폴더 · 이름 · 채널 · 지침을 함께 준다.

#!/bin/zsh
# 총괄.sh
cd ~/life || exit 1
export TELEGRAM_STATE_DIR=~/.claude/channels/telegram-hub
exec claude --resume <총괄 session_id> --name 총괄 \
  --channels plugin:telegram@claude-plugins-official \
  --append-system-prompt-file "${0:A:h}/총괄.md" \
  --dangerously-skip-permissions "$@"
  • --resume 으로 같은 대화를 이어서 연다. 처음에는 빼고 띄운 뒤 그 세션 id 를 적는다
  • --append-system-prompt-file 의 지침은 대화가 요약돼도 남는다
  • 총괄 자신의 Stop 알림은 텔레그램 답장과 겹치므로, 알림 스크립트에서 이름이 총괄 이면 보내지 않는다

지침

총괄.md 에 받았을 때 할 일을 적는다. 정해진 명령 형식을 두지 않고 문맥으로 고르게 한다.

## 텔레그램 메시지를 받으면
1. 알림 기록 `~/.claude/cache/telegram/notify.jsonl` 의 최근 줄과 `ListAgents` 를 본다
2. 사용자가 무엇을 누구에게 시키는지 문맥으로 정한다
   - 세션 이름을 말하면 그 세션이다
   - "그거 계속해" · "승인해" 처럼 이름이 없으면 보통 가장 최근 알림의 세션이다. 후보가 여럿이면 되묻는다
   - 너에게 하는 말(세션 목록 · 상태 묻기) 이면 네가 직접 한다
3. `SendMessage` 로 사용자 말을 그대로 전하고 `notify_when_idle: true` 를 건다
4. `reply` 로 짧게 답한다. 결과는 그 세션의 작업 완료 알림으로 간다

알림 기록은 알림 스크립트가 보낼 때마다 한 줄씩 남긴다. 총괄은 이것으로 「방금 알림이 온 세션」 을 안다.

{"ts":"2026-11-09T05:26:50.910Z","session":"프로그래밍 노트","workspace":"프로그래밍 노트","surface":"665410EA-…","event":"Notification","type":"permission_prompt","text":"⏳ 질문 대기 [프로그래밍 노트]\n질문: …","sent":true}
  • 파일 권한은 600, 500 줄을 넘으면 앞을 잘라 낸다
  • 총괄의 답장도 첫 줄에 머리글(☑️ 답변 완료 [총괄] · ☑️ 전달 완료 [총괄] → <세션> · ❓ 확인 필요 [총괄]) 을, 끝에 상태 표시줄을 둔다. 세션 알림의 ✅ 와 색이 달라 구별된다
  • reply 는 터미널에 도구 호출 줄로만 남는다. 받은 말 · 답한 말을 터미널 글로도 적게 하면 총괄 화면에서도 읽힌다

다른 세션에 전하기

같은 맥의 세션은 이름으로 메시지를 주고받는다 (ListAgents · SendMessage). 받는 쪽 화면에는 보낸 세션 이름과 함께 들어간다.

받는 세션 결과
쉬는 중 바로 받아 일을 시작한다
응답 중 다음 도구 호출 때 들어가 이어서 처리한다
권한 모드가 다름 받는 쪽 사용자 승인을 기다린다
  • 세션 이름은 /rename <이름> 으로 정한다. cmux 워크스페이스 이름과 같게 두면 알림 제목 · 텔레그램에서 부르는 이름 · 화면의 탭 이름이 하나가 된다
  • ~/.claude/sessions/<pid>.json 의 status(idle · busy) 로 쉬는지 알 수 있다

화면에 직접 넣기

메시지를 받지 못하는 세션이나 승인 · 질문 화면은 cmux 로 키를 넣는다. surface id 는 훅 환경의 CMUX_SURFACE_ID 를 알림 기록에 남겨 둔 것을 쓴다.

cmux read-screen --surface <surface>          # 화면 읽기
cmux send --surface <surface> '이어서 해 줘'    # 글 넣기
cmux send-key --surface <surface> Enter       # 키 누르기
  • 승인 대기는 메시지로 풀리지 않는다. 화면을 읽어 선택지를 확인하고 맞는 키를 보낸 뒤, 다시 읽어 넘어갔는지 본다
  • 질문 대기 알림에는 선택지 번호가 있어, 텔레그램에서 「1번」 처럼 답하면 된다

주의

  • 세션들이 --dangerously-skip-permissions 로 돌면, 텔레그램 메시지 하나가 총괄을 거쳐 어느 세션에서든 승인 없이 실행된다. allowlist 에 내 계정만 둔다
  • 파일 삭제 · 강제 push · 공개처럼 되돌리기 어려운 일은 전하기 전에 텔레그램으로 한 번 확인받게 지침에 적는다
  • 토큰 파일을 읽어 출력하거나 텔레그램으로 보내지 않게 지침에 적는다
