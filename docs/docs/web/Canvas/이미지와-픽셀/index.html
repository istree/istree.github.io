캔버스에는 그림 · 동영상 · 다른 캔버스를 drawImage 로 그려 넣고, getImageData 로 픽셀 값을 꺼내 고친 뒤 putImageData 로 되돌린다. 다 그린 캔버스는 PNG · JPEG · WebP 파일로 내보낸다. 사진 줄이기 · 자르기 · 필터 · 워터마크를 서버 없이 브라우저에서 할 때 쓴다. 아래는 이 글의 예제를 쪽에서 바로 그린 캔버스로, SVG 그림 하나를 원본 · 잘라 키우기 · 흑백 · 필터 · 모자이크 · 원으로 잘라 내기 · 색 반전 · 겹치기로 그린 것이다.

그림 넣기

const img = new Image();
img.src = "src.svg";
await img.decode();                                // 다 받고 풀 때까지 — 그 전에 그리면 아무것도 안 나온다

ctx.drawImage(img, 8, 30);                          // 원본 크기로 (8,30) 에
ctx.drawImage(img, 8, 30, 84, 46);                  // 84×46 으로 줄여서
ctx.drawImage(img, 115, 10, 70, 70, 106, 8, 84, 84);   // 원본의 (115,10) 70×70 을 잘라 (106,8) 에 84×84 로
  • 인자가 9 개인 형태는 "원본에서 자를 상자 4 개 · 캔버스에 놓을 상자 4 개" 다
  • img, <video>(지금 장면), 다른 canvas, ImageBitmap 을 모두 받는다
  • 파일 선택으로 받은 사진은 await createImageBitmap(file) 로 바로 그림이 된다

픽셀 읽기 · 쓰기

const px = ctx.getImageData(x, y, w, h);           // 168×168 — data 는 Uint8ClampedArray(112896)
const d = px.data;                                  // [R, G, B, A, R, G, B, A, …] 0 ~ 255
for (let i = 0; i < d.length; i += 4) {
  const v = 0.299 * d[i] + 0.587 * d[i + 1] + 0.114 * d[i + 2];   // 밝기
  d[i] = d[i + 1] = d[i + 2] = v;                   // 흑백
}
ctx.putImageData(px, x, y);

ctx.getImageData(cx, cy, 1, 1).data;                // [245, 198, 199, 255] — 한 점의 색 (스포이트)
  • getImageData · putImageData 의 좌표는 변환(scale(dpr)) 이 적용되지 않은 실제 픽셀이다. DPI 대응한 캔버스에서는 dpr 을 곱해 준다
  • 반전은 d[i] = 255 - d[i] 를 R · G · B 에 한다. 값은 0 ~ 255 로 저절로 잘린다(Clamped)
  • 큰 사진을 매 장면 픽셀로 고치면 느리다. 되는 것은 아래 filter 로 한다

필터 · 겹치기 · 잘라 내기

ctx.filter = "sepia(1) blur(1.5px)";               // CSS filter 와 같은 글
ctx.drawImage(img, …);
ctx.filter = "none";

ctx.imageSmoothingEnabled = false;                  // 작은 그림을 키울 때 부드럽게 하지 않는다 — 모자이크 · 픽셀 그림
ctx.drawImage(small10x10, x, y, 84, 84);

ctx.globalCompositeOperation = "multiply";          // 겹친 곳의 색을 곱한다 — 겹칠수록 어둡다
ctx.globalCompositeOperation = "destination-in";    // 이미 그린 것 중 새 도형과 겹친 곳만 남긴다

ctx.save();
ctx.beginPath();
ctx.arc(cx, cy, r, 0, Math.PI * 2);
ctx.clip();                                         // 그 뒤 그림은 원 안에만 — 프로필 사진
ctx.drawImage(img, …);
ctx.restore();

내보내기

canvas.toDataURL("image/png");                      // "data:image/png;base64,…" — 작은 그림 · img.src
const blob = await new Promise((r) => canvas.toBlob(r, "image/webp", 0.9));   // 파일 — 품질 0 ~ 1

const a = Object.assign(document.createElement("a"), { href: URL.createObjectURL(blob), download: "photo.webp" });
a.click();                                          // 내려받기
await fetch("/upload", { method: "POST", body: blob });   // 올리기
  • 큰 그림은 toDataURL 보다 toBlob 이 빠르고 메모리를 덜 쓴다
  • 사진을 올리기 전에 줄이려면 작은 캔버스에 drawImage 로 줄여 그린 뒤 toBlob 한다

다른 출처의 그림

const x = new Image();
x.src = "https://other.example.com/a.png";
ctx.drawImage(x, 0, 0);          // 그려지기는 한다
ctx.getImageData(0, 0, 1, 1);    // SecurityError: The canvas has been tainted by cross-origin data.
  • 다른 출처의 그림을 그리면 캔버스가 "오염" 되어 읽기 · 내보내기가 막힌다. 남의 사진을 몰래 읽지 못하게 하는 장치다
  • 그 서버가 Access-Control-Allow-Origin 을 보내면, x.crossOrigin = "anonymous" 를 src 보다 먼저 주고 받는다
  • 스크립트로 만든 그림은 오염되지 않는다. 위 예제는 원본 SVG 를 글자로 들고 있다가 URL.createObjectURL(new Blob([svg], { type: "image/svg+xml" })) 로 그림을 만들어, getImageData 로 흑백 · 반전을 한다
  • file:// 로 연 쪽은 그림이 모두 다른 출처로 취급된다. 로컬 서버(python3 -m http.server) 로 연다

예전에는

  • 그림을 img.onload = () => … 콜백 안에서 그렸다. 지금은 await img.decode() 다
  • 흐림 · 흑백을 픽셀 반복으로 직접 계산했다. 지금은 ctx.filter 한 줄이다
