이벤트는 클릭 · 입력 · 키 · 스크롤 같은 일이 일어났다는 알림이다. 요소에 addEventListener 로 함수를 연결해 두면 그 일이 일어날 때 불린다. 이벤트는 누른 요소에서 위로 부모를 따라 올라가므로(버블링), 많은 요소의 이벤트를 부모 하나에서 받는다.

받기

button.addEventListener("click", (e) => {
  e.target;          // 실제로 누른 요소
  e.currentTarget;   // 함수를 연결한 요소 (여기서는 button)
});

button.addEventListener("click", onFirst, { once: true });     // 한 번만
window.addEventListener("scroll", onScroll, { passive: true }); // preventDefault 를 안 한다고 약속 — 스크롤이 부드럽다
button.removeEventListener("click", onClick);                   // 같은 함수를 넘겨야 빠진다

const ac = new AbortController();
document.addEventListener("keydown", onKey, { signal: ac.signal });
window.addEventListener("resize", onResize, { signal: ac.signal });
ac.abort();                                                      // 여럿을 한 번에 뺀다 — 화면을 닫을 때
  • removeEventListener 는 화살표 함수를 그 자리에서 쓰면 뺄 수 없다. signal 을 쓰면 함수를 따로 들고 있지 않아도 된다

전파

<div id="outer"><div id="inner"><button id="btn">누르기</button></div></div>
outer.addEventListener("click", () => log("outer 캡처"), true);   // 세 번째 인자 true — 내려갈 때
outer.addEventListener("click", () => log("outer 버블"));
inner.addEventListener("click", (e) => log(`inner 버블, target=${e.target.id}, currentTarget=${e.currentTarget.id}`));
btn.addEventListener("click", () => log("btn"));
// btn 을 누르면:
// outer 캡처 → btn → inner 버블, target=btn, currentTarget=inner → outer 버블
flowchart LR
  W["window"] -- 캡처 --> O["outer"] -- 캡처 --> I["inner"] -- 캡처 --> B["btn (target)"]
  B -. 버블 .-> I2["inner"] -. 버블 .-> O2["outer"] -. 버블 .-> W2["window"]
메서드 하는 일
e.stopPropagation() 더 올라가지 않는다 — inner 에서 부르면 outer 버블이 불리지 않는다
e.preventDefault() 브라우저의 기본 동작을 막는다 — 링크 이동 · 폼 보내기 · 단축키
e.stopImmediatePropagation() 같은 요소의 다른 함수도 막는다
  • stopPropagation 은 되도록 쓰지 않는다. 바깥에서 "밖을 누르면 닫기" 같은 처리가 이벤트를 못 받게 된다
  • focus · blur · mouseenter 는 올라가지 않는다. 부모에서 받으려면 focusin · focusout · pointerover 를 쓴다

위임

목록의 항목마다 연결하지 않고 목록에 하나만 연결한다. 나중에 더한 항목도 그대로 받는다.

ul.addEventListener("click", (e) => {
  const del = e.target.closest(".del");
  if (del) return del.closest("li").remove();
  const li = e.target.closest("li");
  if (li && ul.contains(li)) li.classList.toggle("done");
});
  • e.target 은 li 안의 <b> 일 수도 있다. closest 로 원하는 요소까지 올라간다

자주 받는 이벤트

이벤트 언제
click · dblclick · contextmenu 누름 · 두 번 · 오른쪽 단추
pointerdown · pointermove · pointerup 마우스 · 터치 · 펜을 한 가지로
keydown · keyup 키 — e.key("a" · "Enter" · "ArrowUp") · e.code("KeyA") · e.ctrlKey · e.metaKey
input · change 값이 바뀌는 중 · 바뀌고 끝남
submit 폼을 보낼 때 — 폼에 연결한다
focusin · focusout 포커스가 들어옴 · 나감 (올라간다)
scroll · resize 스크롤 · 창 크기
DOMContentLoaded · load 문서를 다 읽음 · 그림까지 다 받음
visibilitychange 탭을 숨김 · 다시 봄 — document.hidden 
document.addEventListener("keydown", (e) => {
  if ((e.ctrlKey || e.metaKey) && e.key === "s") {   // ⌘S · Ctrl+S
    e.preventDefault();                              // 브라우저의 "쪽 저장" 을 막는다
    save();
  }
  if (e.key === "Escape") closeDialog();
});
  • 글자 키는 e.key, 자판 위치(게임의 WASD) 는 e.code 로 본다. 한글 입력 중에는 e.isComposing 이 true 이고, 이때 Enter 는 글자를 끝내는 것이라 무시한다

자주 오는 이벤트 줄이기

input · scroll · resize 는 1 초에 수십 번 온다. 멈춘 뒤 한 번만 처리한다.

function debounce(fn, ms) {
  let id;
  return (...args) => { clearTimeout(id); id = setTimeout(() => fn(...args), ms); };
}
search.addEventListener("input", debounce((e) => find(e.target.value), 300));
  • 화면에 그리는 일은 requestAnimationFrame(draw) 로 한 장에 한 번만 한다
  • 요소가 화면에 들어왔는지는 scroll 대신 IntersectionObserver, 크기가 바뀌었는지는 resize 대신 ResizeObserver 로 본다

내 이벤트

ul.addEventListener("todo:add", (e) => console.log(e.detail));     // {id: 5, title: "청소"}
ul.dispatchEvent(new CustomEvent("todo:add", { detail: { id: 5, title: "청소" }, bubbles: true }));
  • 컴포넌트끼리 서로를 몰라도 이벤트로 알린다. 이름에 todo: 처럼 앞말을 붙여 브라우저 이벤트와 겹치지 않게 한다
  • dispatchEvent 는 누가 preventDefault 를 부르면 false 를 돌려준다 (cancelable: true 일 때)

예전에는

  • onclick="…" 속성 · el.onclick = f 로 연결해 함수를 하나만 걸 수 있었다. 지금은 addEventListener 로 여럿을 건다
  • IE 는 attachEvent 와 window.event 를 썼고, 위임은 jQuery 의 .on("click", "li", f) 로 했다
  • 마우스 · 터치를 mousedown · touchstart 로 따로 받았다. 지금은 pointerdown 하나다
