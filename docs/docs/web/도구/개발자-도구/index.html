브라우저의 개발자 도구(⌥⌘I · F12) 는 지금 열린 쪽의 DOM · CSS · 콘솔 · 네트워크 · 저장소 · 성능을 보여 주고 그 자리에서 고치게 한다. 고친 것은 새로 고침하면 사라지므로, 원인을 찾고 시험해 본 뒤 소스에 옮긴다. 아래는 Chrome 기준이고 Firefox · Safari 도 이름만 조금 다르다.

패널

패널 하는 일
Elements DOM 나무 · 걸린 CSS 규칙과 이긴 규칙 · 박스 모델 · Flexbox · Grid 겹쳐 보기
Console 로그 · 오류 · 바로 실행
Sources 중단점 · 한 줄씩 실행 · 로컬 파일로 고쳐 쓰기(Overrides)
Network 요청마다 헤더 · 본문 · 걸린 시간 · 캐시 여부
Application localStorage · IndexedDB · 쿠키 · 캐시 · 서비스 워커
Performance 한 장면에 무엇이 시간을 썼나 — 긴 작업 · 다시 배치 · 그리기
Lighthouse 성능 · 접근성 · SEO 점수와 고칠 점
  • ⌘⇧P 로 명령 창을 열어 "screenshot" · "dark" · "disable JavaScript" 처럼 기능 이름으로 찾는다
  • ⌘⇧C 로 화면에서 요소를 눌러 Elements 로 간다
  • ⌘⇧M 은 기기 모드다. 폭 · 기기 · 터치 · 회전을 바꿔 본다

Elements

  • 규칙 위의 줄 그어진 속성은 다른 규칙에 졌다는 뜻이다. Computed 탭에서 최종 값을 누르면 이긴 규칙으로 간다
  • :hov 로 :hover · :focus 상태를 고정해 놓고 꾸민다
  • display: flex · grid 옆의 단추를 누르면 칸 · 간격이 화면에 겹쳐 그려진다
  • 요소를 오른쪽 클릭 › Break on › subtree modifications 로, 그 요소를 바꾸는 스크립트 줄에서 멈춘다

Console

$0                                  // Elements 에서 선택한 요소
$("#list li")                       // document.querySelector
$$("#list li")                      // querySelectorAll — 배열로
copy(JSON.stringify(data))          // 클립보드로
monitorEvents($0, "click")          // 그 요소의 이벤트를 모두 찍기
console.table(rows)                 // 배열 · 객체를 표로
console.time("load"); console.timeEnd("load")   // load: 12.3 ms
  • 콘솔에서는 await 를 그대로 쓴다: await (await fetch("/api/todos")).json()
  • console.log(obj) 는 펼칠 때의 값을 보인다. 찍은 때의 값을 보려면 console.log(structuredClone(obj)) 를 쓴다

Sources — 중단점

  • 줄 번호를 누르면 중단점, 오른쪽 클릭으로 조건부 중단점(id === 7) · 로그 중단점(코드를 고치지 않고 console.log) 을 단다
  • 코드에 debugger; 를 적어도 그 자리에서 멈춘다
  • 멈춘 상태에서 Scope 에 지역 변수가, Call Stack 에 불린 차례가 보인다. 콘솔에서 그 자리의 변수로 식을 실행한다
  • 빌드된 코드도 소스 맵이 있으면 원래 파일 · 줄로 보인다

Network

  • Preserve log 를 켜면 쪽을 옮겨도 기록이 남는다. 로그인 · 결제처럼 쪽이 넘어가는 흐름을 볼 때 켠다
  • Disable cache 는 개발자 도구가 열려 있을 때만 캐시를 끈다
  • 느린 3G · 오프라인으로 바꿔 대기 화면 · 오류 화면을 본다
  • 요청을 오른쪽 클릭 › Copy as cURL 로 같은 요청을 터미널에서 다시 보낸다. Block request URL 로 그 파일이 없을 때를 본다
  • Size 열의 (disk cache) · (memory cache) 는 서버에 묻지 않은 것, 상태 304 는 물어보고 캐시를 쓴 것이다

Performance · Lighthouse

  • 녹화 › 동작 › 멈춤 하면 장면마다 스크립트 · 배치(Layout) · 그리기가 걸린 시간이 나온다. 빨간 삼각형이 붙은 Long task(50ms 넘음) 가 버벅임의 원인이다
  • CPU 를 4 배 느리게 두고 재면 보통 휴대폰과 비슷하다
  • Lighthouse 는 시크릿 창에서 돌린다. 확장 프로그램이 점수를 바꾼다

휴대폰 쪽 보기

  • Android: USB 디버깅을 켜고 연결한 뒤 Chrome 에서 chrome://inspect 를 연다. 휴대폰의 탭을 PC 개발자 도구로 본다
  • iPhone: 설정 › Safari › 고급 › 웹 속성(Web Inspector) 을 켜고 연결한 뒤, Mac Safari 의 개발자용 메뉴에서 기기를 선택한다

예전에는

  • 개발자 도구가 브라우저에 없어 Firefox 확장 Firebug 를 깔았다. 지금의 개발자 도구는 Firebug 를 본떴다
  • 디버깅을 alert() 로 값을 띄워 했다. 지금은 중단점과 로그 중단점을 쓴다
