헤더는 요청 · 응답에 붙는 이름: 값 줄로, 본문의 형식 · 길이 · 압축 · 언어 · 인증 · 캐시 규칙 같은 덧붙임 정보를 담는다. 그중 캐시 헤더는 "이 응답을 얼마 동안 다시 묻지 않고 써도 되는지, 다시 물을 때 무엇으로 견줄지" 를 정해, 쪽을 빠르게 하고 서버의 짐을 던다.

자주 보는 헤더

헤더 쪽 뜻
Content-Type 둘 다 본문의 형식 — application/json; charset=utf-8
Content-Length · Transfer-Encoding: chunked 둘 다 본문 길이 · 조각으로 나눠 보냄
Accept · Accept-Language · Accept-Encoding 요청 받고 싶은 형식 · 언어 · 압축(gzip, br, zstd)
Content-Encoding 응답 실제로 한 압축 — br
Authorization 요청 인증 — Bearer eyJhbGci…
Location 응답 옮긴 곳 · 새로 만든 것의 주소
Cache-Control · ETag · Last-Modified 응답 캐시 규칙 · 판 표시
Vary 응답 이 요청 헤더가 다르면 다른 응답이다 — Accept-Encoding · Origin
Set-Cookie · Cookie 응답 · 요청 쿠키
Strict-Transport-Security 응답 앞으로 이 사이트는 https 로만
Content-Security-Policy 응답 스크립트 · 그림을 받아도 되는 곳 — XSS 막기
  • 헤더 이름은 대소문자를 가리지 않는다. HTTP/2 부터는 모두 소문자로 오간다
  • 내 헤더는 X- 를 붙이지 않고 뜻이 드러나는 이름을 쓴다(Request-Id). X- 는 예전 관례다

캐시 두 가지

sequenceDiagram
  participant B as 브라우저
  participant S as 서버
  B->>S: GET /assets/app.3f9a1c.js
  S-->>B: 200 · Cache-Control: max-age=31536000, immutable
  Note over B: 1 년 동안 묻지 않고 캐시에서 쓴다
  B->>S: GET /api/todos
  S-->>B: 200 · ETag: "cIgZsr1sIr46" · Cache-Control: no-cache
  B->>S: GET /api/todos · If-None-Match: "cIgZsr1sIr46"
  S-->>B: 304 Not Modified (본문 없음)
  Note over B: 캐시의 본문을 쓴다
방식 헤더 쓰는 곳
묻지 않고 쓰기(신선함) Cache-Control: max-age=초 이름에 해시가 붙은 JS · CSS · 그림
물어보고 쓰기(재검증) ETag + If-None-Match → 304 HTML · API 처럼 바뀔 수 있는 것 
$ curl -i http://127.0.0.1:8801/api/todos
HTTP/1.1 200 OK
ETag: "cIgZsr1sIr46"
Cache-Control: no-cache

$ curl -i -H 'If-None-Match: "cIgZsr1sIr46"' http://127.0.0.1:8801/api/todos
HTTP/1.1 304 Not Modified                        ← 본문 없이 — 그대로 써라
ETag: "cIgZsr1sIr46"

Cache-Control

값 뜻
max-age=31536000, immutable 1 년 동안 그대로 쓴다 — 바뀌면 파일 이름(해시) 이 바뀐다
no-cache 저장은 하되 쓸 때마다 서버에 물어본다 (ETag)
no-store 저장하지 않는다 — 개인 정보 · 은행 쪽
private 브라우저만 저장 — CDN · 프록시는 저장하지 않는다 (로그인한 사람의 응답)
public · s-maxage=60 CDN 도 저장 · CDN 만 60 초
stale-while-revalidate=30 지났어도 30 초 동안은 낡은 것을 먼저 보이고 뒤에서 새로 받는다
  • no-cache 는 "캐시하지 마라" 가 아니다. 저장하지 말라는 것은 no-store 다
  • 흔한 짜임: HTML 은 no-cache, 빌드 도구가 app.3f9a1c.js 처럼 해시를 붙인 파일은 max-age=31536000, immutable 이다. 배포하면 HTML 이 새 파일 이름을 가리켜 바로 바뀐다

압축 · 범위

$ curl -sI -H 'Accept-Encoding: br, gzip' https://developer.mozilla.org/en-US/
HTTP/2 200
content-encoding: br                             ← Brotli 로 줄였다
vary: Accept-Encoding                            ← 압축을 받는지에 따라 응답이 다르다
  • 서버 · CDN 이 Accept-Encoding 을 보고 br(Brotli) · gzip 으로 줄여 보낸다. 글자 파일은 70 ~ 80% 줄어든다
  • 큰 파일 이어받기 · 동영상 건너뛰기는 Range: bytes=1000- 요청과 206 Partial Content 응답으로 한다

확인하기

  • 개발자 도구 네트워크 탭의 Size 열에 (disk cache) · (memory cache) 가 보이면 서버에 묻지 않은 것, 상태가 304 면 물어본 것이다
  • 캐시를 끄고 보려면 네트워크 탭의 "Disable cache" 를 켠다. ⌘⇧R 은 이 쪽만 캐시를 무시하고 다시 받는다

예전에는

  • Expires: Thu, 01 Dec 2026 16:00:00 GMT 처럼 날짜로 정했다. 시계가 어긋나면 틀려서 지금은 max-age 다
  • Pragma: no-cache 는 HTTP/1.0 의 것이다. 지금은 Cache-Control 만 쓴다
  • 캐시를 깨려고 app.js?v=20261108 처럼 쿼리를 붙였다. 일부 프록시가 쿼리가 붙은 것을 캐시하지 않아, 지금은 파일 이름에 해시를 넣는다
