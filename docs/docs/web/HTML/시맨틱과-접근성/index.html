시맨틱 태그는 모양이 아니라 뜻을 나타내는 태그다(header · nav · main · article · button …). 뜻에 맞는 태그를 쓰면 화면 읽기 프로그램 · 키보드 · 검색 엔진이 문서를 제대로 다루고, 따로 손대지 않아도 접근성의 대부분이 해결된다. div 에 스크립트로 같은 일을 시키면 그 기능을 하나하나 다시 만들어야 한다.

쪽의 큰 틀

<body>
  <header>
    <a href="/">메모</a>
    <nav aria-label="주 메뉴">
      <ul>
        <li><a href="/notes" aria-current="page">메모</a></li>
        <li><a href="/settings">설정</a></li>
      </ul>
    </nav>
  </header>

  <main>                                         <!-- 쪽의 본문 — 하나만 -->
    <h1>메모</h1>
    <article>                                    <!-- 따로 떼어도 뜻이 통하는 글 하나 -->
      <h2>장보기</h2>
      <p><time datetime="2026-11-08">11 월 8 일</time> 에 적었다.</p>
    </article>
    <aside>관련 메모</aside>                     <!-- 곁가지 내용 -->
  </main>

  <footer>© 2026</footer>
</body>
태그 뜻
header · footer 쪽 · 글의 머리 · 꼬리
nav 다른 쪽으로 가는 링크 묶음
main 본문 — 쪽에 하나
article 혼자 서는 글 (블로그 글 · 댓글 · 카드)
section 제목이 있는 내용 묶음
aside 곁가지 (사이드바 · 덧붙임)
figure · figcaption 그림 · 표 · 코드와 그 설명
  • 화면 읽기 프로그램은 이 태그들을 랜드마크로 보여 주고, 사용자는 "본문으로" · "메뉴로" 처럼 건너뛴다
  • 제목(h1 ~ h6) 이 문서의 차례가 된다. 글자 크기를 위해 제목 태그를 선택하지 않는다

단추와 링크

하는 일 태그
다른 주소로 간다 <a href>
이 쪽에서 무언가 한다 (열기 · 저장 · 지우기) <button type="button">
폼을 보낸다 <button> (폼 안의 기본 type 은 submit) 
<!-- 하지 않는다 -->
<div class="btn" onclick="save()">저장</div>

<!-- 한다 -->
<button type="button" onclick="save()">저장</button>
  • button 은 Tab 으로 가고, Enter · Space 로 눌리고, "단추" 라고 읽힌다. div 는 셋 다 안 된다(tabIndex 가 -1)
  • 폼 안의 <button> 은 type 을 적지 않으면 submit 이라, 누르면 폼이 보내진다. 보내지 않는 단추는 type="button" 을 적는다

그림 · 이름

<img src="chart.png" alt="11 월 걸음 수. 토요일이 11,200 보로 가장 많다">   <!-- 그림이 전하는 내용 -->
<img src="divider.png" alt="">                                              <!-- 꾸밈 그림 — 빈 alt -->

<button type="button" aria-label="닫기">✕</button>          <!-- 글자 없는 단추에 이름 -->
<svg aria-hidden="true">…</svg>                             <!-- 읽지 않아도 되는 아이콘 -->

<label for="q">검색</label>
<input id="q" type="search">                                <!-- 입력 칸은 label 로 이름 -->
  • alt 를 아예 빼면 화면 읽기 프로그램이 파일 이름을 읽는다. 꾸밈 그림은 alt="" 로 건너뛰게 한다
  • 이름이 보이는 글자로 있으면 그것을 쓰고, 없을 때만 aria-label 을 쓴다

기본으로 있는 위젯

스크립트 없이 HTML 만으로 되는 것은 그것을 쓴다. 키보드 · 포커스 · 읽기가 따라온다.

<details>
  <summary>더 보기</summary>                  <!-- 눌러서 펼치기 · 접기 -->
  <p>숨은 내용</p>
</details>

<dialog id="confirm">                           <!-- 대화상자 -->
  <form method="dialog">                        <!-- 단추를 누르면 닫히고, value 가 returnValue 가 된다 -->
    <p>저장할까요?</p>
    <button value="cancel">취소</button>
    <button value="ok">저장</button>
  </form>
</dialog>
<script>
  const dlg = document.getElementById("confirm");
  dlg.showModal();                              // 뒤를 막고 포커스를 가둔다 · Esc 로 닫힌다
  dlg.addEventListener("close", () => console.log(dlg.returnValue));   // "ok"
</script>
  • showModal() 로 연 대화상자는 ::backdrop 으로 뒤를 어둡게 하고, 닫히면 포커스가 연 단추로 돌아간다

ARIA

태그로 나타낼 수 없는 상태 · 관계만 ARIA 속성으로 더한다. 태그로 되는 것을 ARIA 로 덮지 않는다.

<button aria-expanded="false" aria-controls="menu">메뉴</button>   <!-- 펼쳤는지 -->
<ul id="menu" hidden>…</ul>

<p role="status">저장했다</p>                  <!-- 바뀌면 읽어 준다 (aria-live="polite") -->
<input aria-invalid="true" aria-describedby="email-error">
<p id="email-error">이메일 형식이 아니다</p>

확인하기

  • 키보드만으로(Tab · Shift+Tab · Enter · Space · Esc) 모든 기능을 써 본다. 포커스 테두리가 보여야 한다(outline: none 으로 지우지 않는다)
  • Chrome 개발자 도구의 Lighthouse · 접근성 패널, axe DevTools 로 빠진 이름 · 대비를 찾는다
  • macOS VoiceOver(⌘ F5) 로 직접 들어 본다
