MySQL 에서 PostgreSQL 로 옮기면 대부분의 SQL 은 그대로 돌지만, 자동 번호 · 따옴표 · 이름의 대소문자 · upsert 처럼 자주 쓰는 몇 가지가 다르다. 어떤 것은 문법 오류로 바로 드러나고, 어떤 것은 오류 없이 다른 값을 돌려준다(글자 비교 · 나눗셈). 아래는 같은 SQL 을 mysql:8.4(8.4.13) 와 postgres:18(18.6) 의 빈 DB 에 넣어 본 결과다.

오류로 드러나는 것

쓰는 것 MySQL PostgreSQL
자동 번호 id INT AUTO_INCREMENT PRIMARY KEY id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY (또는 SERIAL)
upsert INSERT … ON DUPLICATE KEY UPDATE n = n + 1 INSERT … ON CONFLICT (name) DO UPDATE SET n = c.n + 1
넣은 행 돌려받기 (없음 — LAST_INSERT_ID()) INSERT … RETURNING id
건너뛰고 가져오기 LIMIT 1, 1 LIMIT 1 OFFSET 1 (둘 다 된다)
이름 감싸기 `Orders` "Orders"

서로 상대의 문법을 넣으면 이렇게 막힌다.

-- PostgreSQL 에 AUTO_INCREMENT
ERROR:  syntax error at or near "AUTO_INCREMENT"
-- MySQL 에 IDENTITY
ERROR 1064 (42000) at line 1: You have an error in your SQL syntax; … near 'IDENTITY PRIMARY KEY, name VARCHAR(20))'
-- PostgreSQL 에 LIMIT 1, 1
ERROR:  LIMIT #,# syntax is not supported
HINT:  Use separate LIMIT and OFFSET clauses.
-- MySQL 에 RETURNING
ERROR 1064 (42000) at line 1: You have an error in your SQL syntax; … near 'RETURNING id'
  • LIMIT n OFFSET m 은 MySQL 에서도 되므로, 둘에 함께 쓸 SQL 은 이 꼴로 적는다
  • GENERATED ALWAYS 열에 번호를 직접 넣으면 ERROR: cannot insert a non-DEFAULT value into column "id" 다. 옮겨 온 자료처럼 번호를 지켜 넣을 때는 INSERT … OVERRIDING SYSTEM VALUE 를 쓰거나 GENERATED BY DEFAULT 로 만든다
  • ON CONFLICT 로 갱신에 그친 시도도 번호를 하나 쓴다. apple 을 갱신한 뒤 넣은 pear 의 번호가 2 가 아니라 3 이었다

오류 없이 값이 다른 것

SELECT 'Apple' = 'apple' AS same, 7/2 AS d, 'a' || 'b' AS cat;
MySQL PostgreSQL
'Apple' = 'apple' 1 — 기본 정렬 규칙이 대소문자를 가리지 않는다 f — 가린다
7/2 3.5000 3 — 정수끼리는 정수 나눗셈
'a' || 'b' 0 — || 가 OR 다 ab — 글자 연결
BOOLEAN 열 1 (속은 TINYINT(1)) t
SELECT "name" FROM c name — 큰따옴표가 글자다 apple — 큰따옴표가 열 이름이다
  • 대소문자를 가리지 않고 찾던 SQL(WHERE email = ?) 은 PostgreSQL 에서 덜 찾는다. lower(email) = lower(?) 로 쓰거나 citext 확장 자료형을 쓴다
  • 나눗셈은 한쪽을 소수로 바꾼다(7::numeric / 2 → 3.5000000000000000). 거꾸로 MySQL 에서 정수 나눗셈은 7 DIV 2(→ 3) 다
  • 글자 연결은 둘 다 되는 CONCAT('a', 'b') 를 쓴다
  • 글자는 '작은따옴표' 로만 적는다. PostgreSQL 에서 "…" 는 이름이다

이름의 대소문자

CREATE TABLE Orders (id INT);
SELECT * FROM orders;
  • PostgreSQL 은 따옴표 없는 이름을 소문자로 바꿔 orders 표를 만든다. 그래서 orders 로 찾아지고, "Orders" 로 찾으면 ERROR: relation "Orders" does not exist 다
  • 리눅스의 MySQL 은 표 이름이 파일 이름이라 대소문자를 가린다. Orders 로 만든 표를 orders 로 찾으면 ERROR 1146 (42S02): Table 'cmp.orders' doesn't exist 다. 이 컨테이너의 lower_case_table_names 는 0(가린다) 이었고, 맥 · 윈도우의 MySQL 은 이 기본값이 달라 찾아진다
  • PostgreSQL 에서는 이름을 모두 소문자와 _ 로 짓는다. 대문자 이름을 따옴표로 만들면 그 뒤로 늘 따옴표를 붙여야 한다

그 밖에

MySQL PostgreSQL
DB 안의 나눔 DB = 스키마 DB 안에 스키마 여럿 (public …), 다른 DB 의 표는 한 SQL 로 읽지 못한다
문자셋 표 · 열마다 (utf8mb4 를 골라야 한다) DB 마다 정하고 보통 UTF8 하나
글자 자료형 VARCHAR(n) 의 길이를 꼭 적는다 text 를 많이 쓴다. varchar(n) 과 빠르기가 같다
날짜 · 시간 DATETIME · TIMESTAMP timestamp · timestamptz(시간대 포함, 이쪽을 쓴다)
지금 시각 NOW() now()
