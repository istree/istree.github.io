PostgreSQL 의 사용자는 role 이다. 로그인할 수 있는 role 이 사용자이고, 로그인하지 않는 role 은 권한을 묶는 그룹으로 쓴다. MySQL 과 달리 role 에는 호스트가 붙지 않는다 — 어디서 들어올지는 pg_hba.conf 가 따로 정한다. 권한은 세 겹이다: DB 에 붙을 권한, 그 안의 스키마(public) 를 쓰거나 만들 권한, 표마다 읽고 쓸 권한. 아래 예제는 PostgreSQL 16.15(Ubuntu 패키지) 에서 postgres 로 role 을 만들고, 각 role 로 127.0.0.1 에 붙어 확인했다.

만들기

CREATE ROLE app LOGIN PASSWORD 'App-pass-1';
CREATE ROLE report LOGIN PASSWORD 'Rep-pass-1';
CREATE DATABASE shop OWNER app;
                             List of roles
 Role name |                         Attributes
-----------+------------------------------------------------------------
 app       |
 postgres  | Superuser, Create role, Create DB, Replication, Bypass RLS
 report    |
  • CREATE USER 는 CREATE ROLE … LOGIN 과 같다
  • 앱의 DB 는 그 앱의 role 을 주인(OWNER) 으로 만든다. 주인은 그 DB 안에서 표를 만들고 지우는 일을 모두 한다

public 스키마 (15 부터)

DB 의 주인이 postgres 이고 app 에게 아무것도 주지 않았을 때, app 은 붙을 수는 있지만 표를 만들지 못한다.

CREATE TABLE t (id int);
-- ERROR:  permission denied for schema public
                                       List of schemas
  Name  |       Owner       |           Access privileges            |      Description
--------+-------------------+----------------------------------------+------------------------
 public | pg_database_owner | pg_database_owner=UC/pg_database_owner+| standard public schema
        |                   | =U/pg_database_owner                   |
  • 15 부터 public 스키마의 주인은 pg_database_owner(그 DB 의 주인) 이고, 다른 role 은 쓰기(U) 만 되고 만들기(C) 는 안 된다. 14 까지는 누구나 public 에 표를 만들 수 있었다
  • ALTER DATABASE shop OWNER TO app 으로 주인을 바꾸자 app 이 바로 표를 만들었다
  • 주인을 바꾸지 않고 만들게 하려면 GRANT CREATE ON SCHEMA public TO app; 이다

표 권한

표를 만든 role 만 그 표를 쓴다. 다른 role 은 따로 받아야 한다.

-- report 로
SELECT * FROM orders;
-- ERROR:  permission denied for table orders

-- app(표 주인) 으로
GRANT SELECT ON ALL TABLES IN SCHEMA public TO report;
  • ALL TABLES IN SCHEMA 는 지금 있는 표에만 준다. 그 뒤에 만든 later 표는 report 가 다시 permission denied for table later 였다
  • 앞으로 만들 표에도 주려면 기본 권한을 정한다. 아래 뒤로 만든 표는 report 가 바로 읽었다
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO report;
  • 기본 권한은 그 명령을 친 role 이 만드는 표에만 걸린다. 마이그레이션을 다른 role 로 돌린다면 그 role 로(또는 FOR ROLE 그role) 정한다
  • SELECT 만 받은 report 가 쓰려 하면 ERROR: permission denied for table orders 다
  • 자동 번호 열이 SERIAL 인 표는 INSERT 만 주면 ERROR: permission denied for sequence s_id_seq 다. 시퀀스 권한(GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO …) 도 준다. GENERATED … AS IDENTITY 열은 표의 INSERT 권한만으로 됐다

읽기 전용 role

모든 DB · 모든 표를 읽기만 하는 role 은 미리 있는 role 을 받아 만든다(14 부터).

CREATE ROLE ro LOGIN PASSWORD 'Ro-pass-1';
GRANT pg_read_all_data TO ro;
  • ro 는 따로 받지 않은 later · orders 를 모두 읽었다. 앞으로 만들 표도 읽는다
  • 쓰기까지 주는 pg_write_all_data 도 있다. 백업 role 에는 pg_read_all_data 를 준다

비밀번호 · 지우기

ALTER ROLE app PASSWORD 'App-pass-2';
REASSIGN OWNED BY report TO app;   -- report 가 가진 것을 app 에게 넘긴다
DROP OWNED BY report;              -- report 에게 준 권한을 거둔다
DROP ROLE report;
  • 가진 표나 받은 권한이 남은 role 은 DROP ROLE 이 ERROR: role "report" cannot be dropped because some objects depend on it 으로 거부한다(DETAIL: 7 objects in database shop). 위 두 줄을 그 DB 마다 먼저 돌린다
  • 비밀번호가 틀리면 FATAL: password authentication failed for user "app" 이다. pg_hba.conf 에 맞는 줄이 없을 때의 no pg_hba.conf entry 와 나눠 본다
