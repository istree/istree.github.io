PostgreSQL 은 Ubuntu 패키지(postgresql) 로 서버에 바로 깔거나, Docker 이미지(postgres) 로 띄운다. 어느 쪽이든 처음 들어가는 관리자는 postgres role 이다. 다만 Ubuntu 패키지는 비밀번호 없이 OS 의 postgres 사용자로만 들어오고(peer), Docker 이미지는 띄울 때 준 비밀번호를 쓴다. 누가 어디서 어떤 방식으로 들어올지는 pg_hba.conf 가 한 줄씩 정한다. 아래 예제는 ubuntu:24.04 에 apt 로 깐 PostgreSQL 16.15 와 postgres:18(18.6) 컨테이너에서 돌렸다.

Ubuntu 패키지

sudo apt install postgresql
pg_lsclusters
Ver Cluster Port Status Owner    Data directory              Log file
16  main    5432 online postgres /var/lib/postgresql/16/main /var/log/postgresql/postgresql-16-main.log
sudo -u postgres psql            # OS 의 postgres 사용자로 들어간다
psql -U postgres                 # 다른 OS 사용자로는 막힌다
# psql: error: connection to server on socket "/var/run/postgresql/.s.PGSQL.5432" failed: FATAL:  Peer authentication failed for user "postgres"
  • 깔면 클러스터(판 16, 이름 main) 하나가 만들어지고 바로 뜬다. 서비스는 systemctl status postgresql@16-main 이다. 판을 올리면 클러스터가 판마다 따로 생긴다 — pg_lsclusters 로 본다
  • 소켓으로 들어오면(local) peer 방식이라 OS 사용자 이름과 role 이름이 같아야 한다. 그래서 sudo -u postgres 로 들어간다
  • 설정은 /etc/postgresql/16/main/(postgresql.conf · pg_hba.conf · conf.d/), 자료는 /var/lib/postgresql/16/main/, 로그는 /var/log/postgresql/ 다
  • 처음에는 127.0.0.1 · ::1 의 5432 에서만 듣는다(listen_addresses = 'localhost')

Docker

docker run -d --name pg \
  -e POSTGRES_PASSWORD=Root-pass-1 \
  -v pg-data:/var/lib/postgresql \
  -p 127.0.0.1:5432:5432 \
  postgres:18
docker logs pg 2>&1 | grep "init process complete"
docker exec -it pg psql -U postgres
  • 처음 띄울 때 임시 서버로 DB 를 만든 뒤 다시 뜬다. 로그에 PostgreSQL init process complete; ready for start up. 이 나온 뒤에 붙는다. pg_isready 는 accepting connections 로 답한다
  • POSTGRES_USER · POSTGRES_DB 를 주면 관리자 이름 · 첫 DB 를 바꾼다. 이 값들은 자료 폴더가 비어 있을 때 한 번만 쓰인다
  • 18 부터 자료 폴더가 /var/lib/postgresql/18/docker 로 바뀌어, 볼륨은 /var/lib/postgresql 에 붙인다. 17 까지처럼 /var/lib/postgresql/data 에 붙이면 Error: in 18+, these Docker images are configured to store database data in a format which is compatible with "pg_ctlcluster" 로 뜨지 않는다
  • 컨테이너 안에서는 비밀번호 없이 들어간다(local all all trust). 바깥에서는 host all all all scram-sha-256 줄 때문에 비밀번호를 묻는다

psql

psql -h 127.0.0.1 -p 5432 -U app shop       # 호스트 · 포트 · role · DB
psql -U app -d shop -c "SELECT now()"       # 명령 하나만
psql -U app -d shop -f schema.sql           # 파일을 돌린다
명령 뜻
\l DB 목록
\c shop 다른 DB 로 옮긴다
\dt · \d orders 표 목록 · 표 하나의 열 · 인덱스
\du role 목록
\dn+ 스키마와 그 권한
\x 한 행을 세로로 보인다 (열이 많을 때)
\q 끝낸다 
                         Table "public.orders"
 Column |  Type   | Collation | Nullable |           Default
--------+---------+-----------+----------+------------------------------
 id     | integer |           | not null | generated always as identity
 item   | text    |           |          |
 qty    | integer |           |          |
Indexes:
    "orders_pkey" PRIMARY KEY, btree (id)
  • DB 이름을 주지 않으면 role 이름과 같은 DB 로 간다. 없으면 FATAL: database "app" does not exist 다
  • 비밀번호는 PGPASSWORD 환경 변수나 ~/.pgpass(호스트:포트:DB:role:비밀번호, 권한 600) 에 둔다

바깥에서 접속

다른 서버에서 붙으려면 두 곳을 고친다. 듣는 주소(listen_addresses) 와 들여보낼 규칙(pg_hba.conf) 이다. 아래는 172.17.0.3 에서 172.17.0.2 의 서버로 붙어 본 것이다.

고친 것 붙으면
(그대로) Connection refused — 127.0.0.1 에서만 듣는다
listen_addresses = '*' 뒤 재시작 FATAL: no pg_hba.conf entry for host "172.17.0.3", user "app", database "shop", no encryption
pg_hba.conf 에 한 줄 더한 뒤 reload 들어간다 
# /etc/postgresql/16/main/conf.d/listen.conf
listen_addresses = '*'
# /etc/postgresql/16/main/pg_hba.conf — 종류 DB role 주소 방식
host    shop    app    172.17.0.0/16    scram-sha-256
sudo systemctl restart postgresql     # listen_addresses 는 재시작해야 바뀐다
sudo systemctl reload postgresql      # pg_hba.conf 는 reload 로 된다
sudo -u postgres psql -c "SELECT line_number, database, user_name, address, auth_method, error FROM pg_hba_file_rules"
  • pg_hba.conf 는 위에서부터 보고 처음 맞는 줄을 따른다. 위 줄은 shop DB 에 app 만 들여보내므로, 같은 곳에서 report 로 붙으면 그대로 no pg_hba.conf entry 다
  • pg_hba_file_rules 는 파일을 읽은 결과다. 잘못 적은 줄은 error 열에 까닭이 나온다
  • 방식은 scram-sha-256(비밀번호) 을 쓴다. trust 는 비밀번호 없이 들여보내므로 바깥 주소에 쓰지 않는다
  • 인터넷에 5432 를 열지 않는다. 방화벽에서 앱 서버에만 열고, 내 컴퓨터에서 볼 때는 SSH 터널(ssh -L 5432:127.0.0.1:5432 서버) 로 붙는다
