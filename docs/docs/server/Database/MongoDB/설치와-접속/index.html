MongoDB 는 Ubuntu 기본 저장소에 없다. MongoDB 의 apt 저장소를 더해 mongodb-org 를 깔거나, Docker 이미지(mongo) 로 띄운다. 둘은 처음 상태가 다르다 — 저장소 패키지는 127.0.0.1 에서만 듣고 인증이 꺼져 있으며, Docker 이미지는 모든 주소에서 듣고 root 사용자를 주면 인증이 켜진다. 사용자는 어느 DB 에서 만들었는지(인증 DB) 가 붙어, 접속할 때 그 DB 를 authSource 로 알려야 한다. 아래 예제는 ubuntu:24.04 에 MongoDB 저장소로 깐 9.0.4 와 mongo:9(9.0.4, mongosh 2.14.0) 컨테이너에서 돌렸다.

Ubuntu 패키지

sudo apt install mongodb        # E: Package 'mongodb' has no installation candidate

curl -fsSL https://pgp.mongodb.com/server-9.asc | sudo gpg -o /usr/share/keyrings/mongodb-server-9.gpg --dearmor
echo "deb [ arch=amd64,arm64 signed-by=/usr/share/keyrings/mongodb-server-9.gpg ] https://repo.mongodb.org/apt/ubuntu noble/mongodb-org/9.0 multiverse" \
  | sudo tee /etc/apt/sources.list.d/mongodb-org-9.0.list
sudo apt update
sudo apt install mongodb-org
sudo systemctl enable --now mongod
  • 서명 키 이름은 server-9.asc 다. 판 번호를 붙인 server-9.0.asc 는 404 였다(8.0 은 server-8.0.asc)
  • mongodb-org 는 서버(mongodb-org-database) · 도구(mongodb-org-tools, mongodump 등) · mongosh 를 함께 깐다
# /etc/mongod.conf
storage:
  dbPath: /var/lib/mongodb
systemLog:
  destination: file
  path: /var/log/mongodb/mongod.log
net:
  port: 27017
  bindIp: 127.0.0.1
  • 처음에는 인증이 꺼져 있어 mongosh 만 치면 누구나 모든 DB 를 다룬다

인증 켜기

설정에 두 줄을 더하고 다시 띄운다.

security:
  authorization: enabled
sudo systemctl restart mongod
mongosh admin --eval 'db.createUser({user: "root", pwd: "Root-pass-1", roles: ["root"]})'
mongosh -u root -p          # 이제부터 이렇게 들어간다
  • 사용자가 하나도 없을 때는 같은 기계(localhost) 에서 첫 사용자 하나를 만들 수 있다(localhost exception). 두 번째부터는 MongoServerError: Command createUser requires authentication 이다
  • 인증을 켠 뒤 로그인하지 않고 listDatabases 를 하면 오류가 아니라 빈 목록이 온다. 권한이 있는 DB 만 보이기 때문이다

Docker

docker run -d --name mongo \
  -e MONGO_INITDB_ROOT_USERNAME=root \
  -e MONGO_INITDB_ROOT_PASSWORD=Root-pass-1 \
  -v mongo-data:/data/db \
  -p 127.0.0.1:27017:27017 \
  mongo:9
docker exec -it mongo mongosh -u root -p
  • 두 환경 변수를 주면 admin DB 에 root 사용자를 만들고 인증을 켠다. 로그에 MongoDB init process complete; ready for start up. 이 나온 뒤에 붙는다. 자료 폴더가 비어 있을 때 한 번만 쓰인다
  • 띄운 옵션은 db.adminCommand({getCmdLineOpts: 1}).parsed 로 본다 — net: { bindIp: '*' }, security: { authorization: 'enabled' }
  • 이미지에는 mongosh 와 mongodump · mongorestore 같은 도구가 들어 있다
  • WiredTiger 캐시는 기본으로 (메모리 − 1 GB) × 50 % 를 잡는다. 컨테이너 여럿을 한 기계에 띄울 때는 --wiredTigerCacheSizeGB 0.25 처럼 줄인다

앱 사용자

앱은 그 앱의 DB 에 사용자를 만들고 그 DB 의 권한만 준다.

use shop
db.createUser({ user: "app", pwd: "App-pass-1", roles: [{ role: "readWrite", db: "shop" }] })
역할 할 수 있는 것
read 그 DB 읽기
readWrite 읽기 · 쓰기 · 컬렉션 만들고 지우기
dbAdmin · userAdmin 인덱스 · 통계 / 사용자 관리
root (admin DB) 모든 것
  • app 은 shop 의 컬렉션을 지울 수는 있었지만(db.tmp.drop() → true) db.dropDatabase() 는 MongoServerError: not authorized on shop to execute command { dropDatabase: 1, … } 였다

연결 문자열

mongodb://app:App-pass-1@db.example.com:27017/shop
mongodb://root:Root-pass-1@db.example.com:27017/shop?authSource=admin
연결 문자열 결과
app@…/shop 들어간다 — 사용자를 만든 DB 와 경로의 DB 가 같다
app@…/other MongoServerError: Authentication failed. — other 에서 app 을 찾는다
root@…/shop MongoServerError: Authentication failed. — root 는 admin 에 있다
root@…/shop?authSource=admin 들어간다
사용자 없이 붙기는 하고 find 에서 MongoServerError: Command find requires authentication
  • authSource 를 주지 않으면 경로의 DB 에서 사용자를 찾는다. 비밀번호가 맞는데 Authentication failed 가 나면 먼저 이것을 본다
  • 비밀번호에 @ · : · / 가 있으면 퍼센트 인코딩(@ → %40) 한다

바깥에서 접속

저장소 패키지는 127.0.0.1 에서만 듣는다. 다른 서버에서 붙으면 MongoNetworkError: connect ECONNREFUSED 172.19.0.3:27017 이다.

# /etc/mongod.conf
net:
  port: 27017
  bindIp: 127.0.0.1,10.0.0.5     # 서버의 내부 주소를 더한다
  • 인증을 켜기 전에 bindIp 를 열지 않는다. 인증이 꺼진 채 바깥에 열린 MongoDB 는 누구나 읽고 지운다
  • 인터넷에 27017 을 열지 않는다. 방화벽에서 앱 서버에만 연다
