MariaDB 는 Ubuntu 패키지(mariadb-server) 로 서버에 바로 깔거나, Docker 이미지(mariadb) 로 띄운다. 둘은 root 로 들어가는 법이 다르다 — Ubuntu 패키지의 root 는 비밀번호 없이 OS 의 root 로만 들어오고, Docker 이미지는 띄울 때 준 비밀번호를 쓴다. 명령 이름은 mariadb · mariadb-dump 이고, MySQL 의 이름(mysql · mysqldump) 은 판과 설치 방법에 따라 있기도 하고 없기도 하다. 아래 예제는 ubuntu:24.04 에 apt 로 깐 MariaDB 10.11.14 와 mariadb:12.3(12.3.3, LTS) 컨테이너에서 돌렸다.

Ubuntu 패키지

sudo apt install mariadb-server
mariadbd --version   # mariadbd  Ver 10.11.14-MariaDB-0ubuntu0.24.04.1 for debian-linux-gnu on aarch64 (Ubuntu 24.04)
sudo mariadb         # 비밀번호 없이 root 로 들어간다
SHOW CREATE USER root@localhost;
CREATE USER `root`@`localhost` IDENTIFIED VIA mysql_native_password USING 'invalid' OR unix_socket
  • root 는 비밀번호 방식과 unix_socket 방식 가운데 하나로 들어온다. 비밀번호 자리에는 맞을 수 없는 값(invalid) 이 들어 있어, 실제로는 "접속한 OS 사용자가 root 인가" 만 본다. sudo mariadb 는 들어가고, 일반 사용자의 mariadb -u root 는 ERROR 1698 (28000): Access denied for user 'root'@'localhost' 로 막힌다
  • mysql.user 는 표가 아니라 보기(view) 다. 계정은 mysql.global_priv 에 JSON 으로 담기고, mysql.user 의 plugin 열은 첫 방식(mysql_native_password) 만 보인다. 계정의 방식은 SHOW CREATE USER 로 본다
  • mysql · mysqldump 는 mariadb · mariadb-dump 를 가리키는 링크로 들어 있다
  • sudo mariadb-secure-installation 은 익명 사용자와 test DB 를 지우고 root 의 원격 로그인을 막는다. Ubuntu 패키지는 처음부터 익명 사용자 · test DB 가 없었다
  • 서비스는 systemctl status mariadb 다. 설정에서 log_error 줄이 주석이라 로그는 파일이 아니라 저널(journalctl -u mariadb) 로 간다
  • 파일 백업 도구 mariadb-backup 은 따로 깐다(sudo apt install mariadb-backup)
자리 · 값
서버 설정 /etc/mysql/mariadb.conf.d/50-server.cnf
자료 /var/lib/mysql/
소켓 /run/mysqld/mysqld.sock
듣는 주소 bind-address = 127.0.0.1
문자셋 · 정렬 utf8mb4 · utf8mb4_general_ci

Docker

docker run -d --name mdb \
  -e MARIADB_ROOT_PASSWORD=Root-pass-1 \
  -v mariadb-data:/var/lib/mysql \
  -p 127.0.0.1:3306:3306 \
  mariadb:12.3
docker logs mdb 2>&1 | grep "init process done"
docker exec -it mdb mariadb -uroot -p
  • 처음 띄울 때 임시 서버로 root 비밀번호 · DB 를 만든 뒤 다시 뜬다. 로그에 MariaDB init process done. Ready for start up. 이 나오고 ready for connections. 가 한 번 더 나온 뒤에 붙는다
  • MARIADB_DATABASE · MARIADB_USER · MARIADB_PASSWORD 를 주면 앱용 DB 와 사용자까지 만든다. 자료 폴더가 비어 있을 때 한 번만 쓰인다
  • 11.8 · 12.3 이미지에는 mysql · mysqldump 이름이 없다. docker exec mdb mysql … 은 exec: "mysql": executable file not found in $PATH 다. 스크립트에 옛 이름이 있으면 mariadb · mariadb-dump 로 바꾼다
  • 이미지는 bind-address 를 정하지 않아 컨테이너 안의 모든 주소에서 듣는다. 바깥에 열지 않으려면 위처럼 -p 127.0.0.1:… 로 붙인다
  • root 는 root@localhost 와 root@% 둘이 만들어진다. 건강 검사용 healthcheck 사용자도 함께 생긴다
  • mariadb:lts 태그는 지금의 LTS(12.3) 를 가리킨다. 판이 바뀌면 따라 바뀌므로 운영에서는 12.3 처럼 판을 적는다

건강 검사는 이미지에 든 healthcheck.sh 로 한다. 2 초마다 검사하게 띄우자 4 초쯤 뒤 healthy 가 됐다.

# compose.yaml
services:
  db:
    image: mariadb:12.3
    environment:
      MARIADB_ROOT_PASSWORD: Root-pass-1
    volumes:
      - mariadb-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      interval: 10s
      retries: 5
volumes:
  mariadb-data:
  • healthcheck.sh 는 /var/lib/mysql/.my-healthcheck.cnf 의 healthcheck 사용자로 붙는다. 앱 컨테이너에 depends_on: db: condition: service_healthy 를 주면 DB 가 준비된 뒤에 뜬다

문자셋

정렬 규칙 기본값
MySQL 8.4 utf8mb4_0900_ai_ci
MariaDB 10.11 (Ubuntu 패키지) utf8mb4_general_ci
MariaDB 12.3 (Docker 이미지) utf8mb4_uca1400_ai_ci
  • 셋 다 대소문자 · 악센트를 가리지 않는다(ai_ci). 다만 이름이 달라 덤프를 옮길 때 걸린다 — 덤프의 표마다 COLLATE=… 가 적혀 있다
  • 클라이언트 문자셋은 LANG 을 보고 정한다. LANG 이 없으면 둘 다 latin1 이고, LANG=C.UTF-8 이면 12.3 은 utf8mb4, 10.11 은 utf8mb3 였다
  • 10.11 클라이언트가 utf8mb3 로 붙으면 한글은 들어가지만 이모지는 ERROR 1366 (22007): Incorrect string value: '\xF0\x9F\x98\x80' for column … 로 막힌다. --default-character-set=utf8mb4 를 주면 들어간다
  • 클라이언트 설정 파일에 적어 두면 LANG 과 상관없이 utf8mb4 로 붙는다
# /etc/mysql/mariadb.conf.d/50-client.cnf
[client]
default-character-set = utf8mb4

바깥에서 접속

Ubuntu 패키지는 127.0.0.1 에서만 듣는다. 다른 서버에서 붙으면 ERROR 2002 (HY000): Can't connect to server on 'ua' (115) 다.

# /etc/mysql/mariadb.conf.d/50-server.cnf
bind-address = 0.0.0.0
sudo systemctl restart mariadb
  • 붙을 사용자는 그 주소에서 들어오는 계정이어야 한다('app'@'%' · 'app'@'10.0.0.%'). root@localhost 로는 바깥에서 들어오지 못한다
  • 인터넷에 3306 을 열지 않는다. 방화벽에서 앱 서버에만 열고, 내 컴퓨터에서 볼 때는 SSH 터널(ssh -L 3306:127.0.0.1:3306 서버) 로 붙는다

접속 암호화 (11.4 부터)

11.4 부터 서버는 인증서를 정하지 않아도 스스로 만든 인증서로 TLS 를 켜고, 클라이언트는 서버 인증서를 확인하는 것이 기본이다. 그래서 옛 서버 · MySQL 서버에 새 클라이언트로 붙으면 막힌다.

클라이언트 → 서버 결과
12.3 → 10.11 (Ubuntu 패키지, TLS 없음) ERROR 2026 (HY000): TLS/SSL error: SSL is required, but the server does not support it
12.3 → MySQL 8.4 ERROR 2026 (HY000): TLS/SSL error: self-signed certificate in certificate chain
12.3 → 12.3 TLSv1.3 으로 붙는다
10.11 → 12.3 TLSv1.3 으로 붙는다
MySQL 8.4 → 12.3 · 10.11 붙는다 
mariadb -h old-db -u app -p --skip-ssl                      # TLS 가 없는 옛 서버
mariadb -h mysql-db -u app -p --skip-ssl-verify-server-cert # 인증서를 확인하지 않는다
  • 12.3 끼리는 인증서를 정하지 않았는데도 확인을 통과했다. 비밀번호를 아는 클라이언트가 인증서의 지문을 비밀번호로 확인하는 방식이라, 비밀번호 방식(mysql_native_password · ed25519) 계정에서 된다
  • --skip-ssl 로 붙으면 오가는 자료가 암호화되지 않는다. 옛 서버에는 인증서를 정해 TLS 를 켜는 편이 낫다
  • 접속 상태는 SHOW SESSION STATUS LIKE 'Ssl_version' 으로 본다(TLSv1.3)
