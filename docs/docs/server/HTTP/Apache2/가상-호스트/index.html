가상 호스트

가상 호스트는 Apache 하나로 여러 사이트를 도메인마다 나눠 내보내는 설정이다. 사이트마다 sites-available/ 에 <VirtualHost> 블록 하나를 담은 파일을 두고 a2ensite 로 켠다. 요청의 Host 헤더를 ServerName · ServerAlias 와 견주어 사이트를 고르고, 맞는 것이 없으면 그 포트의 첫 사이트가 받는다. 아래 예제는 Ubuntu 24.04 의 Apache 2.4.58 로 돌렸다.

사이트 두 개

/etc/apache2/sites-available/a.conf

<VirtualHost *:80>
    ServerName a.test
    ServerAlias www.a.test
    DocumentRoot /var/www/a
    ErrorLog ${APACHE_LOG_DIR}/a-error.log
    CustomLog ${APACHE_LOG_DIR}/a-access.log combined
</VirtualHost>

/etc/apache2/sites-available/b.conf

<VirtualHost *:80>
    ServerName b.test
    DocumentRoot /srv/b
    <Directory /srv/b>
        Require all granted
    </Directory>
</VirtualHost>
sudo a2ensite a b
sudo systemctl reload apache2
apache2ctl -S
VirtualHost configuration:
*:80                   is a NameVirtualHost
         default server localhost (/etc/apache2/sites-enabled/000-default.conf:1)
         port 80 namevhost localhost (/etc/apache2/sites-enabled/000-default.conf:1)
         port 80 namevhost a.test (/etc/apache2/sites-enabled/a.conf:1)
                 alias www.a.test
         port 80 namevhost b.test (/etc/apache2/sites-enabled/b.conf:1)
요청 Host 결과
a.test · www.a.test 200 site A
b.test 200 site B
unknown.test 200 기본 쪽 (000-default)
  • 사이트별 로그를 따로 두면 사이트마다 접근 기록을 보기 쉽다. 빼면 other_vhosts_access.log 에 함께 쌓인다
  • 맞는 이름이 없으면 그 포트에서 처음 읽은 사이트가 받는다. 파일 이름 순서로 읽으므로 000-default.conf 가 맨 앞이다. a2dissite 000-default 로 끄자 default server a.test 가 되어 모르는 이름에 site A 가 나왔다
  • 모르는 이름을 막으려면 000-default.conf 를 남기고 그 DocumentRoot 를 빈 폴더로 두거나 Require all denied 를 준다

폴더 허락 (Directory)

Ubuntu 의 apache2.conf 는 / 를 모두 막고 /var/www/ 와 /usr/share 만 허락한다. /srv/b 처럼 다른 곳을 DocumentRoot 로 두고 <Directory> 를 빠뜨리면 403 이다.

AH01630: client denied by server configuration: /srv/b/
  • 사이트 파일 안에 <Directory /srv/b> Require all granted </Directory> 를 두면 200 이 된다
  • 파일 권한 문제(www-data 가 못 읽음) 도 403 이지만 로그 문구가 다르다: (13)Permission denied: … AH00132: file permissions deny server access: /var/www/html/secret.html

HTTPS

sudo a2enmod ssl headers      # ssl 은 socache_shmcb 도 함께 켠다
<VirtualHost *:80>
    ServerName a.test
    ServerAlias www.a.test
    Redirect permanent / https://a.test/
</VirtualHost>
<VirtualHost *:443>
    ServerName a.test
    DocumentRoot /var/www/a
    SSLEngine on
    SSLCertificateFile    /etc/apache2/ssl/a.crt
    SSLCertificateKeyFile /etc/apache2/ssl/a.key
    Header always set Strict-Transport-Security "max-age=31536000"
</VirtualHost>
curl -sI -H "Host: a.test" "http://127.0.0.1/x?y=1"
# HTTP/1.1 301 Moved Permanently
# Location: https://a.test/x?y=1
curl -skI --resolve a.test:443:127.0.0.1 https://a.test/
# HTTP/1.1 200 OK
# Strict-Transport-Security: max-age=31536000
  • Redirect permanent / https://a.test/ 는 뒤의 경로 · 쿼리를 붙여 보낸다 (/x?y=1 → https://a.test/x?y=1)
  • Header 는 headers 모듈이 켜져 있어야 한다. 끄고 검사하면 Invalid command 'Header', perhaps misspelled or defined by a module not included in the server configuration 이 난다
  • ssl 모듈을 켜면 ports.conf 가 Listen 443 을 함께 연다
  • Let's Encrypt 인증서는 sudo apt install certbot python3-certbot-apache 뒤 sudo certbot --apache -d a.test 로 받고 이 설정까지 고친다
