Apache 도 mod_proxy 로 요청을 안쪽 앱 서버에 넘기는 리버스 프록시가 된다. 이미 Apache 로 사이트를 돌리는 서버에 GitLab · Jenkins · 사내 앱을 같은 도메인의 경로나 다른 도메인으로 붙일 때 쓴다. ProxyPass 가 요청을 넘기고, ProxyPassReverse 가 앱의 응답 헤더에 든 안쪽 주소를 바깥 주소로 고친다. 아래 예제는 Ubuntu 24.04 의 Apache 2.4.58 뒤에 받은 경로와 헤더를 그대로 돌려주는 파이썬 서버(3000 · 3001) 를 두고 돌렸다.

모듈 켜기

sudo a2enmod proxy proxy_http headers       # WebSocket 은 proxy_wstunnel, 부하 분산은 proxy_balancer lbmethod_byrequests
sudo systemctl restart apache2
  • proxy_http 를 빼고 ProxyPass 를 쓰면 500 이고, 로그에 AH01144: No protocol handler was valid for the URL /b/ (scheme 'http'). If you are using a DSO version of mod_proxy, make sure the proxy submodules are included in the configuration using LoadModule. 가 남는다

ProxyPass 의 경로

<VirtualHost *:80>
    ServerName p.test
    ProxyPass /a/ http://127.0.0.1:3000/a/
    ProxyPass /b/ http://127.0.0.1:3000/
    ProxyPass /c  http://127.0.0.1:3000/
</VirtualHost>
요청 앱이 받은 경로
/a/users?x=1 /a/users?x=1
/b/users?x=1 /users?x=1
/c/users /users
/cusers 404 — 넘기지 않음
  • 앞의 경로(/b/) 를 뒤의 주소(http://…/) 로 바꿔 넘긴다. Nginx 와 달리 언제나 바꾸므로, 경로를 그대로 넘기려면 뒤에도 같은 경로를 적는다(/a/ → …/a/)
  • 앞뒤의 끝 / 는 맞춰 적는다. 이 버전에서는 /c 와 …/ 로 어긋나도 /c/users 가 /users 로 갔고 /cusers 는 넘기지 않았지만, 문서는 둘을 맞추라고 한다
  • 여러 줄이면 위에서부터 처음 맞는 것을 쓴다. 긴 경로를 위에 적는다

Host 와 리다이렉트

<VirtualHost *:80>
    ServerName h.test
    ProxyPreserveHost On
    RequestHeader set X-Forwarded-Proto "http"
    ProxyPass        / http://127.0.0.1:3000/
    ProxyPassReverse / http://127.0.0.1:3000/
</VirtualHost>
p.test /b/users → {"Host": "127.0.0.1:3000", "X-Forwarded-For": "127.0.0.1", …}
h.test /users   → {"Host": "h.test", "X-Forwarded-For": "127.0.0.1", "X-Forwarded-Proto": "http", …}
  • X-Forwarded-For 는 Apache 가 저절로 붙인다. Host 는 ProxyPreserveHost On 이어야 바깥 이름이 간다
  • X-Forwarded-Proto 는 붙이지 않는다. HTTPS 사이트(*:443) 에서는 RequestHeader set X-Forwarded-Proto "https" 로 넣어야 앱이 http:// 로 리다이렉트하지 않는다
  • 앱이 Location: http://127.0.0.1:3002/login 으로 리다이렉트할 때, ProxyPassReverse 가 없으면 브라우저가 그 안쪽 주소로 가서 실패한다
설정 받은 Location
ProxyPass 만 http://127.0.0.1:3002/login
ProxyPassReverse 도 http://r2.test/login

WebSocket

ProxyPass /ws/ ws://127.0.0.1:3000/
/ws/chat → {"path": "/chat", "Upgrade": "websocket", "Connection": "Upgrade", …}
  • proxy_wstunnel 모듈을 켜고 ws:// 로 적는다. Apache 2.4.47 부터는 ProxyPass /ws/ http://127.0.0.1:3000/ upgrade=websocket 으로도 된다

부하 분산

ProxyPass /lb/ balancer://app/
<Proxy balancer://app>
    BalancerMember http://127.0.0.1:3000
    BalancerMember http://127.0.0.1:3001
</Proxy>
/lb/ → app1
/lb/ → app2
/lb/ → app1
/lb/ → app2

앱이 죽었거나 늦을 때

경우 응답 오류 로그
앱이 꺼져 있다 503 AH00957: http: attempt to connect to 127.0.0.1:3999 (127.0.0.1:3999) failed · AH01114: HTTP: failed to make connection to backend: 127.0.0.1
앱이 늦다 (ProxyTimeout 2, 5 초 걸림) 502 (2.0 초) (70007)The timeout specified has expired: … AH01102: error reading status line from remote server 127.0.0.1:3000
  • Nginx 는 앱이 꺼지면 502, 늦으면 504 인데 Apache 는 503 · 502 다. 상태 코드보다 로그 문구로 원인을 가린다
  • 시간 제한은 ProxyTimeout(사이트 전체) 로 준다. ProxyPass /slow/ http://127.0.0.1:3000/slow/ timeout=2 처럼 줄마다 주는 값은, 같은 앱 주소로 가는 다른 ProxyPass(/b/ http://127.0.0.1:3000/) 가 먼저 있으면 그 설정을 함께 써서 무시되었다 — 5 초 뒤 200
  • 앱이 꺼진 뒤에는 그 앱을 잠시 빼 두므로(기본 60 초), 앱을 다시 켜도 한동안 503 이 날 수 있다. ProxyPass … retry=0 이면 바로 다시 시도한다

예전에는

  • 옛 글은 ProxyRequests 를 「포워드 프록시면 On, 리버스면 Off」, ProxyPreserveHost 를 「포워드면 Off, 리버스면 On」 으로 적었다. ProxyRequests 는 맞고(리버스 프록시에서 On 이면 남의 요청을 대신 보내 주는 열린 프록시가 된다), ProxyPreserveHost 는 포워드 · 리버스와 상관없이 앱이 바깥 이름을 받아야 하면 On 이다
  • LoadModule proxy_module … 줄을 손으로 적었다. Ubuntu 에서는 a2enmod proxy_http 로 된다
