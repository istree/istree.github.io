Nginx 설정은 블록이 겹친 글자 파일이다. 맨 바깥 http 안에 사이트마다 server 블록이 있고, server 안에서 주소 경로마다 location 블록이 무엇을 할지 정한다. 요청이 오면 Nginx 는 포트와 Host 헤더로 server 를, 경로로 location 을 고른다. 고친 설정은 nginx -t 로 검사하고 reload 로 끊김 없이 적용한다. 아래 예제는 Ubuntu 24.04 에 apt 로 깐 nginx 1.24 로 돌렸다.

파일 배치 (Ubuntu 패키지)

경로 쓰임
/etc/nginx/nginx.conf 메인 설정 — user www-data · worker_processes auto · 로그 · http 블록
/etc/nginx/sites-available/ 사이트마다 파일 하나
/etc/nginx/sites-enabled/ 켤 사이트의 링크 — nginx.conf 가 include /etc/nginx/sites-enabled/*; 로 읽는다
/etc/nginx/conf.d/*.conf 함께 읽는 설정 — 공식 Docker 이미지 · RHEL 계열은 사이트를 여기에 둔다
/etc/nginx/snippets/ 여러 사이트가 함께 쓰는 조각 (include snippets/ssl.conf;)
/var/www/html 기본 사이트의 파일
/var/log/nginx/access.log · error.log 로그 
sudo ln -s /etc/nginx/sites-available/a.conf /etc/nginx/sites-enabled/   # 켜기
sudo rm /etc/nginx/sites-enabled/a.conf                                   # 끄기 — 원본은 남는다

검사와 적용

sudo nginx -t
# nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
# nginx: configuration file /etc/nginx/nginx.conf test is successful
sudo systemctl reload nginx      # nginx -s reload 와 같다 — 접속을 끊지 않는다
sudo nginx -T | grep "^# configuration file"     # 실제로 읽은 파일과 내용 전부
# # configuration file /etc/nginx/nginx.conf:
# # configuration file /etc/nginx/mime.types:
# # configuration file /etc/nginx/sites-enabled/a.conf:
# # configuration file /etc/nginx/sites-enabled/b.conf:
# # configuration file /etc/nginx/sites-enabled/default:
  • 틀린 설정으로 reload 하면 Job for nginx.service failed. 로 실패하고 옛 설정으로 계속 돈다(active). restart 는 먼저 끈 뒤 다시 띄우다 검사에서 걸려 failed 가 되고 사이트가 멈춘다(curl 이 접속 못 함). 늘 nginx -t 뒤에 reload 한다
  • 모든 지시어는 ; 로 끝난다. 빠뜨리면 다음 줄에서 [emerg] … unexpected "}" in /etc/nginx/sites-enabled/a.conf:5 처럼 알려 준다

server — 사이트 고르기

server {
    listen 80;
    server_name a.test www.a.test;
    root /var/www/a;
}
server {
    listen 80;
    server_name b.test;
    root /var/www/b;
}
curl -H "Host: a.test" http://127.0.0.1/        # site A
curl -H "Host: www.a.test" http://127.0.0.1/    # site A
curl -H "Host: unknown.test" http://127.0.0.1/  # default_server 가 받는다
  • server_name 에 맞는 것이 없으면 그 포트의 default_server 가 받는다. default_server 가 없으면 그 포트에서 처음 읽은 server 가 받는다. Ubuntu 의 sites-enabled/default 를 지우자 모르는 이름에 site A 가 나왔다
  • 모르는 이름의 요청을 끊으려면 server { listen 80 default_server; server_name _; return 444; } 를 둔다. 444 는 응답 없이 연결을 닫는다 (curl 은 52 로 끝난다)
  • 같은 이름을 두 server 에 적으면 [warn] conflicting server name "b.test" on 0.0.0.0:80, ignored 가 나고 뒤의 것은 무시된다
  • listen 80; 은 IPv4 만 듣는다. 다른 server 가 listen [::]:80 을 갖고 있으면 localhost(IPv6 ::1 로 먼저 감) 로 들어온 요청은 IPv6 쪽 server 로 간다. 위 설정에 Ubuntu 의 default 를 함께 켜 두었을 때 curl localhost 는 모두 기본 쪽으로 갔고 127.0.0.1 로는 맞게 갔다. 사이트마다 listen [::]:80; 도 함께 적는다

location — 경로 고르기

location = /exact    { return 200 "= /exact\n"; }
location ^~ /static/ { return 200 "^~ /static/\n"; }
location ~ \.php$    { return 200 "~ php\n"; }
location /app/       { return 200 "/app/\n"; }
location /           { return 200 "/\n"; }
요청 받은 곳
/exact = /exact
/exact/ /
/static/x.php ^~ /static/
/app/x.php ~ php
/app/a.css /app/
/etc /
  1. = 로 똑같이 맞는 것이 있으면 바로 그것이다
  2. 접두사(/app/ · ^~ /static/) 중 가장 긴 것을 찾는다. 그것이 ^~ 면 거기서 끝난다
  3. 아니면 정규식(~ 대소문자 구분 · ~* 무시) 을 적은 순서대로 보고 처음 맞는 것을 쓴다
  4. 맞는 정규식이 없으면 2 에서 찾은 가장 긴 접두사를 쓴다
  • 그래서 /app/x.php 는 더 긴 접두사 /app/ 이 있어도 정규식 ~ php 로 갔다. 정적 파일 폴더를 정규식에서 빼려면 ^~ 를 붙인다
  • 설정 파일 안의 순서는 접두사에는 상관없고 정규식끼리만 상관있다
