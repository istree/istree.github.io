Nginx 는 HTML · CSS · JS · 그림 같은 정적 파일을 디스크에서 바로 내보내는 데 빠르다. 요청 경로를 디스크 경로로 바꾸는 root · alias, 파일이 없을 때 다음 후보를 정하는 try_files, 압축과 캐시 헤더만 알면 정적 사이트 · 빌드한 SPA · 내려받기 폴더를 내보낼 수 있다. 아래 예제는 Ubuntu 24.04 의 nginx 1.24 에서 돌렸다.

설정

server {
    listen 80;
    server_name site.test;
    root /var/www/site;
    index index.html;

    location / {
        try_files $uri $uri.html $uri/ =404;
    }
    location /assets/ {
        expires 30d;
    }
    location /files/ {
        alias /srv/files/docs/;
        autoindex on;
    }
    error_page 404 /404.html;
}
요청 결과 까닭
/ 200 home root + / → index.html
/about 200 about page $uri 가 없어 $uri.html → about.html
/about/ 200 about dir $uri/ → about/index.html
/nope 404 not found page 후보가 다 없어 =404 → error_page 의 /404.html
/files/a.txt 200 a alias → /srv/files/docs/a.txt
/files/ 200 Index of /files/ autoindex on — 파일 목록

root 와 alias

  • root 는 경로 전체를 뒤에 붙인다. root /var/www/site; 에서 /about.html 은 /var/www/site/about.html 이다
  • alias 는 location 에 맞은 부분을 바꾼다. location /files/ { alias /srv/files/docs/; } 에서 /files/a.txt 는 /srv/files/docs/a.txt 다
  • location /wrong/ { root /srv/files/docs/; } 처럼 alias 자리에 root 를 쓰면 /srv/files/docs/wrong/a.txt 를 찾아 404 다. 오류 로그에 찾은 경로가 남는다 
    [error] 14#14: *7 open() "/srv/files/docs/wrong/a.txt" failed (2: No such file or directory)
  • alias 는 location 과 끝 / 를 맞춘다(/files/ ↔ …/docs/). 한쪽만 붙이면 탈이 난다
    • location /one/ { alias /srv/files/docs; } — /one/a.txt 가 /srv/files/docs + a.txt 로 붙어 "/srv/files/docsa.txt" 를 찾아 404
    • location /two { alias /srv/files/docs/; } — /two../secret.txt 가 /srv/files/docs/../secret.txt 가 되어 위 폴더의 secret 이 200 으로 나갔다. 폴더 밖 파일이 새는 구멍이다

try_files

try_files $uri $uri.html $uri/ =404;    # 확장자 없는 주소 — /about → about.html
try_files $uri /index.html;             # SPA — 없는 경로는 모두 index.html 로
  • 앞에서부터 있는 파일을 찾고, 마지막 것은 없을 때의 처리다. =404 처럼 코드를 쓰거나 /index.html 처럼 다른 경로로 넘긴다
  • SPA(React · Vue 의 브라우저 라우팅) 는 /users/42 같은 주소를 서버에 파일로 두지 않는다. 마지막 후보를 /index.html 로 두면 200 spa index 가 나와 앱이 경로를 처리한다

폴더 목록과 403

  • 폴더에 index 파일이 없고 autoindex 도 꺼져 있으면 403 이다. 로그에는 directory index of "/srv/files/" is forbidden 이 남는다
  • autoindex on 은 목록을 보인다. 공개할 폴더에만 켠다
  • 파일이 있는데 403 이면 권한을 본다. nginx 는 www-data 로 돌아 경로의 모든 폴더에 x, 파일에 r 이 있어야 한다

캐시 헤더

curl -sI -H "Host: site.test" 127.0.0.1/assets/app.css
# Content-Type: text/css
# Expires: Tue, 08 Dec 2026 10:02:26 GMT
# Cache-Control: max-age=2592000
  • expires 30d 는 Expires 와 Cache-Control: max-age 를 함께 붙인다. 빌드할 때 이름에 해시가 붙는 파일(app.3f9a.js) 은 길게, index.html 은 expires -1;(캐시하지 않음) 로 둔다

압축

Ubuntu 의 nginx.conf 는 gzip on; 이지만 gzip_types 줄이 주석이라 HTML 만 압축한다.

curl -s -o /dev/null -w "%{size_download}B\n" -H "Accept-Encoding: gzip" -H "Host: site.test" 127.0.0.1/assets/app.css
# 3001B — 압축하지 않았다

nginx.conf 의 gzip_types 주석을 풀고 reload 하면 같은 CSS 가 69B 로 온다.

gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript;
  • 아주 작은 응답(기본 20 바이트 미만) 은 압축하지 않는다
  • 그림(png · jpg · webp) 은 이미 압축되어 있어 넣지 않는다
