Nginx 를 쓰다 자주 만나는 오류와 해결을 모았다. 오류 문구는 Ubuntu 24.04 의 nginx 1.24 에서 직접 낸 것이다. 원인은 대개 /var/log/nginx/error.log 에 적혀 있으므로, 화면의 상태 코드만 보지 말고 먼저 sudo tail -f /var/log/nginx/error.log 를 띄워 놓고 다시 요청한다.

unexpected "}"

[emerg] 33#33: unexpected "}" in /etc/nginx/sites-enabled/a.conf:5
  • 지시어 끝의 ; 를 빠뜨렸다. 알려 준 줄의 바로 앞 줄을 본다
  • reload 는 실패하고 옛 설정으로 계속 돈다. 고친 뒤 sudo nginx -t 로 검사하고 다시 reload 한다

413 Request Entity Too Large

[error] 17#17: *27 client intended to send too large body: 2000000 bytes
  • 올린 본문이 client_max_body_size(기본 1 MB) 보다 크다. 파일을 올리는 사이트의 server 나 location 에 늘린다 
    server {
    client_max_body_size 20M;
}
  • 앞에 프록시가 또 있으면(로드 밸런서 · 다른 Nginx) 그쪽 제한도 늘린다

502 Bad Gateway

[error] 17#17: *23 connect() failed (111: Connection refused) while connecting to upstream, … upstream: "http://127.0.0.1:3999/"
  • 넘길 앱이 꺼져 있거나 포트가 틀렸다. curl -I 127.0.0.1:3999 로 앱을 직접 불러 보고, ss -tlnp 로 앱이 어느 주소 · 포트에서 듣는지 본다
  • 앱이 127.0.0.1 이 아니라 컨테이너 안에서만 듣고 있으면(Docker 의 포트를 열지 않음) 닿지 않는다

504 Gateway Time-out

[error] 17#17: *25 upstream timed out (110: Connection timed out) while reading response header from upstream
  • 앱은 살아 있지만 proxy_read_timeout(기본 60 초) 안에 답하지 않았다. 앱이 왜 늦는지 먼저 보고, 원래 오래 걸리는 요청(보고서 · 내보내기) 이면 그 location 만 늘린다

403 Forbidden

[error] 14#14: *8 directory index of "/srv/files/" is forbidden
[error] 17#17: *1 open() "/var/www/p/index.html" failed (13: Permission denied)
  • 앞의 것은 폴더에 index 파일이 없고 autoindex 도 꺼져 있다. index 파일을 두거나 try_files 로 다른 곳에 넘긴다
  • 뒤의 것은 nginx(www-data) 가 파일을 읽지 못한다. 파일은 644, 경로의 폴더는 모두 755 인지 본다 (namei -l /var/www/p/index.html 이 경로의 권한을 한 번에 보인다)
  • 홈 폴더(/home/사용자, 기본 750) 아래의 파일을 내보내면 이 오류가 난다. 사이트 파일은 /var/www 아래에 둔다

404 인데 파일은 있다

[error] 14#14: *7 open() "/srv/files/docs/wrong/a.txt" failed (2: No such file or directory)
  • 로그의 경로가 nginx 가 실제로 찾은 곳이다. root 와 alias 를 바꿔 썼거나 끝 / 가 어긋난 것이다
  • root 는 요청 경로 전체를 붙이고, alias 는 location 에 맞은 부분을 바꾼다

bind() … Address already in use

nginx: [emerg] bind() to 0.0.0.0:80 failed (98: Address already in use)
  • 다른 프로그램(Apache · 다른 nginx · Docker 컨테이너) 이 80 을 잡고 있다. sudo ss -tlnp | grep :80 으로 찾는다
  • Apache 와 함께 깔았으면 하나를 끄거나 포트를 나눈다

conflicting server name

[warn] 39#39: conflicting server name "b.test" on 0.0.0.0:80, ignored
  • 같은 server_name 이 두 파일에 있다. 경고라 뜨기는 하지만 뒤에 읽은 쪽은 무시된다. sudo nginx -T | grep server_name 으로 겹친 곳을 찾는다
  • sites-available 의 파일을 복사해 고치고 옛 링크를 그대로 둔 경우가 많다

다른 사이트가 나온다

  • 요청한 이름의 server 가 없으면 그 포트의 default_server, 없으면 처음 읽은 server 가 받는다
  • IPv4 만 듣는 사이트(listen 80;) 에 localhost 로 붙으면 IPv6(::1) 로 가서 listen [::]:80 을 가진 다른 server(Ubuntu 의 default) 가 받는다. 사이트마다 listen [::]:80; 을 함께 적는다

could not build server_names_hash

[emerg] 24#24: could not build server_names_hash, you should increase server_names_hash_bucket_size: 64
  • 긴 도메인(60 자가 넘는 이름) 이 있다. nginx.conf 의 http 안에 주석으로 있는 server_names_hash_bucket_size 64; 를 풀고 128 로 올린다

key values mismatch

[emerg] 36#36: SSL_CTX_use_PrivateKey("/etc/nginx/ssl/other.key") failed (SSL: error:05800074:x509 certificate routines::key values mismatch)
  • ssl_certificate 와 ssl_certificate_key 가 짝이 아니다. 같은 때 받은 fullchain.pem · privkey.pem 을 함께 쓴다
