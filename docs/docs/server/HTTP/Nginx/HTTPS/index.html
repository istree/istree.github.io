HTTPS 는 인증서 파일 두 개(인증서와 비밀 키) 를 Nginx 에 알려 주고 443 포트를 여는 것으로 된다. 공개 사이트의 인증서는 Let's Encrypt 에서 무료로 받고 certbot 이 90 일마다 저절로 갱신한다. 80 으로 온 요청은 443 으로 돌려보낸다. 아래 예제는 Ubuntu 24.04 의 nginx 1.24 에 스스로 서명한 인증서를 붙여 돌렸고, certbot 은 설치와 갱신 설정만 확인했다(도메인이 없어 발급은 하지 않았다).

설정

server {
    listen 80;
    server_name site.test;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl http2;
    server_name site.test;
    root /var/www/site;

    ssl_certificate     /etc/nginx/ssl/site.crt;
    ssl_certificate_key /etc/nginx/ssl/site.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    add_header Strict-Transport-Security "max-age=31536000" always;
}
curl -sI -H "Host: site.test" "http://127.0.0.1/a?b=1"
# HTTP/1.1 301 Moved Permanently
# Location: https://site.test/a?b=1
curl -s --resolve site.test:443:127.0.0.1 --cacert site.crt https://site.test/    # secure
curl -skI --resolve site.test:443:127.0.0.1 https://site.test/
# HTTP/2 200
# strict-transport-security: max-age=31536000
echo | openssl s_client -connect 127.0.0.1:443 -servername site.test 2>/dev/null | grep "Cipher is"
# New, TLSv1.3, Cipher is TLS_AES_256_GCM_SHA384
  • ssl_certificate 에는 서버 인증서 뒤에 중간 인증서를 이어 붙인 파일(fullchain.pem) 을 준다. 서버 인증서만 주면 브라우저는 되어도 curl · 앱에서 검증이 실패할 수 있다
  • $request_uri 는 경로와 쿼리를 모두 담아, /a?b=1 이 그대로 https://…/a?b=1 로 간다
  • ssl_protocols TLSv1.2 TLSv1.3 이면 TLS 1.1 로 붙는 클라이언트는 끊긴다 (curl --tls-max 1.1 은 35 로 끝났다)
  • Strict-Transport-Security(HSTS) 를 받은 브라우저는 그 기간 동안 http 로 가지 않는다. 처음에는 짧게(max-age=300) 두고 문제없으면 늘린다
  • nginx 1.25.1 부터는 listen 443 ssl; 과 http2 on; 을 따로 쓴다. 옛 꼴을 쓰면 the "listen ... http2" directive is deprecated, use the "http2" directive instead 경고가 난다 (1.28 에서 확인)

스스로 서명한 인증서

내부 시험용으로 만든다. 브라우저 · curl 은 믿지 않으므로 경고가 나거나(curl 은 60 으로 끝남) -k · --cacert 로 따로 믿게 해야 한다.

sudo mkdir -p /etc/nginx/ssl && cd /etc/nginx/ssl
sudo openssl req -x509 -newkey rsa:2048 -nodes -days 30 \
  -keyout site.key -out site.crt -subj "/CN=site.test" -addext "subjectAltName=DNS:site.test"
openssl x509 -in site.crt -noout -subject -enddate
# subject=CN = site.test
# notAfter=Dec  8 10:04:07 2026 GMT
  • 비밀 키는 -rw-------(600) 로 만들어진다. 그대로 root 만 읽게 둔다 — nginx 는 root 로 키를 읽은 뒤 www-data 로 일한다
  • 지금 브라우저는 CN 이 아니라 subjectAltName 을 본다. -addext "subjectAltName=DNS:…" 를 꼭 넣는다
  • 내 컴퓨터에서 개발할 때는 mkcert 가 로컬에서 믿는 인증서를 만들어 준다

Let's Encrypt (certbot)

sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d example.com -d www.example.com   # 받고 nginx 설정까지 고친다
sudo certbot certificates                                 # 받은 인증서와 만료일
sudo certbot renew --dry-run                              # 갱신이 될지 시험
  • 도메인이 이 서버를 가리키고 80 포트가 바깥에서 열려 있어야 한다. Let's Encrypt 가 그 도메인의 80 으로 확인 요청을 보낸다
  • 받은 파일은 /etc/letsencrypt/live/도메인/fullchain.pem · privkey.pem 이다
  • Ubuntu 24.04 의 certbot 2.9 는 certbot.timer 를 함께 깐다. 하루 두 번(OnCalendar=*-*-* 00,12:00:00, 최대 12 시간 무작위로 늦춤) 돌아 만료 30 일 안의 인증서를 갱신한다
  • 플러그인은 nginx(설정을 직접 고침) · webroot(폴더에 확인 파일을 둠) · standalone(잠깐 자기 서버를 띄움) 이 있다. 설정을 손으로 관리하려면 certbot certonly --webroot -w /var/www/site -d example.com 으로 받기만 한다

인증서 오류

[emerg] 36#36: SSL_CTX_use_PrivateKey("/etc/nginx/ssl/other.key") failed (SSL: error:05800074:x509 certificate routines::key values mismatch)
  • 인증서와 비밀 키가 짝이 아니다. 다른 인증서의 키를 주었거나 갱신 뒤 파일 하나만 바꾼 것이다
  • 만료일은 openssl x509 -in 파일 -noout -enddate, 실제로 내보내는 인증서는 openssl s_client -connect 도메인:443 -servername 도메인 으로 본다
