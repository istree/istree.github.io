MariaDB 의 사용자는 MySQL 과 같이 이름과 접속하는 호스트를 묶은 '이름'@'호스트' 하나다. CREATE USER · GRANT · SHOW GRANTS 도 같은 문법으로 쓴다. 다른 곳은 셋이다 — GRANT … IDENTIFIED BY 가 아직 사용자를 만들고, 역할(role) 은 기본 역할로 정해야 로그인할 때 켜지고, 비밀번호의 기본 방식이 mysql_native_password 다. 아래 예제는 mariadb:12.3(12.3.3) 컨테이너에 root 로 들어가 만들고, 같은 Docker 네트워크의 다른 컨테이너에서 붙어 확인했다.

만들기와 권한

CREATE DATABASE shop;
CREATE USER 'app'@'%' IDENTIFIED BY 'App-pass-1';
GRANT ALL PRIVILEGES ON shop.* TO 'app'@'%';
SHOW GRANTS FOR 'app'@'%';
Grants for app@%
GRANT USAGE ON *.* TO `app`@`%` IDENTIFIED BY PASSWORD '*95B7D082CF2B4B751337D4A78D327D07811EE287'
GRANT ALL PRIVILEGES ON `shop`.* TO `app`@`%`
  • SHOW GRANTS 의 첫 줄에 비밀번호 해시가 함께 나온다. 이 줄을 그대로 다른 서버에 넣으면 같은 비밀번호의 사용자가 된다
  • 이미 있는 사용자를 다시 만들면 ERROR 1396 (HY000): Operation CREATE USER failed for 'app'@'%' 다. CREATE USER IF NOT EXISTS 는 오류 대신 Note 1973 … it already exists 를 남기고 넘어간다
  • CREATE OR REPLACE USER 는 있던 사용자를 지우고 새로 만든다. 받아 둔 권한도 사라진다 — SELECT 를 받은 tmp 를 다시 만들자 GRANT USAGE 한 줄만 남았다

GRANT 가 사용자를 만든다

MySQL 8 에서 막힌 문법이 MariaDB 에서는 된다.

GRANT SELECT ON shop.* TO 'g2'@'%' IDENTIFIED BY 'G2-pass-1';   -- 사용자를 만들고 권한을 준다
GRANT SELECT ON shop.* TO 'g1'@'%';
-- ERROR 1133 (28000): Can't find any matching row in the user table
  • 비밀번호 없이 없는 사용자에게 주면 막힌다. 기본 sql_mode 의 NO_AUTO_CREATE_USER 때문이다
  • 옛 설치 글 · 스크립트의 GRANT … IDENTIFIED BY 가 MariaDB 에서는 돌고 MySQL 8 에서는 돌지 않는다. 둘에 함께 쓸 스크립트는 CREATE USER 뒤 GRANT 로 나눈다

역할

권한을 역할에 모아 두고 사용자에게 역할을 준다.

CREATE ROLE reader;
GRANT SELECT ON shop.* TO reader;
CREATE USER 'report'@'%' IDENTIFIED BY 'Rep-pass-1';
GRANT reader TO 'report'@'%';

역할을 받았어도 로그인하면 꺼져 있다.

-- report 로
SELECT CURRENT_ROLE();        -- NULL
SELECT * FROM shop.orders;
-- ERROR 1142 (42000): SELECT command denied to user 'report'@'172.18.0.2' for table `shop`.`orders`
SET ROLE reader;              -- 이 접속에서만 켠다
SELECT * FROM shop.orders;    -- 읽힌다

로그인할 때 켜지게 하려면 기본 역할을 정한다.

SET DEFAULT ROLE reader FOR 'report'@'%';   -- root 가
SET DEFAULT ROLE reader;                     -- report 가 스스로
  • 정한 뒤 다시 붙자 CURRENT_ROLE() 이 reader 였고 바로 읽혔다. SHOW GRANTS 끝에 SET DEFAULT ROLE `reader` FOR `report`@`%` 줄이 나온다
  • 앱 계정에 역할로 권한을 준다면 기본 역할까지 정해야 한다. 빠뜨리면 앱은 붙기는 하고 쿼리마다 command denied 를 받는다
  • 역할을 만든 root 에게도 그 역할이 WITH ADMIN OPTION 으로 주어진다
  • DROP ROLE reader 는 받은 사용자가 있어도 지워진다. 기본 역할 줄은 남지만 로그인하면 CURRENT_ROLE() 이 NULL 이고 다시 command denied 다

인증 방식

비밀번호 기본 방식
MySQL 8.4 caching_sha2_password
MariaDB mysql_native_password
클라이언트 → 서버 결과
MySQL 8.4 → MariaDB(mysql_native_password 계정) 붙는다
MariaDB 10.11 · 12.3 → MySQL 8.4(caching_sha2_password 계정) 붙는다 (12.3 은 인증서 확인을 끄고)
MySQL 8.4 → MariaDB(ed25519 계정) ERROR 2059 (HY000): Authentication plugin 'client_ed25519' cannot be loaded

mysql_native_password 는 해시가 SHA-1 이라 약하다. MariaDB 클라이언트만 붙는다면 ed25519 를 쓴다.

INSTALL SONAME 'auth_ed25519';
CREATE USER 'e'@'%' IDENTIFIED VIA ed25519 USING PASSWORD('E-pass-1');
SHOW CREATE USER 'e'@'%';
CREATE USER `e`@`%` IDENTIFIED VIA ed25519 USING 'AHKSLYUnuwgrJfPysylC7zyaOfGm7t3wiTtBnqS8e2E'
  • ed25519 는 플러그인이라 먼저 INSTALL SONAME 한다. 한 번 깔면 서버를 다시 띄워도 남는다
  • mysql.user 의 plugin 열에서 계정마다 방식을 본다(app 은 mysql_native_password, e 는 ed25519)
  • MySQL 클라이언트로 붙는 곳(MySQL 용 도구 · 옛 앱) 이 있으면 그 계정은 mysql_native_password 로 둔다

비밀번호 · 지우기

ALTER USER 'app'@'%' IDENTIFIED BY 'App-pass-2';
RENAME USER 'report'@'%' TO 'report'@'10.0.0.%';
DROP USER 'report'@'10.0.0.%';
  • SET PASSWORD FOR 'app'@'%' = PASSWORD('…') 도 된다
  • DROP USER 는 그 사용자의 권한도 함께 지운다. 그 사용자가 만든 표는 남는다
