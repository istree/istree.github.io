MySQL 의 사용자는 이름과 접속하는 호스트를 묶은 '이름'@'호스트' 하나다. 같은 이름이라도 호스트가 다르면 다른 계정이고, 비밀번호 · 권한도 따로다. 앱마다 사용자를 따로 만들고 그 앱의 DB 에만 필요한 권한을 준다. 아래 예제는 mysql:8.4(8.4.13) 컨테이너에 root 로 들어가 만들고, 같은 Docker 네트워크의 다른 컨테이너에서 붙어 확인했다.

만들기와 권한

CREATE DATABASE shop;
CREATE USER 'app'@'%' IDENTIFIED BY 'App-pass-1';
CREATE USER 'report'@'10.0.0.%' IDENTIFIED BY 'Rep-pass-1';
GRANT ALL PRIVILEGES ON shop.* TO 'app'@'%';
GRANT SELECT ON shop.* TO 'report'@'10.0.0.%';
SHOW GRANTS FOR 'app'@'%';
+-----------------------------------------------+
| Grants for app@%                              |
+-----------------------------------------------+
| GRANT USAGE ON *.* TO `app`@`%`               |
| GRANT ALL PRIVILEGES ON `shop`.* TO `app`@`%` |
+-----------------------------------------------+
호스트 뜻
'localhost' 같은 서버에서 소켓으로
'%' 어디서든
'10.0.0.%' · '10.0.0.0/255.255.255.0' 그 대역에서
'app.lan' 그 이름의 호스트에서
  • USAGE 는 "아무 권한 없음" 이다. 사용자를 만들면 저절로 붙는다
  • shop.* 은 shop 의 모든 표, *.* 은 모든 DB 다. 앱 사용자에게 *.* 을 주지 않는다
  • MySQL 8 은 GRANT 가 사용자를 만들지 않는다. 없는 사용자에게 주면 ERROR 1410 (42000): You are not allowed to create a user with GRANT 다. 먼저 CREATE USER 한다
  • FLUSH PRIVILEGES 는 mysql.user 표를 직접 고쳤을 때만 필요하다. CREATE USER · GRANT 는 바로 적용된다

누구로 들어왔나

SELECT user(), current_user();
-- app@172.18.0.3   app@%
  • user() 는 실제로 붙은 곳, current_user() 는 MySQL 이 고른 계정이다. 권한은 current_user() 의 것이다
  • report 를 10.0.0.% 로 만들었으므로, 다른 대역(172.18.0.3) 에서 맞는 비밀번호로 붙어도 ERROR 1045 (28000): Access denied for user 'report'@'172.18.0.3' (using password: YES) 다

localhost 와 % 가 함께 있을 때

'app'@'%' 만 있을 때는 같은 서버(localhost) 에서도 app@% 로 들어간다. 여기에 'app'@'localhost' 를 다른 비밀번호로 더하면, localhost 에서는 더 좁은 app@localhost 를 먼저 고른다.

mysql -uapp -pApp-pass-1      # %의 비밀번호
ERROR 1045 (28000): Access denied for user 'app'@'localhost' (using password: YES)
  • 비밀번호가 맞는데 Access denied 가 나면 SELECT user, host FROM mysql.user WHERE user = 'app'; 으로 같은 이름의 계정이 더 있는지 본다
  • 같은 서버 · 바깥 모두 쓰는 앱이면 'app'@'%' 하나만 두거나, 둘을 같은 비밀번호 · 권한으로 맞춘다

권한 줄이기

REVOKE ALL PRIVILEGES ON shop.* FROM 'app'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON shop.* TO 'app'@'%';
INSERT INTO shop.t VALUES (1);  -- 된다
DROP TABLE shop.t;
ERROR 1142 (42000) at line 1: DROP command denied to user 'app'@'172.18.0.3' for table 't'
  • 운영 앱에는 자료를 다루는 네 권한만 주고, 표를 만들고 바꾸는 일(마이그레이션) 은 따로 만든 사용자로 한다
  • 읽기 전용 보고서 사용자는 SELECT 만 준다
  • 백업 사용자는 SELECT, SHOW VIEW, TRIGGER, EVENT, LOCK TABLES 를 준다. 이 사용자로 mysqldump 하면 Access denied; you need (at least one of) the PROCESS privilege(s) for this operation' when trying to dump tablespaces 가 찍히므로 --no-tablespaces 를 붙인다

비밀번호 · 지우기

ALTER USER 'app'@'%' IDENTIFIED BY 'App-pass-2';   -- 옛 비밀번호는 바로 막힌다
DROP USER 'app'@'localhost';
SELECT user, host, plugin FROM mysql.user ORDER BY user, host;
  • 비밀번호 규칙(validate_password) 은 Docker 이미지에서는 꺼져 있어 '1234' 도 받았다. Ubuntu 의 mysql_secure_installation 에서 켜면 짧은 비밀번호를 거부한다
  • MySQL 8 의 기본 인증은 caching_sha2_password 다. 아주 옛 클라이언트 라이브러리는 이것을 몰라 Authentication plugin 'caching_sha2_password' cannot be loaded 로 실패한다. 라이브러리를 올리는 것이 답이다

예전에는

  • 옛 글은 create user 뒤 grant all privileges on DB.* to … 만 적었다. 지금도 같지만, MySQL 5.7 까지 되던 GRANT … IDENTIFIED BY '비밀번호'(사용자를 함께 만듦) 는 8.0 부터 문법 오류다
  • 모든 IP 를 허용할 때 localhost 대신 % 를 쓴다는 옛 메모는 맞다. 다만 같은 이름의 localhost 계정이 함께 있으면 위처럼 그쪽이 먼저 골라진다
