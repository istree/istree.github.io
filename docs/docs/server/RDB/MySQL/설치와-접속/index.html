MySQL 은 Ubuntu 패키지(mysql-server) 로 서버에 바로 깔거나, Docker 이미지(mysql) 로 띄운다. 둘은 root 로 들어가는 법이 다르다 — Ubuntu 패키지의 root 는 비밀번호 없이 OS 의 root 로만 들어오고, Docker 이미지는 띄울 때 준 비밀번호를 쓴다. 처음 띄운 뒤에는 앱이 쓸 DB 와 사용자를 따로 만들고, 바깥에서 접속하게 할지 정한다. 아래 예제는 ubuntu:24.04 에 apt 로 깐 MySQL 8.0.46 과 mysql:8.4(8.4.13) 컨테이너에서 돌렸다.

Ubuntu 패키지

sudo apt install mysql-server
mysqld --version     # /usr/sbin/mysqld  Ver 8.0.46-0ubuntu0.24.04.4 for Linux on aarch64 ((Ubuntu))
sudo mysql           # 비밀번호 없이 root 로 들어간다
SELECT user, host, plugin FROM mysql.user;
user              host       plugin
debian-sys-maint  localhost  caching_sha2_password
mysql.infoschema  localhost  caching_sha2_password
mysql.session     localhost  caching_sha2_password
mysql.sys         localhost  caching_sha2_password
root              localhost  auth_socket
  • root 는 auth_socket 이라 비밀번호 대신 "접속한 OS 사용자가 root 인가" 를 본다. sudo mysql 로는 들어가고, 일반 사용자의 mysql -u root -p 는 막힌다
  • root 에 비밀번호를 주려면 ALTER USER root@localhost IDENTIFIED WITH caching_sha2_password BY '…'; 이다. 그 뒤로는 sudo mysql 도 Access denied for user 'root'@'localhost' (using password: NO) 로 막히고 mysql -u root -p 로 들어간다. 앱용 사용자를 따로 만들고 root 는 그대로 두는 편이 낫다
  • sudo mysql_secure_installation 은 익명 사용자 · 시험 DB 를 지우고 root 의 원격 로그인을 막는다. 처음 깐 뒤 한 번 돌린다
  • 설정 파일은 /etc/mysql/mysql.conf.d/mysqld.cnf, 자료는 /var/lib/mysql/, 포트는 3306, 기본 문자셋은 utf8mb4 다

Docker

docker run -d --name my \
  -e MYSQL_ROOT_PASSWORD=Root-pass-1 \
  -v mysql-data:/var/lib/mysql \
  -p 127.0.0.1:3306:3306 \
  mysql:8.4
docker logs my 2>&1 | grep "ready for connections"
docker exec -it my mysql -uroot -p
  • 처음 띄울 때 임시 서버로 root 비밀번호 · DB 를 만든 뒤 다시 뜬다. 로그에 ready for connections … port: 3306 이 나오기 전에 붙으면 Access denied 가 날 수 있다 (mysqladmin ping 은 임시 서버에서 먼저 성공해 기다리기에 쓸 수 없었다)
  • MYSQL_DATABASE · MYSQL_USER · MYSQL_PASSWORD 를 함께 주면 앱용 DB 와 사용자까지 만든다
  • 이 환경 변수는 자료 폴더가 비어 있을 때 한 번만 쓰인다. 볼륨이 남아 있으면 비밀번호를 바꿔 띄워도 옛 비밀번호 그대로다
  • mysql:5.7 은 arm64 판이 없어 M1 맥에서는 --platform linux/amd64 로 돌려야 한다. 새로 쓸 때는 8.4(LTS) 를 쓴다

클라이언트

mysql -h 127.0.0.1 -P 3306 -u app -p shop      # 호스트 · 포트 · 사용자 · 비밀번호 묻기 · DB
mysql -u app -p -e "SELECT NOW()"              # 명령 하나만
mysql -u app -p shop < schema.sql              # 파일을 돌린다
옵션 뜻
-h 호스트. localhost 면 소켓 파일로, 127.0.0.1 이면 TCP 로 붙는다
-u · -p 사용자 · 비밀번호 (-p 뒤에 붙여 쓰면 묻지 않지만 기록에 남는다)
-e SQL 하나를 돌리고 끝낸다
-t · -B 표 모양 · 탭으로 나눈 출력
--default-character-set=utf8mb4 클라이언트 문자셋

비밀번호를 매번 치지 않으려면 ~/.my.cnf(권한 600) 에 둔다. mysql · mysqldump 가 함께 읽는다.

[client]
user=root
password=Root-pass-1

한글이 깨질 때

mysql:8.4 컨테이너 안에서 docker exec … mysql 로 한글을 넣었더니, 화면에는 바르게 보였지만 덤프에서 깨졌다.

SELECT @@character_set_client;                 -- latin1
SELECT item, HEX(item), CHAR_LENGTH(item) FROM shop.orders;
-- 사과  C3ACE2809AC2ACC3AAC2B3C2BC  6
  • 컨테이너에 LANG 이 없어 클라이언트가 latin1 로 붙었고, UTF-8 글자를 latin1 로 읽어 한 번 더 바꿔 저장했다(사과 가 6 글자). 같은 latin1 클라이언트로 읽으면 거꾸로 풀려 바르게 보여 알아채기 어렵다
  • --default-character-set=utf8mb4 를 주거나 docker exec -e LANG=C.UTF-8 로 붙으면 utf8mb4 가 되어 EC82ACEAB3BC(2 글자) 로 바르게 들어간다
  • 앱의 접속 설정에도 문자셋을 적는다 (JDBC characterEncoding=UTF-8, 그 밖에는 charset=utf8mb4)

바깥에서 접속

Ubuntu 패키지는 127.0.0.1 에서만 듣는다.

# /etc/mysql/mysql.conf.d/mysqld.cnf
bind-address = 127.0.0.1      # 이대로면 다른 서버에서 ERROR 2003 (HY000): Can't connect to MySQL server on 'umy:3306' (111)
  • 다른 서버의 앱이 붙어야 하면 bind-address = 0.0.0.0 으로 바꾸고 sudo systemctl restart mysql 한다. 바꾼 뒤 같은 사용자(app@%) 로 붙었다
  • 사용자도 그 호스트에서 들어올 수 있게 만들어야 한다('app'@'10.0.0.%'). 방화벽에서는 3306 을 앱 서버에만 연다
  • 인터넷에 3306 을 열지 않는다. 내 컴퓨터에서 볼 때는 SSH 터널(ssh -L 3306:127.0.0.1:3306 서버) 로 붙는다
