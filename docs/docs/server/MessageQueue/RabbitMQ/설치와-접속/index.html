RabbitMQ 는 Ubuntu 패키지(rabbitmq-server) 나 Docker 이미지(rabbitmq) 로 띄운다. 다만 Ubuntu 24.04 의 패키지는 3.12.1 로 지원이 끝난 줄기라, 서버에 바로 깔 때는 RabbitMQ 팀의 apt 저장소를 쓴다. 앱은 5672(AMQP) 로, 사람은 관리 화면 15672 로 붙는다. 사용자는 vhost 마다 권한을 받는다. vhost 는 한 서버 안의 따로 떨어진 공간으로, 큐 · 교환기 이름이 vhost 마다 따로다. 처음 있는 guest 는 지우거나 막는다. 아래 예제는 rabbitmq:4.4-management(4.4.0, Erlang 29.1.2) 컨테이너와, 같은 Docker 네트워크의 Java 클라이언트(amqp-client 5.37.1, JDK 25) 로 돌렸다.

Docker

docker run -d --name rq --hostname rq --network mq-net \
  -e RABBITMQ_DEFAULT_USER=admin -e RABBITMQ_DEFAULT_PASS=Admin-pass-1 \
  -v rq-data:/var/lib/rabbitmq \
  -p 127.0.0.1:5672:5672 -p 127.0.0.1:15672:15672 \
  rabbitmq:4.4-management
docker logs rq 2>&1 | grep "Server startup complete"
  • 6 초 만에 Server startup complete; 4 plugins started. 가 나왔다. -management 태그는 관리 화면 · HTTP API(rabbitmq_management) 를 켠 이미지다. Prometheus 지표(rabbitmq_prometheus) 는 -management 가 없는 이미지에도 켜져 있다
  • 자료 폴더 이름에 호스트 이름이 들어간다(data dir : /var/lib/rabbitmq/mnesia/rabbit@rq). --hostname 을 정하지 않으면 컨테이너마다 이름이 바뀌어, 볼륨을 붙여도 다시 띄우면 다른 폴더를 쓴다
  • RABBITMQ_DEFAULT_USER 를 주지 않으면 guest/guest 관리자가 생긴다. 이미지의 /etc/rabbitmq/conf.d/10-defaults.conf 가 loopback_users.guest = false 라, 이 guest 는 네트워크 어디서든 붙는다. 다른 컨테이너에서 guest 로 붙어 큐를 만들었다
  • 설정은 /etc/rabbitmq/conf.d/ 의 .conf 파일이다. 파일을 붙여 넣을 때는 이 폴더에 둔다

사용자 · vhost · 권한

rabbitmqctl add_vhost shop
rabbitmqctl add_user app 'App-pass-1'
rabbitmqctl set_permissions -p shop app '^app\..*|^q-app$' '^app\..*|^q-app$' '^app\..*|^q-app$'
rabbitmqctl list_permissions -p shop
user	configure	write	read
app	^app\..*|^q-app$	^app\..*|^q-app$	^app\..*|^q-app$
  • 권한 셋은 정규식이다. configure(큐 · 교환기 만들기 · 지우기) · write(보내기 · 바인딩) · read(받기) 순서다. '.*' '.*' '.*' 이면 그 vhost 의 모든 것이다
붙은 것 결과
비밀번호가 틀림 ACCESS_REFUSED - Login was refused using authentication mechanism PLAIN.
권한이 없는 vhost(/) NOT_ALLOWED - access to vhost '/' refused for user 'app' (코드 530)
정규식 밖의 큐 other 를 만듦 ACCESS_REFUSED - configure access to queue 'other' in vhost 'shop' refused for user 'app' (코드 403)
app.orders 를 만듦 된다
  • 클라이언트에 오는 오류는 짧다. 서버 로그에 까닭이 남는다(PLAIN login refused: user 'app' - invalid credentials)
  • 앱마다 vhost 를 나누면 큐 이름이 겹쳐도 되고, 권한을 vhost 하나로 묶어 줄 수 있다

관리 화면 · HTTP API

http://localhost:15672 에 관리자로 들어간다. 같은 것을 HTTP API 로도 본다.

curl -u admin:Admin-pass-1 http://rq:15672/api/overview
# {"product_version":"4.4.0","rabbitmq_version":"4.4.0","management_version":"4.4.0","erlang_version":"29.1.2", …}
사용자 태그 관리 화면 · API
없음 {"error":"not_authorised","reason":"Not management user"}
monitoring 개요 · 큐 · 연결을 본다. /api/users 는 Not administrator user
administrator 모두 
rabbitmqctl set_user_tags app monitoring
rabbitmqctl delete_user guest
  • 모니터링 도구에 줄 사용자는 monitoring 태그로 만든다
  • 명령줄 관리 도구 rabbitmqadmin(2.35.0) 도 이미지에 있다. 관리 API 를 쓰므로 다른 서버에서도 돈다(rabbitmqadmin -H rq -u admin -p … list queues)

메모리 · 디스크 경보

rabbitmq-diagnostics status
Memory high watermark setting: 0.6 of available memory, computed to: 2.4567 gb
  • 쓰는 메모리가 한도(기본 vm_memory_high_watermark 0.6) 를 넘거나 디스크 남은 자리가 한도(기본 disk_free_limit 50 MB) 밑이면, 서버가 보내는 쪽 연결을 모두 멈춘다
  • 한도를 rabbitmqctl set_vm_memory_high_watermark absolute 50MB 로 낮춰 경보를 켰다. 보내기가 경보를 끌 때까지 7.7 초 멈췄고, 클라이언트는 그 사이 알림을 받았다
conn.addBlockedListener(reason -> log("막힘: " + reason), () -> log("풀림"));
// 막힘: low on memory
// 풀림
  • 받는 쪽은 멈추지 않는다. 컨슈머가 큐를 비우면 메모리가 줄어 경보가 풀린다. 경보가 자주 나면 컨슈머가 따라가지 못하는 것이다
  • 운영에서는 disk_free_limit 를 메모리 크기쯤으로 올린다(disk_free_limit.absolute = 4GB)

Java 클라이언트

<dependency>
  <groupId>com.rabbitmq</groupId>
  <artifactId>amqp-client</artifactId>
  <version>5.37.1</version>
</dependency>
var f = new ConnectionFactory();
f.setHost("rq"); f.setUsername("app"); f.setPassword("App-pass-1"); f.setVirtualHost("shop");
try (Connection c = f.newConnection(); Channel ch = c.createChannel()) {
    ch.queueDeclare("app.orders", true, false, false, null);
    ch.basicPublish("", "app.orders", MessageProperties.PERSISTENT_TEXT_PLAIN, "hello".getBytes());
}
  • 연결(TCP) 하나에 채널을 여럿 연다. 연결은 앱마다 하나 · 둘로 오래 두고, 스레드마다 채널을 쓴다
  • 채널에서 오류(권한 · 없는 큐) 가 나면 그 채널이 닫힌다. 다시 쓰려면 채널을 새로 연다

Ubuntu 패키지

apt-cache policy rabbitmq-server     # Candidate: 3.12.1-1ubuntu1.7
  • 3.12 는 지원이 끝났고 4.x 와 기능 · 설정이 다르다. 서버에 바로 깔 때는 RabbitMQ 설명서의 Debian · Ubuntu 안내대로 RabbitMQ 팀의 저장소(Erlang 패키지 포함) 를 더한다
