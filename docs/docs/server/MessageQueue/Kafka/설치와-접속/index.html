Kafka 는 Java 로 된 서버다. Ubuntu 기본 저장소에는 없어, Apache 가 내는 tar 를 받아 풀거나 Docker 이미지(apache/kafka) 로 띄운다. 브로커는 클라이언트에게 "나는 이 주소에 있다" 고 알려 주고(advertised.listeners), 클라이언트는 그 주소로 다시 붙는다. 그래서 처음 붙은 주소가 맞아도, 알려 준 주소가 클라이언트에서 닿지 않으면 보내기가 시간 초과로 실패한다. Docker 에서는 컨테이너끼리 쓰는 리스너와 바깥에서 쓰는 리스너를 나눠 둔다. 아래 예제는 apache/kafka:4.4.0(JDK 25) 컨테이너 한 대(브로커 겸 컨트롤러) 와, 같은 Docker 네트워크의 maven:3.9-eclipse-temurin-25 컨테이너에서 돈 Java 클라이언트(kafka-clients 4.4.0) 로 돌렸다.

그대로 띄우면

docker run -d --name k1 --hostname k1 --network kafka-net apache/kafka:4.4.0
docker logs k1 | grep -E "process.roles|advertised.listeners|log.dirs"
	advertised.listeners = [PLAINTEXT://localhost:9092]
	log.dirs = [/tmp/kraft-combined-logs]
	process.roles = [broker, controller]
  • 4 초 만에 Kafka Server started 가 나왔다. 브로커와 컨트롤러(메타데이터 관리) 를 한 프로세스가 맡는다
  • 자료가 컨테이너 안의 /tmp 에 쌓인다. 컨테이너를 지우면 메시지도 사라진다
  • 같은 네트워크의 다른 컨테이너에서 k1:9092 로 보내자 처음 연결은 됐지만 그 뒤로 이 경고가 되풀이되고, 15 초 뒤(delivery.timeout.ms) 실패했다
WARN … Connection to node 1 (localhost/127.0.0.1:9092) could not be established. Node may not be available.
TimeoutException: Expiring 1 record(s) for t1-0:15001 ms has passed since batch creation.
  • 브로커가 알려 준 localhost:9092 는 클라이언트 컨테이너 자신이라 닿지 않는다
  • 없는 토픽 t1 에 보냈는데 토픽이 저절로 생겼다(auto.create.topics.enable=true)

리스너 나누기

docker run -d --name k1 --hostname k1 --network kafka-net -p 127.0.0.1:9092:9092 \
  -e KAFKA_NODE_ID=1 \
  -e KAFKA_PROCESS_ROLES=broker,controller \
  -e KAFKA_LISTENERS=INTERNAL://:19092,EXTERNAL://:9092,CONTROLLER://:9093 \
  -e KAFKA_ADVERTISED_LISTENERS=INTERNAL://k1:19092,EXTERNAL://localhost:9092 \
  -e KAFKA_LISTENER_SECURITY_PROTOCOL_MAP=INTERNAL:PLAINTEXT,EXTERNAL:PLAINTEXT,CONTROLLER:PLAINTEXT \
  -e KAFKA_INTER_BROKER_LISTENER_NAME=INTERNAL \
  -e KAFKA_CONTROLLER_LISTENER_NAMES=CONTROLLER \
  -e KAFKA_CONTROLLER_QUORUM_VOTERS=1@k1:9093 \
  -e KAFKA_LOG_DIRS=/var/lib/kafka/data \
  -e KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR=1 \
  -e KAFKA_AUTO_CREATE_TOPICS_ENABLE=false \
  -e KAFKA_HEAP_OPTS="-Xmx512m -Xms512m" \
  -v k1-data:/var/lib/kafka/data \
  apache/kafka:4.4.0
어디서 붙는 주소 결과
같은 네트워크의 컨테이너 k1:19092 (INTERNAL) 보내졌다
같은 네트워크의 컨테이너 localhost:9092 Connection to node -1 (localhost/127.0.0.1:9092) could not be established
맥(호스트) localhost:9092 (EXTERNAL, -p) 보내졌다
  • 환경 변수 KAFKA_… 는 설정 이름의 . 을 _ 로, 소문자를 대문자로 바꾼 것이다(log.dirs → KAFKA_LOG_DIRS). 하나라도 주면 이미지의 기본 설정을 쓰지 않으므로, 위의 줄을 함께 준다
  • 리스너마다 이름을 짓고 LISTENER_SECURITY_PROTOCOL_MAP 에서 방식(PLAINTEXT · SSL · SASL_SSL) 을 붙인다. 브로커끼리는 INTER_BROKER_LISTENER_NAME 의 리스너로 이야기한다
  • 서버에 바로 깔았다면 EXTERNAL 의 알리는 주소는 다른 서버가 찾을 수 있는 이름 · IP 다(EXTERNAL://kafka1.lan:9092)
  • CLUSTER_ID 를 주지 않으면 이미지에 정해진 값(Using provided cluster id 5L6g3nShT-eMCtK--X86sw) 으로 자료 폴더를 만든다. 브로커 여럿을 묶을 때는 kafka-storage.sh random-uuid 로 하나 만들어 모두에 준다
  • 토픽 자동 생성을 끄자, 없는 토픽에 보내기가 60 초(max.block.ms) 뒤 TimeoutException: Topic t1 not present in metadata after 60000 ms. 로 실패했다. 운영에서는 끄고 토픽을 미리 만든다(오타 토픽이 생기지 않게)

명령줄 도구

이미지의 /opt/kafka/bin/ 에 있다. 서버에 붙을 주소는 --bootstrap-server 로 준다.

kafka-topics.sh --bootstrap-server k1:19092 --create --topic orders --partitions 3
kafka-topics.sh --bootstrap-server k1:19092 --list
printf 'kim:apple\nlee:pear\n' | kafka-console-producer.sh --bootstrap-server k1:19092 --topic orders \
  --reader-property parse.key=true --reader-property key.separator=:
kafka-console-consumer.sh --bootstrap-server k1:19092 --topic orders --from-beginning \
  --formatter-property print.key=true --formatter-property print.partition=true
도구 하는 일
kafka-topics.sh 토픽 만들기 · 목록 · 설명 · 파티션 늘리기
kafka-console-producer.sh · kafka-console-consumer.sh 한 줄씩 보내기 · 받기
kafka-consumer-groups.sh 그룹의 offset · LAG 보기, offset 되돌리기
kafka-configs.sh 토픽 · 브로커 설정 바꾸기
kafka-get-offsets.sh 파티션마다 처음 · 끝 offset
kafka-metadata-quorum.sh KRaft 컨트롤러 상태
  • 4.4 에서 --property 는 Warning: --property is deprecated … 를 낸다. 보내기는 --reader-property, 받기는 --formatter-property 로 쓴다
  • --group 없이 띄운 kafka-console-consumer.sh 도 console-consumer-50559 같은 그룹을 만들고, 그 그룹은 남는다(kafka-consumer-groups.sh --list)

Java 클라이언트

<dependency>
  <groupId>org.apache.kafka</groupId>
  <artifactId>kafka-clients</artifactId>
  <version>4.4.0</version>
</dependency>
var props = new Properties();
props.put("bootstrap.servers", "k1:19092");
props.put("key.serializer", "org.apache.kafka.common.serialization.StringSerializer");
props.put("value.serializer", "org.apache.kafka.common.serialization.StringSerializer");
try (var p = new KafkaProducer<String, String>(props)) {
    RecordMetadata m = p.send(new ProducerRecord<>("orders", "kim", "apple")).get();
    System.out.printf("partition %d offset %d%n", m.partition(), m.offset());
}
mvn dependency:copy-dependencies -DoutputDirectory=lib    # kafka-clients 와 lz4 · snappy · zstd · slf4j
java -cp 'lib/*' Producer.java k1:19092                   # 한 파일짜리는 컴파일 없이 돈다
  • bootstrap.servers 는 처음 붙을 브로커다. 브로커가 여럿이면 둘셋을 적는다. 하나에 붙으면 나머지 브로커 주소는 메타데이터로 받는다
  • send 는 바로 돌아오고 보내기는 뒤에서 한다. 위처럼 .get() 으로 기다리면 결과(파티션 · offset) 나 오류를 바로 본다. 많이 보낼 때는 콜백(send(record, (m, e) -> …)) 을 쓴다
