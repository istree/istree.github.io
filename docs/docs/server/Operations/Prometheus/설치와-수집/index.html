Prometheus 는 설정 파일 하나(prometheus.yml) 에 어디서 지표를 당겨 올지(scrape_configs) 를 적고 띄운다. 대상마다 job 이름을 붙이고, 그 job 의 주소들(targets) 을 15 초쯤마다 찾아가 /metrics 를 읽는다. 리눅스 서버의 CPU · 메모리 · 디스크는 node_exporter 가, 앱의 지표는 앱이 스스로 내놓는다. 모은 것은 디스크에 보존 기간 동안 두고, 설정을 바꾸면 다시 띄우지 않고 다시 읽힌다. 아래 예제는 Docker 네트워크 하나에 prom/prometheus:v3.13.5(LTS) · prom/node-exporter:v1.12.1 · Spring Boot 4.1.2 앱(app) 을 띄워 돌렸다.

설정

# prometheus.yml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: prometheus
    static_configs:
      - targets: ["localhost:9090"]
  - job_name: node
    static_configs:
      - targets: ["node:9100"]
  - job_name: shop
    metrics_path: /actuator/prometheus
    static_configs:
      - targets: ["app:8080"]
  • metrics_path 의 기본은 /metrics 다. Spring Boot 앱은 /actuator/prometheus 로 바꾼다
  • 같은 일을 하는 서버 여럿은 한 job 의 targets 에 함께 적는다. 모은 값에는 job 과 instance(주소) 라벨이 붙는다

띄우기

docker network create mon
docker run -d --name node --network mon --pid host --uts host -v /:/host:ro,rslave \
  prom/node-exporter:v1.12.1 --path.rootfs=/host
docker run -d --name prom --network mon -p 127.0.0.1:9090:9090 \
  -v $PWD/prometheus.yml:/etc/prometheus/prometheus.yml \
  -v prom-data:/prometheus \
  prom/prometheus:v3.13.5 \
  --config.file=/etc/prometheus/prometheus.yml --storage.tsdb.path=/prometheus \
  --storage.tsdb.retention.time=15d --web.enable-lifecycle
msg="Starting Prometheus Server" mode=server version="(version=3.13.5, …)"
msg="TSDB retention updated" duration=15d size=0B percentage=0
msg="Server is ready to receive web requests."
  • node_exporter 를 컨테이너로 띄울 때는 바깥 기계를 보도록 / 를 붙이고 --path.rootfs=/host, --pid host 를 준다. --uts host 가 없으면 서버 이름(node_uname_info 의 nodename) 이 컨테이너 id(cfb0cdc79988) 로 나왔고, 주자 colima 였다. 서버에 바로 깔면(prometheus-node-exporter 패키지 · 받은 파일) 이것이 필요 없다
  • 이미지의 기본 명령은 --config.file=… --storage.tsdb.path=/prometheus 다. 옵션을 더하려고 명령을 바꾸면 이 둘이 빠지므로 다시 적는다. 빠뜨렸더니 자료가 /prometheus/data 에 쌓였다(작업 폴더 /prometheus 아래 기본값 data/)
  • 보존 기간의 기본은 15 일이다. --storage.tsdb.retention.size=10GB 로 크기 한도도 준다
  • 화면은 http://localhost:9090. 인증이 없으므로 바깥에 열지 않는다
  • Ubuntu 24.04 의 prometheus 패키지는 2.45.3 이다. 3.x 와 화면 · 일부 설정이 다르다

대상 보기

화면의 Status → Targets 나 API 로 본다.

curl -s localhost:9090/api/v1/targets
node        http://node:9100/metrics               up
prometheus  http://localhost:9090/metrics          up
shop        http://app:8080/actuator/prometheus    up

대상이 죽거나 주소가 틀리면 down 과 까닭이 나온다.

상황 lastError
앱 컨테이너를 멈춤 Get "http://app:8080/actuator/prometheus": dial tcp: lookup app on 127.0.0.11:53: no such host
포트를 틀리게 적음(app:8081) Get "http://app:8081/metrics": dial tcp 172.19.0.2:8081: connect: connection refused
  • 대상마다 up 시계열이 저절로 생긴다. 붙으면 1, 못 붙으면 0 이다. 앱을 멈추자 up{instance="app:8080", job="shop"} 가 0 이었다. "앱이 죽었다" 경보는 이것으로 건다
  • 한 번 읽는 데 걸린 시간도 남는다(lastScrapeDuration 0.035 초, 시계열 scrape_duration_seconds)

설정 다시 읽기

promtool check config /etc/prometheus/prometheus.yml
# SUCCESS: /etc/prometheus/prometheus.yml is valid prometheus config file syntax
curl -X POST localhost:9090/-/reload      # --web.enable-lifecycle 가 있어야 한다
  • 틀린 파일은 promtool 이 줄 번호와 함께 알린다. targets 를 목록이 아닌 곳에 적자 line 4: cannot unmarshal !!map into []*targetgroup.Group 이었다
  • --web.enable-lifecycle 없이 띄웠다면 kill -HUP 으로 다시 읽힌다

자리 · 크기

curl -s localhost:9090/api/v1/query --data-urlencode 'query=prometheus_tsdb_head_series'   # 1959
curl -s localhost:9090/api/v1/query --data-urlencode 'query=count({job="shop"})'           # 524
  • 대상 셋에서 시계열이 2 천 개쯤이었고, 그 가운데 앱 하나가 524 개였다. 디스크는 몇 분에 464 KB 였다
  • 크기는 시계열 수 × 보존 기간에 비례한다. 시계열이 갑자기 늘면 라벨에 바뀌는 값(사용자 id · 주문 번호) 이 들어간 것이다
