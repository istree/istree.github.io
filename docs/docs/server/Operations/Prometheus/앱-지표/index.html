Spring Boot 앱은 Actuator 와 Micrometer 로 지표를 낸다. micrometer-registry-prometheus 를 넣고 prometheus 엔드포인트를 열면 /actuator/prometheus 에 JVM · Tomcat · HTTP 요청 지표가 Prometheus 형식으로 나온다. 앱만의 지표(만든 주문 수) 는 MeterRegistry 로 counter · gauge · timer 를 만들어 더한다. 지표는 라벨 조합마다 시계열이 하나씩 생기므로, 라벨에는 가짓수가 적은 값만 넣는다. DB · 큐처럼 남이 만든 서버는 exporter 나 그 서버의 지표 플러그인으로 모은다. 아래 예제는 Spring Boot 4.1.2 앱(web · actuator · prometheus) 을 Docker 로 띄우고 prom/prometheus:v3.13.5 로 모았다.

내놓기

<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
<dependency>
  <groupId>io.micrometer</groupId>
  <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus
curl localhost:8080/actuator/prometheus | grep -c "^[a-z]"     # 516 줄
앞붙이 줄 수 보는 것
http_server_requests_seconds 424 주소 · 상태마다 요청 수 · 걸린 시간
jvm_ 60 힙 · GC · 스레드 · 클래스
tomcat_ · executor_ 13 세션 · 스레드 풀
process_ · system_ 9 CPU · 열린 파일 · 올라온 시간
logback_ 5 수준별 로그 줄 수
  • 이름은 64 가지, 종류는 counter 13 · gauge 43 · histogram 2 · summary 2 였다
  • /actuator/prometheus 는 바깥에 열지 않는다. Nginx 에서 막거나 관리 포트를 따로 둔다(management.server.port)

HTTP 요청

http_server_requests_seconds_count{error="none",exception="none",method="GET",outcome="SUCCESS",status="200",uri="/orders/{id}"} 1
http_server_requests_seconds_count{error="none",exception="none",method="GET",outcome="CLIENT_ERROR",status="404",uri="/**"} 1
  • uri 는 실제 주소가 아니라 매핑의 틀(/orders/{id}) 이다. 주문 번호마다 시계열이 생기지 않는다. 없는 주소는 모두 /** 로 묶인다
  • 처음에는 _count · _sum · _max 만 나온다. 백분위를 구하려면 구간(_bucket) 을 켠다
management:
  metrics:
    distribution:
      percentiles-histogram:
        http.server.requests: true
  • 켜자 성공한 /orders/{id} 하나에만 _bucket 줄이 69 개 생겼다. 516 줄 가운데 HTTP 가 424 줄이 된 것이 이것이다. 구간은 라벨 조합마다 붙으므로, 꼭 볼 지표에만 켠다
  • 환경 변수로 줄 때 percentiles-histogram 의 - 를 _ 로 바꾸면(…_PERCENTILES_HISTOGRAM_…) 앱이 percentiles.histogram 으로 읽어 Failed to bind properties … to double[] 로 뜨지 않았다. MANAGEMENT_METRICS_DISTRIBUTION_PERCENTILESHISTOGRAM_HTTP_SERVER_REQUESTS=true 로 붙여 쓴다

앱의 지표

@RestController
public class OrderController {
    private final Counter created;

    public OrderController(MeterRegistry registry) {
        this.created = Counter.builder("shop_orders_created").description("만든 주문 수").register(registry);
    }

    @PostMapping("/orders")
    public Map<String, Object> create() {
        created.increment();
        return Map.of("ok", true);
    }
}
# HELP shop_orders_total 만든 주문 수
# TYPE shop_orders_total counter
shop_orders_total 9.0
  • 이름을 shop_orders_created 로 지었는데 shop_orders_total 로 나왔다. Prometheus 의 Java 클라이언트는 이름 끝의 _total · _created · _bucket · _info 를 형식이 쓰는 말로 보고 떼어 낸 뒤(RESERVED_METRIC_NAME_SUFFIXES), counter 에 _total 을 붙인다. 이름 끝에 이 말들을 쓰지 않는다(shop_orders_placed)
  • 이름은 앱_무엇_단위(shop_payment_seconds) 로 짓는다. 단위는 초 · 바이트로 맞춘다
  • 걸린 시간은 Timer, 지금 개수(큐 길이) 는 Gauge, 늘기만 하는 수는 Counter 로 만든다

라벨

  • 라벨 값 하나하나가 따로 시계열이다. Counter.builder("shop_orders").tag("user", userId) 처럼 사용자 id · 주문 번호 · 전체 URL 을 라벨에 넣으면 사용자 수만큼 시계열이 생겨 Prometheus 의 메모리 · 디스크가 늘어난다
  • 라벨에는 가짓수가 정해진 것(상태 코드 · 결제 수단 · 결과 SUCCESS/FAIL) 만 넣는다. 한 사용자의 일은 로그로 본다
  • 시계열이 많은 지표는 Prometheus 에서 찾는다. topk(3, count by (__name__) ({job="shop"})) 는 http_server_requests_seconds_bucket 345 · http_server_requests_active_seconds_bucket 58 · jvm_memory_max_bytes 8 이었다

JVM 메모리

jvm_memory_max_bytes{area="heap",id="G1 Eden Space"} -1.0
jvm_memory_max_bytes{area="heap",id="G1 Old Gen"} 3.07232768E9
jvm_memory_max_bytes{area="heap",id="G1 Survivor Space"} -1.0
  • G1 의 Eden · Survivor 는 최대값이 정해져 있지 않아 -1 이다. 힙 쓴 비율을 sum(used) / sum(max) 로 내면 -1 이 섞여 0.0087 처럼 틀린 값이 나왔다
  • 최대값은 Old Gen 의 것(id="G1 Old Gen") 을 쓰거나, 쓴 양을 JVM 옵션으로 정한 힙(-Xmx) 과 견준다
