Grafana 도 경보를 낸다. 규칙은 데이터 소스에 보낼 질의와 조건(임계값) 으로 적고, 조건이 for 동안 이어지면 알림 정책에 따라 연락처(contact point) 로 보낸다. Prometheus 의 규칙 · Alertmanager 와 하는 일이 같아서, 둘 중 한 곳에 두는 것이 보통이다. Grafana 쪽은 화면에서 만들기 쉽고 Prometheus 밖의 데이터 소스(로그 · DB) 에도 걸 수 있다. 규칙 · 연락처 · 정책도 설정 파일로 넣는다. 아래 예제는 grafana/grafana:13.3.0 에 prom/prometheus:v3.13.5 를 붙이고, 받은 것을 찍기만 하는 webhook 서버로 받았다.

설정 파일로 넣기

# provisioning/alerting/shop.yml
apiVersion: 1
contactPoints:
  - orgId: 1
    name: hook
    receivers:
      - uid: hook
        type: webhook
        settings:
          url: http://hook:5001/
policies:
  - orgId: 1
    receiver: hook
    group_by: [alertname]
    group_wait: 10s
    group_interval: 1m
groups:
  - orgId: 1
    name: shop
    folder: 서버
    interval: 20s
    rules:
      - uid: shop-down
        title: ShopDown (Grafana)
        condition: C
        data:
          - refId: A
            relativeTimeRange: { from: 300, to: 0 }
            datasourceUid: prom
            model: { refId: A, expr: 'up{job="shop"}', instant: true }
          - refId: C
            datasourceUid: __expr__
            model:
              refId: C
              type: threshold
              expression: A
              conditions:
                - evaluator: { type: lt, params: [1] }
        for: 30s
        noDataState: Alerting
        execErrState: Error
        labels: { severity: critical }
        annotations: { summary: "shop 이 응답하지 않는다" }
  • 규칙은 질의 단계(A) 와 조건 단계(C) 로 나뉜다. A 가 up 을 가져오고, C 가 "1 보다 작다" 를 본다
  • noDataState: Alerting 은 질의 결과가 아예 없을 때도 경보로 친다. 지표가 사라지는 장애(대상이 목록에서 빠짐) 를 놓치지 않는다
  • 넣은 것은 API 에서 provenance: file 로 보이고, 화면에서 고치지 못한다

간격을 틀리면 뜨지 않는다

처음에 interval: 15s 로 적었더니 Grafana 가 뜨지 않고 멈췄다(Exited (1)).

Error: ✗ invalid service state: … failure: alert rules: invalid alert rule:
  interval (15s) should be non-zero and divided exactly by scheduler interval: 10
  • 규칙의 간격은 Grafana 의 계산 간격(10 초) 으로 나눠떨어져야 한다(10 · 20 · 30 초 …). Prometheus 에 맞춰 15 초로 적으면 안 된다
  • provisioning 파일 하나가 틀리면 Grafana 전체가 뜨지 않는다. 고친 파일은 띄우기 전에 다른 Grafana 에서 먼저 넣어 본다

경보가 오기까지

앱을 멈추고 webhook 에 오기까지를 쟀다. 같은 때 Prometheus 의 같은 규칙(for: 30s) 도 돌고 있었다.

11:58:43 firing ShopDown app:8080 app:8080 가 응답하지 않는다          ← Prometheus · Alertmanager, 54 초
11:59:00 firing ShopDown (Grafana) app:8080 shop 이 응답하지 않는다    ← Grafana, 71 초
  • Grafana 쪽이 17 초 늦었다. Grafana 는 Prometheus 가 모은 값을 20 초마다 다시 물어 본 뒤 for 를 세므로, 같은 규칙이라도 Prometheus 보다 늦게 알릴 수 있다
  • 두 곳에 같은 경보를 두면 알림이 두 번 온다. 한 곳을 정한다

어디에 둘까

Prometheus 규칙 + Alertmanager Grafana 경보
규칙 쓰기 YAML 에 PromQL 화면에서 질의 · 조건, 또는 YAML
데이터 소스 Prometheus 만 Prometheus · Loki · DB 등 여럿
Grafana 가 죽으면 그대로 알린다 알리지 못한다
묶기 · 막기 Alertmanager Grafana 안의 알림 정책 · silence
  • 서버 · 앱의 핵심 경보(죽음 · 오류율) 는 Prometheus 에 둔다. 보는 화면(Grafana) 이 죽어도 알림은 와야 한다
  • 여러 데이터 소스를 엮는 경보나 화면에서 자주 바꾸는 경보는 Grafana 에 둔다
