대시보드는 패널 여럿을 한 화면에 모은 것이다. 패널마다 PromQL 식을 하나 이상 적고, 시계열 그래프 · 큰 숫자(stat) · 표 같은 형태를 정한다. 위에 변수($instance) 를 두면 같은 대시보드로 앱 · 서버를 바꿔 본다. 리눅스 서버 · JVM 처럼 흔한 것은 남이 만든 대시보드를 번호로 가져온다. 만든 대시보드는 JSON 이므로 파일로 저장해 provisioning 으로 넣으면, 저장소에 두고 서버마다 같은 것을 띄운다. 아래 예제는 grafana/grafana:13.3.0 에 prom/prometheus:v3.13.5 를 붙이고, Spring Boot 4.1.2 앱(요청의 5 % 가 500 · 5 % 가 300 ms) 과 node_exporter 1.12.1 의 지표로 그렸다.

앱 대시보드

패널 형태 식
초당 요청 (상태별) 시계열 sum by (status) (rate(http_server_requests_seconds_count{job="shop",instance=~"$instance",uri!~"/actuator.*"}[$__rate_interval]))
오류율 (5 분) stat · 3 % 넘으면 빨강 5xx 의 rate ÷ 모든 rate
힙 사용 stat sum by (instance) (jvm_memory_used_bytes{area="heap",instance=~"$instance"})
응답 시간 시계열 · 식 셋 histogram_quantile(0.5 · 0.95 · 0.99, sum by (le) (rate(…_bucket[$__rate_interval])))
  • $__rate_interval 은 Grafana 가 수집 간격과 보는 기간에 맞춰 넣는 범위다. [1m] 처럼 박아 두면 긴 기간을 볼 때 점이 성겨지거나 비어 보인다
  • uri!~"/actuator.*" 로 Prometheus 가 지표를 읽어 가는 요청을 뺐다. 빼지 않으면 15 초마다의 수집이 요청 수에 섞인다
  • 단위를 정한다(reqps · percentunit · bytes · s). 숫자 옆에 req/s · % · MiB · ms 가 붙는다
  • stat 은 기본 임계값(80 넘으면 빨강) 이 있어, 바이트를 담은 힙 패널이 늘 빨갛게 나왔다. 뜻이 없는 패널은 임계값을 한 색으로 둔다
  • p95 가 0 과 270 ms 를 오갔다. 느린 요청이 딱 5 % 라 p95 가 그 경계에 걸린 것이다. p99 는 340 ms 로 고르게 나왔다

변수

{
  "name": "instance",
  "type": "query",
  "datasource": { "type": "prometheus", "uid": "prom" },
  "query": "label_values(up{job=\"shop\"}, instance)",
  "includeAll": true,
  "multi": true
}
  • label_values(지표, 라벨) 이 그 라벨의 값들을 내려 목록으로 보인다. 앱이 늘면 저절로 목록에 더해진다
  • 식에는 instance=~"$instance" 로 쓴다. 여럿을 선택하거나 All 이면 정규식(a|b) 으로 바뀌므로 = 가 아니라 =~ 다

가져오기

리눅스 서버는 Node Exporter Full(번호 1860) 을 가져왔다. 화면의 Dashboards → New → Import 에 번호를 넣거나 API 로 넣는다.

curl -s https://grafana.com/api/dashboards/1860/revisions/latest/download -o 1860.json

  • 패널 28 개, 변수 넷(ds_prometheus · job · nodename · node) 이었다. 데이터 소스를 변수로 받아, 가져올 때 따로 정할 것이 없었다
  • node_exporter 를 컨테이너로 띄우면 Nodename 이 컨테이너 id 로 나온다. node_exporter 에 --uts host 를 준다
  • JVM 은 JVM (Micrometer)(번호 4701) 이 있다. 가져온 대시보드는 지표 이름 · 라벨이 내 것과 같은지 보고 쓴다

파일로 넣기

# provisioning/dashboards/files.yml
apiVersion: 1
providers:
  - name: files
    folder: 서버
    type: file
    allowUiUpdates: false
    options:
      path: /var/lib/grafana/dashboards
  • 이 폴더의 JSON(shop.json) 이 「서버」 폴더 아래 대시보드가 된다. 화면에서 만든 대시보드는 Share → Export 로 JSON 을 받아 이 폴더에 둔다
  • 파일을 고치자 10 초 안에 대시보드의 판(version) 이 2 가 됐다. 다시 띄우지 않아도 읽는다
  • 파일로 넣은 대시보드를 API 로 저장하려 하자 {"message":"Cannot save provisioned dashboard"}(400) 였다. 화면에서 고친 것도 저장되지 않으므로, 고칠 때는 파일을 고친다
