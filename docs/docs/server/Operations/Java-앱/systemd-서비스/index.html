systemd 서비스

서버에서는 jar 를 systemd 서비스로 띄운다. 그러면 서버가 다시 켜질 때 저절로 뜨고, 앱이 죽으면 다시 뜨며, 로그는 저널에 모인다. 앱은 root 가 아니라 앱만의 사용자로 돌리고, 설정 · 비밀번호는 유닛 파일이 아니라 따로 둔 환경 파일에 넣는다. Java 는 SIGTERM 으로 끝나면 종료 코드 143 을 내므로 이것을 정상 종료로 알려 줘야 한다. 아래 예제는 Ubuntu 24.04(systemd 255) 에 openjdk-25-jre-headless(25.0.5) 를 깔고, Spring Boot 4.1.2 앱 jar 를 서비스로 띄웠다.

자리 · 사용자

sudo apt install openjdk-25-jre-headless
sudo useradd --system --home /opt/shop --shell /usr/sbin/nologin shop
sudo install -d -o shop -g shop /opt/shop
sudo install -o shop -g shop -m 644 shop.jar /opt/shop/shop.jar
자리 담는 것
/opt/shop/shop.jar 앱
/etc/shop/shop.env 설정 · 비밀번호
/etc/systemd/system/shop.service 유닛
저널(journalctl -u shop) 로그
  • --system 사용자는 로그인하지 못하고(nologin) 홈 폴더가 앱 자리다. 앱이 뚫려도 그 사용자의 권한만 갖는다

환경 파일

# /etc/shop/shop.env
SERVER_PORT=8080
JAVA_OPTS=-Xms256m -Xmx256m
SPRING_PROFILES_ACTIVE=prod
DB_PASSWORD=Db-pass-1
sudo chown root:root /etc/shop/shop.env
sudo chmod 600 /etc/shop/shop.env
  • 파일을 root 만 읽게(600) 두어도 앱은 떴다. 환경 파일은 systemd(root) 가 읽어 앱에 넘긴다. shop 사용자로 그 파일을 읽으면 Permission denied 였다
  • systemctl show shop -p Environment 에는 환경 파일의 값이 나오지 않았다(Environment=). 유닛에 Environment=DB_PASSWORD=… 로 적으면 누구나 systemctl show · systemctl cat 으로 본다
  • 넘긴 값은 프로세스의 환경에 남는다. 같은 사용자 · root 는 /proc/<PID>/environ 에서 DB_PASSWORD=Db-pass-1 을 읽었다

유닛

# /etc/systemd/system/shop.service
[Unit]
Description=shop (Spring Boot)
After=network-online.target
Wants=network-online.target

[Service]
User=shop
Group=shop
WorkingDirectory=/opt/shop
EnvironmentFile=/etc/shop/shop.env
ExecStart=/usr/bin/java $JAVA_OPTS -jar /opt/shop/shop.jar
SuccessExitStatus=143
Restart=on-failure
RestartSec=5
TimeoutStopSec=40

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now shop
systemctl status shop
● shop.service - shop (Spring Boot)
     Loaded: loaded (/etc/systemd/system/shop.service; enabled; preset: enabled)
     Active: active (running) since Mon 2026-11-09 17:27:41 KST; 6s ago
   Main PID: 60830 (java)
     Memory: 243.8M (peak: 244.1M)
     CGroup: /system.slice/shop.service
             └─60830 /usr/bin/java -Xms256m -Xmx256m -jar /opt/shop/shop.jar
  • WorkingDirectory 가 실행 폴더라, /opt/shop/application.yml 을 두면 jar 안의 설정을 덮어쓴다
  • TimeoutStopSec 은 graceful shutdown 의 기다림(30 초) 보다 길게 둔다. 그 안에 끝나지 않으면 systemd 가 SIGKILL 을 보낸다

유닛에서 걸린 것

고친 것 결과
SuccessExitStatus=143 을 뺌 systemctl stop 만 해도 Active: failed (Result: exit-code) · ExecMainStatus=143. 있으면 Result=success · inactive
$JAVA_OPTS 를 ${JAVA_OPTS} 로 씀 Invalid initial heap size: -Xms256m -Xmx256m · Error: Could not create the Java Virtual Machine. 로 뜨지 않고 다시 뜨기를 되풀이
  • systemd 는 $이름 을 빈칸에서 나눠 인자 여럿으로, ${이름} 은 통째로 인자 하나로 넣는다. JVM 옵션 여럿을 한 변수에 담았다면 $JAVA_OPTS 로 쓴다
  • failed 로 남으면 모니터링이 정상 정지를 장애로 센다

죽었을 때

sudo kill -9 $(systemctl show shop -p MainPID --value)
journalctl -u shop -n 30
systemd[1]: shop.service: Main process exited, code=killed, status=9/KILL
systemd[1]: shop.service: Failed with result 'signal'.
systemd[1]: shop.service: Scheduled restart job, restart counter is at 1.
systemd[1]: Started shop.service - shop (Spring Boot).
  • RestartSec=5 뒤 다시 떴고, 죽이고 9 초 뒤 다시 응답했다(5 초 기다림 + 뜨는 데 3 ~ 4 초). NRestarts 가 1 이 됐다
  • Restart=on-failure 는 비정상 종료 · 신호로 죽었을 때만 다시 띄운다. systemctl stop 으로 끈 것은 다시 띄우지 않는다
  • ${JAVA_OPTS} 시험처럼 늘 실패하는 서비스는 activating (auto-restart) 로 다시 띄우기를 되풀이했다. 고친 뒤 systemctl reset-failed shop 으로 실패 기록을 지우고 띄운다

새 판으로 바꾸기

sudo install -o shop -g shop -m 644 shop.jar /opt/shop/shop.jar.new
sudo mv /opt/shop/shop.jar.new /opt/shop/shop.jar      # 바꿔치기는 한 번에
sudo systemctl restart shop
  • 0.1 초마다 요청을 보내면서 바꾸자, 3.7 초 동안 연결이 거부됐다(000 33 번). 앞 판이 graceful 로 끝나고 새 판이 뜨는 데 3.3 초(Started ShopApplication in 3.316 seconds) 걸린 만큼이다
  • 끊기지 않게 하려면 앱을 둘 띄우고 Nginx 뒤에서 하나씩 바꾼다
  • 같은 유닛을 포트만 바꿔 여럿 띄울 때는 템플릿 유닛 shop@.service 를 쓴다. ExecStart=… -jar /opt/shop/shop.jar --server.port=%i 로 적고 systemctl enable --now shop@8081 shop@8082 로 띄운다
