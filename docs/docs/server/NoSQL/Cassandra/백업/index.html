Cassandra 의 백업은 노드마다 뜨는 스냅숏이다. nodetool snapshot 은 그 노드의 자료 파일(SSTable) 을 하드 링크로 묶어 두므로 순식간에 끝나고, 처음에는 자리를 거의 차지하지 않는다. 클러스터 전체를 뜨려면 모든 노드에서 같은 이름으로 뜬다. 스냅숏은 같은 디스크에 있으므로 다른 곳으로 옮겨야 백업이 되고, 표 구조(스키마) 는 따로 CQL 로 떠 둔다. 되살릴 때는 스냅숏의 파일을 표에 다시 넣는다(nodetool import). 아래 예제는 cassandra:5(5.0.9) 노드 셋, 복제 계수 3 에서 돌렸다.

뜨기

# 노드마다
nodetool snapshot -t before-1109 shop
# Snapshot directory: before-1109
nodetool listsnapshots
Snapshot name Keyspace name Column family name True size Size on disk Creation time
before-1109   shop          orders_by_user     1.28 KiB  8.04 KiB     2026-11-09T05:00:55.939Z
before-1109   shop          kv                 1.09 KiB  16.12 KiB    2026-11-09T05:00:55.939Z
before-1109   shop          orders_by_item     1.2 KiB   6.27 KiB     2026-11-09T05:00:55.939Z

Total TrueDiskSpaceUsed: 0 bytes
  • True size 는 스냅숏만 쥐고 있는 크기다. 하드 링크라 원본과 파일을 함께 쓰는 동안은 0 에 가깝고, 원본 파일이 합쳐지거나(compaction) 지워지면 스냅숏이 그 파일을 혼자 쥐며 늘어난다
  • 파일은 표 폴더 아래에 생긴다
/var/lib/cassandra/data/shop/kv-2fad9cd0dbfa11f1af14c36fc528848f/snapshots/before-1109/
  manifest.json
  nb-1-big-Data.db  nb-1-big-Index.db  nb-1-big-Statistics.db  …
  nb-2-big-…
  • 스냅숏 폴더에는 그 표를 만드는 schema.cql 도 들어 있다. 키스페이스까지 함께 떠 두려면 cqlsh -e "DESCRIBE KEYSPACE shop" > shop-schema.cql 을 한다. 표 폴더 이름의 뒷부분(2fad9cd0…) 은 표마다의 id 라, 새 클러스터에서는 표를 다시 만든 뒤 그 폴더로 넣는다
  • 스냅숏 폴더를 다른 서버 · 저장소로 복사한다(rsync · Medusa). 디스크가 죽으면 스냅숏도 함께 잃는다

지워진 것도 남긴다

TRUNCATE shop.kv 를 하자 스냅숏이 저절로 하나 생겼다.

truncated-1794200466303-kv shop  kv  16.12 KiB 16.12 KiB 2026-11-09T05:01:06.303Z
  • auto_snapshot: true(기본) 라 TRUNCATE · DROP TABLE 전에 뜬다. 표를 지우자 dropped-1794200973432-tmp 가 생겼다. 실수로 지운 표를 이것으로 되살린다
  • 그 대신 쌓이기만 하므로 nodetool clearsnapshot 으로 치운다

되살리기

TRUNCATE 로 빈 kv 에 스냅숏을 다시 넣었다. 복제 계수 3 이라 세 노드 모두에서 한다.

# 노드마다
d=$(ls -d /var/lib/cassandra/data/shop/kv-*)
mkdir -p /tmp/restore
cp $d/snapshots/before-1109/* /tmp/restore/
chown -R cassandra:cassandra /tmp/restore
nodetool import shop kv /tmp/restore
CONSISTENCY ALL;
SELECT * FROM shop.kv;
 k | v
---+---------
 1 |     new
 8 |    hint
 2 |       x
 7 | only-c1
 3 |       y
  • nodetool import 는 서버를 멈추지 않고 그 폴더의 SSTable 을 표에 넣는다. 넣은 뒤 /tmp/restore 에는 manifest.json · schema.cql 만 남았다 — SSTable 은 표 폴더로 옮겨진다. 그래서 스냅숏 폴더가 아니라 복사본으로 넣는다
  • 노드 하나에만 넣고 나머지는 nodetool repair 로 채울 수도 있다. 다만 자료가 크면 노드마다 넣는 편이 빠르다

치우기

nodetool clearsnapshot -t before-1109 -- shop    # 그 이름만
nodetool clearsnapshot --all -- shop             # 모두
nodetool listsnapshots                           # There are no snapshots

매일 뜨기

#!/bin/bash
# 노드마다 cron 으로 — 스냅숏을 뜨고 /backup(다른 디스크 · 저장소) 으로 옮긴 뒤 지운다
set -euo pipefail
t=daily-$(date +%F)
mkdir -p /backup/$(hostname)
nodetool snapshot -t $t shop
cqlsh -e "DESCRIBE KEYSPACE shop" > /backup/$(hostname)/shop-schema-$t.cql
rsync -a --include='*/' --include="snapshots/$t/**" --exclude='*' --prune-empty-dirs \
  /var/lib/cassandra/data/shop/ /backup/$(hostname)/$t/
nodetool clearsnapshot -t $t -- shop
  • 스냅숏 사이의 쓰기까지 살리려면 incremental_backups: true(기본 false) 로 새로 만들어지는 SSTable 을 backups/ 폴더에 따로 모은다
  • 노드가 여럿이면 스크립트보다 Medusa 처럼 클러스터를 한꺼번에 뜨고 되살리는 도구가 낫다
