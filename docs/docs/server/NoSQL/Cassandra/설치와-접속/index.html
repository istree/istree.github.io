Cassandra 는 Java 로 된 서버다. Ubuntu 기본 저장소에는 없어(apt-cache policy cassandra → Candidate: (none)) Apache 의 저장소를 더하거나 Docker 이미지(cassandra) 로 띄운다. 띄우면 9042(CQL) 로 앱을 받고, 7000 으로 다른 노드와 이야기한다. 처음에는 인증이 꺼져 있다. 메모리를 많이 잡으므로 힙 크기를 정해 띄우고, cqlsh 로 CQL 을 치고 nodetool 로 노드 상태를 본다. 아래 예제는 cassandra:5(5.0.9, OpenJDK 17) 컨테이너에서 돌렸다.

Docker

docker network create cass-net
docker run -d --name c1 --hostname c1 --network cass-net \
  -e MAX_HEAP_SIZE=768M \
  -e CASSANDRA_CLUSTER_NAME=shop \
  -e CASSANDRA_DC=dc1 \
  -e CASSANDRA_ENDPOINT_SNITCH=GossipingPropertyFileSnitch \
  -v c1-data:/var/lib/cassandra \
  cassandra:5
docker exec -it c1 cqlsh
  • 처음 뜨는 데 65 초 걸렸다. 그동안 cqlsh 는 Connection error 다. 로그에 Starting listening for CQL clients on /0.0.0.0:9042 · Startup complete 가 나온 뒤에 붙는다. 다시 띄울 때는 30 초쯤이었다
  • CASSANDRA_DC · CASSANDRA_RACK 은 GossipingPropertyFileSnitch 일 때 쓰인다. 복제 계수를 DC 마다 정하므로('dc1': 3) 처음부터 이름을 정해 둔다
  • 설정 파일은 /etc/cassandra/cassandra.yaml, 자료는 /var/lib/cassandra/ 다

메모리

힙
정하지 않으면 기계 메모리의 절반 (상한 31 GB)
MAX_HEAP_SIZE=768M 768 MB — 노드 하나가 메모리 1 GB 쯤을 썼다
  • 컨테이너는 기계 전체의 메모리를 보고 계산한다. 8 GB 기계에 정하지 않은 노드 셋을 띄우면 저마다 4 GB 를 잡으려 한다
  • 5.0 은 G1 GC 를 쓴다(jvm17-server.options 의 -XX:+UseG1GC). HEAP_NEWSIZE 를 함께 주면 로그에 HEAP_NEWSIZE has erroneously been set and will be ignored in combination with G1 이 나온다. MAX_HEAP_SIZE 만 준다
  • 768 MB 는 노드 셋을 한 기계에 띄워 보려고 줄인 값이다

cqlsh

SELECT release_version FROM system.local;     -- 5.0.9
DESCRIBE KEYSPACES;
DESCRIBE KEYSPACE shop;                        -- 키스페이스 · 표를 만드는 CQL 로 보인다
CONSISTENCY QUORUM;                            -- 이 접속의 일관성 수준
cqlsh 10.0.0.5 9042 -u app -p 'App-pass-1'    # 다른 노드 · 사용자
cqlsh -f schema.cql                            # 파일을 돌린다
cqlsh -e "SELECT * FROM shop.kv WHERE k = 1"   # 명령 하나만
  • -p 로 비밀번호를 주면 Warning: Using a password on the command line interface can be insecure. 가 나온다. 비밀번호는 ~/.cassandra/credentials(권한 600) 에 두면 -u · -p 없이 들어간다
[PlainTextAuthProvider]
username = admin
password = Admin-pass-1

인증 켜기

노드마다 cassandra.yaml 의 두 줄을 바꾸고 한 대씩 다시 띄운다.

authenticator: PasswordAuthenticator     # AllowAllAuthenticator 였다
authorizer: CassandraAuthorizer          # AllowAllAuthorizer 였다
-- cqlsh -u cassandra -p cassandra (처음 있는 관리자)
CREATE ROLE admin WITH SUPERUSER = true AND LOGIN = true AND PASSWORD = 'Admin-pass-1';
CREATE ROLE app WITH LOGIN = true AND PASSWORD = 'App-pass-1';
GRANT SELECT ON KEYSPACE shop TO app;
GRANT MODIFY ON KEYSPACE shop TO app;
ALTER KEYSPACE system_auth WITH replication = {'class': 'NetworkTopologyStrategy', 'dc1': 3};
nodetool repair -full system_auth
  • 켠 뒤 로그인 없이 붙으면 AuthenticationFailed('Remote end requires authentication') 다
  • app 은 읽고 썼고, DROP TABLE 은 Unauthorized: … User app has no DROP permission on <table shop.kv> or any of its parents 였다
  • system_auth 의 복제 계수는 처음에 1 이다(SimpleStrategy). 이대로 app 의 role 을 가진 노드(getendpoints system_auth roles app) 를 끄자, 다른 노드로도 app 로그인이 Unable to perform authentication: Cannot achieve consistency level 로 실패했다. 복제 계수를 노드 수만큼 올리고 repair 하자 노드 하나가 꺼져도 들어갔다
  • admin 을 만든 뒤 cassandra role 은 막는다(ALTER ROLE cassandra WITH SUPERUSER = false AND LOGIN = false). 이름 · 비밀번호가 모두에게 알려져 있다. 막은 뒤 cassandra 로는 Bad credentials 였다
