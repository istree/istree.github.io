Redis 는 자료를 메모리에 두지만, 다시 띄워도 남도록 디스크에 두 가지로 적는다. RDB 는 어느 순간의 메모리를 통째로 뜬 파일(dump.rdb) 이고, AOF 는 들어온 쓰기 명령을 차례로 적은 기록이다. RDB 는 작고 빨리 읽히지만 마지막으로 뜬 뒤의 변경을 잃는다. AOF 는 많아야 1 초 치만 잃지만 파일이 커진다. 기본은 RDB 만 켜져 있다. 캐시로만 쓰면 둘 다 꺼도 되고, 세션 · 큐처럼 잃으면 안 되는 자료를 두면 AOF 를 켠다. 아래 예제는 redis:8(8.10.3) 컨테이너와 Ubuntu 패키지의 Redis 7.0.15 에서 돌렸다.

RDB

save 3600 1 300 100 60 10000    # 1 시간에 1 번 · 5 분에 100 번 · 1 분에 1 만 번 이상 바뀌면 뜬다
dbfilename dump.rdb
dir /var/lib/redis              # Docker 이미지는 /data
BGSAVE      → Background saving started     자식 프로세스가 뜬다
SAVE        → OK                            다 뜰 때까지 서버가 멈춘다
LASTSAVE    → 1794198400                    마지막으로 뜬 시각

키 둘을 넣고 바로 끝내 봤다.

끝내는 법 다시 띄우면
docker stop (SIGTERM) 2 개 — 로그에 Saving the final RDB snapshot before exiting. · DB saved on disk
docker kill -s KILL 0 개 — 위 save 조건에 닿기 전이라 뜬 적이 없다
  • 제대로 끝내면 끝나기 전에 한 번 뜬다. 갑자기 죽으면(전원 · OOM killer · kill -9) 마지막으로 뜬 뒤의 변경을 잃는다
  • 뜬 상태는 INFO persistence 의 rdb_changes_since_last_save · rdb_last_bgsave_status:ok 로 본다
  • BGSAVE 는 자식 프로세스를 만든다. 로그의 WARNING Memory overcommit must be enabled! 를 그대로 두면 메모리가 빠듯할 때 뜨기에 실패할 수 있다(vm.overcommit_memory = 1)
  • 캐시로만 쓰고 다시 띄울 때 빈 채로 시작해도 되면 save "" 로 끈다

AOF

appendonly yes
appendfsync everysec     # 1 초마다 디스크에 밀어 넣는다

AOF 를 켜고 키 둘을 넣은 뒤 1.5 초 뒤 kill 했다. 다시 띄우자 둘 다 있었다.

DB loaded from base file appendonly.aof.1.base.rdb: 0.000 seconds
DB loaded from incr file appendonly.aof.1.incr.aof: 0.000 seconds

자료 폴더 안은 이렇다(7 부터).

dump.rdb
appendonlydir/
  appendonly.aof.1.base.rdb     # 바탕 (RDB 형식)
  appendonly.aof.1.incr.aof     # 그 뒤의 쓰기 명령
  appendonly.aof.manifest       # 어느 파일을 어떤 순서로 읽을지
# appendonly.aof.1.incr.aof 의 앞
*3
$3
SET
$1
c
$1
3
appendfsync 잃을 수 있는 것
always 거의 없다 (쓰기마다 디스크에, 느리다)
everysec (기본) 1 초 치
no OS 가 밀어 넣을 때까지 (보통 30 초쯤)
  • AOF 가 켜져 있으면 띄울 때 dump.rdb 가 아니라 AOF 를 읽는다
  • 기록이 길어지면 Redis 가 스스로 바탕 파일을 새로 뜨고 기록을 비운다(auto-aof-rewrite-percentage 100 · auto-aof-rewrite-min-size 64mb)
  • Docker 에서 CONFIG SET appendonly yes 로 켠 것은 다시 띄우면 꺼진다. 그 사이에 넣은 키는 AOF 를 읽지 않아 사라졌다. 설정 파일이나 redis-server --appendonly yes 로 띄운다

백업

RDB 파일 하나가 백업이다.

redis-cli -h 10.0.0.5 -a 'Redis-pass-1' --rdb /backup/redis-$(date +%F).rdb    # 서버에서 RDB 를 받아 온다
# 또는 서버에서
redis-cli BGSAVE && cp /var/lib/redis/dump.rdb /backup/
  • --rdb 는 복제처럼 붙어 RDB 를 받아 온다(Transfer finished with success after 190 bytes). 다른 기계에서 받을 수 있다
  • BGSAVE 는 바로 돌아오므로, 복사하기 전에 INFO persistence 의 rdb_bgsave_in_progress:0 을 본다

되살리기

서버를 멈추고 dump.rdb 를 바꿔 넣고 띄운다. AOF 가 켜져 있으면 이대로는 안 된다.

되살리는 법 다시 띄우면
AOF 켠 채 dump.rdb 만 바꿈 0 개 — AOF(지운 뒤의 상태) 를 읽었다
AOF 켠 채 appendonlydir 도 지움 0 개 — 빈 AOF 를 새로 만들고 dump.rdb 는 읽지 않았다
AOF 끄고 띄움 → CONFIG SET appendonly yes → AOF 켜고 다시 띄움 백업의 키가 모두 있었다 
docker stop redis                                  # 끝날 때 지금 상태로 dump.rdb 를 덮어쓴다
docker cp backup.rdb redis:/data/dump.rdb          # 그러니 멈춘 뒤에 넣는다
# appendonly no 로 띄운다 → 키를 확인한다
redis-cli CONFIG SET appendonly yes                # 지금 메모리로 AOF 를 새로 만든다
# 설정을 appendonly yes 로 돌려 다시 띄운다
  • Redis 는 멈출 때 메모리의 상태로 dump.rdb 를 덮어쓴다. AOF 를 켠 채 바꿔 넣고 띄웠다가 멈추자, 넣은 백업(190 바이트) 이 빈 DB 의 RDB(89 바이트) 로 덮였다. 넣기 전에 백업 파일을 다른 곳에 남겨 둔다
  • Ubuntu 패키지에서는 sudo systemctl stop redis-server 뒤 /var/lib/redis/dump.rdb 를 바꾸고, 주인을 redis:redis 로 둔다
