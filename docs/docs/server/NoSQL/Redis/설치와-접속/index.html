Redis 는 Ubuntu 패키지(redis-server) 로 서버에 바로 깔거나, Docker 이미지(redis) 로 띄운다. 둘은 처음 상태가 다르다 — Ubuntu 패키지는 127.0.0.1 에서만 듣고 보호 모드(protected-mode) 가 켜져 있으며, Docker 이미지는 설정 파일 없이 모든 주소에서 듣고 보호 모드가 꺼져 있다. 어느 쪽이든 처음에는 비밀번호가 없다. 앱이 붙기 전에 비밀번호나 ACL 사용자를 만들고, 바깥에 열지 않는다. 아래 예제는 ubuntu:24.04 에 apt 로 깐 Redis 7.0.15 와 redis:8(8.10.3) 컨테이너에서 돌렸다.

Ubuntu 패키지

sudo apt install redis-server
redis-server --version   # Redis server v=7.0.15 sha=00000000:0 malloc=jemalloc-5.3.0 bits=64 build=d064f9f48c901a92
redis-cli PING           # PONG
자리 · 값
설정 /etc/redis/redis.conf
자료 /var/lib/redis/dump.rdb
로그 /var/log/redis/redis-server.log
서비스 systemctl status redis-server
듣는 주소 bind 127.0.0.1 -::1 · port 6379
보호 모드 protected-mode yes
저장 save 3600 1 300 100 60 10000 (RDB) · appendonly no
메모리 한도 없음 (maxmemory 0)
  • 로그에 WARNING Memory overcommit must be enabled! 가 나온다. 디스크에 남길 때(BGSAVE) 자식 프로세스를 만드는데, 메모리가 빠듯하면 실패할 수 있다는 경고다. /etc/sysctl.conf 에 vm.overcommit_memory = 1 을 더한다
  • Ubuntu 24.04 에는 Valkey 패키지(valkey-server, 7.2.13) 도 있다. 명령 · 설정이 Redis 7.2 와 같다

Docker

docker run -d --name redis -p 127.0.0.1:6379:6379 -v redis-data:/data redis:8
docker exec -it redis redis-cli
  • 설정 파일 없이 뜬다(INFO server 의 config_file: 이 비어 있다). bind * -::*, protected-mode no 라 컨테이너에 닿는 곳이면 어디서든 비밀번호 없이 붙는다. 로그에도 WARNING: Redis does not require authentication and is not protected by network restrictions. 가 나온다
  • 자료 폴더는 /data 다. 저장 기본값은 Ubuntu 패키지와 같다(save 3600 1 300 100 60 10000, AOF 꺼짐)
  • 8 의 이미지에는 검색 · JSON · 시계열 · 블룸 필터 · 벡터 모듈이 들어 있다(MODULE LIST 에 search · ReJSON · timeseries · bf · vectorset)
  • CONFIG SET 으로 바꾼 값은 다시 띄우면 사라진다. 설정 파일이 없어 CONFIG REWRITE 도 ERR The server is running without a config file 이다

운영에서는 설정 파일을 붙여 띄운다.

# redis.conf
requirepass Redis-pass-1
appendonly yes
maxmemory 256mb
maxmemory-policy allkeys-lru
docker run -d --name redis -p 127.0.0.1:6379:6379 \
  -e REDISCLI_AUTH=Redis-pass-1 \
  -v $PWD/redis.conf:/usr/local/etc/redis/redis.conf \
  -v redis-data:/data \
  --health-cmd 'redis-cli ping | grep -q PONG' \
  redis:8 redis-server /usr/local/etc/redis/redis.conf
  • 설정 파일을 붙인 채 CONFIG REWRITE 를 하면 ERR Rewriting config file: Permission denied 였다. 컨테이너는 redis 사용자로 돌고, 붙인 파일은 내 사용자의 것이라서다. 바꿀 값은 파일을 고치고 다시 띄운다
  • REDISCLI_AUTH 환경 변수는 redis-cli 가 비밀번호로 읽는다. 위처럼 주면 건강 검사 · docker exec … redis-cli 에 비밀번호를 적지 않아도 된다. 띄우고 5 초 뒤 healthy 였다
  • redis-server --requirepass … 로 줘도 되지만 비밀번호가 프로세스 목록 · docker inspect 에 남는다

redis-cli

redis-cli -h 10.0.0.5 -p 6379 -a 'Redis-pass-1'   # 호스트 · 포트 · 비밀번호
redis-cli -n 1 SET x 1                            # 1 번 DB 에
redis-cli --scan --pattern 'user:*'               # 키 찾기 (KEYS 대신)
redis-cli INFO keyspace                           # DB 마다 키 수
명령 뜻
PING 살아 있으면 PONG
INFO · INFO memory 서버 상태 · 메모리(used_memory_human)
DBSIZE 지금 DB 의 키 수
SELECT 1 다른 DB 로 옮긴다 (0 ~ 15)
--bigkeys 자료형마다 키 수 · 큰 키를 훑는다
MONITOR 들어오는 명령을 모두 보인다 (운영 서버에서는 잠깐만)
  • -a 로 비밀번호를 주면 Warning: Using a password with '-a' or '-u' option on the command line interface may not be safe. 가 나온다. --no-auth-warning 으로 끄거나 REDISCLI_AUTH 환경 변수를 쓴다
  • DB 번호(-n) 는 한 서버 안의 이름 공간이다. 사용자 · 메모리 한도는 함께 쓴다. 앱을 나눌 때는 키 앞붙이(app1:) 나 서버를 나눈다

바깥에서 접속

다른 서버에서 붙으면 세 단계로 막힌다.

고친 것 붙으면
(그대로) Could not connect to Redis at ur:6379: Connection refused — 127.0.0.1 에서만 듣는다
bind 0.0.0.0 -:: DENIED Redis is running in protected mode because protected mode is enabled and no password is set for the default user. …
requirepass Redis-pass-1 비밀번호 없이 NOAUTH Authentication required., 틀리면 AUTH failed: WRONGPASS invalid username-password pair or user is disabled., 맞으면 PONG 
# /etc/redis/redis.conf
bind 0.0.0.0 -::
requirepass Redis-pass-1
  • 보호 모드는 "비밀번호가 없고 bind 를 열었을 때" 바깥 접속을 막는다. 비밀번호를 정하면 보호 모드와 상관없이 붙는다
  • -:: 의 - 는 그 주소를 쓸 수 없어도 뜨기를 멈추지 말라는 뜻이다
  • 인터넷에 6379 를 열지 않는다. Redis 는 빨라서 바깥에서 1 초에 많은 비밀번호를 시험할 수 있다. 비밀번호는 길게 짓고, 방화벽에서 앱 서버에만 연다

ACL 사용자

requirepass 는 default 사용자의 비밀번호다. 앱마다 쓸 키 · 명령을 나누려면 ACL 사용자를 만든다(6 부터).

ACL SETUSER app on >App-pass-1 ~app:* +@read +@write -@dangerous
redis-cli --user app --pass App-pass-1 SET app:1 hello     # OK
redis-cli --user app --pass App-pass-1 SET other:1 x       # NOPERM this user has no permissions to access one of the keys used as arguments
redis-cli --user app --pass App-pass-1 FLUSHALL            # NOPERM this user has no permissions to run the 'flushall' command
redis-cli --user app --pass App-pass-1 KEYS '*'            # NOPERM this user has no permissions to run the 'keys' command
redis-cli --user app --pass App-pass-1 CONFIG GET maxmemory  # NOPERM this user has no permissions to run the 'config|get' command
규칙 뜻
on · off 쓸 수 있음 · 막음
>비밀번호 비밀번호를 더한다
~app:* 이 패턴의 키만
+@read · +@write 읽기 · 쓰기 명령 묶음
-@dangerous FLUSHALL · KEYS · CONFIG 같은 위험한 명령을 뺀다
  • --scan --pattern 'app:*' 은 됐다. SCAN 은 @dangerous 가 아니다
  • 막힌 시도는 ACL LOG 에 사용자 · 명령 · 주소와 함께 남는다
  • ACL SETUSER 는 메모리에만 있다. Ubuntu 패키지에서 ACL SAVE 는 ERR This Redis instance is not configured to use an ACL file. 였고, CONFIG REWRITE 를 하자 redis.conf 끝에 user app on #e2e2… ~app:* … 줄이 적혀 다시 띄운 뒤에도 남았다

사용자를 파일 하나에 따로 두려면 aclfile 을 정한다.

# /etc/redis/redis.conf
aclfile /etc/redis/users.acl
sudo install -o redis -g redis -m 640 /dev/null /etc/redis/users.acl   # 빈 파일
sudo systemctl restart redis-server
redis-cli ACL SETUSER default '>Redis-pass-1'   # 이때 default 는 비밀번호가 없다 (아래)
redis-cli -a 'Redis-pass-1' ACL SAVE       # users.acl 에 사용자를 모두 적는다
  • redis.conf 에 user 줄이 남은 채 aclfile 을 더하면 뜨지 않는다. 로그에 Configuring Redis with users defined in redis.conf and at the same setting an ACL file path is invalid. 가 나온다. user 줄을 users.acl 로 옮긴다
  • aclfile 을 쓰면 requirepass 가 무시된다. requirepass 가 그대로 있는데도 다시 띄우자 default 가 nopass 로 열려, 비밀번호 없이 PONG 이 왔다. default 의 비밀번호도 ACL SETUSER 로 정해 users.acl 에 둔다
  • 파일을 손으로 고친 뒤에는 ACL LOAD 로 다시 읽는다
