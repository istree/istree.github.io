Redis 의 값은 자료형이 있다. 문자열 하나만 담는 키도 있고, 필드가 여럿인 해시 · 순서가 있는 리스트 · 겹치지 않는 집합 · 점수로 줄 세운 정렬 집합도 있다. 명령은 자료형마다 따로이고(GET · HGET · LPOP …), 다른 자료형의 명령을 쓰면 오류다. 키마다 만료 시간을 줄 수 있어 캐시 · 세션 · 잠금에 쓴다. 명령 하나하나는 원자적이고, 여럿을 묶을 때는 MULTI 나 Lua 스크립트를 쓴다. 아래 예제는 redis:8(8.10.3) 컨테이너의 redis-cli 에서 돌렸다.

문자열

SET greeting hello EX 60      → OK          60 초 뒤 사라진다
TTL greeting                  → 60
SET lock:1 a NX EX 10         → OK          없을 때만 넣는다
SET lock:1 b NX EX 10         → (nil)       이미 있어 넣지 않았다
INCR views                    → 1
INCRBY views 10               → 11
SET n abc
INCR n                        → ERR value is not an integer or out of range
  • NX 는 키가 없을 때만, XX 는 있을 때만 넣는다. SET … NX EX 한 줄이 "잠금을 잡고 10 초 뒤 저절로 풀기" 다
  • INCR 은 원자적이다. 여러 서버가 함께 올려도 빠지는 수가 없어 조회수 · 요청 수 세기에 쓴다. 속은 문자열이지만 OBJECT ENCODING views 는 int 다

해시 · 리스트 · 집합 · 정렬 집합

HSET user:1 name kim age 30   → 2
HINCRBY user:1 age 1          → 31
HGETALL user:1                → name kim age 31

RPUSH q a b c                 → 3
LPOP q                        → a           앞에서 꺼낸다 (큐)
LRANGE q 0 -1                 → b c

SADD tags x y x               → 2           겹친 x 는 한 번
SISMEMBER tags y              → 1

ZADD rank 100 kim 250 lee 180 park
ZREVRANGE rank 0 1 WITHSCORES → lee 250 park 180
ZINCRBY rank 100 kim          → 200
ZRANK rank kim                → 1           낮은 점수부터 0, 1, 2
자료형 쓰임
문자열 캐시 값(JSON) · 카운터 · 잠금
해시 객체 하나 (사용자 · 세션). 필드 하나만 읽고 고친다
리스트 큐 · 최근 본 목록 (LPUSH + LTRIM)
집합 태그 · 오늘 들어온 사용자 (겹치지 않게)
정렬 집합 순위표 · 시간순 목록 (점수 = 시각)
  • 해시 키에 GET user:1 을 하면 WRONGTYPE Operation against a key holding the wrong kind of value 다. TYPE 으로 자료형을 본다
  • 키 이름은 : 로 마디를 나눈다(user:1 · session:abc). Redis 는 이름의 뜻을 모르지만, --scan --pattern 'user:*' · ACL 의 ~user:* 가 이 형태로 묶는다

만료

EXPIRE user:1 30              → 1
TTL user:1                    → 30
PERSIST user:1                → 1           만료를 없앤다
TTL user:1                    → -1          만료 없음
TTL nokey                     → -2          키가 없다
SET greeting bye
TTL greeting                  → -1          SET 이 만료를 지웠다
  • 만료가 있던 키에 SET 을 다시 하면 만료가 사라진다. 값을 바꾸면서 남은 시간을 두려면 SET … KEEPTTL, 새로 정하려면 SET … EX 를 함께 준다
  • 해시 · 리스트는 키 전체에만 만료가 붙는다. 7.4 부터는 해시 필드마다 줄 수 있다(HEXPIRE)

KEYS 대신 SCAN

키 100 만 개를 넣고 KEYS * 를 돌렸다.

SLOWLOG GET 1    → KEYS 103061 마이크로초
  • KEYS 는 모든 키를 한 번에 훑는 동안 서버를 붙잡는다. 그사이 다른 클라이언트의 PING 이 86 ms 를 기다렸다(평소 2 ms). Redis 는 명령을 하나씩 처리하기 때문이다
  • redis-cli --scan --pattern 'k:99999*' 는 5.5 초 걸렸지만 조금씩 나눠 훑어서 서버를 오래 붙잡지 않는다. 운영 서버에서는 SCAN 을 쓴다
  • SCAN 0 MATCH 'k:1*' COUNT 10 은 다음 커서와 키 몇 개를 돌려준다. 커서가 0 으로 돌아올 때까지 되풀이한다. 같은 키가 두 번 나올 수 있다
  • 같은 까닭으로 큰 키의 HGETALL · SMEMBERS · LRANGE 0 -1 이나 FLUSHALL 도 서버를 붙잡는다. SLOWLOG GET 으로 오래 걸린 명령을 찾는다

여러 명령을 묶기

MULTI … EXEC 사이의 명령은 다른 클라이언트의 명령이 끼어들지 않고 한꺼번에 돈다.

MULTI
DECR stock                    → QUEUED
INCR sold                     → QUEUED
EXEC                          → 2  1

중간 명령이 실패해도 앞뒤 명령은 그대로 적용된다. 되돌리기는 없다.

MULTI
SET a 1
INCR stockx_not
LPUSH a x
SET b 2
EXEC                          → OK  1  WRONGTYPE …  OK
GET b                         → 2

값을 읽고 그 값으로 판단해 쓸 때는 WATCH 를 건다. 읽은 뒤 다른 클라이언트가 그 키를 바꾸면 EXEC 가 아무것도 하지 않는다.

p = r.pipeline()
p.watch("stock")
s = int(p.get("stock"))
# 그사이 다른 클라이언트가 stock 을 0 으로 바꿨다
p.multi()
p.set("stock", s - 1)
p.execute()     # redis.exceptions.WatchError: Watched variable changed.
  • 실패하면 처음부터 다시 읽고 시도한다. 다툼이 잦은 키라면 아래 스크립트가 낫다

Lua 스크립트

스크립트 하나가 통째로 원자적으로 돈다. "재고가 있으면 하나 줄인다" 를 한 번에 한다.

EVAL "local s = tonumber(redis.call('GET', KEYS[1])); if s and s > 0 then return redis.call('DECR', KEYS[1]) else return -1 end" 1 stock
  • stock 이 3 일 때 2, 0 일 때 -1 을 돌려주고 값은 그대로 0 이었다
  • 쓰는 키는 KEYS[1] 처럼 인자로 넘긴다. 스크립트 안에 키 이름을 적지 않는다
  • 스크립트가 도는 동안에도 서버는 다른 명령을 받지 못한다. 키 100 만 개를 넣는 스크립트처럼 오래 도는 일은 스크립트로 하지 않는다
  • 스크립트는 시작할 때만 메모리 한도를 본다. 한도 2 MB 에서도 도중의 SET 은 막히지 않아 메모리가 한도를 넘었다
