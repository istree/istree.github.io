MongoDB 의 백업은 대개 mongodump 로 DB 를 BSON 파일로 떠 두고 mongorestore 로 넣는 것이다. 폴더에 컬렉션마다 파일로 뜨거나, --archive --gzip 으로 파일 하나로 뜬다. 복제 세트에서는 secondary 에서 떠 primary 의 짐을 던다. 넣을 때는 같은 _id 의 문서가 이미 있으면 그 문서를 건너뛰므로, 덤프 때의 모습으로 되돌리려면 --drop 을 준다. 아래 예제는 mongo:9(9.0.4) 의 노드 셋 복제 세트에서 뜨고 단독 mongod 에 넣어 봤다. 도구는 이미지에 든 mongodump 100.20.0 이다.

뜨기

U='mongodb://root:Root-pass-1@mongo1:27017,mongo2:27017,mongo3:27017/?replicaSet=rs0&authSource=admin'

mongodump --uri "$U&readPreference=secondary" --db shop --archive=shop.archive.gz --gzip   # 3775 바이트
mongodump --uri "$U" --out dump/                                                            # 폴더로, DB 모두
done dumping `shop.ticks` (400 documents)
done dumping `shop.orders` (3 documents)
dump/
  prelude.json
  admin/system.users.bson         # 사용자
  admin/system.version.bson
  shop/orders.bson                # 문서
  shop/orders.metadata.json       # 인덱스 · 옵션
  shop/ticks.bson
  shop/ticks.metadata.json
옵션 뜻
--db shop · --collection orders 그 DB · 컬렉션만
--archive=파일 --gzip 파일 하나로, 압축해서
--query '{"at": {"$gte": …}}' 조건에 맞는 문서만 (컬렉션 하나일 때)
--dumpDbUsersAndRoles --db 로 뜰 때 그 DB 의 사용자 · 역할도
--oplog 뜨는 동안의 변경도 함께 떠서 한 시점으로 맞춘다 (전체를 뜰 때만)
  • 사용자는 admin DB 에 담긴다. --db shop 으로만 뜨면 shop 의 사용자(app) 가 빠진다. --dumpDbUsersAndRoles 를 주자 dumping users and roles for 'shop' 줄이 나왔다
  • --db shop --oplog 는 Failed: bad option: --oplog mode only supported on full dumps 다
  • 인덱스는 정의(metadata.json) 만 뜨고, 넣을 때 다시 만든다. 큰 컬렉션은 넣는 시간이 길다

넣기

M='mongodb://root:Root-pass-1@db2:27017/?authSource=admin'
mongorestore --uri "$M" --archive=shop.archive.gz --gzip
# 403 document(s) restored successfully. 0 document(s) failed to restore.
넣은 상황 결과
빈 서버에 403 document(s) restored successfully. 0 document(s) failed to restore.
같은 것을 한 번 더 continuing through error: E11000 duplicate key error … 가 줄마다 나고 0 document(s) restored successfully. 403 document(s) failed to restore.
문서를 지우고 new 를 넣은 뒤 --drop 으로 덤프 때의 세 문서(apple · milk · pear) 로 돌아갔다. new 는 사라졌다
--nsFrom='shop.*' --nsTo='shop_copy.*' shop_copy DB 로 넣었다. shop 은 그대로다
--nsInclude='shop.orders' --drop orders 만 넣었다(3 개)
  • --drop 이 없으면 있던 문서는 고쳐지지 않는다. 같은 _id 의 문서는 실패로 세고 넘어간다
  • 운영 DB 에 넣기 전에 --nsTo 로 다른 이름에 넣어 보거나 --dryRun 으로 무엇을 넣을지 본다
  • 비밀번호를 명령줄에 적으면 프로세스 목록에 남는다. password: … 한 줄을 적은 YAML 을 --config=파일 로 주고 연결 문자열에서는 비밀번호를 뺀다(mongodb://root@…)

Docker 에서

docker exec mongo mongodump -u root -p Root-pass-1 --authenticationDatabase admin \
  --db shop --archive --gzip > shop.archive.gz
docker exec -i mongo mongorestore -u root -p Root-pass-1 --authenticationDatabase admin \
  --archive --gzip --drop < shop.archive.gz
  • --archive 뒤에 파일 이름이 없으면 표준 출력 · 입력으로 쓴다. docker exec -i 가 있어야 파일이 들어간다

매일 뜨기

#!/bin/bash
# /usr/local/bin/mongo-backup.sh — root 의 crontab 에서 돈다
set -euo pipefail
umask 077
d=/var/backups/mongodb
mongodump --config=/root/.mongodump.yaml \
  --uri 'mongodb://root@mongo1:27017,mongo2:27017,mongo3:27017/?replicaSet=rs0&authSource=admin&readPreference=secondary' \
  --oplog --archive=$d/all-$(date +%F).archive.gz --gzip
find $d -name "all-*.archive.gz" -mtime +14 -delete
# /root/.mongodump.yaml (권한 600)
password: Root-pass-1
  • 전체를 --oplog 로 뜨면, 넣을 때 mongorestore --oplogReplay 로 뜨기가 끝난 시점에 맞춘다(replaying oplog · applied 0 oplog entries). 이때 --nsExclude 는 함께 쓰지 못한다(Failed: cannot use --oplogReplay with excludes specified)
  • 덤프는 뜬 시점으로만 돌아간다. 그 사이의 변경까지 살리거나 큰 DB 를 빨리 되살리려면 디스크 스냅숏 · 시점 복구를 하는 도구를 쓴다
  • 샤딩 클러스터는 mongos 로 떠도 샤드마다 시점이 달라진다. 이때는 balancer 를 멈추고 뜨거나 클러스터 백업 도구를 쓴다
