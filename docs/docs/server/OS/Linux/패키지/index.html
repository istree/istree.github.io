Ubuntu 의 프로그램은 apt 로 저장소에서 받아 깔고 올린다. apt 는 패키지 목록을 받아 두고(update), 그 목록에서 버전과 의존 패키지를 골라 깔며(install · upgrade), 실제 파일을 놓는 일은 dpkg 에 맡긴다. 서버에서는 깔기보다 관리가 더 잦다 — 무엇이 올라갈지 미리 보고, 올리면 안 되는 패키지를 고정하고, 지운 뒤 남은 것을 치우고, 보안 업데이트는 자동으로 받게 둔다. 아래 예제는 ubuntu:24.04 컨테이너(apt 2.8) 에서 돌렸다.

깔기 · 올리기

sudo apt update                  # 저장소의 패키지 목록을 새로 받는다
apt list --upgradable            # 올릴 수 있는 것
sudo apt upgrade                 # 깔린 것을 올린다
sudo apt install nginx           # 깐다 (의존 패키지도 함께)
sudo apt install nginx=1.24.0-2ubuntu7.19   # 버전을 정해 깐다

apt list --upgradable 은 새 버전과 지금 버전을 함께 보인다.

apt/noble-updates,noble-security 2.8.4ubuntu0.1 arm64 [upgradable from: 2.8.3]
libpcre2-8-0/noble-updates,noble-security 10.42-4ubuntu2.2 arm64 [upgradable from: 10.42-4ubuntu2.1]
  • update 는 목록만 받고 아무것도 올리지 않는다. 깔거나 올리기 전에 먼저 한다
  • upgrade 는 새 패키지를 깔거나 지워야 하는 업데이트는 건너뛴다(kept back). 그것까지 하려면 sudo apt full-upgrade 다
  • 무엇이 바뀔지 먼저 보려면 apt upgrade -s(흉내만) 를 쓴다
  • 스크립트 · Dockerfile 에서는 묻지 않게 DEBIAN_FRONTEND=noninteractive apt-get install -y … 로 쓴다. apt 는 사람이 보는 출력이라 스크립트에서 쓰면 WARNING: apt does not have a stable CLI interface 를 찍는다

무엇이 깔렸나

apt policy nginx          # 깔린 버전 · 깔릴 버전 · 어느 저장소에서
apt show nginx            # 설명 · 의존 · 크기
dpkg -l nginx             # 상태 — ii 깔림 · rc 지웠지만 설정이 남음 · hi 고정됨
dpkg -L nginx             # 이 패키지가 놓은 파일
dpkg -S /usr/sbin/nginx   # 이 파일을 놓은 패키지 — nginx: /usr/sbin/nginx
nginx:
  Installed: (none)
  Candidate: 1.24.0-2ubuntu7.19
  Version table:
     1.24.0-2ubuntu7.19 500
        500 http://ports.ubuntu.com/ubuntu-ports noble-updates/main arm64 Packages
        500 http://ports.ubuntu.com/ubuntu-ports noble-security/main arm64 Packages
     1.24.0-2ubuntu7 500
  • Candidate 가 install 하면 깔릴 버전이다. 같은 패키지가 여러 저장소에 있으면 우선순위(500) 가 같을 때 버전이 높은 쪽을 고른다

고정 (hold)

sudo apt-mark hold libpcre2-8-0
apt-mark showhold
sudo apt upgrade        # 2 upgraded, 0 newly installed, 0 to remove and 1 not upgraded.
sudo apt-mark unhold libpcre2-8-0
  • 고정한 패키지는 upgrade 가 건너뛰고 apt list --upgradable 에 그대로 남는다. DB · 런타임처럼 올릴 때를 사람이 정해야 하는 것에 쓴다
  • 고정한 패키지는 지우지도 못한다. apt remove -y nginx 가 E: Held packages were changed and -y was used without --allow-change-held-packages. 로 멈췄다. 먼저 unhold 한다

지우기 · 치우기

sudo apt remove nginx       # 프로그램만 지운다 — /etc/nginx 는 남는다
sudo apt autoremove         # 함께 깔렸다가 이제 아무도 쓰지 않는 의존 패키지를 지운다
sudo apt purge nginx-common # 설정 파일까지 지운다 — /etc/nginx 가 없어진다
dpkg -l | grep '^rc'        # 지웠지만 설정이 남은 패키지
sudo apt purge '~c'         # 그것들의 설정을 한꺼번에 지운다
sudo apt clean              # 받아 둔 .deb 파일(/var/cache/apt/archives) 을 지운다
  • nginx 를 remove 해도 함께 깔린 nginx-common · iproute2 등 아홉 개는 남았다. autoremove 가 그것들을 지웠다
  • 설정을 새로 시작하고 싶을 때는 purge 뒤 다시 깐다. remove 뒤 다시 깔면 남은 옛 설정을 그대로 쓴다

저장소 더하기

Ubuntu 가 주는 것보다 새 버전이 필요하면 만든 곳의 저장소를 더한다. 24.04 는 저장소를 /etc/apt/sources.list.d/*.sources 파일에 적는다(기본 저장소도 ubuntu.sources). 아래는 nginx.org 저장소다.

curl -fsSL https://nginx.org/keys/nginx_signing.key | sudo gpg --dearmor -o /usr/share/keyrings/nginx.gpg

/etc/apt/sources.list.d/nginx.sources

Types: deb
URIs: https://nginx.org/packages/ubuntu
Suites: noble
Components: nginx
Signed-By: /usr/share/keyrings/nginx.gpg
sudo apt update
apt policy nginx    # Candidate: 1.30.6-1~noble — nginx.org 의 버전이 높아 그쪽이 깔린다
  • Signed-By 는 이 저장소에만 쓸 열쇠다. 열쇠가 없으면 apt update 가 NO_PUBKEY 2FD21310B49F6B46 경고를 내고 그 저장소를 건너뛴다
  • Suites 는 배포판 이름(noble = 24.04) 이다. 배포판을 올린 뒤에는 이 이름도 바꿔야 한다

보안 업데이트 자동으로

unattended-upgrades 는 매일 apt-daily · apt-daily-upgrade 타이머로 보안 업데이트를 받아 깐다. 컨테이너 · colima 가상 머신 같은 작은 이미지에는 깔려 있지 않았다.

sudo apt install unattended-upgrades
cat /etc/apt/apt.conf.d/20auto-upgrades
# APT::Periodic::Update-Package-Lists "1";
# APT::Periodic::Unattended-Upgrade "1";
sudo unattended-upgrade --dry-run -v    # 무엇을 올릴지 흉내만
systemctl list-timers 'apt-daily*'

/etc/apt/apt.conf.d/50unattended-upgrades 에서 받을 저장소와 동작을 정한다.

Unattended-Upgrade::Allowed-Origins {
	"${distro_id}:${distro_codename}";
	"${distro_id}:${distro_codename}-security";
	"${distro_id}ESMApps:${distro_codename}-apps-security";
	"${distro_id}ESM:${distro_codename}-infra-security";
//	"${distro_id}:${distro_codename}-updates";
};
//Unattended-Upgrade::Remove-Unused-Dependencies "false";
//Unattended-Upgrade::Automatic-Reboot "false";
//Unattended-Upgrade::Automatic-Reboot-Time "02:00";
  • 기본은 -security 만 받는다. 더한 저장소(nginx.org 등) 는 여기에 적지 않으면 자동으로 올리지 않는다
  • 한 일은 /var/log/unattended-upgrades/unattended-upgrades.log 에 남는다 — INFO Packages that will be upgraded: apt libapt-pkg6.0t64 libpcre2-8-0
  • 커널 · libc 가 올라가면 다시 켜야 적용된다. /var/run/reboot-required 파일이 생기면 재부팅할 때다. 스스로 다시 켜게 하려면 Automatic-Reboot "true" 와 시간을 정한다
  • Docker 의 ubuntu 이미지는 /etc/apt/apt.conf.d/docker-disable-periodic-update 로 이 자동 업데이트를 끈다. 컨테이너는 이미지를 새로 만들어 올린다
