정해진 때에 명령을 돌리는 방법은 둘이다. 오래 써 온 cron 은 한 줄에 주기와 명령을 적어 간단하고, systemd 타이머는 파일 두 개가 들지만 로그가 journal 에 남고 꺼져 있던 동안 놓친 실행을 챙긴다. 백업 · 로그 정리 · 인증서 갱신 같은 서버 일에 쓴다. 아래 예제는 colima 의 Ubuntu 24.04 가상 머신에 cron 을 깔고 실제로 1 분을 기다려 결과를 봤다.

crontab

crontab -e        # 내 작업을 고친다 (처음이면 편집기를 선택)
crontab -l        # 목록
crontab -r        # 모두 지운다 — 되돌릴 수 없다
crontab 파일      # 파일 내용으로 통째로 바꾼다
sudo crontab -u deploy -l     # 다른 사용자의 것

한 줄은 다섯 칸의 주기(분 · 시 · 일 · 월 · 요일) 와 명령이다. 칸에 * 를 두면 모든 값이라, * * * * * 는 매분이다.

칸 값
분 0–59
시 0–23
일 1–31
월 1–12
요일 0–7 (0 · 7 은 일요일, 1–6 은 월–토)
적는 법 뜻
0,20,40 * * * * 매시 0 · 20 · 40 분
0-30 * * * * 매시 0 분부터 30 분까지 매분
*/10 * * * * 10 분마다
30 3 * * * 매일 03:30
0 9 * * 1-5 평일 09:00
@reboot 부팅할 때 한 번

로그 남기기

* * * * * $HOME/cron/job.sh >> $HOME/cron/job.log 2>&1     # 이어 쓰기
* * * * * /home/test.sh > /dev/null 2>&1                    # 출력을 버린다
  • 출력을 받지 않으면 cron 은 메일로 보내려 한다. 메일 서버가 없는 서버에서는 오류가 어디에도 남지 않으므로, 출력을 파일로 받아 두어야 실패를 알 수 있다
  • cron 이 언제 무엇을 돌렸는지는 journalctl -u cron 에 남는다 
    Nov 08 18:54:01 colima CRON[23559]: (geon) CMD (docker ps > $HOME/cron/which.log 2>&1)

cron 에서 다르게 도는 것

cron 의 작업은 로그인 셸이 아니다. 매분 env 를 파일로 남겨 보면 변수가 이것뿐이다.

HOME=/home/geon.guest
LOGNAME=geon
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
LANG=C.UTF-8
SHELL=/bin/sh
PWD=/home/geon.guest
  • 셸은 /bin/sh 이고 .bashrc · .profile 을 읽지 않는다. nvm · rbenv · pyenv 로 깐 명령, .bashrc 의 변수는 없다. 명령은 전체 경로로 쓰거나 crontab 위에 PATH=… 줄을 둔다
  • 현재 폴더는 홈이다. 스크립트 안에서 cd 하거나 전체 경로를 쓴다
  • % 는 cron 에서 줄바꿈이라 \% 로 적는다. date +%F >> pct.log 는 파일조차 생기지 않았고, date +\%F >> pct2.log 에만 2026-11-08 이 남았다

crontab 백업

crontab -l > ~/crontab.txt                         # 지금 것을 파일로
50 23 * * * crontab -l > /home/deploy/crontab.txt  # 매일 23:50 에 스스로 저장
  • crontab -e 대신 저장소의 파일을 crontab 파일 로 넣으면 서버마다 같은 작업을 유지할 수 있다

systemd 타이머

같은 일을 서비스 하나와 타이머 하나로 적는다.

/etc/systemd/system/backup.service

[Unit]
Description=Backup home

[Service]
Type=oneshot
ExecStart=/usr/bin/tar czf /tmp/home-backup.tgz -C /home .

/etc/systemd/system/backup.timer

[Unit]
Description=Daily backup

[Timer]
OnCalendar=*-*-* 03:30:00
Persistent=true

[Install]
WantedBy=timers.target
sudo systemctl daemon-reload
sudo systemctl enable --now backup.timer
systemctl list-timers backup.timer
# NEXT                        LEFT LAST PASSED UNIT         ACTIVATES
# Mon 2026-11-09 03:30:00 KST   8h -         - backup.timer backup.service
sudo systemctl start backup.service      # 기다리지 않고 지금 한 번
journalctl -u backup.service             # 결과
  • Persistent=true 는 꺼져 있어 놓친 실행을 켜질 때 한 번 돌린다. cron 은 놓친 것을 챙기지 않는다
  • OnCalendar 형식은 systemd-analyze calendar 로 다음 실행 때를 확인한다 
    systemd-analyze calendar "Mon..Fri *-*-* 09:00"
#   Original form: Mon..Fri *-*-* 09:00
# Normalized form: Mon..Fri *-*-* 09:00:00
#     Next elapse: Mon 2026-11-09 09:00:00 KST
  • hourly · daily · weekly 같은 줄임말과 *:0/10(10 분마다) 도 쓴다
  • 시스템이 이미 쓰는 타이머(apt-daily · fstrim · logrotate …) 도 systemctl list-timers 에 함께 나온다
