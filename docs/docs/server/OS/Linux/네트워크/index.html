리눅스 서버의 네트워크는 ip 명령으로 보고, Ubuntu 에서는 netplan 의 YAML 파일 하나로 IP · 게이트웨이 · DNS 를 정한다. netplan 은 이 파일을 읽어 systemd-networkd(서버) 나 NetworkManager(데스크톱) 설정으로 바꿔 준다. 고정 IP 를 줄 때는 원격으로 고치다 연결이 끊길 수 있으므로 netplan try 로 적용한다. 아래 예제는 colima 의 Ubuntu 24.04 가상 머신(netplan 1.1.2) 에서 돌렸고, 고정 IP 설정은 가상 머신의 연결을 끊지 않도록 netplan generate --root-dir 로 따로 만들어 확인했다.

지금 상태 보기

ip -br addr          # 인터페이스마다 상태 · IP
# lo               UNKNOWN        127.0.0.1/8 ::1/128
# eth0             UP             192.168.5.1/24 metric 200 fe80::5055:55ff:feb5:5a18/64
# docker0          DOWN           172.17.0.1/16 fe80::d018:b2ff:fe89:4c77/64
ip route             # 경로 — default 가 게이트웨이
# default via 192.168.5.2 dev eth0 proto dhcp src 192.168.5.1 metric 200
# 192.168.5.0/24 dev eth0 proto kernel scope link src 192.168.5.1 metric 200
cat /etc/resolv.conf # DNS — nameserver 192.168.5.1
getent hosts example.com    # 이름 풀이 확인 — /etc/hosts 와 DNS 를 차례로 본다
  • -br 은 짧게 보기다. 빼면 MAC · MTU 까지 나온다
  • ifconfig · route · netstat 는 net-tools 패키지로 옛 명령이다. 기본으로 깔려 있지 않다
  • 외부로 나가는지 확인할 때는 ping -c 3 1.1.1.1(IP) 과 ping -c 3 example.com(이름) 을 나눠 본다. IP 는 되고 이름이 안 되면 DNS 문제다

고정 IP (netplan)

/etc/netplan/01-static.yaml

network:
  version: 2
  ethernets:
    eth0:
      addresses: [192.168.2.20/24]
      routes:
        - to: default
          via: 192.168.2.1
      nameservers:
        addresses: [1.1.1.1, 8.8.8.8]
        search: [lan]
sudo chmod 600 /etc/netplan/01-static.yaml
sudo netplan try        # 적용하고 120 초 안에 Enter 를 누르지 않으면 되돌린다
sudo netplan apply      # 바로 적용

netplan 이 이 파일로 만든 systemd-networkd 설정이다.

[Match]
Name=eth0

[Network]
LinkLocalAddressing=ipv6
Address=192.168.2.20/24
DNS=1.1.1.1
DNS=8.8.8.8
Domains=lan

[Route]
Destination=0.0.0.0/0
Gateway=192.168.2.1
  • 인터페이스 이름(eth0 · ens3 · enp0s1 …) 은 ip -br link 로 확인한다
  • DHCP 로 받으려면 addresses · routes 대신 dhcp4: true 를 쓴다
  • 파일은 이름 순서로 읽고 뒤의 것이 앞의 것을 덮는다. 클라우드 이미지에는 50-cloud-init.yaml 이 있으니, 고칠 내용은 그보다 뒤 이름으로 두거나 그 파일을 고친다 (cloud-init 이 다시 쓰지 않게 하려면 /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg 에 network: {config: disabled})
  • 원격(SSH) 에서 바꿀 때는 꼭 netplan try 를 쓴다. 잘못 적어 연결이 끊겨도 저절로 되돌아온다

netplan 오류

잘못 적은 파일을 netplan generate 로 검사하면 이렇게 나온다 (--root-dir 로 돌려 붙은 경로 앞부분과 시각은 뺐다).

/etc/netplan/01-static.yaml:6:7: Invalid YAML: inconsistent indentation:
      dhcp4: true
      ^
** (generate:23424): WARNING **: `gateway4` has been deprecated, use default routes instead.
** (generate:23464): WARNING **: Permissions for /etc/netplan/01-static.yaml are too open. Netplan configuration should NOT be accessible by others.
  • YAML 은 들여쓰기가 뜻이다. 공백으로만, 같은 단계는 같은 칸에 맞춘다
  • gateway4: 192.168.2.1 은 옛 꼴이다. routes: - to: default via: … 로 바꾼다
  • 파일 권한은 600 이다. 와이파이 비밀번호 같은 것이 들어 있을 수 있어 netplan 이 경고한다
  • 적용 전 검사는 sudo netplan generate 다. 오류가 없으면 아무것도 찍지 않는다

이름 풀이 (/etc/hosts · DNS)

127.0.0.1   localhost
192.168.2.30  db.lan db
  • /etc/hosts 는 DNS 보다 먼저 본다. 몇 대 안 되는 서버끼리 이름으로 부를 때 쓴다
  • Ubuntu 의 /etc/resolv.conf 는 systemd-resolved 가 관리하는 파일로 이어져 있어(nameserver 127.0.0.53) 직접 고치면 다시 덮인다. DNS 는 netplan 의 nameservers 로 정하고 resolvectl status 로 확인한다

예전에는

  • Ubuntu 16.04 까지는 /etc/network/interfaces 에 iface eth0 inet static · address · netmask · gateway 를 적고 service networking restart 했다. 18.04 부터 netplan 이다
  • DNS 는 /etc/resolvconf/resolv.conf.d/head 에 nameserver 8.8.8.8 을 적고 service resolvconf restart 했다. 지금은 netplan 의 nameservers 다
