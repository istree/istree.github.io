서버가 갑자기 멈추는 흔한 까닭은 디스크가 차는 것이다. 디스크가 차면 로그 · DB 가 쓰지 못해 오류를 내고, 새 파일도 만들지 못한다. 그래서 디스크 일은 대개 "어디가 찼나" 를 찾는 것에서 시작한다 — df 로 어느 파일 시스템이 찼는지 보고, du 로 그 안에서 큰 폴더를 좁혀 간다. 디스크를 새로 붙일 때는 lsblk 로 장치를 찾아 파일 시스템을 만들고 /etc/fstab 에 적어 부팅 때 붙게 한다. 아래 예제는 colima 의 Ubuntu 24.04 가상 머신에서 돌렸고, 디스크를 채우고 붙이는 예제는 파일로 만든 디스크(루프 장치) 로 했다.

얼마나 찼나 (df)

df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/root        19G  1.2G   18G   7% /
/dev/vda16      891M   33M  796M   4% /boot
/dev/vda15       98M  6.4M   92M   7% /boot/efi
/dev/vdb1        20G  3.3G   16G  18% /mnt/lima-colima
tmpfs           2.0G     0  2.0G   0% /dev/shm
  • -h 는 읽기 쉬운 단위다. df -h /var 처럼 경로를 주면 그 경로가 있는 파일 시스템만 보인다
  • Size 에서 Used 를 빼도 Avail 이 되지 않는다. ext4 는 root 몫으로 5% 를 남겨 두어, 일반 사용자에게는 그만큼 일찍 찬다
  • tmpfs 는 메모리 위의 파일 시스템이다. 디스크 걱정과는 상관없다

어디가 큰가 (du)

sudo du -xh --max-depth=1 / | sort -h | tail
sudo du -xh --max-depth=1 /var | sort -h | tail
17M	/var/log
122M	/var/cache
222M	/var/lib
360M	/var
  • -x 는 다른 파일 시스템(/proc · 붙인 디스크) 으로 넘어가지 않는다. 빼면 엉뚱한 곳까지 세느라 오래 걸린다
  • 큰 것이 나온 폴더로 들어가 같은 명령을 되풀이한다
  • 서버에서 자주 커지는 곳은 정해져 있다
곳 보기 줄이기
systemd 로그 journalctl --disk-usage sudo journalctl --vacuum-size=200M
로그 파일 du -sh /var/log/* logrotate 설정
apt 가 받은 파일 du -sh /var/cache/apt sudo apt clean
Docker 이미지 · 볼륨 docker system df docker image prune · docker volume prune

꽉 찼을 때

dd if=/dev/zero of=/mnt/data/big bs=1M count=500
# dd: error writing '/mnt/data/big': No space left on device
df -h /mnt/data
# /dev/loop0      172M  168M     0 100% /mnt/data
echo hi > /mnt/data/x
# bash: echo: write error: No space left on device

No space left on device 는 자리가 없을 때 말고도, 파일 개수(inode) 가 다 찼을 때도 나온다. 작은 파일이 아주 많이 생기는 폴더(세션 · 캐시) 에서 일어난다.

touch /mnt/small/f54
# touch: cannot touch '/mnt/small/f54': No space left on device
df -h /mnt/small       # /dev/loop0   96M   24K   89M   1% /mnt/small  — 자리는 남았다
df -i /mnt/small       # /dev/loop0    64    64     0  100% /mnt/small  — inode 가 찼다
  • df -h 에 여유가 있는데 이 오류가 나면 df -i 를 본다
  • inode 개수는 파일 시스템을 만들 때 정해지고 나중에 늘릴 수 없다. 많은 파일을 지워야 풀린다

지웠는데 줄지 않을 때

큰 로그 파일을 지웠는데 df 가 그대로면, 그 파일을 아직 열고 있는 프로세스가 있는 것이다. 파일 이름은 사라졌지만 프로세스가 닫을 때까지 자리를 돌려주지 않는다.

rm /mnt/data/big
df -h /mnt/data        # /dev/loop0      172M  168M     0 100% /mnt/data  — 그대로
du -sh /mnt/data       # 20K — 파일로는 보이지 않는다
sudo lsof +L1          # 지워졌지만 열려 있는 파일
COMMAND   PID USER   FD   TYPE DEVICE  SIZE/OFF NLINK NODE NAME
sleep   54014 root    3r   REG    7,0 175382528     0   12 /mnt/data/big (deleted)
  • 그 프로세스를 다시 켜거나(systemctl restart …) 끄면 자리가 돌아온다
  • 쓰고 있는 로그는 지우지 말고 비운다. : > /mnt/data/app.log(또는 truncate -s 0) 는 파일을 그대로 두고 크기만 0 으로 만들어, 열고 있는 프로세스가 있어도 바로 자리가 돌아왔다
  • lsof 는 기본으로 깔려 있지 않을 수 있다(sudo apt install lsof). 없으면 ls -l /proc/*/fd 2>/dev/null | grep deleted 로도 찾는다

디스크 붙이기

lsblk -f                       # 장치 · 파티션 · 파일 시스템 · UUID · 붙은 곳
sudo mkfs.ext4 -L data /dev/vdc        # 파일 시스템을 만든다 — 안의 자료는 모두 지워진다
sudo mkdir -p /mnt/data
sudo mount /dev/vdc /mnt/data
sudo blkid /dev/vdc            # UUID="a617790e-…" TYPE="ext4"

부팅 때 붙게 하려면 /etc/fstab 에 적는다. 장치 이름(/dev/vdc) 은 디스크를 더하거나 빼면 바뀔 수 있으므로 UUID 로 적는다.

UUID=a617790e-7c97-48f1-a1fd-30f5c870ed79  /mnt/data  ext4  defaults,nofail  0  2
sudo findmnt --verify          # 0 parse errors, 0 errors, …
sudo systemctl daemon-reload
sudo mount -a                  # fstab 의 것을 붙여 본다
findmnt /mnt/data
  • fstab 이 틀리면 부팅이 멈추고 응급 모드로 들어갈 수 있다. 고친 뒤에는 다시 켜기 전에 findmnt --verify 와 mount -a 로 확인한다. 없는 UUID 를 적었을 때 [E] unreachable on boot required source: UUID=0000 으로 알려 줬다
  • nofail 은 그 디스크가 없어도 부팅을 이어 간다. 꼭 있어야 하는 디스크가 아니면 붙인다
  • 마지막 두 숫자는 덤프(0) 와 부팅 때 검사 순서다. / 는 1, 나머지는 2 다
  • fstab 을 고친 뒤 daemon-reload 하지 않으면 findmnt --verify 가 "systemd still uses the old version" 경고를 낸다

스왑 파일

메모리가 작은 서버는 스왑을 두어, 메모리가 모자랄 때 프로세스가 죽는(OOM) 대신 느려지게 한다. 파티션을 따로 나누지 않고 파일로 만든다.

sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
swapon --show      # /swapfile file 1024M   0B   -2
free -h            # Swap:  1.0Gi  0B  1.0Gi

/etc/fstab

/swapfile  none  swap  sw  0  0
  • 권한을 600 으로 하지 않으면 swapon: /swapfile: insecure permissions 0644, 0600 suggested. 경고가 나온다. 스왑에는 메모리 내용이 그대로 들어가므로 다른 사용자가 읽지 못하게 한다
  • 끌 때는 sudo swapoff /swapfile 뒤 파일과 fstab 줄을 지운다
  • 얼마나 일찍 스왑을 쓸지는 vm.swappiness(기본 60) 로 정한다. DB 서버는 낮춰(10) 두는 일이 많다
