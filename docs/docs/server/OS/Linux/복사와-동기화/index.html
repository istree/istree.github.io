폴더를 복사할 때는 대상 폴더가 이미 있는지, 원본 경로 끝에 / 가 붙었는지에 따라 결과가 달라진다. 빌드 결과를 배포 폴더로 옮기는 일처럼 "대상을 원본과 똑같이" 만들려면 cp 보다 rsync --delete 가 맞고, 다른 서버로 보낼 때도 rsync 가 바뀐 파일만 보낸다. 아래 예제는 Ubuntu 24.04 컨테이너(GNU coreutils · rsync 3.2.7) 에서, 원본 new/ 와 이미 있는 대상 dest/ 로 돌렸다.

폴더 파일
new/ (원본) a.txt · sub/b.txt
dest/ (대상, 이미 있음) a.txt · old/x.txt

cp 로 폴더 복사

cp -r new dest          # dest 가 있으면 그 안에 new 가 들어간다
# dest/a.txt  dest/new/a.txt  dest/new/sub/b.txt  dest/old/x.txt
cp -r new/. dest        # new 의 안쪽을 dest 에 — 덮어쓴다
cp -rT new dest         # 같은 결과 — 대상을 폴더가 아닌 "이 이름" 으로 본다(-T)
# dest/a.txt  dest/old/x.txt  dest/sub/b.txt
  • 대상이 없으면 cp -r new dest 는 dest 를 새로 만들어 복사한다. 같은 명령이 대상이 있을 때와 없을 때 다르게 동작하는 것이 실수의 원인이다
  • 덮어쓰기는 원본에 없는 파일(old/x.txt) 을 지우지 않는다. 똑같이 만들려면 대상을 지우고 복사하거나 rsync --delete 를 쓴다
  • -T 는 GNU 판에만 있다. 맥의 cp 에는 없다

cp -a 는 권한 · 소유자 · 시각을 그대로 옮긴다. 백업 · 이전에는 -a 를 쓴다.

cp new/a.txt c1         # -rw------- 2026-11-08 — 시각이 지금으로 바뀐다
cp -a new/a.txt c2      # -rw------- 2020-01-02 — 원본과 같다

rsync

rsync -a new dest       # 끝에 / 가 없으면 폴더째 — dest/new/… (cp -r 과 같다)
rsync -a new/ dest/     # 끝에 / 가 있으면 안쪽을 — dest/a.txt dest/sub/b.txt dest/old/x.txt
rsync -a --delete new/ dest/    # 원본에 없는 것은 지운다 — dest/a.txt dest/sub/b.txt

--delete 는 먼저 -n(해 보기) 와 -v 로 무엇을 지울지 본다.

rsync -a --delete -n -v new/ dest/
sending incremental file list
deleting old/x.txt
deleting old/
sub/
sub/b.txt

sent 124 bytes  received 47 bytes  342.00 bytes/sec
total size is 4  speedup is 0.02 (DRY RUN)
  • -a 는 하위 폴더 · 권한 · 시각 · 링크를 모두 옮기는 묶음이다. 거의 늘 붙인다
  • 끝 / 하나로 결과가 바뀐다. 원본은 new/, 대상은 dest/ 처럼 둘 다 붙이는 버릇을 들인다
  • 다시 돌리면 바뀐 파일만 보낸다. 같은 폴더를 두 번째 보내면 목록이 비고, a.txt 하나를 고치면 a.txt 만 나온다
  • 크기와 고친 시각이 같으면 내용이 달라도 건너뛴다. 시각을 맞춰 둔 다른 내용의 a.txt 는 그대로 남았고, -c(체크섬으로 비교) 를 붙여야 바뀌었다

다른 서버로

rsync -av site/ user@server:/var/www/site/      # ssh 로 보낸다 — 양쪽에 rsync 가 있어야 한다
rsync -av -e "ssh -p 2222" site/ user@server:/var/www/site/    # 포트 · 키 같은 ssh 옵션
scp site/index.html user@server:/tmp/           # 파일 하나 · 몇 개는 scp 로
  • 받는 서버에 rsync 가 없으면 연결 뒤 바로 끊긴다. 맥에서 보냈을 때는 rsync(23275): error: io_read_nonblocking 과 child … exited with status 127(명령 없음) 이 났다. apt install rsync 로 깐다
  • 큰 파일을 느린 망으로 보낼 때는 -z(압축) · --partial --progress(끊기면 이어서, 진행 표시) 를 붙인다

맥과 다른 점

  • macOS 15 의 rsync 는 GNU rsync 가 아니라 openrsync(protocol 29) 다. 기본 옵션은 같지만 드물게 쓰는 옵션은 없을 수 있다. 같은 것을 쓰려면 brew install rsync 로 깐다
  • 맥의 cp 에는 -T 가 없다. cp -R new/ dest 처럼 원본 끝에 / 를 붙이면 안쪽을 복사한다

예전에는

  • 옛 글의 「두 단계로 처리」 는 rm -rf a/ 뒤에 cp -rf a/ b/ 를 적어, 원본을 지우고 복사하는 순서가 되어 있었다. 지울 것은 대상이다 — rm -rf dest && cp -r new dest
