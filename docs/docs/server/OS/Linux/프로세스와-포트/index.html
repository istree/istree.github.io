서버에서 "무엇이 돌고 있나", "이 포트를 누가 잡고 있나", "왜 느린가" 를 볼 때 쓰는 명령을 모았다. 프로세스는 번호(PID) 로 가리키고, 끝낼 때는 신호를 보낸다. 포트는 프로그램 하나만 잡을 수 있어서, 서버가 Address already in use 로 뜨지 않으면 먼저 잡고 있는 프로세스를 찾는다. 아래 예제는 Ubuntu 24.04 컨테이너에서 파이썬 웹 서버(python3 -m http.server 8000) 를 띄워 놓고 돌렸다.

프로세스 보기

ps aux | head -1; ps aux | grep [h]ttp.server
# USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
# root        2081  1.9  0.4  25752 18588 ?        S    09:51   0:00 python3 -m http.server 8000
pgrep -af http.server
# 2081 python3 -m http.server 8000
ps -ef | grep [h]ttp           # 셋째 칸이 부모 PID(PPID)
# root        2081       1  1 09:51 ?        00:00:00 python3 -m http.server 8000
  • ps aux 는 모든 프로세스를 사용자 · CPU · 메모리(RSS, KB) 와 함께 보인다. ps -ef 는 부모 PID 를 보인다
  • grep [h]ttp 처럼 첫 글자를 [ ] 로 감싸면 grep 자신이 목록에 나오지 않는다
  • pgrep -af 무늬 는 명령줄 전체에서 찾아 PID 와 명령을 찍는다
  • 부모 · 자식 관계는 ps -ef --forest 나 pstree -p 로 본다

부하 보기

top -b -n 1 | head -5       # 한 번만 찍기. 그냥 top 은 계속 갱신 — q 로 끝
top - 09:51:10 up 45 min,  0 user,  load average: 0.08, 0.06, 0.08
Tasks:   4 total,   1 running,   3 sleeping,   0 stopped,   0 zombie
%Cpu(s):  0.0 us,  0.0 sy,  0.0 ni, 95.7 id,  4.3 wa,  0.0 hi,  0.0 si,  0.0 st
MiB Mem :   3904.7 total,    179.7 free,    414.8 used,   3493.6 buff/cache
MiB Swap:      0.0 total,      0.0 free,      0.0 used.   3489.9 avail Mem
free -h
#                total        used        free      shared  buff/cache   available
# Mem:           3.8Gi       414Mi       179Mi       788Ki       3.4Gi       3.4Gi
nproc                       # CPU 수 — 2
  • load average 는 1 · 5 · 15 분 동안 돌거나 기다린 프로세스 수의 평균이다. CPU 수(nproc) 보다 오래 크면 밀려 있다
  • top 안에서 P 는 CPU 순, M 은 메모리 순, 1 은 CPU 마다 보기다
  • 메모리는 free 가 아니라 available 을 본다. 리눅스는 남는 메모리를 파일 캐시(buff/cache) 로 쓰고 필요하면 내준다
  • 더 보기 좋은 htop 은 apt install htop 으로 깐다

포트를 잡은 프로세스

ss -tlnp
# State  Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
# LISTEN 0      5            0.0.0.0:8000      0.0.0.0:*    users:(("python3",pid=2081,fd=3))
sudo lsof -nP -iTCP:8000 -sTCP:LISTEN
# COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
# python3 2081 root    3u  IPv4  68335      0t0  TCP *:8000 (LISTEN)
sudo fuser -v 8000/tcp
#                      USER        PID ACCESS COMMAND
# 8000/tcp:            root       2081 F.... python3

같은 포트로 하나 더 띄우면 이렇게 된다.

OSError: [Errno 98] Address already in use
  • ss -tlnp 는 TCP(t) 의 듣는 소켓(l) 을 숫자로(n) 프로세스와 함께(p) 보인다. 남의 프로세스 이름은 sudo 로 돌려야 나온다
  • 0.0.0.0:8000 은 모든 주소에서, 127.0.0.1:8000 은 이 컴퓨터 안에서만 받는다
  • lsof -i :8000 은 맥에서도 된다. -nP 는 주소 · 포트를 이름으로 바꾸지 않아 빠르다

끝내기

kill 2081                   # SIGTERM — 정리하고 끝내라
kill $(pgrep -f http.server)
pkill -f http.server        # 무늬로 찾아 한 번에
kill -9 2099                # SIGKILL — 듣지 않을 때만
신호 번호 뜻
SIGTERM 15 끝내라 — kill 의 기본. 프로그램이 받아 정리하고 끝낸다
SIGKILL 9 바로 죽인다 — 프로그램이 막을 수 없고 정리할 틈이 없다
SIGINT 2 Ctrl-C
SIGHUP 1 터미널이 끊겼다. 데몬에는 "설정을 다시 읽어라" 로 쓴다 (nginx -s reload 와 같은 일)
  • -9 는 마지막 수단이다. 파일을 쓰다 죽어 자료가 깨질 수 있다. SIGTERM 을 무시하게 해 둔 셸(trap "" TERM) 은 kill 로는 그대로 S(잠) 상태였고 kill -9 에서 Killed 로 끝났다
  • pkill · pgrep -f 는 명령줄 전체에서 찾으므로 무늬가 넓으면 엉뚱한 것까지 끝낸다. 먼저 pgrep -af 로 목록을 본다
  • 서비스로 도는 프로그램은 kill 대신 systemctl stop · restart 로 다룬다

로그아웃해도 돌게

nohup ./long-job.sh > job.log 2>&1 &
  • 터미널을 닫으면 SIGHUP 을 받아 함께 끝나는 것을 nohup 이 막는다
  • 오래 돌 서버 프로그램은 systemd 서비스로 만드는 것이 맞다. 손으로 돌리다 끊길 걱정이 있는 작업은 tmux · screen 안에서 돌린다
