서버 프로그램은 systemd 의 서비스로 돌린다. systemd 는 부팅 때 서비스를 띄우고, 죽으면 다시 띄우고, 출력을 로그(journal) 에 모은다. 서비스마다 유닛 파일 하나에 무엇을 누구 권한으로 어떻게 돌릴지 적고, systemctl 로 켜고 끄며, journalctl 로 로그를 본다. 아래 예제는 colima 의 Ubuntu 24.04 가상 머신(systemd 255) 에서 파이썬 웹 서버를 hello 서비스로 만들어 돌렸다.

다루기

sudo systemctl start nginx          # 켠다
sudo systemctl stop nginx           # 끈다
sudo systemctl restart nginx        # 껐다 켠다
sudo systemctl reload nginx         # 끄지 않고 설정만 다시 읽는다 (되는 서비스만)
sudo systemctl enable --now nginx   # 부팅 때 켜지게 하고 지금도 켠다
sudo systemctl disable --now nginx  # 부팅 때 켜지지 않게 하고 지금 끈다
systemctl status nginx
systemctl is-active nginx           # active · inactive · failed
systemctl --failed                  # 실패한 유닛 목록
systemctl list-units --type=service --state=running
  • enable 은 부팅 때 켤지만 정하고 지금 켜지는 않는다. --now 를 붙여야 지금도 켜진다
  • 설정을 고친 웹 서버는 reload 로 접속을 끊지 않고 적용한다. 먼저 설정 검사(nginx -t) 를 한다

서비스 만들기

/etc/systemd/system/hello.service

[Unit]
Description=Hello web server
After=network.target

[Service]
User=hello
WorkingDirectory=/opt/hello
ExecStart=/usr/bin/python3 -m http.server 8000
Restart=on-failure
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
sudo useradd -r -s /usr/sbin/nologin hello      # 로그인할 수 없는 서비스용 사용자
sudo systemctl daemon-reload                     # 유닛 파일을 새로 읽는다
sudo systemctl enable --now hello
# Created symlink /etc/systemd/system/multi-user.target.wants/hello.service → /etc/systemd/system/hello.service.
systemctl status hello

항목 뜻
After=network.target 네트워크가 올라온 뒤에 띄운다
User= 이 사용자로 돌린다. 빼면 root 다
ExecStart= 돌릴 명령. 전체 경로로 쓰고, 앞에서(foreground) 도는 명령이어야 한다
Restart=on-failure 0 이 아닌 코드 · 신호로 죽으면 다시 띄운다 (always 는 정상 종료도)
Environment= · EnvironmentFile= 환경 변수 · 그 파일 (/etc/hello.env)
WantedBy=multi-user.target enable 하면 일반 부팅 때 켜진다
  • 프로그램을 kill -9 로 죽이면 Restart=on-failure 가 곧바로 다시 띄운다. 로그에 Scheduled restart job, restart counter is at 1. 이 남고 PID 가 바뀐다
  • 파이썬은 출력을 모아 두었다 내보내서 로그가 늦게 보인다. PYTHONUNBUFFERED=1 로 바로 쓰게 한다
  • 패키지가 깐 유닛(/usr/lib/systemd/system/) 은 고치지 않는다. 바꿀 것만 덧붙이는 파일(drop-in) 을 sudo systemctl edit nginx 로 만든다

설정 덧붙이기 (drop-in)

/etc/systemd/system/hello.service.d/override.conf

[Service]
ExecStart=
ExecStart=/usr/bin/python3 -m http.server 8001
sudo systemctl daemon-reload && sudo systemctl restart hello
systemctl cat hello          # 원래 파일과 덧붙인 파일을 함께 보인다
  • ExecStart= 는 빈 값으로 한 번 지우고 다시 적는다. 지우지 않으면 명령이 둘이 되어 Service has more than one ExecStart= setting, which is only allowed for Type=oneshot services. Refusing. 으로 뜨지 않는다
  • systemctl edit 이름 은 이 폴더 · 파일을 만들고 저장하면 daemon-reload 까지 한다

로그 보기

journalctl -u hello -n 5            # 마지막 다섯 줄
journalctl -u hello -f              # 따라 보기
journalctl -u hello --since "10 min ago"
journalctl -p err -b                # 이번 부팅의 오류만
journalctl --disk-usage             # Archived and active journals take up 8.0M in the file system.
  • 남의 서비스 로그는 sudo 나 adm · systemd-journal 그룹이 있어야 보인다
  • 오래된 로그는 sudo journalctl --vacuum-size=200M 으로 줄인다

뜨지 않을 때

유닛 파일의 명령 경로를 틀리게 고치고 돌리면 이렇게 된다.

sudo systemctl restart hello
# Warning: The unit file, source configuration file or drop-ins of hello.service changed on disk. Run 'systemctl daemon-reload' to reload units.

daemon-reload 를 하지 않으면 고치기 전 내용으로 돈다. 다시 읽고 띄우면 실패한다.

× hello.service - Hello web server
     Loaded: loaded (/etc/systemd/system/hello.service; enabled; preset: enabled)
     Active: failed (Result: exit-code) since Sun 2026-11-08 18:52:10 KST; 372ms ago
    Process: 22749 ExecStart=/usr/bin/python9 -m http.server 8000 (code=exited, status=203/EXEC)
hello.service: Start request repeated too quickly.
hello.service: Failed with result 'exit-code'.
Failed to start hello.service - Hello web server.
  • status=203/EXEC 는 명령을 실행하지 못했다는 뜻이다. 경로 · 실행 권한을 본다
  • 짧은 시간에 여러 번 죽으면 systemd 가 다시 띄우기를 멈춘다(Start request repeated too quickly). 고친 뒤 sudo systemctl reset-failed hello 하고 다시 띄운다
  • systemctl status 아래의 로그 몇 줄로 모자라면 journalctl -u 이름 -n 50 으로 더 본다

예전에는

  • service ssh restart · /etc/init.d/nginx restart 처럼 SysV init 스크립트를 썼다. 지금도 service 명령은 systemctl 로 넘겨 주지만, 새로 쓸 때는 systemctl 이다
  • 부팅 때 띄울 명령을 /etc/rc.local 에 적었다. 지금은 유닛 파일을 만들어 enable 한다
