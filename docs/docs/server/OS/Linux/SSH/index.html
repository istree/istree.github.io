SSH 는 다른 컴퓨터의 셸에 암호화된 연결로 들어가는 방법이다. 서버에는 OpenSSH 서버(sshd) 가 돌고, 내 컴퓨터의 ssh 로 들어간다. 비밀번호 대신 키로 들어가고, 자주 가는 서버는 ~/.ssh/config 에 이름을 붙이며, 서버 쪽에서는 root 로그인과 비밀번호 로그인을 막는 것이 기본이다. 아래 예제는 맥(OpenSSH 9.9) 에서 colima 의 Ubuntu 24.04 가상 머신(OpenSSH 9.6) 에 deploy 사용자로 들어가며 돌렸다.

키 만들기

ssh-keygen -t ed25519 -C "geon@mac"     # ~/.ssh/id_ed25519 · id_ed25519.pub 을 만든다
  • id_ed25519 는 비밀 키(권한 600), id_ed25519.pub 은 공개 키다. 서버에는 공개 키만 올린다
  • 비밀 키에 암호(passphrase) 를 걸고, 맥에서는 ssh-add --apple-use-keychain ~/.ssh/id_ed25519 로 키체인에 넣어 매번 묻지 않게 한다
  • ed25519 가 지금 기본이다. 아주 옛 서버만 rsa(-t rsa -b 4096) 를 쓴다

서버에 공개 키 올리기

ssh-copy-id deploy@server         # 비밀번호로 한 번 들어가 authorized_keys 에 더한다

비밀번호 로그인이 막힌 서버는 다른 계정 · 콘솔로 들어가 직접 넣는다.

sudo -u deploy mkdir -p /home/deploy/.ssh
echo "ssh-ed25519 AAAA… geon@mac" | sudo -u deploy tee -a /home/deploy/.ssh/authorized_keys
sudo chmod 700 /home/deploy/.ssh
sudo chmod 600 /home/deploy/.ssh/authorized_keys
  • 권한이 느슨하면 sshd 가 키를 쓰지 않는다. authorized_keys 를 666 으로 두자 로그인이 Permission denied (publickey). 로 막히고, 서버 로그에 Authentication refused: bad ownership or modes for file /home/deploy/.ssh/authorized_keys 가 남았다
  • 서버 로그는 sudo journalctl -u ssh 로 본다. 클라이언트에서는 ssh -v 로 어떤 키를 시도했는지 본다

~/.ssh/config

Host vm
  HostName 127.0.0.1
  Port 49428
  User deploy
  IdentityFile ~/.ssh/id_ed25519
ssh vm 'whoami; hostname'
# deploy
# colima
scp file.txt vm:/tmp/        # scp · rsync 도 이 이름을 쓴다
  • Host * 아래에 ServerAliveInterval 60 을 두면 오래 가만히 있어도 연결이 끊기지 않는다
  • 처음 들어가는 서버는 지문(fingerprint) 을 묻고 ~/.ssh/known_hosts 에 남긴다. 서버를 다시 깔아 지문이 바뀌면 ssh-keygen -R 호스트 로 옛 것을 지운다

서버 설정 (sshd)

Ubuntu 24.04 의 /etc/ssh/sshd_config 는 맨 위에서 Include /etc/ssh/sshd_config.d/*.conf 를 읽는다. 바꿀 것은 이 폴더에 파일로 둔다.

/etc/ssh/sshd_config.d/50-local.conf

PermitRootLogin no
PasswordAuthentication no
sudo sshd -t                          # 검사 — 문제가 없으면 아무것도 찍지 않는다
sudo systemctl reload ssh
sudo sshd -T | grep -E '^(permitrootlogin|passwordauthentication|pubkeyauthentication) '
# permitrootlogin without-password
# pubkeyauthentication yes
# passwordauthentication no
  • sshd -T 는 모든 파일을 합친 최종 값을 보인다. 위 출력은 colima 가상 머신의 기본값이다 (without-password 는 prohibit-password 의 옛 이름 — root 는 키로만)
  • 틀린 값을 넣으면 sshd -t 가 /etc/ssh/sshd_config.d/99-test.conf line 1: unsupported option "maybe". 처럼 알려 준다. 검사 없이 재시작하면 sshd 가 뜨지 않아 원격으로 다시 들어갈 수 없다
  • 설정을 바꿀 때는 지금 연결을 닫지 말고 새 창으로 들어가 본다. 막혔으면 열려 있는 창에서 되돌린다
  • 비밀번호 로그인을 막은 서버에 비밀번호로 들어가려 하면 Permission denied (publickey). 로 끝난다

터널 (포트 넘기기)

서버 안에서만 열린 포트(DB · 관리 화면) 를 내 컴퓨터로 끌어온다.

ssh -f -N -L 9100:127.0.0.1:9000 vm     # 내 9100 → 서버의 127.0.0.1:9000
curl -s localhost:9100 | head -1        # <!DOCTYPE HTML>
  • -N 은 명령 없이 연결만, -f 는 뒤로 보낸다. 끝낼 때는 그 ssh 프로세스를 끝낸다
  • 거꾸로 내 컴퓨터의 포트를 서버에 여는 것은 -R 이다
  • 다른 서버를 거쳐 들어가려면 ssh -J 거칠서버 목적서버 다 (config 에서는 ProxyJump)

예전에는

  • 옛 글은 설치 뒤 PermitRootLogin yes 로 root 비밀번호 로그인을 열었다. 인터넷에 열린 서버는 몇 분 안에 비밀번호 대입 공격을 받으므로, 일반 사용자 + 키 + sudo 로 들어간다
  • 설정을 고친 뒤 service ssh restart 로 다시 띄웠다. 지금은 sshd -t 로 검사하고 systemctl reload ssh 한다
