서버의 방화벽은 바깥에서 들어오는 연결 가운데 열어 둔 포트만 받고 나머지는 막는다. 리눅스 커널의 netfilter 가 실제로 걸러 내고, Ubuntu 에서는 그 규칙을 ufw 로 짧게 적는다. 처음에는 "들어오는 것은 모두 막고, SSH · 웹만 연다" 로 두고, DB 같은 포트는 그것을 쓰는 서버의 IP 에만 연다. 아래 예제는 Docker 컨테이너 안에서(ufw 0.36.2, 컨테이너마다 따로인 네트워크) ufw 를 켜고, 같은 네트워크의 다른 컨테이너에서 붙어 확인했다. 「Docker 와 함께」 는 그 컨테이너 안에 Ubuntu 의 Docker(29.1.3) 를 깔아 돌렸다.

켜기

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp         # SSH 를 먼저 연다
sudo ufw allow 80/tcp
sudo ufw allow from 172.18.0.3 to any port 3306 proto tcp
sudo ufw enable
sudo ufw status verbose
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), deny (routed)
New profiles: skip

To                         Action      From
--                         ------      ----
22/tcp                     ALLOW IN    Anywhere
80/tcp                     ALLOW IN    Anywhere
3306/tcp                   ALLOW IN    172.18.0.3
22/tcp (v6)                ALLOW IN    Anywhere (v6)
80/tcp (v6)                ALLOW IN    Anywhere (v6)

다른 서버에서 붙어 본 결과다.

포트 172.18.0.3 (허용한 IP) 172.18.0.4
80 (허용) 열림 열림
8080 (규칙 없음) 막힘 막힘
3306 (IP 만 허용) 열림 막힘
  • SSH 로 들어가 있는 서버에서는 enable 전에 반드시 allow 22/tcp(또는 allow OpenSSH) 를 한다. 빼먹으면 SSH 로 다시 들어갈 수 없다
  • 규칙은 IPv4 · IPv6 에 함께 들어간다((v6) 줄). IP 를 정한 규칙은 그 IP 의 판에만 들어간다
  • enable 하면 부팅 때도 켜진다(Firewall is active and enabled on system startup)

규칙 적기

sudo ufw allow 443/tcp
sudo ufw allow 6000:6010/tcp                   # 포트 범위
sudo ufw allow from 10.0.0.0/24                # 그 대역에서 오는 것 모두
sudo ufw allow from 10.0.0.0/24 to any port 5432 proto tcp
sudo ufw deny 8080/tcp
sudo ufw reject 8081/tcp
sudo ufw limit 22/tcp                          # 30 초에 6 번째 연결부터 막는다
sudo ufw insert 1 deny from 203.0.113.7        # 맨 앞에 넣는다
  • 규칙은 위에서부터 보고 처음 맞는 것을 따른다. 특정 IP 를 막는 규칙은 insert 1 로 허용 규칙보다 앞에 둔다
  • deny 는 응답 없이 버리고 reject 는 거절을 돌려준다. curl 로 붙으면 deny 는 5 초를 기다리다 시간 초과(종료 코드 28), reject 는 바로 Connection refused(종료 코드 7) 였다
  • limit 을 건 22 번에 잇달아 붙어 보니 다섯 번은 열리고 여섯 번째부터 막혔다. 비밀번호를 마구 넣어 보는 공격을 늦춘다

앱 이름으로

패키지가 /etc/ufw/applications.d/ 에 포트 묶음을 두면 이름으로 열 수 있다. nginx 를 깔면 셋이 생긴다.

sudo ufw app list            # Nginx Full · Nginx HTTP · Nginx HTTPS
sudo ufw app info "Nginx Full"
#   Ports:
#     80,443/tcp
sudo ufw allow "Nginx Full"

지우기

sudo ufw status numbered
sudo ufw delete 3                 # 번호로 — 묻는다 (스크립트에서는 --force)
sudo ufw delete allow 80/tcp      # 적은 그대로 앞에 delete 를 붙인다
sudo ufw disable                  # 끈다 (규칙은 남는다)
sudo ufw reset                    # 규칙까지 모두 지운다
  • 번호로 지우면 IPv4 줄만 지워지고 (v6) 줄은 남는다. 규칙 그대로 지우면 둘 다 지워진다
  • 하나를 지우면 뒤의 번호가 당겨진다. 여럿을 지울 때는 매번 status numbered 로 다시 본다

로그

막힌 연결은 커널 로그에 [UFW BLOCK] 으로 남는다. ufw 패키지가 넣은 rsyslog 설정(/etc/rsyslog.d/20-ufw.conf) 이 이 줄을 /var/log/ufw.log 로도 모은다.

[UFW BLOCK] IN=eth0 OUT= … SRC=172.18.0.3 DST=172.18.0.2 … PROTO=TCP SPT=54024 DPT=5432 … SYN
  • sudo journalctl -k | grep UFW 로 본다. SRC 가 누가, DPT 가 어느 포트로 왔는지다
  • 열었어야 할 포트가 막혔는지 볼 때 쓴다. 너무 많으면 sudo ufw logging off 로 끈다

Docker 와 함께

Docker 가 -p 로 연 포트는 ufw 규칙을 지나친다. Docker 가 연 포트로 온 연결은 컨테이너로 넘겨지는 길(FORWARD) 을 타는데, ufw 의 허용 · 거부 규칙은 서버로 들어오는 길(INPUT) 에 걸려 있기 때문이다. Docker 를 깐 서버에서 ufw 로 모두 막고 22 번만 연 뒤 다른 서버에서 붙어 본 결과다.

띄운 것 결과
docker run -p 8000:80 nginx:alpine 열림 (200)
docker run -p 127.0.0.1:8001:80 nginx:alpine 막힘 — 서버 안에서만 받는다
서버에 바로 띄운 프로그램 (8002) 막힘 — ufw 가 막는다
  • 바깥에 열 필요가 없는 포트(DB · 관리 화면) 는 -p 127.0.0.1:포트:포트 로 띄우고, 같은 서버의 Nginx 가 받아 넘긴다
  • 컨테이너의 포트를 IP 별로 막으려면 Docker 가 남겨 둔 DOCKER-USER 체인에 iptables 규칙을 넣는다. 이 체인은 포트를 컨테이너 쪽으로 바꾼 뒤에 보므로, 바깥 포트(8000) 로 걸려면 --dport 8000 이 아니라 원래 포트를 보는 조건을 쓴다
sudo iptables -I DOCKER-USER -i eth0 -p tcp -m conntrack --ctorigdstport 8000 -j DROP
규칙 8000 에 붙으면
--dport 8000 열림 — 이미 80 으로 바뀌어 맞지 않는다
--dport 80 막힘 — 그 컨테이너 포트를 쓰는 것이 모두 막힌다
--ctorigdstport 8000 막힘
