리눅스의 파일마다 주인(사용자) 과 그룹이 있고, 주인 · 그룹 · 나머지가 저마다 읽기 · 쓰기 · 실행을 할 수 있는지가 정해져 있다. 서버에서는 root 로 일하지 않고, 배포용 · 서비스용 사용자를 따로 만들어 필요한 폴더에만 권한을 주며, 관리 명령은 sudo 로 돌린다. 아래 예제는 Ubuntu 24.04 컨테이너에서 deploy 사용자와 web 그룹을 만들어 돌렸다.

사용자와 그룹

sudo adduser --disabled-password --comment "" deploy    # 홈 폴더 · 셸까지 만든다
id deploy
# uid=1001(deploy) gid=1001(deploy) groups=1001(deploy),100(users)

sudo groupadd web
sudo usermod -aG web deploy        # 그룹에 더한다 — -a 를 꼭 붙인다
id deploy
# uid=1001(deploy) gid=1001(deploy) groups=1001(deploy),100(users),1002(web)

sudo usermod -G sudo deploy        # -a 를 빠뜨리면 그룹을 이것 하나로 바꾼다
id deploy
# uid=1001(deploy) gid=1001(deploy) groups=1001(deploy),27(sudo) — users · web 이 빠졌다
  • adduser 는 Debian · Ubuntu 의 편한 명령이고, useradd -m -s /bin/bash 이름 이 어디에나 있는 기본 명령이다. useradd 는 -m 을 빼면 홈 폴더를 만들지 않는다
  • 비밀번호는 sudo passwd deploy 로 정한다. SSH 키로만 들어올 사용자는 비밀번호를 두지 않는다(--disabled-password)
  • 그룹을 바꾸면 그 사용자가 다시 로그인해야 적용된다
  • 사용자 목록은 /etc/passwd, 그룹은 /etc/group 에 있다. getent passwd deploy · getent group web 으로 본다

권한 읽기

ls -l /srv/site
# -rw-rw---- 1 deploy web  3 Nov  8 09:49 index.html
# -rwxr-xr-x 1 deploy web 10 Nov  8 09:49 run.sh
stat -c "%A %a %U:%G %n" /srv/site
# drwxr-x--- 750 deploy:web /srv/site
자리 d rwx r-x ---
뜻 종류(d 폴더 · - 파일 · l 링크) 주인 그룹 나머지
글자 숫자 파일에서 폴더에서
r 4 읽기 안의 이름 보기(ls)
w 2 쓰기 안에 만들기 · 지우기 · 이름 바꾸기
x 1 실행 들어가기(cd) · 안의 파일에 닿기
  • 숫자는 자리마다 더한다. 750 = 주인 rwx(7) · 그룹 r-x(5) · 나머지 ---(0)
  • 폴더에 x 가 없으면 안의 파일 권한이 열려 있어도 닿지 못한다. 위에서 나머지(guest) 는 cat /srv/site/index.html 이 Permission denied 였다
  • 흔한 값은 폴더 755 · 파일 644, 비밀이 든 파일 600, 실행 파일 755 다

chmod · chown

chmod 750 /srv/site                       # 숫자로
chmod +x /srv/site/run.sh                 # 모두에 실행을 더한다
chmod g+w,o-r /srv/site/index.html        # 그룹에 쓰기를 더하고 나머지의 읽기를 뺀다
chown -R deploy:web /srv/site             # 주인:그룹, -R 은 안쪽까지
  • 글자 꼴은 u(주인) · g(그룹) · o(나머지) · a(모두) 와 + · - · = 다
  • chmod -R 755 는 파일에도 실행 권한을 준다. 폴더와 파일을 나눠 주려면 find … -type d -exec chmod 755 {} + · find … -type f -exec chmod 644 {} + 를 쓴다
  • chown 은 root(sudo) 만 할 수 있다

새 파일의 기본 권한 (umask)

umask              # 0022
touch f; mkdir d
stat -c "%A %a %n" f d
# -rw-r--r-- 644 f
# drwxr-xr-x 755 d
  • 파일은 666, 폴더는 777 에서 umask 만큼 뺀다. 그룹이 함께 고치는 폴더라면 umask 0002 로 두어 664 · 775 로 만든다

특별한 권한

stat -c "%A %a %n" /tmp /usr/bin/passwd
# drwxrwxrwt 1777 /tmp            — t: 누구나 쓰지만 남의 파일은 못 지운다 (sticky)
# -rwsr-xr-x 4755 /usr/bin/passwd — s: 실행하면 주인(root) 권한으로 돈다 (setuid)
  • 그룹 폴더에 chmod g+s 폴더 를 주면 안에 만든 파일이 폴더의 그룹을 따른다. 여럿이 함께 쓰는 배포 폴더에 쓴다

sudo

Ubuntu 는 sudo 그룹에 든 사용자가 모든 명령을 sudo 로 돌릴 수 있다(/etc/sudoers 의 %sudo ALL=(ALL:ALL) ALL). 명령 몇 개만 허락하려면 /etc/sudoers.d/ 에 파일을 둔다.

echo "deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx" | sudo tee /etc/sudoers.d/deploy
sudo chmod 440 /etc/sudoers.d/deploy
sudo visudo -cf /etc/sudoers.d/deploy      # /etc/sudoers.d/deploy: parsed OK
sudo -l -U deploy
#     (ALL : ALL) ALL
#     (ALL) NOPASSWD: /usr/bin/systemctl restart nginx
  • sudoers 에 틀린 줄이 들어가면 sudo 가 모두 멈춰 고칠 길이 막힌다. 저장 전에 꼭 visudo -c 로 검사한다. NOPASSWD 뒤의 : 를 빠뜨리면 syntax error 가 난다
  • sudo -i 는 root 셸을 연다. 한 번만 돌릴 때는 sudo 명령 을 쓴다
  • 명령은 전체 경로로 적는다. NOPASSWD 로 허락한 명령은 비밀번호 없이 돌므로 배포 스크립트에서 쓴다
