셸은 명령을 받아 프로그램을 실행하는 프로그램이다. 리눅스 서버에 SSH 로 들어가면 대개 bash 가 뜨고, 명령 하나하나보다 이를 묶는 법(파이프 · 리다이렉트 · 치환) 과 줄 편집 단축키가 일의 속도를 정한다. 맥의 기본 셸 zsh 도 대부분 같게 동작한다. 아래 예제는 Ubuntu 24.04 컨테이너의 bash 5.2 에서 돌렸다.

줄 편집 단축키

키 하는 일
Ctrl-A · Ctrl-E 줄 처음 · 끝으로
Alt-B · Alt-F 한 단어 앞 · 뒤로
Ctrl-U · Ctrl-K 커서 왼쪽 · 오른쪽을 지운다 (지운 것은 버퍼에)
Ctrl-W · Alt-D 커서 앞 · 뒤 단어를 지운다
Ctrl-Y 버퍼에 있는 것을 붙인다
Ctrl-_ 되돌린다
Ctrl-T · Alt-T 두 글자 · 두 단어의 자리를 바꾼다
Alt-U · Alt-L · Alt-C 커서부터 단어 끝까지 대문자 · 소문자 · 첫 글자만 대문자
Ctrl-X Ctrl-X 커서와 표시(mark) 사이를 오간다 — 줄 처음으로 갔다가 돌아올 때
Ctrl-X Ctrl-E 지금 줄을 편집기($EDITOR) 로 연다. 긴 명령을 고칠 때
Ctrl-L 화면을 지운다
Ctrl-D 빈 줄이면 로그아웃, 아니면 커서의 글자를 지운다
Tab 자동 완성 (두 번 누르면 후보 목록)
  • 키 목록은 bind -P 로 본다. 위 표는 Ubuntu 의 bash 에서 bind -P 로 확인한 것이다
  • 맥 터미널에서 Alt 키가 먹지 않으면 터미널 앱의 설정(프로파일 › 키보드) 에서 Option 키를 Meta 키로 쓰게 켠다

히스토리

키 · 꼴 하는 일
Ctrl-R 이전 명령을 글자로 찾는다. 다시 누르면 더 앞의 것
Ctrl-P · Ctrl-N (↑ · ↓) 이전 · 다음 명령
Alt-. 앞 명령의 마지막 인자를 넣는다
!! 앞 명령 전체 — sudo !! 로 sudo 를 빠뜨린 명령을 다시
!$ 앞 명령의 마지막 인자 
echo one two
echo !$         # 펼친 명령 'echo two' 를 먼저 찍고 실행한다 → two
ls /etc/hostname
sudo !!         # sudo ls /etc/hostname
fc -l -3        # 최근 세 개
  • history 로 목록을 보고 !번호 로 다시 실행한다
  • 앞에 공백을 두고 친 명령은 히스토리에 남지 않는다. Ubuntu 가 새 사용자의 .bashrc 에 HISTCONTROL=ignoreboth 를 넣어 두기 때문이다. 비밀번호가 든 명령에 쓴다

파이프와 리다이렉트

printf "b\na\nb\nc\n" | sort | uniq -c | sort -rn     # 앞 명령의 출력을 다음 명령의 입력으로
#       2 b
#       1 c
#       1 a

ls /nope > out.txt 2>&1        # 출력 · 오류를 모두 파일로
ls /nope 2>/dev/null; echo $?  # 오류는 버리고 종료 코드만 — 2
echo hi | tee a.txt | tr a-z A-Z   # 화면(다음 명령) 과 파일에 함께 — HI, a.txt 에는 hi
꼴 뜻
> 파일 · >> 파일 출력을 덮어쓰기 · 이어 쓰기
2> 파일 오류(stderr) 만
> 파일 2>&1 출력과 오류를 같은 파일로 — 순서가 바뀌면(2>&1 > 파일) 오류는 화면에 남는다
< 파일 파일을 입력으로
/dev/null 버리는 곳
  • $? 는 바로 앞 명령의 종료 코드다. 0 이 성공이다
  • a && b 는 a 가 성공하면 b, a || b 는 실패하면 b 를 돌린다. mkdir /tmp/x 2>/dev/null || echo "이미 있음"

치환

echo "오늘은 $(date +%Y-%m-%d), 파일 $(ls /etc | wc -l) 개"   # 명령 치환 — 오늘은 2026-11-08, 파일 74 개
diff <(printf "a\nb\n") <(printf "a\nc\n")                     # 프로세스 치환 — 명령의 출력을 파일처럼
# 2c2
# < b
# ---
# > c
  • $( ) 는 명령의 출력을 글자로 넣는다. 옛 꼴 `…` 은 겹쳐 쓰기 어려워 쓰지 않는다
  • <( ) 는 출력을 임시 파일 이름(/dev/fd/63) 으로 넘긴다. 파일 둘을 받는 diff · comm 에 명령 결과를 바로 줄 때 쓴다
  • 히어 문서는 끝 표시를 따옴표로 감싸면 변수를 펼치지 않는다 
    cat <<EOF          # 홈: /root
홈: $HOME
EOF
cat <<"EOF"        # 홈: $HOME
홈: $HOME
EOF

스크립트 따라가기

bash -x script.sh                 # 실행하는 줄을 + 를 붙여 찍는다
bash -xc 'name=geon; echo hello $name'
# + name=geon
# + echo hello geon
# hello geon
  • 스크립트 안에서는 set -x 로 켜고 set +x 로 끈다
  • 스크립트 첫머리에 set -euo pipefail 을 두면 실패한 명령 · 없는 변수 · 파이프 중간의 실패에서 멈춘다

작업 제어

sleep 30 &        # 뒤에서 돌린다 — [1] 8
sleep 31 &        # [2] 9
jobs
# [1]-  Running                 sleep 30 &
# [2]+  Running                 sleep 31 &
kill %1           # 작업 번호로 끝낸다
  • 앞에서 돌던 프로그램은 Ctrl-C 로 끝내고, Ctrl-Z 로 멈춘다. 멈춘 것은 fg 로 다시 앞에, bg 로 뒤에서 이어 돌린다 (fg %2 처럼 번호를 준다)
  • 뒤에서 돌린 작업도 로그아웃하면 끝난다. 남기려면 nohup 명령 & 이나 tmux · screen 안에서 돌린다

예전에는

  • 옛 글은 Alt-B 를 「다음 단어로」, Alt-F 를 「이전 단어로」 로 적었다. 반대다 — B(back) 가 앞, F(forward) 가 뒤다
  • Ctrl-X 를 「커서를 이전 위치로」 로 적었는데, 그것은 Ctrl-X Ctrl-X 두 번이다
  • 일시정지한 프로그램을 % 로 다시 시작한다고 적었다. % 는 fg 와 같아서 앞으로 가져온다
