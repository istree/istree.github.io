컨테이너 안에서 쓴 파일은 컨테이너를 지우면 함께 사라진다. DB 자료 · 업로드 파일처럼 남겨야 하는 것은 호스트 폴더나 볼륨에 두고 컨테이너에 연결한다. 또 컨테이너는 저마다 IP 를 받는 작은 네트워크 안에 있어서, 바깥에서 들어오려면 포트를 열고 컨테이너끼리 찾으려면 같은 네트워크에 넣는다. 아래 예제는 맥(colima) 에서 Nginx · Alpine 컨테이너로 돌렸다.

호스트 폴더 연결 (바인드 마운트)

mkdir -p site && echo '<h1>안녕</h1>' > site/index.html
docker run -d --name web -p 127.0.0.1:8080:80 -v "$PWD/site:/usr/share/nginx/html:ro" nginx:1.28-alpine
echo '<h1>고침</h1>' > site/index.html
curl -s localhost:8080            # <h1>고침</h1> — 호스트에서 고친 것이 바로 보인다
docker exec web sh -c 'echo x > /usr/share/nginx/html/a'
# sh: can't create /usr/share/nginx/html/a: Read-only file system
  • 경로는 절대 경로로 쓴다. 지금 폴더는 "$PWD/site" 로 쓴다
  • 끝에 :ro 를 붙이면 컨테이너가 읽기만 한다. 설정 파일 · 정적 파일에 쓴다
  • 소스 폴더를 연결하면 고친 것이 바로 반영되어 개발할 때 편하다
  • 호스트에 없는 경로를 주면 Docker 가 빈 폴더를 만들어 연결한다. 오류가 나지 않으므로 경로를 잘못 적으면 컨테이너가 빈 폴더를 본다

볼륨

Docker 가 관리하는 저장 공간이다. 이름을 붙여 만들고 여러 컨테이너가 함께 쓴다.

docker volume create data
docker run --rm -v data:/data alpine:3.22 sh -c 'echo 1 > /data/n'
docker run --rm -v data:/data alpine:3.22 cat /data/n       # 1 — 컨테이너가 바뀌어도 남는다
docker volume ls
docker volume inspect -f '{{.Mountpoint}}' data             # /var/lib/docker/volumes/data/_data
바인드 마운트 볼륨
쓰는 법 -v /호스트/경로:/안 -v 이름:/안
자리 호스트의 아무 폴더 Docker 가 정한 곳 (/var/lib/docker/volumes)
알맞은 곳 설정 파일 · 소스 · 호스트에서 고칠 것 DB 자료 · 컨테이너만 쓰는 것
  • 비어 있는 볼륨을 처음 연결하면 이미지의 그 경로에 있던 파일이 볼륨에 복사된다. 빈 볼륨을 Nginx 의 /usr/share/nginx/html 에 연결하면 50x.html · index.html 이 들어 있다. 빈 호스트 폴더를 연결하면 복사하지 않고 이미지의 파일을 가려 아무것도 없다
  • 맥 · 윈도우에서 볼륨은 가상 머신 안에 있어 Finder · 탐색기로 볼 수 없다. 꺼내려면 백업처럼 컨테이너로 tar 를 만든다
  • 이미지가 VOLUME 으로 정해 둔 경로(mysql 의 /var/lib/mysql, wordpress 의 /var/www/html) 에 아무것도 연결하지 않으면 이름 없는 볼륨이 생긴다. 컨테이너를 지워도 남으므로 docker volume prune 으로 지운다 (이름 있는 볼륨까지 지우려면 -a)

포트

docker run -d --name web -p 127.0.0.1:8080:80 nginx:1.28-alpine
docker port web                   # 80/tcp -> 127.0.0.1:8080
  • -p 8080:80 은 모든 주소(0.0.0.0) 에 연다. 리눅스 서버에서는 방화벽(ufw) 규칙보다 먼저 적용되어 바깥에 열리므로, 리버스 프록시 뒤에 둘 컨테이너는 127.0.0.1: 을 붙인다
  • 포트를 열지 않은 컨테이너도 같은 네트워크의 컨테이너끼리는 닿는다. DB 는 포트를 열지 않고 네트워크로만 연결한다

네트워크

사용자 정의 네트워크에 함께 넣으면 컨테이너 이름이 곧 주소가 된다.

docker network create app
docker run -d --name db --network app nginx:1.28-alpine
docker run --rm --network app alpine:3.22 sh -c "wget -qO- http://db | grep -o '<title>.*</title>'"
# <title>Welcome to nginx!</title>
docker run --rm alpine:3.22 wget -qO- -T 2 http://db
# wget: bad address 'db' — 기본 네트워크에서는 이름을 찾지 못한다
docker network ls
NETWORK ID     NAME      DRIVER    SCOPE
a1f1b33e1fb8   app       bridge    local
1465f1a70229   bridge    bridge    local
89925d9ee49c   host      host      local
ea60aaf3f02b   none      null      local
  • 네트워크를 정하지 않으면 기본 bridge 에 들어간다. 여기서는 IP 로만 닿고 이름으로는 찾지 못한다
  • docker network connect app web 으로 실행 중인 컨테이너를 네트워크에 더한다
  • Compose 는 프로젝트마다 네트워크를 하나 만들어 서비스를 모두 넣는다. 서비스 이름(db) 으로 바로 닿는다

컨테이너에서 호스트로

python3 -m http.server 9001 --bind 127.0.0.1       # 호스트(맥) 에서
docker run --rm alpine:3.22 sh -c 'getent hosts host.docker.internal; wget -qO- http://host.docker.internal:9001/ | head -c 50'
# 192.168.5.2       host.docker.internal  host.docker.internal
# <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"
  • 컨테이너 안의 localhost 는 컨테이너 자신이다. 호스트의 서비스는 host.docker.internal 로 닿는다 (Docker Desktop · colima)
  • 리눅스의 Docker 엔진에서는 이 이름이 없다. --add-host=host.docker.internal:host-gateway 를 붙인다

예전에는

  • 컨테이너끼리 연결할 때 --link mysql_57:mysql 을 썼다. 지금은 사용자 정의 네트워크에 함께 넣는다
  • 윈도우에서는 route -p add 172.17.0.0 MASK 255.255.255.0 10.0.75.2 처럼 경로를 더해 호스트에서 컨테이너 IP 로 바로 들어갔다. Hyper-V 시절의 방법이고, 지금은 포트를 열어 쓴다
