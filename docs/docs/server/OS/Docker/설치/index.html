Docker 엔진은 리눅스 커널 위에서 돈다. 리눅스 서버에는 엔진을 바로 깔고, 맥 · 윈도우에서는 작은 리눅스 가상 머신을 띄워 그 안에서 엔진을 돌린다. 이 가상 머신은 Docker Desktop 이나 colima 가 알아서 띄우고 끄므로, 사용자는 리눅스에서와 같은 docker 명령을 쓴다. 깔고 나면 docker version 에 클라이언트와 서버(엔진) 가 함께 나오는지 확인한다.

리눅스

공식 스크립트가 배포판을 알아보고 Docker 저장소를 더한 뒤 패키지를 깐다.

curl -fsSL https://get.docker.com -o get-docker.sh
sh get-docker.sh --dry-run      # 실제로 돌릴 명령만 보인다
sudo sh get-docker.sh

--dry-run 을 Ubuntu 24.04(arm64) 에서 돌리면 아래 명령이 나온다.

apt-get -qq update >/dev/null
DEBIAN_FRONTEND=noninteractive apt-get -y -qq install ca-certificates curl >/dev/null
install -m 0755 -d /etc/apt/keyrings
curl -fsSL "https://download.docker.com/linux/ubuntu/gpg" -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=arm64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu noble stable" > /etc/apt/sources.list.d/docker.list
apt-get -qq update >/dev/null
DEBIAN_FRONTEND=noninteractive apt-get -y -qq install docker-ce docker-ce-cli containerd.io docker-compose-plugin docker-ce-rootless-extras docker-buildx-plugin docker-model-plugin >/dev/null
  • 엔진(docker-ce) 과 함께 Compose · Buildx 플러그인도 깔린다. docker compose · docker buildx 가 바로 된다
  • 공식 문서는 이 스크립트를 운영 서버에는 권하지 않는다. 운영 서버에서는 위에 나온 명령을 문서대로 하나씩 돌려 버전을 고정한다
  • 배포판의 docker.io 패키지도 있지만 버전이 늦다. Docker 저장소의 docker-ce 를 쓴다

sudo 없이 쓰려면 사용자를 docker 그룹에 넣는다.

sudo usermod -aG docker $USER    # 다시 로그인해야 적용된다
  • docker 그룹은 root 와 같은 권한이다. 컨테이너에 호스트의 / 를 연결하면 무엇이든 고칠 수 있으므로, 믿을 수 있는 사용자만 넣는다

맥

가볍게 쓰려면 Homebrew 로 colima 와 docker CLI 를 깐다.

brew install colima docker docker-compose docker-buildx
colima start --cpu 2 --memory 4 --disk 20      # 가상 머신 — CPU 2 · 메모리 4 GB · 디스크 20 GB
docker context ls
NAME       DESCRIPTION                               DOCKER ENDPOINT                                  ERROR
colima *   colima                                    unix:///Users/geon/.colima/default/docker.sock
default    Current DOCKER_HOST based configuration   unix:///var/run/docker.sock
  • colima 가 colima 컨텍스트를 만들고 기본으로 정한다. docker 명령은 이 컨텍스트의 소켓으로 간다
  • brew 로 깐 Compose · Buildx 는 플러그인 폴더를 알려 줘야 docker compose 로 불린다. ~/.docker/config.json 에 {"cliPluginsExtraDirs": ["/opt/homebrew/lib/docker/cli-plugins"]} 를 넣는다
  • colima stop 은 가상 머신을 끄고, colima delete 는 이미지 · 볼륨째 지운다
  • Docker Desktop 은 앱 하나로 엔진 · Compose · 화면을 함께 준다. 직원 250 명 이상이거나 매출 1,000 만 달러 이상인 회사는 유료 구독이 있어야 쓴다

윈도우

  • Docker Desktop 을 깔고 WSL 2 를 백엔드로 쓴다. WSL 이 없으면 관리자 PowerShell 에서 wsl --install 을 먼저 돌린다
  • 리눅스 컨테이너와 윈도우 컨테이너 중 하나를 선택한다. 서버용 이미지는 대부분 리눅스 컨테이너다
  • Docker Desktop 은 사용자가 로그인해야 뜬다. 늘 켜 두는 PC 라면 설정의 「Start Docker Desktop when you sign in to your computer」 를 켜고, 윈도우 자동 로그인(netplwiz 에서 「사용자 이름과 암호를 입력해야 이 컴퓨터를 사용할 수 있음」 해제) 을 켠다

확인

docker version --format 'Client {{.Client.Version}} · Server {{.Server.Version}} · {{.Server.Os}}/{{.Server.Arch}}'
# Client 29.9.3 · Server 29.5.2 · linux/arm64

docker run --rm hello-world
# Hello from Docker!
# This message shows that your installation appears to be working correctly.
  • Server 가 나오지 않고 failed to connect to the docker API 가 나오면 엔진이 꺼져 있거나 컨텍스트가 다른 소켓을 가리키는 것이다. 맥은 colima start, 리눅스는 sudo systemctl start docker 로 켠다
  • 맥에서도 서버가 linux/arm64 로 나온다. 엔진은 가상 머신 안의 리눅스에서 돈다

예전에는

  • 맥 · 윈도우에서는 VirtualBox 가상 머신을 쓰는 Docker Toolbox 와 화면 도구 Kitematic 을 썼다. 둘 다 끝났고 지금은 Docker Desktop · colima 를 쓴다
  • 윈도우용 Docker Desktop 은 Hyper-V 가상 머신 위에서 돌았고 윈도우 10 Pro 이상이 있어야 했다. 지금은 WSL 2 위에서 돌아 Home 판에서도 된다. Home 판은 리눅스 컨테이너만 돌린다
