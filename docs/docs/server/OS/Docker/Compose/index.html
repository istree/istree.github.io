Compose 는 컨테이너 여럿을 compose.yaml 파일 하나에 적어 함께 띄우고 내리는 도구다. docker run 에 길게 붙이던 포트 · 볼륨 · 환경 변수를 파일로 남기고, 서비스끼리는 Compose 가 만든 네트워크에서 이름으로 찾는다. 지금은 docker compose(띄어 씀) 로 부르는 Docker 플러그인이다. 아래 예제는 WordPress 와 MySQL 을 함께 띄운다.

compose.yaml

services:
  db:
    image: mysql:8.4
    environment:
      MYSQL_DATABASE: wp
      MYSQL_USER: wpuser
      MYSQL_PASSWORD: ${DB_PASSWORD}
      MYSQL_RANDOM_ROOT_PASSWORD: "1"
    volumes:
      - db-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-u", "wpuser", "-p${DB_PASSWORD}"]
      interval: 5s
      retries: 20
    restart: unless-stopped

  wordpress:
    image: wordpress:6
    ports:
      - "127.0.0.1:8080:80"
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_NAME: wp
      WORDPRESS_DB_USER: wpuser
      WORDPRESS_DB_PASSWORD: ${DB_PASSWORD}
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

volumes:
  db-data:

같은 폴더의 .env 에 비밀번호를 둔다. ${DB_PASSWORD} 가 이 값으로 바뀐다.

DB_PASSWORD=wppwd
  • WORDPRESS_DB_HOST: db 처럼 서비스 이름이 곧 주소다. DB 는 ports 를 열지 않아 바깥에서는 닿지 않는다
  • 파일 이름은 compose.yaml 이 기본이다. 옛 이름 docker-compose.yml 도 읽는다
  • .env 는 저장소에 넣지 않는다. .gitignore 에 적고, 어떤 값이 있어야 하는지는 .env.example 로 남긴다
  • docker compose config 는 .env 를 채워 넣은 최종 설정을 보인다. 값이 잘 들어갔는지 볼 때 쓴다

띄우기 · 보기 · 내리기

docker compose up -d
 Container wp-db-1 Starting
 Container wp-db-1 Started
 Container wp-db-1 Waiting
 Container wp-db-1 Healthy
 Container wp-wordpress-1 Starting
 Container wp-wordpress-1 Started
docker compose ps --format 'table {{.Service}}\t{{.Status}}\t{{.Ports}}'
SERVICE     STATUS                    PORTS
db          Up 15 seconds (healthy)   3306/tcp, 33060/tcp
wordpress   Up 5 seconds              127.0.0.1:8080->80/tcp
docker compose logs --tail 2 db                  # -f 로 따라 본다. 서비스 이름을 빼면 모두
docker compose exec db mysql -uwpuser -p wp      # 서비스 안에서 명령
docker compose down                              # 컨테이너 · 네트워크를 지운다. 볼륨은 남는다
docker compose down -v                           # 볼륨까지 지운다 — DB 자료가 사라진다
  • 컨테이너 이름은 폴더이름-서비스-번호(wp-db-1) 로 붙는다. 폴더 이름이 프로젝트 이름이 된다 (-p 이름 으로 바꾼다)
  • stop · start 는 컨테이너를 지우지 않고 멈추고 다시 띄운다

고치고 다시 띄우기

compose.yaml 을 고친 뒤 up -d 를 다시 돌리면 바뀐 서비스만 다시 만든다. WordPress 의 포트만 바꿨을 때는 이렇게 나온다.

 Container wp-db-1 Running
 Container wp-wordpress-1 Recreate
 Container wp-wordpress-1 Recreated
  • 이미지 태그는 같고 내용만 새로 나왔으면 docker compose pull 로 받은 뒤 up -d 한다
  • 자기 Dockerfile 로 만드는 서비스는 image: 대신 build: . 를 쓰고, 고친 뒤 up -d --build 로 다시 만든다

띄우는 순서

depends_on 만 쓰면 DB 컨테이너가 시작 하자마자 WordPress 를 띄운다. MySQL 은 시작하고 몇 초 뒤에야 접속을 받으므로, healthcheck 를 두고 condition: service_healthy 로 준비 될 때까지 기다린다. 위 출력의 Waiting → Healthy 가 이 기다림이다.

예전에는

  • 따로 까는 파이썬 프로그램 docker-compose(붙여 씀) 를 썼고, 파일 맨 위에 version: "3.8" 을 적었다. 지금은 Docker 플러그인 docker compose 이고, version 을 적으면 "the attribute version is obsolete, it will be ignored" 경고가 나온다
  • docker run --link mysql_57:mysql … wordpress 처럼 명령을 길게 이어 붙였다. 지금은 같은 내용을 compose.yaml 로 적는다
