Dockerfile 은 이미지를 만드는 순서를 적은 글자 파일이다. 바탕 이미지(FROM) 위에 파일을 넣고(COPY) 명령을 돌려(RUN) 층을 하나씩 쌓으며, 마지막에 컨테이너가 뜰 때 돌릴 명령(CMD) 을 정한다. 같은 Dockerfile 이면 어느 컴퓨터에서 만들어도 같은 이미지가 나오므로, 서버에 손으로 깔던 일을 파일로 남기는 셈이다. 아래 예제는 정적 HTML 을 Nginx 이미지에 넣는 것부터 시작한다.

기본

FROM nginx:1.28-alpine
ENV TZ=Asia/Seoul
WORKDIR /usr/share/nginx/html
COPY site/ .
EXPOSE 80
docker build -t my-site:1.0 .         # . 은 빌드 컨텍스트 — 이 폴더를 엔진에 보낸다
docker run --rm my-site:1.0 sh -c 'ls -A; echo $TZ; date'
50x.html
index.html
Asia/Seoul
Sun Nov  8 18:15:57 KST 2026
명령 뜻
FROM 이미지 바탕 이미지. 맨 처음에 둔다
RUN 명령 빌드할 때 명령을 돌리고 결과를 층으로 남긴다 (패키지 설치 …)
COPY 원본 대상 빌드 컨텍스트의 파일을 이미지에 넣는다
WORKDIR 경로 이후 명령과 컨테이너의 현재 폴더. 없으면 만든다
ENV 이름=값 환경 변수. 빌드에도, 실행한 컨테이너에도 남는다
ARG 이름 빌드할 때만 쓰는 값 (--build-arg 이름=값)
EXPOSE 80 이 포트를 쓴다는 표시. 포트를 열지는 않는다 — 여는 것은 run -p 다
USER 이름 이후 명령과 컨테이너를 이 사용자로 돌린다
CMD [...] · ENTRYPOINT [...] 컨테이너가 뜰 때 돌릴 명령
  • 시간대는 TZ 만 주면 된다. 이 이미지에는 시간대 자료(tzdata) 가 들어 있어 date 가 KST 로 나온다. 자료가 없는 이미지는 TZ 를 줘도 UTC 시각 그대로라(ubuntu:24.04 는 09:26:16 Asia, alpine:3.22 는 09:26:17 UTC) tzdata 를 깔아야 한다
  • 태그를 -t 이름:버전 으로 붙인다. 빼면 이름 없는 <none> 이미지가 된다

층과 캐시

명령 한 줄이 층 하나가 되고, 바뀌지 않은 층은 다시 만들지 않는다. 같은 파일로 다시 빌드하면 모두 캐시에서 온다.

#6 [2/3] WORKDIR /usr/share/nginx/html
#6 CACHED
#7 [3/3] COPY site/ .
#7 CACHED
docker history --format '{{.CreatedBy}}\t{{.Size}}' my-site:1.0 | head -4
EXPOSE [80/tcp]	0B
COPY site/ . # buildkit	24.6kB
WORKDIR /usr/share/nginx/html	4.1kB
ENV TZ=Asia/Seoul	0B
  • 한 층이 바뀌면 그 아래 층은 모두 다시 만든다. 잘 바뀌지 않는 것(패키지 설치) 을 위에, 자주 바뀌는 것(소스 COPY) 을 아래에 둔다
  • 앱은 의존성 목록만 먼저 넣어 설치하고 소스를 나중에 넣는다. 소스만 고쳤을 때 설치 층을 다시 쓴다 
    COPY package.json package-lock.json ./
RUN npm ci
COPY . .
  • apt-get update 와 install 은 한 RUN 에 함께 쓰고, 끝에 rm -rf /var/lib/apt/lists/* 로 목록을 지워 층을 줄인다. 따로 쓰면 오래된 목록이 캐시에 남는다

.dockerignore

docker build . 은 폴더 전체를 엔진에 보낸다. 보내지 않을 것은 .dockerignore 에 적는다.

.env
node_modules
.git

.env · node_modules 가 있는 폴더에서 COPY . /ctx 로 넣어 보면 이 둘이 빠진다.

.dockerignore
Dockerfile
site
  • 비밀번호가 든 .env 가 이미지에 들어가면 이미지를 받은 누구나 꺼내 본다. 꼭 적는다

CMD 와 ENTRYPOINT

FROM alpine:3.22
ENTRYPOINT ["echo", "hello"]
CMD ["world"]
docker run --rm ep                       # hello world
docker run --rm ep docker                # hello docker — 뒤에 준 인자가 CMD 를 바꾼다
docker run --rm --entrypoint date ep -u +%Y   # 2026 — ENTRYPOINT 도 바꿀 수 있다
  • CMD 만 두면 docker run 이미지 다른명령 으로 통째로 바뀐다. 명령은 고정하고 인자만 바꾸게 하려면 ENTRYPOINT 에 명령, CMD 에 기본 인자를 둔다
  • ["…", "…"] 꼴로 쓴다. CMD sleep 1000 처럼 글자로 쓰면 /bin/sh -c 로 돌아, Ubuntu 에서는 셸이 PID 1 이 되고(1 /bin/sh -c sleep 1000) docker stop 의 SIGTERM 이 프로그램에 가지 않는다
  • 서버 프로그램은 앞(foreground) 에서 돌아야 한다. 뒤로 빠지는(데몬) 명령이면 PID 1 이 바로 끝나 컨테이너도 멈춘다. Nginx 는 daemon off;, Apache 는 apachectl -D FOREGROUND 로 띄운다

여러 단계 빌드

빌드 도구가 필요한 단계와 실행 단계를 나눠, 결과물만 작은 이미지에 옮긴다.

FROM node:24-alpine AS build
WORKDIR /app
COPY app/ .
RUN node build.js            # dist/index.html 을 만든다

FROM nginx:1.28-alpine
COPY --from=build /app/dist/ /usr/share/nginx/html/
docker build -t my-site:multi .
docker run --rm my-site:multi cat /usr/share/nginx/html/index.html   # <h1>built 2026-11-08</h1>
  • 마지막 FROM 부터가 결과 이미지다. Node 는 빌드에만 쓰이고 결과 이미지(91.6MB) 에는 들어가지 않는다
  • Java · Go · C++ 처럼 컴파일하는 프로그램은 컴파일러가 든 이미지에서 빌드하고, 실행 파일만 작은 이미지로 옮긴다

다른 CPU 용으로

M1 맥에서 만든 이미지는 arm64 다. amd64(인텔 · AMD) 서버에 올릴 이미지는 플랫폼을 정해 만든다.

docker build --platform linux/amd64 -t my-site:amd64 .
docker image inspect -f '{{.Os}}/{{.Architecture}}' my-site:amd64 my-site:1.0
# linux/amd64
# linux/arm64
  • 둘 다 담으려면 docker buildx build --platform linux/amd64,linux/arm64 --push … 로 만들어 레지스트리에 올린다
  • 다른 CPU 용 빌드 · 실행은 에뮬레이션(QEMU) 으로 돌아 느리다

예: Jenkins 이미지에 rbenv 넣기

Jenkins 에서 Ruby 프로젝트를 빌드하려고 공식 이미지에 rbenv 를 더한다.

FROM jenkins/jenkins:lts-jdk21
USER root
RUN apt-get update \
 && apt-get install -y --no-install-recommends build-essential libssl-dev libreadline-dev zlib1g-dev libyaml-dev libffi-dev \
 && rm -rf /var/lib/apt/lists/*
ENV RBENV_ROOT=/opt/rbenv
ENV PATH="$RBENV_ROOT/bin:$RBENV_ROOT/shims:$PATH"
RUN git clone --depth 1 https://github.com/rbenv/rbenv.git $RBENV_ROOT \
 && git clone --depth 1 https://github.com/rbenv/ruby-build.git $RBENV_ROOT/plugins/ruby-build \
 && chown -R jenkins:jenkins $RBENV_ROOT
USER jenkins
docker build -t jenkins-rbenv .
docker run --rm -v ~/jenkins_home:/var/jenkins_home --entrypoint sh jenkins-rbenv -c 'whoami; rbenv --version; rbenv install -l | head -2'
# jenkins
# rbenv 1.3.2
# 3.3.13
# 3.4.12
  • 패키지는 root 로 깔고, 끝에 USER jenkins 로 돌려놓는다. 공식 이미지가 jenkins 사용자로 돌기 때문이다
  • rbenv 를 jenkins 의 홈(/var/jenkins_home) 에 깔면 안 된다. 이 경로에는 보통 호스트 폴더 · 볼륨을 연결하므로, 연결하는 순간 이미지 안의 rbenv 가 가려져 rbenv: not found 가 난다. /opt 처럼 연결하지 않는 곳에 둔다
  • 옛 글은 curl … rbenv-installer | bash -; exit 0 으로 깔았다. exit 0 이 실패를 덮어 rbenv 가 없는 이미지가 조용히 만들어지므로, git clone 으로 바꾸고 실패하면 빌드가 멈추게 했다
