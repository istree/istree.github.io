Docker 를 쓰다 자주 만나는 오류와 해결을 모았다. 오류 문구는 Docker 29(맥 colima) 에서 직접 낸 것이다. 문구로 찾기 쉽게 제목에 오류의 앞부분을 적었다.

failed to connect to the docker API

failed to connect to the docker API at unix:///var/run/docker.sock; check if the path is correct and if the daemon is running: dial unix /var/run/docker.sock: connect: no such file or directory
  • 엔진이 꺼져 있거나, docker 가 엔진이 없는 소켓을 보고 있다
  • 맥: colima start 로 켠다. 켜져 있는데도 나면 docker context ls 로 * 가 colima 에 있는지 보고, 아니면 docker context use colima 로 바꾼다
  • 리눅스: sudo systemctl start docker, 부팅 때 켜려면 sudo systemctl enable docker

permission denied while trying to connect to the docker API

permission denied while trying to connect to the docker API at unix:///var/run/docker.sock
  • 리눅스에서 docker 그룹이 아닌 사용자가 소켓에 닿았다
  • sudo usermod -aG docker $USER 뒤 다시 로그인한다. 지금 셸에서 바로 쓰려면 newgrp docker
  • docker 그룹은 root 와 같은 권한이다. 믿을 수 있는 사용자만 넣는다

port is already allocated

docker: Error response from daemon: failed to set up container networking: driver failed programming external connectivity on endpoint web2 (347be2ba…): Bind for 0.0.0.0:8080 failed: port is already allocated
  • 다른 컨테이너가 그 포트를 쓰고 있다. docker ps --filter publish=8080 으로 찾는다
  • 컨테이너가 아닌 프로그램이 쓰고 있으면 lsof -nP -iTCP:8080 -sTCP:LISTEN(맥 · 리눅스) 으로 찾는다. 맥의 colima 는 포트를 ssh 프로세스로 넘기므로, 컨테이너가 연 포트는 ssh 로 나온다
  • 윈도우는 netstat -ano | findstr :8080 으로 PID 를 찾고 taskkill /F /PID 번호 로 끝낸다. 재부팅 뒤 포트가 남아 컨테이너가 뜨지 않을 때도 이렇게 한다

The container name "/web" is already in use

docker: Error response from daemon: Conflict. The container name "/web" is already in use by container "9163705c7f9c…". You have to remove (or rename) that container to be able to reuse that name.
  • 멈춘 컨테이너도 이름을 차지한다. docker ps -a 로 보고 docker rm web 하거나 docker rename web web-old 한다
  • 한 번 돌리고 버릴 컨테이너는 처음부터 --rm 을 붙인다

no matching manifest for linux/arm64/v8

Error response from daemon: no matching manifest for linux/arm64/v8 in the manifest list entries: no match for platform in manifest: not found
  • M1 맥 같은 arm64 에서 amd64 용으로만 나온 이미지를 받았다. mysql:5.7 이 그렇다
  • 새 버전(mysql:8.4) 에 arm64 판이 있으면 그것을 쓴다
  • 꼭 그 이미지여야 하면 --platform linux/amd64 로 받아 에뮬레이션으로 돌린다. docker run --rm --platform linux/amd64 mysql:5.7 mysqld --version → Ver 5.7.44 for Linux on x86_64. 느리다
  • 거꾸로 맥에서 만든 이미지를 amd64 서버에서 돌리면 exec format error 로 멈춘다. 빌드할 때 --platform linux/amd64 를 준다

연결한 폴더가 비어 있다 (맥 colima)

-v 로 연결한 폴더가 컨테이너 안에서 비어 있고, Nginx 라면 403 Forbidden 이 나며 로그에 이렇게 남는다.

[error] 30#30: *1 directory index of "/usr/share/nginx/html/" is forbidden
  • colima 는 맥의 홈 폴더(/Users/이름) 만 가상 머신에 연결한다. /tmp 같은 홈 밖의 경로를 주면 가상 머신 안에 같은 이름의 빈 폴더가 만들어져 연결된다
  • 프로젝트를 홈 폴더 아래에 둔다. 다른 곳이 필요하면 colima start --edit 로 mounts 에 경로를 더한다
  • 리눅스에서도 경로를 잘못 적으면 같은 일이 생긴다. Docker 는 없는 경로를 빈 폴더로 만들고 오류를 내지 않는다

컨테이너가 뜨자마자 멈춘다

  • 컨테이너는 PID 1 이 끝나면 멈춘다. 서버 프로그램이 스스로 뒤로 빠지면(데몬) PID 1 이 바로 끝난다
  • 앞에서 돌게 띄운다: Apache 는 apachectl -D FOREGROUND, Nginx 는 nginx -g 'daemon off;'
  • docker logs 이름 으로 멈추기 전의 출력을 본다. 설정 오류 · 빠진 환경 변수가 여기에 나온다

docker stop 이 10 초 걸린다

  • PID 1 이 SIGTERM 을 처리하지 않아, 10 초 기다린 뒤 SIGKILL 로 끝난 것이다. 종료 코드가 137 로 남는다
  • --init 을 붙이거나, Dockerfile 의 CMD 를 ["…"] 꼴로 써서 프로그램이 직접 PID 1 이 되게 한다

unable to delete … (must be forced)

Error response from daemon: conflict: unable to delete ubuntu:24.04 (must be forced) - container c3dbdf3b3669 is using its referenced image fe81560990fa
  • 멈춘 컨테이너가 그 이미지를 쓰고 있다. docker ps -a --filter ancestor=ubuntu:24.04 로 찾아 먼저 지운다

예전에는

  • docker login 에서 unauthorized: incorrect username or password. 가 나면 이메일 대신 hub.docker.com 에서 확인한 사용자 이름으로 로그인해 풀었다 (옛 기록)
  • Docker Toolbox · Hyper-V 시절 윈도우에서는 볼륨 연결이 끊기는 일이 있었고, SMB v1 을 끄고 재부팅하면 된다는 이야기가 있었다(docker/for-win#2677). 지금의 WSL 2 백엔드에서는 이 방법을 쓰지 않는다
