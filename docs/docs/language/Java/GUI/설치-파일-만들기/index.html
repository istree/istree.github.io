Java 데스크톱 앱(AWT · Swing · JavaFX) 을 사용자가 더블클릭해 설치하는 파일로 묶을 때는 JDK 의 jpackage 를 쓴다. 앱 jar 와 함께 줄인 JVM 을 넣으므로, 사용자 컴퓨터에 Java 가 없어도 돈다. 줄인 JVM 은 jdeps 로 필요한 모듈을 찾고 jlink 로 만든다. 여기의 예제는 JDK 25 · macOS 에서 만들어 확인했다.

flowchart LR
  J["memo.jar"] --> D["jdeps<br/>필요한 모듈 찾기"]
  D --> L["jlink<br/>줄인 JVM (78 MB)"]
  J --> P["jpackage"]
  L --> P
  P --> A[".app · .dmg · .msi · .deb"]

줄인 JVM 만들기

jar --create --file input/memo.jar --main-class com.example.Main -C out .

jdeps --print-module-deps --ignore-missing-deps input/memo.jar     # java.base,java.desktop

jlink --add-modules java.base,java.desktop \
      --strip-debug --no-header-files --no-man-pages \
      --output runtime                                               # 294 MB 인 JDK 가 78 MB 로
  • Swing 앱은 java.desktop 하나면 된다. 리플렉션 · 서비스로만 쓰는 모듈(java.naming · jdk.crypto.ec …) 은 jdeps 가 못 찾으니, 돌려 보고 ClassNotFoundException 이 나면 더한다
  • JavaFX 앱은 JavaFX jmods(javafx-jmods-27.0.1) 를 --module-path 에 주고 javafx.controls 를 더한다

앱 · 설치 파일 만들기

# 설치 없이 바로 도는 앱 폴더 — dist/메모.app
jpackage --type app-image --name 메모 --app-version 1.0.0 \
         --input input --main-jar memo.jar --main-class com.example.Main \
         --runtime-image runtime --dest dist

# 설치 파일 — dist/Memo-1.0.0.dmg
jpackage --type dmg --name Memo --app-version 1.0.0 --vendor "Example" \
         --input input --main-jar memo.jar --main-class com.example.Main \
         --runtime-image runtime --dest dist
$ dist/메모.app/Contents/MacOS/메모 --version
메모 1.0.0 25.0.5+8-LTS
옵션 하는 일
--type app-image · dmg · pkg · msi · exe · deb · rpm
--input · --main-jar · --main-class 앱 jar 가 있는 폴더 · 실행할 jar · 메인 클래스
--runtime-image jlink 로 만든 JVM — 빼면 jpackage 가 알아서 만든다
--icon 아이콘 (macOS .icns · Windows .ico · Linux .png)
--java-options JVM 옵션 (-Xmx512m · --enable-native-access=javafx.graphics)
--app-version · --vendor · --copyright 설치 파일 정보
--win-menu · --win-shortcut · --win-dir-chooser Windows 시작 메뉴 · 바탕 화면 바로 가기 · 설치 폴더 고르기
  • 설치 파일은 만드는 OS 의 것만 만든다. Windows 용은 Windows 에서, Linux 용은 Linux 에서 만든다(CI 에서 OS 마다 돌린다)
  • Windows 의 msi · exe 는 WiX Toolset 을 먼저 설치해야 한다
  • 빌드 도구에서는 플러그인으로 같은 일을 한다. Maven 은 org.panteleyev:jpackage-maven-plugin, Gradle 은 org.beryx.runtime 이나 org.panteleyev.jpackageplugin 이다

macOS 에서 dmg 가 멈출 때

jpackage --type dmg 는 dmg 창의 모양(아이콘 자리 · 배경) 을 Finder 에 AppleScript 로 시킨다. 터미널에 Finder 자동화 권한이 없으면 권한을 묻는 창을 기다리며 멈춘다(osascript … Memo-dmg-setup.scpt 가 계속 떠 있다).

  • 권한 주기: 시스템 설정 → 개인정보 보호 및 보안 → 자동화 → 터미널 → Finder 를 켠다
  • 꾸미기 없이 만들기: 그 osascript 프로세스를 끝내면 jpackage 가 기본 모양으로 dmg 를 마저 만든다
  • 다른 사람에게 줄 앱은 Apple 개발자 인증서로 서명하고(--mac-sign · --mac-signing-key-user-name) 공증(notarytool) 해야 경고 없이 열린다

예전에는

  • JDK 8 의 javapackager 로 만들었다. JDK 11 에서 빠졌고 JDK 16 부터 jpackage 가 정식이다
  • 사용자에게 JRE 를 따로 설치하게 하고 .jar 를 나눠 줬다. Oracle 이 JRE 를 따로 내지 않게 된 뒤로는 앱마다 JVM 을 넣는다
  • Launch4j · install4j 로 .exe 를 만들었다. 지금도 쓰지만 기본은 jpackage 다
