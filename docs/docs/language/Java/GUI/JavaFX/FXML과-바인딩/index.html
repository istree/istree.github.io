FXML 은 화면의 노드 트리를 XML 로 적는 파일이다. 화면 모양은 FXML 에, 동작은 컨트롤러 클래스에 두어 둘을 나눈다. 값과 화면은 속성 바인딩으로 이어, 값이 바뀌면 화면이 저절로 따라가게 한다. 아래 그림은 이 글의 로그인 화면을 캡처한 것이다.

FXML

<!-- src/main/resources/Login.fxml -->
<?xml version="1.0" encoding="UTF-8"?>
<?import javafx.geometry.Insets?>
<?import javafx.scene.control.*?>
<?import javafx.scene.layout.*?>
<VBox xmlns="http://javafx.com/javafx" xmlns:fx="http://javafx.com/fxml"
      fx:controller="com.example.LoginController" spacing="8">
  <padding><Insets top="12" right="12" bottom="12" left="12"/></padding>
  <Label text="로그인" style="-fx-font-size: 16; -fx-font-weight: bold"/>
  <TextField fx:id="email" promptText="이메일"/>
  <PasswordField fx:id="password" promptText="비밀번호"/>
  <Label fx:id="message"/>
  <Button fx:id="login" text="들어가기" defaultButton="true" onAction="#onLogin" maxWidth="Infinity"/>
</VBox>
  • 태그 이름이 클래스, 속성이 setter 다(text="…" → setText). 쓰는 클래스는 <?import?> 로 가져온다
  • fx:id 는 컨트롤러의 같은 이름 필드에, onAction="#onLogin" 은 컨트롤러의 메서드에 연결된다
  • 화면 빌더 Scene Builder(Gluon) 로 끌어 놓으며 FXML 을 만들 수 있다

컨트롤러

public class LoginController {
    @FXML private TextField email;            // fx:id 와 이름이 같아야 한다
    @FXML private PasswordField password;
    @FXML private Label message;
    @FXML private Button login;

    @FXML private void initialize() {         // 필드가 모두 채워진 뒤 불린다 — 생성자에서는 아직 null
        login.disableProperty().bind(
            email.textProperty().isEmpty()
                 .or(password.textProperty().length().lessThan(8)));      // 비밀번호 8 자 미만이면 막는다
        message.textProperty().bind(Bindings.createStringBinding(
            () -> email.getText().isEmpty() || email.getText().contains("@") ? "" : "이메일 형식이 아니다",
            email.textProperty()));                                          // email 이 바뀔 때마다 다시 계산
    }

    @FXML private void onLogin() {
        message.textProperty().unbind();
        message.setText(email.getText() + " 로 들어갔다");
    }
}
var loader = new FXMLLoader(getClass().getResource("/Login.fxml"));
Parent root = loader.load();
LoginController controller = loader.getController();   // 값을 넘기거나 부를 때
stage.setScene(new Scene(root));
잘못 오류
FXML 파일 경로가 틀려 getResource 가 null IllegalStateException: Location is not set.
onAction="#onSubmit" 인데 그 메서드가 없다 LoadException: Error resolving onAction='#onSubmit', either the event handler is not in the Namespace or there is an error in the script.
fx:id 와 필드 이름이 다르다 오류 없이 필드가 null — 쓰는 곳에서 NullPointerException
  • 리소스 경로는 / 로 시작하면 클래스 경로의 맨 위부터다. Maven · Gradle 은 src/main/resources 다
  • 모듈(module-info.java) 을 쓰면 컨트롤러 패키지를 opens com.example to javafx.fxml; 로 열어야 FXML 이 private 필드에 넣는다

속성

JavaFX 의 값은 속성(property) 이다. 값과 함께 "바뀌었다" 는 알림을 가진다.

class Person {
    private final StringProperty name = new SimpleStringProperty(this, "name", "");
    private final IntegerProperty age = new SimpleIntegerProperty(this, "age", 0);

    public StringProperty nameProperty() { return name; }   // 이 세 메서드가 JavaFX 의 관례다
    public String getName() { return name.get(); }
    public void setName(String v) { name.set(v); }
    public IntegerProperty ageProperty() { return age; }
}

p.nameProperty().addListener((obs, oldValue, newValue) -> IO.println(oldValue + " → " + newValue));
p.setName("park");                       // lee → park

바인딩

var other = new SimpleStringProperty();
other.bindBidirectional(p.nameProperty());       // 양쪽 — 어느 쪽을 고쳐도 같아진다
p.setName("kim");      // other 도 "kim"
other.set("lee");      // p 도 "lee"

StringExpression label = Bindings.concat(p.nameProperty(), " (", p.ageProperty().asString(), "세)");
p.ageProperty().set(30);
label.get();           // "lee (30세)"

BooleanBinding adult = p.ageProperty().greaterThanOrEqualTo(19);   // true

var copy = new SimpleStringProperty();
copy.bind(p.nameProperty());                     // 한쪽 — 따라가기만
copy.set("x");                                   // RuntimeException: A bound value cannot be set.
  • 한쪽 바인딩(bind) 이 걸린 속성은 직접 바꿀 수 없다. 바꾸려면 먼저 unbind() 한다
  • 바인딩은 값이 필요할 때 다시 계산한다(lazy). 계산이 무거우면 Bindings.createXxxBinding 에 쓰는 속성만 알려 준다
  • 리스너 · 바인딩은 대상이 사라질 때까지 남는다. 오래 사는 모델에 잠깐 쓰는 화면을 묶으면 화면이 메모리에서 빠지지 않는다. 닫을 때 unbind 하거나 WeakChangeListener 를 쓴다
