제네릭은 타입을 매개변수로 받아, 컬렉션 · 도우미 클래스를 여러 타입에 쓰면서 꺼낼 때 캐스팅하지 않게 한다. 람다는 메서드 하나짜리 인터페이스(함수형 인터페이스) 를 짧게 만드는 문법으로, 정렬 기준 · 콜백 · 스트림의 단계를 넘길 때 쓴다.

제네릭 클래스 · 메서드

class Box<T> {
    private final T value;
    Box(T value) { this.value = value; }
    T get() { return value; }
    <R> Box<R> map(Function<? super T, ? extends R> f) {   // 메서드에도 타입 매개변수
        return new Box<>(f.apply(value));
    }
}

Box<String> name = new Box<>("geon");        // 오른쪽은 <> — 왼쪽에서 추론
Box<Integer> length = name.map(String::length);
length.get();                                 // 4 — 캐스팅 없이 Integer

record Pair<A, B>(A first, B second) {}
var p = new Pair<>("kim", 30);                // Pair<String, Integer>
  • 제네릭에는 원시 타입을 쓸 수 없다. List<int> 는 error: unexpected type … required: reference 다. List<Integer> 로 쓴다
  • 타입 정보는 컴파일할 때만 있고 실행 중에는 지워진다. 그래서 new T() · T.class · instanceof List<String> 은 쓸 수 없다

경계 · 와일드카드

static <T extends Comparable<? super T>> T maxOf(List<? extends T> list) {   // 비교할 수 있는 타입만
    T best = list.get(0);
    for (T t : list) if (t.compareTo(best) > 0) best = t;
    return best;
}
maxOf(List.of(3, 9, 4));               // 9

static double sum(List<? extends Number> nums) { … }    // Number 의 자식이면 무엇이든 — 읽기만
sum(List.of(1, 2.5, 3L));              // 6.5

static void fill(List<? super Integer> out) {           // Integer 를 넣을 수 있는 곳 — 쓰기만
    for (int i = 0; i < 3; i++) out.add(i);
}
fill(new ArrayList<Number>());
  • 꺼내 읽기만 하면 ? extends T, 넣기만 하면 ? super T 다(PECS — Producer Extends, Consumer Super)
  • List<String> 은 List<Object> 가 아니다: incompatible types: ArrayList<String> cannot be converted to List<Object>. 둘 다 받으려면 List<?> · List<? extends Object> 로 받는다

람다 · 함수형 인터페이스

Function<Integer, Integer> doubleIt = x -> x * 2;
Function<Integer, Integer> plus1 = x -> x + 1;
doubleIt.andThen(plus1).apply(5);       // 11 — 두 배 한 뒤 1
doubleIt.compose(plus1).apply(5);       // 12 — 1 더한 뒤 두 배

Predicate<String> notBlank = s -> !s.isBlank();
notBlank.and(s -> s.length() < 5).test("abc");   // true

Runnable task = () -> IO.println("run");
task.run();
인터페이스 모양 쓰는 곳
Function<T, R> T → R 바꾸기 (map)
Predicate<T> T → boolean 거르기 (filter)
Consumer<T> T → 없음 하나씩 처리 (forEach)
Supplier<T> 없음 → T 만들기 · 늦게 계산
BiFunction<T, U, R> · UnaryOperator<T> · BinaryOperator<T> 인자 둘 · 같은 타입 합치기 · 바꾸기
Runnable · Callable<T> 없음 → 없음 · 없음 → T 스레드 작업

직접 만들 때는 추상 메서드를 하나만 두고 @FunctionalInterface 를 붙인다.

@FunctionalInterface
interface Validator {
    boolean check(String s);
    default Validator and(Validator other) { return s -> check(s) && other.check(s); }
}

Validator notEmpty = s -> !s.isEmpty();
notEmpty.and(s -> s.length() <= 3).check("abcd");    // false
  • 람다는 바깥의 지역 변수를 읽을 수만 있다. 다시 대입하는 변수를 쓰면 local variables referenced from a lambda expression must be final or effectively final 이다. 바뀌는 값은 필드나 AtomicInteger 에 둔다

메서드 참조

람다가 메서드 하나를 부르기만 하면 클래스::메서드 로 줄인다.

Function<String, Integer> len = String::length;          // s -> s.length()
BiFunction<Integer, Integer, Integer> add = Integer::sum; // (a, b) -> Integer.sum(a, b)
Consumer<String> print = System.out::println;            // s -> System.out.println(s)
Supplier<List<String>> make = ArrayList::new;            // () -> new ArrayList<>()

Comparator

정렬 기준도 함수를 조립해 만든다.

var people = new ArrayList<>(List.of(
    new Pair<>("kim", 30), new Pair<>("lee", 25), new Pair<>("park", 30)));

people.sort(Comparator.comparing(Pair<String, Integer>::second)   // 나이로
    .reversed()                                                    // 큰 순서
    .thenComparing(Pair::first));                                  // 같으면 이름순
// [kim 30, park 30, lee 25]

예전에는

  • 제네릭이 없던 때(Java 1.4) 는 List 에 Object 를 넣고 꺼낼 때마다 (String) list.get(0) 으로 캐스팅했다. 지금도 타입 매개변수 없이(List list) 쓰면 경고가 난다
  • 람다가 없던 때(Java 7) 는 new Comparator<User>() { public int compare(User a, User b) { … } } 처럼 익명 클래스를 썼다
  • new ArrayList<String>() 처럼 오른쪽에도 타입을 적었다. Java 7 부터 <> 다
