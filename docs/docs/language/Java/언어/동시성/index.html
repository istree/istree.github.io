Java 는 처음부터 스레드가 있던 언어다. 지금은 스레드를 직접 만들기보다 ExecutorService 에 작업을 맡기고, 결과는 Future · CompletableFuture 로 받는다. Java 21 의 가상 스레드는 요청 · 파일 · DB 처럼 기다리는 일이 많은 작업을 스레드 하나씩에 맡겨도 될 만큼 가볍다.

스레드

Thread t = Thread.ofPlatform().start(() -> IO.println("플랫폼 스레드"));
t.join();                                   // 끝나기를 기다린다

Thread v = Thread.ofVirtual().start(() -> IO.println("가상 " + Thread.currentThread().isVirtual()));
v.join();

여러 스레드가 같은 값을 지키지 않고 고치면 결과가 틀린다.

int[] count = {0};
// 스레드 넷이 각각 100_000 번 count[0]++
IO.println(count[0]);          // 400000 이어야 하는데 175323

++ 는 읽기 · 더하기 · 쓰기 세 단계라, 두 스레드가 같은 값을 읽고 둘 다 1 만 더한다. 지키는 길은 셋이다.

var counter = new AtomicInteger();
counter.incrementAndGet();               // 값 하나는 atomic

synchronized (lock) { count++; }         // 블록 하나를 한 스레드만

var rl = new ReentrantLock();            // 시간 제한 · 공정성이 필요하면
rl.lock();
try { count++; } finally { rl.unlock(); }
  • 스레드끼리 함께 쓰는 표 · 큐는 ConcurrentHashMap · LinkedBlockingQueue 를 쓴다: map.merge("hits", 1, Integer::sum) 은 잠금 없이 안전하다
  • 스레드를 멈출 때는 interrupt() 를 부른다. 자고 있던(sleep · take) 스레드에 InterruptedException 이 난다. 잡아서 정리하고 끝낸다. 그냥 삼키지 않는다

ExecutorService

스레드 묶음(풀) 에 작업을 넣고, Future 로 결과를 받는다. try-with-resources 로 열면 블록 끝에서 작업이 끝나기를 기다리고 닫는다(Java 19+).

try (var pool = Executors.newFixedThreadPool(4)) {
    Future<Integer> f = pool.submit(() -> { Thread.sleep(50); return 42; });
    f.get(1, TimeUnit.SECONDS);            // 42 — 끝날 때까지 기다린다 (시간 제한)

    Future<Integer> fail = pool.submit(() -> { throw new IllegalStateException("작업 실패"); });
    try {
        fail.get();
    } catch (ExecutionException e) {
        e.getCause().getMessage();         // "작업 실패" — 작업의 예외는 cause 에
    }

    List<Future<String>> all = pool.invokeAll(List.of(() -> "a", () -> "b"));   // 모두 맡기고 기다리기
}
  • submit 한 작업의 예외는 get() 하기 전까지 아무 데도 나오지 않는다. 결과를 받지 않는 작업은 안에서 잡아 로그를 남긴다

CompletableFuture

결과가 나오면 할 일을 이어 붙인다. 여러 비동기 작업을 합치고, 실패 · 시간 초과를 처리한다.

var price = CompletableFuture.supplyAsync(() -> loadPrice());     // 1500
var qty = CompletableFuture.supplyAsync(() -> loadQty());         // 3

price.thenCombine(qty, (p, q) -> p * q)       // 둘이 끝나면 합치기
     .thenApply(total -> total + "원")         // 바꾸기
     .join();                                  // "4500원"

CompletableFuture.supplyAsync(() -> callApi())
    .exceptionally(e -> -1)                    // 실패하면 기본값
    .join();

CompletableFuture.supplyAsync(() -> slowCall())
    .completeOnTimeout("기본값", 100, TimeUnit.MILLISECONDS)   // 늦으면 기본값
    .join();

CompletableFuture.allOf(a, b, c).join();       // 모두 기다리기
  • join() 은 예외를 CompletionException 으로 감싸 던지고, get() 은 ExecutionException 으로 감싼다
  • 실행할 풀을 주지 않으면 공용 ForkJoinPool 에서 돈다. 기다리는 일(I/O) 은 두 번째 인자로 따로 만든 풀을 준다

가상 스레드

가상 스레드는 JVM 이 관리하는 아주 가벼운 스레드다. 기다리는 동안(sleep · 소켓 · 파일 · JDBC) 은 OS 스레드를 놓아주므로, 만 개 · 십만 개를 만들어도 된다.

try (var exec = Executors.newVirtualThreadPerTaskExecutor()) {     // 작업마다 가상 스레드 하나
    for (int i = 0; i < 10_000; i++)
        exec.submit(() -> { Thread.sleep(Duration.ofMillis(100)); return null; });
}
실행기 100 ms 씩 기다리는 작업 10,000 개
newFixedThreadPool(100) 10,370 ms — 100 개씩 차례로
newVirtualThreadPerTaskExecutor() 150 ms — 모두 함께
  • 기다리는 일이 많은 서버 · 크롤러에 쓴다. 계산만 하는 일(CPU) 은 코어 수보다 빨라지지 않으니 그대로 고정 크기 풀을 쓴다
  • 가상 스레드는 풀에 모아 두지 않는다. 작업마다 새로 만든다
  • 동시에 너무 많이 부르지 않게 할 때는 풀 크기 대신 Semaphore 로 막는다

기다리기 도구

var latch = new CountDownLatch(3);              // 세 번 세면 열린다
for (int i = 0; i < 3; i++) Thread.ofVirtual().start(latch::countDown);
latch.await(1, TimeUnit.SECONDS);               // true

var queue = new LinkedBlockingQueue<Integer>(); // 만드는 쪽 · 쓰는 쪽 사이의 큐
queue.add(1);
queue.take();                                   // 비었으면 들어올 때까지 기다린다

예전에는

  • new Thread(runnable).start() 로 스레드를 직접 만들었다. 지금도 되지만 Thread.ofPlatform() · ofVirtual() 빌더가 이름 · 데몬 같은 설정을 함께 준다
  • 풀을 쓰고 나면 shutdown() · awaitTermination() 을 직접 불렀다. Java 19 부터 try-with-resources 로 닫는다
  • 기다리는 일이 많으면 스레드가 모자라 리액티브(WebFlux · RxJava) 로 짰다. Java 21 의 가상 스레드로 보통의 동기 코드 그대로 쓴다
  • wait() · notify() 로 스레드끼리 신호를 주고받았다. 지금은 BlockingQueue · CountDownLatch · CompletableFuture 를 쓴다
