Java 의 코드는 모두 클래스 안에 있다. 상태와 동작을 묶는 보통 클래스, 데이터만 담는 record, 정해진 값 몇 개인 enum, 동작의 약속인 interface 를 쓰고, sealed 로 물려받을 수 있는 타입을 정한다.

클래스

class Account {
    private final String owner;                // final — 생성자에서 한 번만 정한다
    private long balance;
    private static int count = 0;              // 클래스에 하나

    Account(String owner) { this(owner, 0); }                 // 다른 생성자 부르기
    Account(String owner, long balance) {
        this.owner = Objects.requireNonNull(owner, "owner");  // null 이면 NullPointerException: owner
        this.balance = balance;
        count++;
    }

    void deposit(long amount) {
        if (amount <= 0) throw new IllegalArgumentException("0 보다 커야 한다: " + amount);
        balance += amount;
    }
    long balance() { return balance; }
    static int count() { return count; }

    @Override
    public String toString() { return owner + ": " + balance; }
}

var a = new Account("geon");
a.deposit(100);
IO.println(a);                 // geon: 100 — toString 이 불린다
접근 제한 보이는 곳
private 그 클래스 안
(없음) 같은 패키지
protected 같은 패키지 + 자식 클래스
public 어디서나
  • 필드는 private 으로 두고 메서드로 내준다. 바뀌지 않을 필드는 final 로 둔다
  • 생성자에서 인자를 검사해 잘못된 객체가 만들어지지 않게 한다

상속

class Savings extends Account {
    private final double rate;

    Savings(String owner, double rate) {
        super(owner);                          // 부모 생성자 — 맨 앞에
        this.rate = rate;
    }
    void addInterest() { deposit(Math.round(balance() * rate)); }

    @Override                                  // 부모 메서드를 바꾼다 — 이름이 틀리면 컴파일 오류
    public String toString() { return super.toString() + " (이자 " + rate * 100 + "%)"; }
}

var s = new Savings("kim", 0.05);
s.deposit(1000);
s.addInterest();               // kim: 1050 (이자 5.0%)
  • 부모는 하나만 둔다(extends 하나). 여러 갈래의 동작은 인터페이스로 더한다
  • 물려줄 생각이 없는 클래스는 final 로 둔다

인터페이스

interface Shape {
    double area();                                       // 구현할 메서드
    default String describe() {                          // 기본 구현
        return getClass().getSimpleName() + " 넓이 " + String.format("%.2f", area());
    }
    static Shape unit() { return new Square(1); }        // 정적 메서드
}

record Square(double side) implements Shape {
    public double area() { return side * side; }
}

for (Shape sh : List.of(new Square(2), Shape.unit()))
    IO.println(sh.describe());                           // Square 넓이 4.00 · Square 넓이 1.00

record

값을 담는 클래스다. 생성자 · 읽기 메서드 · equals · hashCode · toString 을 만들어 준다. 필드는 바꿀 수 없다.

record Point(int x, int y) {
    Point withX(int nx) { return new Point(nx, y); }     // 바꾼 복사본을 돌려준다
    static Point origin() { return new Point(0, 0); }
}

var p = new Point(1, 2);
p.x();                         // 1 — getX() 가 아니라 x()
p.toString();                  // "Point[x=1, y=2]"
p.equals(new Point(1, 2));     // true — 값이 같으면 같다
p.x = 2;                       // error: cannot assign a value to final variable x

record Circle(double r) implements Shape {
    Circle {                                             // 짧은 생성자 — 검사만 적는다
        if (r < 0) throw new IllegalArgumentException("반지름이 음수다");
    }
    public double area() { return Math.PI * r * r; }
}
  • DTO · 응답 · 맵의 키처럼 값으로 다루는 것은 record 로 쓴다

enum

enum Status {
    DRAFT("초안"), PUBLISHED("공개");

    private final String label;
    Status(String label) { this.label = label; }
    String label() { return label; }
}

Status.PUBLISHED.label();      // "공개"
Status.valueOf("DRAFT");       // 이름으로 찾기 — 없으면 IllegalArgumentException
Status.values();               // [DRAFT, PUBLISHED]

sealed

물려받을 수 있는 타입을 정해 둔다. switch 에서 모든 갈래를 다뤘는지 컴파일러가 검사한다.

sealed interface Result permits Ok, Err {}
record Ok(String data) implements Result {}
record Err(String message) implements Result {}

String render(Result r) {
    return switch (r) {                        // default 가 없어도 된다 — 갈래가 둘뿐인 것을 안다
        case Ok(var data) -> "ok " + data;     // record 를 풀어 꺼낸다
        case Err(var msg) -> "err " + msg;
    };
}
  • 갈래를 빠뜨리면 error: the switch expression does not cover all possible input values 로 컴파일되지 않는다. 갈래를 더하면 고칠 곳을 모두 찾아 준다

equals · hashCode

보통 클래스를 HashMap 의 키 · HashSet 에 넣으려면 둘을 함께 만든다. 하나만 만들면 같은 값이 두 번 들어간다.

final class User {
    private final String id;
    private final String name;
    User(String id, String name) { this.id = id; this.name = name; }

    @Override public boolean equals(Object o) { return o instanceof User u && id.equals(u.id); }
    @Override public int hashCode() { return id.hashCode(); }
}

new HashSet<>(List.of(new User("1", "a"), new User("1", "b"))).size();   // 1 — id 가 같으면 같은 사용자

예전에는

  • 값 클래스를 필드 · 생성자 · getter · equals · hashCode · toString 으로 수십 줄 썼다(또는 Lombok). Java 16 부터 record 다
  • 정해진 값은 public static final int DRAFT = 0; 처럼 정수 상수로 썼다. Java 5 부터 enum 이다
  • 인터페이스에 구현을 둘 수 없어 AbstractXxx 클래스를 같이 만들었다. Java 8 부터 default 메서드다
