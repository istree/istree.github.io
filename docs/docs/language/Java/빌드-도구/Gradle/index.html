Gradle 은 빌드를 Kotlin(또는 Groovy) 코드로 적는 도구다. Maven 과 같은 폴더 구조 · Maven Central 을 쓰면서, 바뀐 것만 다시 빌드하고 결과를 캐시해 빠르다. 안드로이드 · Spring Boot 프로젝트의 기본이다. 여기의 예제는 Gradle 9.9 · Java 25 로 돌렸다.

설치 · 프로젝트 만들기

brew install gradle           # macOS — 처음 만들 때만 쓴다
sdk install gradle

gradle init --type java-application --dsl kotlin --test-framework junit-jupiter \
            --package com.example --project-name demo --java-version 25
settings.gradle.kts
gradle/libs.versions.toml          의존성 판 목록 (version catalog)
gradle/wrapper/                    Gradle Wrapper
gradlew · gradlew.bat
app/build.gradle.kts
app/src/main/java/com/example/App.java
app/src/test/java/com/example/AppTest.java
  • 프로젝트는 늘 ./gradlew 로 빌드한다. Wrapper 가 정해진 판의 Gradle 을 받아 쓰므로, 설치된 Gradle 판과 상관없이 모두 같은 판으로 빌드한다
  • Wrapper 를 더하거나 판을 바꿀 때: gradle wrapper --gradle-version 9.9.0

build.gradle.kts

// settings.gradle.kts
rootProject.name = "notes"
// build.gradle.kts
plugins {
    application                                   // run · installDist · distZip
}

group = "com.example"
version = "1.0.0"

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(25)   // 없으면 Gradle 이 JDK 를 받는다
    }
}

repositories {
    mavenCentral()
}

dependencies {
    implementation("tools.jackson.core:jackson-databind:3.2.4")
    testImplementation(platform("org.junit:junit-bom:6.1.3"))
    testImplementation("org.junit.jupiter:junit-jupiter")
    testRuntimeOnly("org.junit.platform:junit-platform-launcher")
}

application {
    mainClass = "com.example.notes.App"
}

tasks.test {
    useJUnitPlatform()
    testLogging { events("passed", "failed") }    // 테스트마다 결과 줄
}
설정 Maven scope 뜻
implementation compile 컴파일 · 실행에 쓴다. 이 모듈을 쓰는 쪽에는 드러나지 않는다
api (java-library 플러그인) compile 쓰는 쪽에도 드러난다 — 공개 API 의 타입
compileOnly provided 컴파일만 (Lombok · 어노테이션)
runtimeOnly runtime 실행만 (JDBC 드라이버)
testImplementation test 테스트에서만
  • 툴체인을 정하면 JAVA_HOME 이 다른 판이어도 그 판으로 컴파일한다
  • platform(...) 은 BOM 이다. JUnit · Spring 처럼 모듈이 여럿인 것의 판을 한 번에 맞춘다

명령

./gradlew build                 # 컴파일 · 테스트 · jar — build/libs/notes-1.0.0.jar
./gradlew test                  # 테스트
./gradlew test --tests NoteTest # 하나만
./gradlew run                   # 실행 (application)
./gradlew installDist           # build/install/notes/bin/notes — 실행 스크립트 + 의존성 jar
./gradlew clean
./gradlew dependencies --configuration runtimeClasspath   # 의존성 트리
./gradlew tasks                 # 쓸 수 있는 작업
./gradlew build --scan          # 빌드 기록을 웹으로 — 느린 곳 · 실패 찾기

  • 같은 작업을 다시 하면 바뀐 것이 없는 단계는 UP-TO-DATE 로 건너뛴다. 테스트를 다시 돌리려면 --rerun 을 준다
  • application 의 jar 는 내 클래스만 들어 있다. 의존성까지 한 파일로 내려면 Shadow 플러그인(com.gradleup.shadow) 을 쓰고, 보통은 installDist · distZip 으로 낸다

version catalog

여러 모듈이 같은 판을 쓰도록 gradle/libs.versions.toml 에 모아 두고 이름으로 가져온다.

[versions]
jackson = "3.2.4"
junit = "6.1.3"

[libraries]
jackson-databind = { module = "tools.jackson.core:jackson-databind", version.ref = "jackson" }
junit-bom = { module = "org.junit:junit-bom", version.ref = "junit" }
dependencies {
    implementation(libs.jackson.databind)
    testImplementation(platform(libs.junit.bom))
}

여러 모듈

// settings.gradle.kts
rootProject.name = "notes"
include("core", "app")

// app/build.gradle.kts
dependencies {
    implementation(project(":core"))
}
  • 모듈마다 같은 설정은 buildSrc 나 build-logic 의 convention 플러그인으로 뺀다

Maven 과 견주기

Maven Gradle
설정 pom.xml (XML) build.gradle.kts (Kotlin)
빌드 속도 늘 처음부터 바뀐 것만 · 캐시 · 데몬
고치기 플러그인 설정으로 코드로 작업을 바로 짠다
쓰는 곳 기업 · 오래된 프로젝트 안드로이드 · 새 Spring 프로젝트

예전에는

  • 설정을 Groovy(build.gradle) 로 썼다. Gradle 8 부터 gradle init 의 기본이 Kotlin DSL 이다
  • 의존성을 compile · testCompile 로 적었다. Gradle 7 에서 빠졌고 implementation · testImplementation 이다
  • sourceCompatibility = 1.8 로 판을 정했다. 지금은 툴체인을 쓴다
