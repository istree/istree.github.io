Maven 은 pom.xml 하나에 프로젝트 이름 · 의존성 · 플러그인을 적고, 정해진 폴더 구조와 단계(compile → test → package) 로 빌드하는 도구다. 의존성은 Maven Central 에서 받아 ~/.m2/repository 에 모아 둔다. 설정이 XML 이라 길지만, 어느 프로젝트나 모양이 같아 읽기 쉽다. 여기의 예제는 Maven 3.10 · Java 25 로 돌렸다.

설치

brew install maven            # macOS
sdk install maven             # SDKMAN
mvn -v                        # Apache Maven 3.10.0 … Java version: 25.0.5
  • 프로젝트에 Maven Wrapper(mvnw) 를 두면 Maven 을 설치하지 않은 사람도 같은 판으로 빌드한다: mvn wrapper:wrapper 뒤 ./mvnw package

폴더 구조

pom.xml
src/main/java/com/example/notes/App.java
src/main/java/com/example/notes/Note.java
src/main/resources/            설정 파일 · 리소스 — jar 안으로 들어간다
src/test/java/com/example/notes/NoteTest.java
target/                        빌드 결과 (git 에 올리지 않는다)

pom.xml

<project xmlns="http://maven.apache.org/POM/4.0.0" …>
  <modelVersion>4.0.0</modelVersion>

  <groupId>com.example</groupId>          <!-- 조직 -->
  <artifactId>notes</artifactId>          <!-- 프로젝트 이름 -->
  <version>1.0.0</version>

  <properties>
    <maven.compiler.release>25</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>

  <dependencyManagement>
    <dependencies>
      <dependency>                          <!-- BOM — JUnit 모듈들의 판을 한 번에 맞춘다 -->
        <groupId>org.junit</groupId>
        <artifactId>junit-bom</artifactId>
        <version>6.1.3</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>

  <dependencies>
    <dependency>
      <groupId>tools.jackson.core</groupId>
      <artifactId>jackson-databind</artifactId>
      <version>3.2.4</version>
    </dependency>
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <scope>test</scope>                   <!-- 테스트에서만 -->
    </dependency>
  </dependencies>

  <build>
    <plugins>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <artifactId>maven-surefire-plugin</artifactId>   <!-- 테스트 실행 -->
        <version>3.6.1</version>
      </plugin>
      <plugin>
        <groupId>org.codehaus.mojo</groupId>
        <artifactId>exec-maven-plugin</artifactId>       <!-- mvn exec:java -->
        <version>3.6.4</version>
        <configuration><mainClass>com.example.notes.App</mainClass></configuration>
      </plugin>
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <artifactId>maven-shade-plugin</artifactId>      <!-- 의존성까지 넣은 jar 하나 -->
        <version>3.6.2</version>
        <executions>
          <execution>
            <phase>package</phase>
            <goals><goal>shade</goal></goals>
            <configuration>
              <transformers>
                <transformer implementation="org.apache.maven.plugins.shade.resource.ManifestResourceTransformer">
                  <mainClass>com.example.notes.App</mainClass>
                </transformer>
              </transformers>
            </configuration>
          </execution>
        </executions>
      </plugin>
    </plugins>
  </build>
</project>
scope 컴파일 테스트 실행 · 패키지
compile (기본) ○ ○ ○
provided ○ ○ 서버 · 실행 환경이 준다 (Servlet API)
runtime — ○ ○ (JDBC 드라이버)
test — ○ —
  • 플러그인 판을 적지 않으면 Maven 판마다 다른 기본값이 쓰여 빌드가 달라진다. 판을 정해 둔다
  • 의존성 좌표(groupId:artifactId:version) 는 Maven Central 에서 찾는다

명령

mvn compile                 # 컴파일 — target/classes
mvn test                    # 테스트까지
mvn package                 # target/notes-1.0.0.jar
mvn clean package           # target 을 지우고 다시
mvn install                 # ~/.m2 에도 넣는다 — 다른 로컬 프로젝트가 쓰게
mvn test -Dtest=NoteTest    # 테스트 하나만
mvn package -DskipTests     # 테스트 건너뛰기
mvn exec:java               # 실행
mvn dependency:tree         # 의존성 트리 — 판 충돌을 찾는다
mvn versions:display-dependency-updates   # 새 판이 나온 의존성
$ java -jar target/notes-1.0.0.jar
[{"id":1,"text":"장보기"},{"id":2,"text":"운동하고 샤워하기"}]
Note[id=3, text=청소]
  • 단계는 차례로 돈다. mvn package 는 compile · test 를 거친다
  • mvn dependency:tree 로 누가 어떤 판을 끌어왔는지 본다. 같은 라이브러리의 판이 여럿이면 가장 가까운 것 하나가 쓰인다

[INFO] +- tools.jackson.core:jackson-databind:jar:3.2.4:compile
[INFO] \- org.junit.jupiter:junit-jupiter:jar:6.1.3:test
[INFO]    +- org.junit.jupiter:junit-jupiter-api:jar:6.1.3:test

테스트 (JUnit)

// src/test/java/com/example/notes/NoteTest.java
import org.junit.jupiter.api.Test;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;
import static org.junit.jupiter.api.Assertions.*;

class NoteTest {
    @Test
    void shortTextIsTitle() {
        assertEquals("장보기", new Note(1, "장보기").title());
    }

    @ParameterizedTest
    @CsvSource({"운동하고 샤워하기, 운동하고 …", "abcdef, abcde…"})
    void longTextIsCut(String text, String expected) {
        assertEquals(expected, new Note(1, text).title());
    }

    @Test
    void nullTextThrows() {
        assertThrows(NullPointerException.class, () -> new Note(1, null).title());
    }
}
[INFO] Tests run: 4, Failures: 0, Errors: 0, Skipped: 0
[INFO] BUILD SUCCESS

여러 모듈

<!-- 맨 위 pom.xml -->
<packaging>pom</packaging>
<modules>
  <module>core</module>
  <module>app</module>             <!-- app 의 pom 에서 core 를 dependency 로 -->
</modules>
  • 맨 위에서 mvn package 하면 모듈 사이의 의존 순서대로 빌드한다. 공통 판 · 플러그인은 맨 위 pom 의 dependencyManagement · pluginManagement 에 둔다

예전에는

  • 판을 <source>1.8</source> · <target>1.8</target> 로 정했다. 지금은 maven.compiler.release 하나다(옛 API 를 쓰면 컴파일 오류로 잡는다)
  • JUnit 4 는 @Test 가 org.junit.Test 이고 @Before · @RunWith 를 썼다. JUnit 5 부터 org.junit.jupiter.api, @BeforeEach · @ExtendWith 다
  • Maven 4 가 준비 중이다(2026-11 RC). pom 의 모델이 4.1.0 으로 바뀌지만 4.0.0 pom 도 그대로 빌드한다
