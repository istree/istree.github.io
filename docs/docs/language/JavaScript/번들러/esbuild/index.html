esbuild 는 Go 로 짠 번들러 · 변환기다. JavaScript · TypeScript · JSX · CSS 를 묶고 줄이는 일을 Webpack 보다 수십 배 빠르게 한다. 설정 파일 없이 명령줄 한 줄로 쓰고, 더 필요하면 JavaScript API 로 빌드 스크립트를 짠다. Vite 7 까지 개발 서버의 변환을 esbuild 가 맡았고, tsup · Angular CLI 같은 도구도 안에서 esbuild 를 쓴다.

설치

npm install -D esbuild
npx esbuild --version

명령줄

# 브라우저용 — src/app.ts 와 거기서 import 한 것을 dist/app.js 하나로
npx esbuild src/app.ts --bundle --outdir=dist --minify --sourcemap --target=es2020

# Node 용 — node_modules 는 묶지 않고 import 로 남긴다
npx esbuild src/server.js --bundle --platform=node --format=esm --packages=external --outfile=dist/server.mjs
옵션 하는 일
--bundle import 를 따라가 한 파일로 묶는다. 빼면 파일 하나만 변환한다
--outfile · --outdir 결과 파일 하나 · 결과 폴더 (입력이 여럿이거나 CSS 가 나오면 outdir)
--minify · --sourcemap 줄이기 · 소스맵
--platform=browser|node|neutral 어디서 돌릴지. node 면 fs 같은 내장 모듈을 묶지 않는다
--format=iife|esm|cjs 결과 모듈 형식. 브라우저 기본은 iife
--target=es2020,chrome100 이 버전에서 돌도록 새 문법을 바꾼다
--external:express · --packages=external 묶지 않을 패키지 · node_modules 모두
--define:__VERSION__='"1.0"' 식을 글자 그대로 바꿔 넣는다 (값은 JSON)
--loader:.svg=dataurl 확장자마다 읽는 법 (text · dataurl · file · copy …)
  • import "./style.css" 처럼 CSS 를 가져오면 dist/app.css 가 따로 나온다
  • 쓰지 않는 export 는 묶을 때 빠진다(tree shaking)
  • --minify 로 묶으면 process.env.NODE_ENV 를 "production" 으로, 아니면 "development" 로 바꿔 넣는다 (브라우저용)
  • 브라우저에 global 이 없어 Node 용으로 짠 라이브러리가 멈추면 --define:global=globalThis 를 준다

JavaScript API

옵션이 늘면 빌드 스크립트로 옮긴다. 명령줄 옵션과 이름이 같다(--outdir → outdir).

// build.mjs — node build.mjs
import * as esbuild from "esbuild";

const result = await esbuild.build({
  entryPoints: ["src/app.ts"],
  bundle: true,
  outdir: "dist",
  minify: true,
  sourcemap: true,
  target: ["es2020"],
  define: { __VERSION__: '"1.0"' },
  loader: { ".svg": "dataurl" },
  metafile: true,                                  // 무엇이 얼마나 들어갔는지
});
console.log(await esbuild.analyzeMetafile(result.metafile));
  dist/app.js       192b   100.0%
   ├ src/logo.svg    72b    37.5%
   ├ src/app.ts      59b    30.7%
   └ src/util.js     17b     8.9%

지켜보기 · 개발 서버

context 로 만들면 고칠 때마다 다시 묶고(watch), 폴더를 웹 서버로 띄운다(serve).

const ctx = await esbuild.context({ entryPoints: ["src/app.ts"], bundle: true, outdir: "www/js" });
await ctx.watch();
const { port } = await ctx.serve({ servedir: "www" });   // http://localhost:8000
  • 명령줄은 npx esbuild src/app.ts --bundle --outdir=www/js --watch --servedir=www 다
  • 명령줄의 --watch 는 입력(stdin) 이 닫히면 멈춘다. 다른 도구가 띄우거나 백그라운드로 돌릴 때는 --watch=forever 를 준다
  • 묶은 결과를 메모리에서 바로 내준다. 페이지를 새로 고치면 새 결과를 받는다. 모듈만 바꿔 끼우는 HMR 은 없다

플러그인

onResolve(import 이름 → 경로) 와 onLoad(경로 → 내용) 에 함수를 단다.

const envPlugin = {
  name: "env",
  setup(build) {
    build.onResolve({ filter: /^env$/ }, args => ({ path: args.path, namespace: "env" }));
    build.onLoad({ filter: /.*/, namespace: "env" }, () => ({
      contents: JSON.stringify({ HOME: process.env.HOME }),
      loader: "json",
    }));
  },
};

await esbuild.build({ entryPoints: ["src/app.js"], bundle: true, outfile: "dist/app.js", plugins: [envPlugin] });
// src/app.js 에서 import { HOME } from "env";

하지 않는 것

  • TypeScript 의 타입을 검사하지 않고 지우기만 한다. const x: number = "a" 도 그대로 빌드된다. 검사는 tsc --noEmit 을 따로 돌린다
  • HTML 을 읽지 않는다. 진입점은 JS · CSS 파일이고, HTML 은 직접 둔다
  • 코드 나누기(--splitting) 는 --format=esm 에서만 된다
