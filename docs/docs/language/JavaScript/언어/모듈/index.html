모듈은 파일 하나를 범위 하나로 만들고, 밖에 보일 것만 내보낸다. 언어에 모듈이 없던 때는 전역 객체 · 즉시 실행 함수로 흉내 냈고, Node.js 는 CommonJS 를 만들었다. 지금 표준은 ES 모듈(import · export) 이다. 옛 코드를 읽을 일이 많으므로 옛 방식도 같이 적는다.

ES 모듈

// math.js
export const PI = 3.14;
export function sum(a, b) { return a + b; }
export default class Calculator { ... }   // 파일에 하나

// main.js
import Calculator, { PI, sum as add } from "./math.js";   // 기본 + 이름 · 다른 이름
import * as math from "./math.js";                        // 전부를 객체 하나로
import "./polyfill.js";                                   // 실행만 한다
  • 경로에 확장자(.js) 까지 쓴다. 번들러는 빼도 찾아 주지만 브라우저 · Node.js 는 찾지 않는다
  • 기본 내보내기는 가져오는 쪽에서 이름을 마음대로 붙인다. 찾기 · 이름 바꾸기가 쉬우려면 이름 내보내기를 쓴다
  • 가져온 이름은 읽기 전용이다. 내보낸 쪽에서 값을 바꾸면 가져온 쪽에도 보인다(살아 있는 연결)

여러 파일을 한곳에서 다시 내보내면 가져오는 쪽 경로가 짧아진다.

// components/index.js
export { Button } from "./Button.js";
export { Dialog, default as Modal } from "./Dialog.js";
export * from "./icons.js";

필요할 때 가져오기

import() 는 Promise 를 돌려준다. 처음에 쓰지 않는 무거운 코드를 나중에 읽는다.

button.onclick = async () => {
  const { openEditor } = await import("./editor.js");
  openEditor();
};

브라우저

<script type="module" src="./main.js"></script>
<script type="module">
  import { sum } from "./math.js";
</script>
  • 모듈 스크립트는 defer 처럼 HTML 을 다 읽은 뒤 돈다. 자동으로 strict 모드다
  • file:// 로 열면 막힌다. 로컬 서버(npx serve 등) 로 연다
  • 패키지 이름(import "lodash") 은 브라우저가 모른다. 번들러를 쓰거나 import map 으로 경로를 알려 준다

Node.js

package.json 에 "type": "module" 을 두면 .js 를 ES 모듈로 읽는다. 없으면 CommonJS 로 읽는다. 확장자로 정할 수도 있다: .mjs 는 ES 모듈, .cjs 는 CommonJS.

{
  "type": "module",
  "exports": {
    ".": "./src/index.js",
    "./utils": "./src/utils.js"
  }
}
  • exports 는 패키지를 가져가는 쪽에 보일 경로를 정한다. 적지 않은 파일은 가져갈 수 없다
  • ES 모듈에는 __dirname 이 없다. import.meta.dirname(Node.js 20.11+) 이나 new URL(".", import.meta.url) 을 쓴다
  • 내장 모듈은 node: 를 붙인다: import { readFile } from "node:fs/promises";

CommonJS

Node.js 의 원래 방식이다. npm 의 오래된 패키지 · 설정 파일에 아직 많다.

// math.js
const PI = 3.14;
function sum(a, b) { return a + b; }
module.exports = { PI, sum };       // 또는 exports.sum = sum;

// main.js
const { sum } = require("./math");  // 확장자를 빼도 된다
const fs = require("fs");
  • require 는 동기로 읽고 결과를 캐시한다. 두 번째부터는 같은 객체가 온다
  • ES 모듈에서 CommonJS 를 import 하면 module.exports 가 기본 내보내기로 온다. CommonJS 에서 ES 모듈은 await import() 로 읽는다 (Node.js 22.12+ 는 require 도 된다)

옛 방식

네임스페이스 객체

전역 이름 하나만 만들고, 나머지는 그 아래에 둔다.

var SHOP = SHOP || {};                   // 다른 파일이 먼저 만들었으면 그것을 쓴다
SHOP.format = {
  price: function (n) { return n.toLocaleString() + "원"; },
};
SHOP.Cart = function () { ... };

모듈 패턴

즉시 실행 함수가 비공개 변수를 감추고, 공개할 것만 객체로 돌려준다. 클로저를 쓴다.

var settings = (function () {
  var values = { theme: "light" };       // 비공개
  function save() { localStorage.setItem("settings", JSON.stringify(values)); }
  return {
    get: function (key) { return values[key]; },
    set: function (key, value) { values[key] = value; save(); },
  };
})();

AMD

브라우저에서 파일을 비동기로 읽으려고 만든 형식이다. RequireJS 가 읽는다.

define(["jquery", "./util"], function ($, util) {
  return { init: function () { ... } };
});
  • UMD 는 CommonJS · AMD · 전역 변수 어디서나 돌도록 감싼 형식이다. 라이브러리의 dist/*.umd.js 가 이것이다

파일 읽어 실행하기

브라우저용 스크립트(전역에 함수를 두는 파일) 를 Node.js 에서 같이 쓰고 싶을 때, 고칠 수 없으면 읽어서 vm 으로 돌린다.

import { readFileSync } from "node:fs";
import vm from "node:vm";

const context = {};
vm.runInNewContext(readFileSync("common/prop.js", "utf8"), context);
context.someFunction();    // prop.js 가 전역에 둔 것
  • 고칠 수 있으면 파일을 ES 모듈로 바꾸고 양쪽에서 import 한다. 번들러가 브라우저용으로 묶는다
