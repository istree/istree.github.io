JavaScript 는 한 스레드에서 돈다. 파일 · 네트워크 · 타이머처럼 기다리는 일은 맡겨 두고 바로 다음 줄로 넘어가며, 끝나면 이벤트 루프가 결과를 처리할 함수를 불러 준다. 그 함수를 넘기는 방식이 콜백 → Promise → async/await 순서로 바뀌어 왔다.

이벤트 루프

  • 콜 스택 — 지금 도는 함수. 비어야 다음 일을 꺼낸다
  • 마이크로태스크 큐 — Promise 의 then · await 다음 줄. 스택이 빌 때마다 모두 비운다
  • 태스크 큐 — setTimeout · 이벤트 · I/O 콜백. 한 번에 하나씩 꺼낸다
console.log(1);
setTimeout(() => console.log(4), 0);
Promise.resolve().then(() => console.log(3));
console.log(2);
// 1 2 3 4
  • 오래 걸리는 계산을 그대로 돌리면 그동안 화면이 멈춘다. 잘게 나눠 setTimeout 으로 넘기거나 Web Worker 로 보낸다

콜백

끝나면 부를 함수를 넘긴다. Node.js 의 옛 API 는 첫 인자가 오류다(error-first).

fs.readFile("a.txt", "utf8", (err, text) => {
  if (err) return console.error(err);
  console.log(text);
});

차례로 이어지는 일이 많으면 안으로 계속 들어간다(콜백 지옥). 오류도 단계마다 따로 처리해야 한다.

Promise

나중에 값(또는 오류) 이 들어올 자리다. then 이 새 Promise 를 돌려주므로 줄줄이 연결한다.

fetch("/api/user")
  .then(res => res.json())
  .then(user => fetch(`/api/posts?user=${user.id}`))
  .then(res => res.json())
  .then(posts => console.log(posts))
  .catch(err => console.error(err))      // 어느 단계의 오류든 여기로 온다
  .finally(() => hideSpinner());

콜백 API 는 Promise 로 감싸서 쓴다.

const sleep = ms => new Promise(resolve => setTimeout(resolve, ms));

function loadImage(src) {
  return new Promise((resolve, reject) => {
    const img = new Image();
    img.onload = () => resolve(img);
    img.onerror = () => reject(new Error(`이미지를 읽지 못함: ${src}`));
    img.src = src;
  });
}
  • Node.js 는 Promise 판 API 가 따로 있다: import { readFile } from "node:fs/promises";. 콜백 API 는 util.promisify 로 바꾼다

async · await

await 는 Promise 가 끝날 때까지 그 함수만 멈춘다. 동기 코드처럼 위에서 아래로 읽힌다.

async function showPosts() {
  try {
    const user = await (await fetch("/api/user")).json();
    const posts = await (await fetch(`/api/posts?user=${user.id}`)).json();
    render(posts);
  } catch (err) {
    console.error(err);
  } finally {
    hideSpinner();
  }
}
  • async 함수는 늘 Promise 를 돌려준다. 부르는 쪽도 await 하거나 .catch 를 단다. 그냥 두면 오류가 사라진다(unhandled rejection)
  • ES 모듈 맨 위에서는 async 없이 await 를 쓴다(top-level await)

순서대로 · 한꺼번에

서로 기대지 않는 일은 한꺼번에 시작하고 함께 기다린다. 하나씩 await 하면 시간이 더해진다.

// 느리다: a 가 끝나야 b 를 시작한다
const a = await getA();
const b = await getB();

// 빠르다: 둘을 함께 시작한다
const [a, b] = await Promise.all([getA(), getB()]);
함수 끝나는 때 결과
Promise.all 모두 성공 · 하나라도 실패 값 배열 · 첫 오류
Promise.allSettled 모두 끝남 { status, value | reason } 배열
Promise.race 가장 먼저 끝난 하나 그 값 · 오류
Promise.any 가장 먼저 성공한 하나 그 값 · 모두 실패면 AggregateError

반복문에서 하나씩 해야 하면 for...of 안에서 await 한다. forEach 는 await 를 기다리지 않는다.

for (const file of files) {
  await upload(file);         // 하나씩 차례로
}
await Promise.all(files.map(upload));   // 한꺼번에

시간 제한 · 취소

fetch 같은 API 는 AbortSignal 을 받는다.

const res = await fetch(url, { signal: AbortSignal.timeout(5000) });   // 5 초 넘으면 오류

const controller = new AbortController();
fetch(url, { signal: controller.signal });
cancelButton.onclick = () => controller.abort();                       // 사용자가 취소

signal 을 받지 않는 일은 race 로 시간 제한을 건다. 원래 일은 계속 돈다.

const timeout = ms => new Promise((_, reject) =>
  setTimeout(() => reject(new Error("시간 초과")), ms));
const result = await Promise.race([work(), timeout(3000)]);

차례로 오는 값

for await...of 는 비동기로 하나씩 오는 값을 돈다. 스트림 · 페이지 단위 API 에 쓴다.

async function* pages(url) {
  while (url) {
    const res = await (await fetch(url)).json();
    yield res.items;
    url = res.next;
  }
}

for await (const items of pages("/api/items")) {
  render(items);
}
