함수형 프로그래밍은 값을 바꾸는 명령을 늘어놓는 대신, 입력을 받아 새 값을 돌려주는 작은 함수를 조립해 프로그램을 짜는 방식이다. JavaScript 는 함수가 값이고 배열 메서드 · 펼치기 · 클로저가 있어 이 방식을 그대로 쓴다. 모두 함수형으로 짤 필요는 없고, 데이터를 바꾸고 거르고 모으는 코드에 쓰면 읽기 쉽고 테스트하기 쉬워진다.

아래 예제는 이 주문 목록을 쓴다.

const orders = [
  { id: 1, customer: "kim",  item: "펜",   price: 1500,  qty: 2, status: "paid" },
  { id: 2, customer: "lee",  item: "공책", price: 3000,  qty: 1, status: "paid" },
  { id: 3, customer: "kim",  item: "가방", price: 25000, qty: 1, status: "cancel" },
  { id: 4, customer: "park", item: "펜",   price: 1500,  qty: 5, status: "paid" },
];

순수 함수

같은 입력이면 늘 같은 값을 돌려주고, 밖의 것을 바꾸지 않는 함수다. 결과가 인자에만 달려 있어 테스트 · 캐시 · 재사용이 쉽다.

let taxRate = 0.1;
const priceWithTax = price => price * (1 + taxRate);                 // 밖의 변수에 달려 있다
const withTax = (price, rate) => Math.round(price * (1 + rate));     // 인자만 본다 — 순수

withTax(1000, 0.1);   // 1100
  • 화면 그리기 · 파일 쓰기 · 요청 보내기 같은 부수 효과는 없앨 수 없다. 계산은 순수 함수로 하고, 부수 효과는 그 결과를 받아 쓰는 바깥 한 곳에 모은다
  • 인자로 받은 객체 · 배열을 고치지 않는다. 고친 새 값을 돌려준다(아래 불변 데이터)

불변 데이터

원래 값을 바꾸지 않고, 바꾼 복사본을 만든다. 누가 언제 바꿨는지 추적할 일이 없어지고, React · Vue 처럼 "새 값인지" 로 변화를 알아채는 도구와 맞는다.

const sorted = orders.toSorted((a, b) => b.price - a.price);   // sort 와 달리 원래 배열은 그대로
const changed = orders.with(0, { ...orders[0], status: "cancel" });   // 0 번만 바꾼 새 배열
changed[1] === orders[1];          // true — 바뀌지 않은 것은 같이 쓴다

[1, 2, 3, 4].toSpliced(1, 2);      // [1, 4]
[1, 2, 3].toReversed();            // [3, 2, 1]
const next = { ...user, name: "geon" };              // 객체는 펼쳐서 덮어쓴다
const deep = structuredClone(state);                  // 통째로 깊이 복사
원래 배열을 바꾼다 새 배열을 돌려준다
sort toSorted
reverse toReversed
splice toSpliced
arr[i] = v with(i, v)
push [...arr, v]
  • Object.freeze 는 바깥 한 겹만 얼린다. Object.freeze({ tags: ["x"] }).tags.push("y") 는 그대로 된다. 얼린 객체의 속성에 대입하면 strict 모드(모듈) 에서 TypeError 가 난다

배열로 데이터 다루기

반복문 대신 거르기(filter) · 바꾸기(map) · 모으기(reduce) 를 이어서 쓴다. 단계마다 이름이 보이고, 중간 변수가 없다.

const total = orders
  .filter(o => o.status === "paid")
  .map(o => o.price * o.qty)
  .reduce((sum, n) => sum + n, 0);              // 13500

const byCustomer = Object.groupBy(orders, o => o.customer);
// { kim: [주문 1, 3], lee: [주문 2], park: [주문 4] }

const qtyByItem = Object.fromEntries(
  Object.entries(Object.groupBy(orders.filter(o => o.status === "paid"), o => o.item))
    .map(([item, list]) => [item, list.reduce((n, o) => n + o.qty, 0)]),
);
// { 펜: 7, 공책: 1 }

const bySize = Map.groupBy(orders, o => (o.price >= 10000 ? "big" : "small"));   // 키가 문자열이 아니어도 된다
bySize.get("big");                              // [주문 3]

["a b", "c"].flatMap(s => s.split(" "));        // ["a", "b", "c"] — map 하고 한 겹 펴기
  • SQL 로 치면 filter 가 WHERE, map 이 SELECT, Object.groupBy 가 GROUP BY, toSorted 가 ORDER BY 다
  • reduce 안에서 { ...acc, [k]: v } 처럼 매번 복사하면 항목이 많을 때 느려진다. 모으는 값은 reduce 안에서만 쓰는 지역 값이므로 acc[k] = v 로 고쳐도 된다
  • 한 번 돌아 끝나는 일을 메서드 여러 개로 나누면 배열을 여러 번 돈다. 수만 개를 넘지 않으면 읽기 쉬운 쪽을 고른다

고차 함수

함수를 받거나 돌려주는 함수다. 조건 · 키 이름을 바꿔 끼울 수 있게 된다.

const not = pred => (...args) => !pred(...args);           // 조건 뒤집기
const prop = key => obj => obj?.[key];                     // 속성 꺼내는 함수
const byKey = key => (a, b) => String(a[key]).localeCompare(String(b[key]));   // 정렬 비교 함수

const isBlank = s => s.trim() === "";
["a", " ", "b"].filter(not(isBlank));      // ["a", "b"]
orders.map(prop("item"));                  // ["펜", "공책", "가방", "펜"]
orders.toSorted(byKey("customer"));        // kim · kim · lee · park

부분 적용 · 커링

인자 일부를 미리 채운 새 함수를 만든다.

const partial = (fn, ...preset) => (...later) => fn(...preset, ...later);
const greet = (greeting, name) => `${greeting}, ${name}`;
const hello = partial(greet, "Hello");
hello("geon");                             // "Hello, geon"

const log = console.log.bind(console, "[app]");   // bind 로도 앞쪽 인자를 채운다
log("start");                              // [app] start

const won = unit => amount => `${amount.toLocaleString()} ${unit}`;   // 인자를 하나씩 받는다
won("원")(12000);                          // "12,000 원"
  • 커링한 함수는 map 에 바로 넘기기 좋다: prices.map(won("원"))

함수 조립

작은 함수를 이어 붙여 새 함수를 만든다. pipe 는 왼쪽부터, compose 는 오른쪽부터 부른다.

const pipe = (...fns) => x => fns.reduce((v, f) => f(v), x);
const compose = (...fns) => x => fns.reduceRight((v, f) => f(v), x);

const slugify = pipe(
  s => s.trim(),
  s => s.toLowerCase(),
  s => s.replace(/[^\p{L}\d]+/gu, "-"),    // 글자 · 숫자가 아닌 것을 - 로
  s => s.replace(/^-|-$/g, ""),
);
slugify("  Hello, 정규식 World!  ");        // "hello-정규식-world"

pipe(n => n + 1, n => n * 2)(5);           // 12 — (5 + 1) * 2
compose(n => n + 1, n => n * 2)(5);        // 11 — 5 * 2 + 1

조건 하나를 검사하는 함수를 만들고, 여럿을 묶어 검증기로 쓴다. 규칙을 더하고 빼기 쉽다.

const rule = (test, message) => value => (test(value) ? null : message);
const validator = (...rules) => value => rules.map(r => r(value)).filter(Boolean);

const checkPassword = validator(
  rule(s => s.length >= 8, "8 자 이상"),
  rule(s => /\d/.test(s), "숫자 포함"),
  rule(s => /[A-Z]/.test(s), "대문자 포함"),
);

checkPassword("abc");          // ["8 자 이상", "숫자 포함", "대문자 포함"]
checkPassword("Secret123");    // [] — 통과

메모이제이션

순수 함수는 같은 입력에 같은 결과를 내므로, 한 번 계산한 값을 표에 넣어 두고 다시 쓸 수 있다. 만들기 비싼 객체(Intl 포매터 · 정규식) 를 키마다 한 번만 만들 때 쓴다.

function memoize(fn) {
  const cache = new Map();
  return arg => {
    if (!cache.has(arg)) cache.set(arg, fn(arg));
    return cache.get(arg);
  };
}

const formatter = memoize(lang => new Intl.NumberFormat(lang));
formatter("ko").format(1234.5);        // "1,234.5"
formatter("de").format(1234.5);        // "1.234,5"
formatter("ko") === formatter("ko");   // true — 같은 객체를 다시 쓴다
  • 키는 Map 이 같은 값으로 보는 것(원시 값 · 같은 객체) 이어야 한다. 객체 인자는 JSON.stringify 로 키를 만들거나 WeakMap 을 쓴다
  • 표가 끝없이 커질 수 있다. 키 종류가 많으면 크기를 제한한다

재귀

트리 · 중첩 객체처럼 같은 모양이 안에 또 있는 데이터는 재귀로 돈다.

const tree = {
  name: "docs",
  children: [
    { name: "a.md" },
    { name: "img", children: [{ name: "b.png" }, { name: "c.png" }] },
  ],
};

const countFiles = node =>
  node.children ? node.children.reduce((n, c) => n + countFiles(c), 0) : 1;

const paths = (node, base = "") => {
  const p = base ? `${base}/${node.name}` : node.name;
  return node.children ? node.children.flatMap(c => paths(c, p)) : [p];
};

countFiles(tree);   // 3
paths(tree);        // ["docs/a.md", "docs/img/b.png", "docs/img/c.png"]

JavaScript 엔진은 꼬리 재귀를 줄여 주지 않는다. 깊이가 수천을 넘으면 RangeError: Maximum call stack size exceeded 가 난다. 깊이를 모르는 데이터는 스택 배열과 반복문으로 바꾼다.

function allPaths(root) {
  const out = [];
  const stack = [[root, ""]];
  while (stack.length) {
    const [node, base] = stack.pop();
    const p = base ? `${base}/${node.name}` : node.name;
    if (node.children) for (const c of node.children.toReversed()) stack.push([c, p]);
    else out.push(p);
  }
  return out;
}

게으른 계산

제너레이터는 값을 달라고 할 때 하나씩 만든다. 끝이 없는 목록도 표현하고, 필요한 만큼만 계산한다. 이터레이터에는 map · filter · take · toArray 같은 메서드가 있다(Iterator helpers).

function* naturals() {
  let n = 1;
  while (true) yield n++;
}

naturals()
  .filter(n => n % 3 === 0)
  .map(n => n * n)
  .take(4)
  .toArray();                        // [9, 36, 81, 144] — 네 개를 찾으면 멈춘다

orders.values().filter(o => o.price > 2000).take(1).toArray();   // 처음 하나만 찾고 멈춘다
new Set([1, 2, 3]).values().map(x => x * 2).toArray();           // [2, 4, 6]
  • 배열 메서드는 단계마다 배열 전체를 만든다. 이터레이터 메서드는 값 하나씩 모든 단계를 지나가고, take 를 채우면 멈춘다
  • 비동기로 하나씩 오는 것(페이지 나눈 API · 파일 줄) 은 async function* 과 for await 로 돈다
