Tauri 앱은 웹 프로젝트(Vite) 안에 Rust 프로젝트(src-tauri) 를 둔 모양이다. 개발할 때는 Vite 개발 서버의 화면을 창에 띄우고, 빌드할 때는 Vite 가 만든 dist 를 앱 안에 넣는다. 화면에서 Rust 함수(명령) 를 invoke 로 부르고, Rust 는 이벤트로 화면에 알린다.

파일 하는 일
src/ · index.html · vite.config.js 화면. 보통의 Vite 프로젝트다
src-tauri/tauri.conf.json 앱 이름 · 식별자 · 창 · 빌드 명령 · 설치 파일 설정
src-tauri/src/lib.rs 명령 · 상태 · 플러그인을 등록하고 앱을 띄운다
src-tauri/src/main.rs 데스크톱의 시작점. lib.rs 의 run() 을 부른다
src-tauri/Cargo.toml Rust 의존성 (tauri · 플러그인)
src-tauri/capabilities/default.json 화면에서 부를 수 있는 기능(권한)
src-tauri/icons/ 앱 아이콘 
flowchart LR
  W["화면<br/>(OS 웹뷰)"] -- "invoke('greet')" --> R["Rust 코어<br/>lib.rs 명령"]
  R -- "emit('tick')" --> W
  W -- "플러그인 API<br/>(fs · dialog …)" --> C{"capabilities<br/>권한"}
  C -- "허용한 것만" --> R

준비

macOS 는 Xcode Command Line Tools 와 Rust 가 있으면 된다.

xcode-select --install
curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh     # Rust (rustup)
  • Windows 는 Microsoft C++ Build Tools 와 WebView2(Windows 10 · 11 에는 들어 있다), Linux 는 libwebkit2gtk-4.1-dev 같은 패키지가 더 필요하다. Prerequisites 에 OS 마다 정리되어 있다

프로젝트 만들기

npm create tauri-app@latest my-app     # 화면 언어 · 프레임워크(React · Vue · Svelte · Vanilla …) 를 묻는다
cd my-app
npm install
npm run tauri dev                      # Vite 개발 서버 + Rust 빌드 + 창
  • 처음 tauri dev 는 Rust 크레이트 수백 개를 컴파일해 몇 분 걸린다. 다음부터는 바뀐 것만 컴파일한다
  • 화면 코드를 고치면 Vite 가 바로 바꾸고, Rust 코드를 고치면 다시 컴파일해 창을 새로 띄운다
  • 이미 있는 Vite 프로젝트에 붙이려면 npm install -D @tauri-apps/cli 뒤에 npx tauri init 을 한다. 개발 서버 주소 · dist 위치를 묻는다

tauri.conf.json

{
  "productName": "my-app",
  "version": "0.1.0",
  "identifier": "com.example.myapp",
  "build": {
    "beforeDevCommand": "npm run dev",
    "devUrl": "http://localhost:1420",
    "beforeBuildCommand": "npm run build",
    "frontendDist": "../dist"
  },
  "app": {
    "windows": [{ "title": "my-app", "width": 800, "height": 600 }],
    "security": { "csp": null }
  }
}
  • identifier 는 앱을 가려내는 이름이다. 역 도메인(com.회사.앱) 으로 쓰고, 설정 · 데이터 폴더 이름도 이것으로 정해진다
  • devUrl 의 포트는 vite.config.js 의 server.port(1420, strictPort) 와 같아야 한다
  • 창 이름(label) 을 따로 주지 않으면 main 이다. capabilities 의 windows 가 이 이름을 가리킨다

명령

Rust 함수에 #[tauri::command] 를 붙이고 generate_handler! 에 등록하면, 화면에서 invoke("이름", 인자) 로 부른다. 돌려준 값은 JSON 으로 바뀌어 Promise 로 온다.

// src-tauri/src/lib.rs
#[tauri::command]
fn greet(name: &str) -> String {
    format!("Hello, {}!", name)
}

#[tauri::command]
async fn read_note(path: String) -> Result<String, String> {     // Err 는 화면에서 reject
    std::fs::read_to_string(&path).map_err(|e| e.to_string())
}

pub fn run() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![greet, read_note])   // 모든 명령을 한 번에
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
import { invoke } from "@tauri-apps/api/core";

const msg = await invoke("greet", { name: "geon" });              // "Hello, geon!"
try {
  const text = await invoke("read_note", { path: "/nope.txt" });
} catch (e) {
  console.error(e);                                              // "No such file or directory (os error 2)"
}
  • 인자 이름은 Rust 에서 snake_case(file_path), 화면에서 camelCase(filePath) 로 쓴다
  • 오래 걸리는 일은 async fn 으로 만든다. async 가 없는 명령은 메인 스레드에서 돌아 그동안 창이 멈춘다
  • async 명령은 &str 같은 빌린 인자를 받지 못한다. String 으로 받는다
  • 돌려주는 값 · 오류는 serde::Serialize 여야 한다. 표준 오류는 map_err(|e| e.to_string()) 으로 문자열로 바꾼다
  • invoke_handler 를 두 번 부르면 앞의 것이 없어진다. 명령은 generate_handler! 하나에 모두 넣는다
  • 명령을 다른 모듈(commands.rs) 에 두면 pub 를 붙이고 commands::greet 로 등록한다. 화면에서는 그대로 invoke("greet") 다

상태

앱 전체에서 쓰는 값은 manage 로 맡기고, 명령의 State 인자로 받는다. 여러 스레드에서 부르므로 고칠 값은 Mutex 로 감싼다.

use std::sync::Mutex;
use tauri::State;

struct Counter(Mutex<i32>);

#[tauri::command]
fn increment(counter: State<Counter>) -> i32 {
    let mut n = counter.0.lock().unwrap();
    *n += 1;
    *n
}

tauri::Builder::default()
    .manage(Counter(Mutex::new(0)))
    .invoke_handler(tauri::generate_handler![increment])
  • 명령에 app: tauri::AppHandle · window: tauri::WebviewWindow 인자를 더하면 앱 · 부른 창을 받는다

이벤트

Rust 에서 화면으로 먼저 알릴 때는 이벤트를 쓴다.

use tauri::Emitter;

tauri::Builder::default()
    .setup(|app| {
        let handle = app.handle().clone();
        std::thread::spawn(move || {
            for n in 1..=3 {
                std::thread::sleep(std::time::Duration::from_millis(500));
                handle.emit("tick", n).unwrap();          // 모든 창에. 한 창에만은 emit_to("main", …)
            }
        });
        Ok(())
    })
import { listen } from "@tauri-apps/api/event";

const unlisten = await listen("tick", e => console.log(e.payload));   // 1, 2, 3
unlisten();                                                           // 그만 듣기
  • listen 은 Promise 다. await 한 뒤에 unlisten 을 불러야 떼어진다
  • 진행률처럼 한 명령이 값을 여러 번 보내면 이벤트 대신 tauri::ipc::Channel 인자를 쓴다

플러그인과 권한

파일 · 대화 상자 · HTTP 같은 기능은 플러그인으로 넣는다. tauri add 가 Rust · npm 패키지를 설치하고 lib.rs 와 capabilities 에 등록한다.

npm run tauri add fs          # dialog · http · store · shell · notification …

화면에서 플러그인 API 를 부를 수 있는지는 capabilities/default.json 의 permissions 가 정한다. 적지 않은 것은 막힌다.

{
  "identifier": "default",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "fs:default",
    {
      "identifier": "fs:allow-read-text-file",
      "allow": [{ "path": "$HOME/notes/**" }]
    }
  ]
}
import { readTextFile, BaseDirectory } from "@tauri-apps/plugin-fs";

await readTextFile("notes/a.txt", { baseDir: BaseDirectory.Home });   // 허용한 곳 — 읽힌다
await readTextFile("secret.txt", { baseDir: BaseDirectory.Home });    // 막힌다 (reject)
  • fs:default 는 앱 전용 폴더($APPDATA · $APPCONFIG …) 만 연다. 다른 곳은 위처럼 명령마다 allow 로 범위를 준다
  • 직접 만든 명령(invoke) 은 권한 없이 부른다. 파일을 넓게 다뤄야 하면 플러그인 범위를 넓히기보다 명령으로 만들어 Rust 에서 검사한다
  • 권한 이름은 src-tauri/gen/schemas/ 에 만들어지는 스키마에 있다. 에디터가 $schema 로 자동 완성한다

개발자 도구

React 의 StrictMode 처럼 개발 모드에서 effect 가 두 번 돌면 invoke 도 두 번 불린다. tauri dev 로 띄운 창에서 오른쪽 클릭 → "요소 검사"(macOS) 로 웹 개발자 도구를 연다. Rust 의 println! 은 tauri dev 를 띄운 터미널에 나온다.
