훅은 use 로 시작하는 함수로, 컴포넌트에 상태 · 그린 뒤 할 일 · DOM 참조 같은 것을 붙인다. 컴포넌트의 맨 위에서만 부른다. 조건 · 반복문 · 중첩 함수 안에서 부르면 순서가 어긋나 오류가 난다.

useState

컴포넌트가 기억하는 값이다. 바꾸면 컴포넌트를 다시 그린다.

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
  • 이전 값으로 계산할 때는 함수를 넘긴다: setCount(c => c + 1). 한 번에 여러 번 바꿔도 맞게 쌓인다
  • 객체 · 배열은 고치지 않고 새로 만들어 넣는다: setUser({ ...user, name }) · setList([...list, item]) · setList(list.filter(x => x.id !== id)). 고치기만 하면 같은 객체라서 다시 그리지 않는다
  • 바꾼 값은 다음 그릴 때 보인다. setCount(1) 바로 뒤의 count 는 아직 앞 값이다
  • props · 상태로 계산되는 값은 상태로 두지 않고 그릴 때 계산한다: const total = items.length

useEffect

그린 뒤에 할 일(데이터 받기 · 구독 · 타이머) 을 둔다. 두 번째 인자의 값이 바뀔 때만 다시 돈다.

import { useEffect, useState } from "react";

function User({ id }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    fetch(`/api/users/${id}`, { signal: controller.signal })
      .then(res => res.json())
      .then(setUser)
      .catch(() => {});
    return () => controller.abort();     // 정리 — id 가 바뀌거나 사라질 때
  }, [id]);                              // id 가 바뀔 때만

  return user ? <p>{user.name}</p> : <p>읽는 중</p>;
}
  • [] 를 주면 처음 한 번만 돈다. 빼면 그릴 때마다 돈다
  • 개발 모드(StrictMode) 에서는 확인하려고 두 번 돈다. 정리 함수가 맞으면 문제없다
  • effect 안에서 쓰는 props · 상태는 모두 두 번째 인자에 넣는다. 빼면 앞 값을 계속 쓴다
  • 이벤트 때문에 할 일(저장 버튼 → 요청) 은 effect 가 아니라 이벤트 처리 함수에서 한다

useRef

다시 그려도 남는 값이다. 바꿔도 다시 그리지 않는다. DOM 요소를 받을 때도 쓴다.

import { useEffect, useRef } from "react";

function Search() {
  const input = useRef(null);
  useEffect(() => input.current.focus(), []);
  return <input ref={input} />;
}

DOM 을 직접 다루는 라이브러리(D3 · 차트 · 에디터) 는 ref 로 DOM 을 받아 effect 안에서 붙이고, 정리 함수에서 뗀다.

function Chart({ data }) {
  const ref = useRef(null);
  useEffect(() => {
    const chart = createChart(ref.current, data);   // 라이브러리가 ref.current 안을 그린다
    return () => chart.destroy();
  }, [data]);
  return <div ref={ref} />;
}
  • 타이머 id · 앞 값처럼 화면에 안 보이는 값을 둘 때도 쓴다: timer.current = setInterval(…)
  • 자식 컴포넌트의 DOM 을 받으려면 자식이 ref 를 props 로 받아 요소에 단다(19+). 예전에는 forwardRef 로 감쌌다

useContext

위에서 준 값을 아래 어디서든 받는다. props 로 몇 단계를 내려 주지 않아도 된다.

import { createContext, useContext, useState } from "react";

const ThemeContext = createContext("light");          // 없을 때 기본값

function App() {
  const [theme, setTheme] = useState("dark");
  return (
    <ThemeContext value={theme}>                      {/* 19+. 예전에는 ThemeContext.Provider */}
      <Toolbar />
      <button onClick={() => setTheme(t => t === "dark" ? "light" : "dark")}>바꾸기</button>
    </ThemeContext>
  );
}

function Button() {
  const theme = useContext(ThemeContext);
  return <button className={theme}>저장</button>;
}
  • 값이 바뀌면 그 Context 를 읽는 컴포넌트가 모두 다시 그려진다. 자주 바뀌는 값과 드물게 바뀌는 값은 Context 를 나눈다
  • 앱 전체 상태가 커지면 Zustand · Redux Toolkit 같은 상태 관리 라이브러리를 쓴다

커스텀 훅

여러 컴포넌트에서 쓰는 상태와 effect 를 함수로 뺀다. 이름은 use 로 시작한다.

function useFetch(url) {
  const [data, setData] = useState(null);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setData(null);
    fetch(url, { signal: controller.signal })
      .then(res => res.json())
      .then(setData)
      .catch(e => e.name !== "AbortError" && setError(e));
    return () => controller.abort();
  }, [url]);

  return { data, error };
}

function User({ id }) {
  const { data: user, error } = useFetch(`/api/users/${id}`);
  …
}
  • 상태는 나누어 쓰지 않는다. 훅을 부르는 컴포넌트마다 따로 생긴다
  • 데이터 받기가 많으면 TanStack Query 같은 라이브러리가 캐시 · 다시 받기 · 로딩 상태를 맡는다

성능

부모가 다시 그려지면 자식도 모두 다시 그려진다. 대부분 빠르므로, 느린 것을 찾은 뒤에 줄인다.

import { memo, useMemo, useCallback } from "react";

const Row = memo(function Row({ item, onRemove }) { … });     // props 가 같으면 건너뛴다

const sorted = useMemo(() => [...items].sort(byName), [items]); // items 가 바뀔 때만 계산
const remove = useCallback(id => setItems(l => l.filter(x => x.id !== id)), []);   // 같은 함수를 계속 넘긴다

<Row item={item} onRemove={remove} />
  • memo 자식에 객체 · 함수를 새로 만들어 넘기면 매번 달라 소용이 없다. useMemo · useCallback 으로 함께 쓴다
  • React Compiler 를 켜면 이것을 컴파일러가 알아서 붙인다
  • 무엇이 다시 그려지는지는 React Developer Tools 의 Profiler 로 본다
