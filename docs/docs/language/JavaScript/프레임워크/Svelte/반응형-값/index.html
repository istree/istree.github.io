Svelte 5 는 runes 로 반응형 값을 만든다. $state 로 둔 값이 바뀌면 그 값을 쓰는 화면 · $derived · $effect 만 다시 돈다. 컴파일러가 읽고 쓰는 곳을 찾아 코드를 만들므로, 값은 보통 변수처럼 읽고 대입한다.

$state

<script>
  let count = $state(0);
  let user = $state({ name: "geon", tags: ["a"] });
</script>

<button onclick={() => count++}>{count}</button>
<button onclick={() => user.tags.push("b")}>{user.tags.length}</button>   <!-- 안쪽을 바꿔도 된다 -->
  • 객체 · 배열을 $state 에 넣으면 안쪽까지 반응형이 된다. push · user.name = … 도 화면에 바로 나온다. React 처럼 새 객체를 만들 필요가 없다
  • 큰 목록을 통째로만 바꾸면 $state.raw(list) 로 둔다. 안쪽을 지켜보지 않아 빠르고, 바꿀 때는 list = [...list, x] 처럼 새 값을 대입한다
  • 반응형 객체는 Proxy 다. console.log · structuredClone · 외부 라이브러리에 넘길 때는 $state.snapshot(user) 로 보통 객체를 만든다

$derived

다른 값에서 계산한 값이다. 쓰는 값이 바뀌면 다시 계산한다.

<script>
  let count = $state(0);
  const doubled = $derived(count * 2);

  let todos = $state([]);
  const summary = $derived.by(() => {           // 여러 줄로 계산할 때
    const done = todos.filter(t => t.done).length;
    return `${done} / ${todos.length}`;
  });
</script>
  • $derived 안에서는 값을 바꾸지 않는다. 계산만 한다
  • 예전에는 $: doubled = count * 2 로 썼다

$effect

값이 바뀔 때 화면 밖의 일(타이머 · 구독 · 캔버스 그리기 · 로그) 을 한다. 화면에 붙은 뒤 처음 돌고, 안에서 읽은 $state 가 바뀌면 다시 돈다. 돌려준 함수는 다시 돌기 전 · 컴포넌트가 사라질 때 불린다.

<script>
  let seconds = $state(0);
  let running = $state(true);

  $effect(() => {
    if (!running) return;
    const id = setInterval(() => seconds++, 1000);
    return () => clearInterval(id);          // 정리
  });
</script>
  • 다른 값을 계산하려고 $effect 를 쓰지 않는다. $derived 가 맞다
  • 안에서 읽기만 하고 다시 돌 이유로 삼지 않을 값은 untrack(() => …) 로 감싼다 (import { untrack } from "svelte")
  • 화면이 그려지기 전에 돌아야 하면(스크롤 자리 맞추기) $effect.pre 를 쓴다

같은 값을 읽고 쓰면 끝없이 돈다

$effect 안에서 읽은 값을 그 안에서 바꾸면, 바뀐 것을 보고 다시 돌기를 되풀이한다. Svelte 가 멈추고 effect_update_depth_exceeded 오류를 낸다. 개발 모드에서는 Maximum update depth exceeded. This typically indicates that an effect reads and writes the same piece of state 가 함께 나온다.

let log = $state([]);
$effect(() => {
  log.push(`count=${count}`);      // log 를 읽고(push 가 length 를 읽는다) 쓴다 — 끝없이 돈다
});

$effect(() => {
  const c = count;                 // count 만 지켜본다
  untrack(() => log.push(`count=${c}`));
});

데이터 받기

값이 바뀔 때마다 서버에서 받아 오려면 $effect 안에서 부르고, 앞의 요청은 정리 함수에서 취소한다. 빨리 바뀌어도 마지막 것만 남는다.

<script>
  let { userId } = $props();
  let user = $state(null);

  $effect(() => {
    const ctrl = new AbortController();
    fetch(`/api/users/${userId}`, { signal: ctrl.signal })
      .then(r => r.json())
      .then(data => (user = data))
      .catch(() => {});                    // 취소된 요청
    return () => ctrl.abort();             // userId 가 또 바뀌면 앞의 요청을 취소
  });
</script>

<p>{user?.name ?? "불러오는 중"}</p>
  • 한 번만 받으면 {#await} 블록으로 쓰는 편이 짧다
  • SvelteKit 에서는 쪽마다 +page.js 의 load 함수에서 받는다

예전에는

Svelte 3 · 4 는 컴포넌트의 맨 위 let 이 그대로 반응형이었다.

<script>
  let count = 0;                    // Svelte 5: let count = $state(0)
  $: doubled = count * 2;           // $derived(count * 2)
  $: console.log(count);            // $effect(() => console.log(count))
  $: if (count > 10) count = 10;    // 값 바꾸기 — Svelte 5 에서는 이벤트 처리 함수에서
</script>
  • 배열은 items.push(x) 만으로는 화면이 바뀌지 않아 items = [...items, x] 나 items = items 를 덧붙였다. Svelte 5 의 $state 배열은 push 만으로 된다
  • 한 파일에 runes 를 하나라도 쓰면 그 컴포넌트는 Svelte 5 방식(runes 모드) 으로 컴파일된다. 옛 문법을 섞으면 $: is not allowed in runes mode, use `$derived` or `$effect` instead 로 빌드가 멈춘다
