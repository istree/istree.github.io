Node 에 들어 있는 모듈 가운데 스크립트에서 자주 쓰는 것을 모았다. 파일 · 경로 · 다른 프로그램 실행 · 이벤트 · HTTP 요청은 패키지 없이 한다. 내장 모듈은 node:fs 처럼 node: 를 붙여 가져온다. 같은 이름의 npm 패키지와 헷갈리지 않는다.

파일

fs/promises 의 함수는 Promise 를 돌려준다. await 로 쓴다.

import { readFile, writeFile, appendFile, mkdir, rm, cp, rename } from "node:fs/promises";

await mkdir("out/logs", { recursive: true });           // 중간 폴더까지, 있어도 오류 없음
await writeFile("out/a.txt", "hello\n");                 // 없으면 만들고, 있으면 덮는다
await appendFile("out/a.txt", "world\n");
const text = await readFile("out/a.txt", "utf8");        // "hello\nworld\n" — utf8 을 빼면 Buffer

await writeFile("out/data.json", JSON.stringify({ n: 1 }, null, 2));
const data = JSON.parse(await readFile("out/data.json", "utf8"));

await cp("src", "backup", { recursive: true });          // 폴더 복사
await rename("out/a.txt", "out/b.txt");                  // 이름 바꾸기 · 옮기기
await rm("backup", { recursive: true, force: true });    // rm -rf — 없어도 오류 없음
  • 인코딩을 주지 않으면 Buffer 가 온다. 글자는 늘 "utf8" 을 준다
  • 상대 경로는 스크립트 위치가 아니라 실행한 폴더(process.cwd()) 기준이다. 스크립트 옆의 파일은 import.meta.dirname 으로 찾는다(아래 경로)
  • 동기 함수(readFileSync …) 는 node:fs 에 있다. 짧은 스크립트 · 시작할 때 설정 읽기에는 써도 된다

폴더 돌기

import { readdir, stat, glob } from "node:fs/promises";
import { existsSync } from "node:fs";
import path from "node:path";

await readdir("src");                                    // [ 'a', 'three.txt', 'two.md' ]

const entries = await readdir("src", { recursive: true, withFileTypes: true });
entries.filter(e => e.isFile()).map(e => path.join(e.parentPath, e.name));
// [ 'src/three.txt', 'src/two.md', 'src/a/one.md' ]

await Array.fromAsync(glob("src/**/*.md"));              // [ 'src/two.md', 'src/a/one.md' ]

const s = await stat("out/b.txt");                       // s.size · s.isFile() · s.isDirectory() · s.mtime
existsSync("out");                                       // 있는지만 — true / false
  • glob 은 async 이터레이터다. for await (const f of glob("**/*.md", { exclude: ["node_modules/**"] })) 처럼 돈다
  • 있는지 보고 나서 여는 대신, 바로 열고 ENOENT 를 잡는 편이 낫다. 그 사이에 파일이 바뀔 수 있다

경로

import path from "node:path";

const f = "/Users/geon/notes/2026/a.test.md";
path.basename(f);                 // a.test.md
path.basename(f, ".md");          // a.test
path.extname(f);                  // .md
path.dirname(f);                  // /Users/geon/notes/2026
path.parse(f);                    // { root, dir, base, ext, name }

path.join("src", "../dist", "app.js");          // dist/app.js — 붙이고 정리
path.resolve("dist");                           // 실행한 폴더 기준 절대 경로
path.relative("/Users/geon/notes", f);          // 2026/a.test.md

path.join(import.meta.dirname, "data.json");    // 이 스크립트 옆의 파일
  • 경로는 + 로 붙이지 않고 path.join 을 쓴다. Windows 의 \ 도 맞춰 준다
  • import.meta.dirname · import.meta.filename 은 CommonJS 의 __dirname · __filename 이다
  • import.meta.url 은 file:///…/p.js 꼴이다. 경로로는 fileURLToPath(import.meta.url), 경로를 URL 로는 pathToFileURL("/tmp/a b.txt").href(file:///tmp/a%20b.txt) 로 바꾼다 (node:url)

다른 프로그램 실행

결과를 받을 때는 execFile, 출력을 흘려 보낼 때는 spawn 을 쓴다.

import { execFile, exec, spawn } from "node:child_process";
import { promisify } from "node:util";

const run = promisify(execFile);
const { stdout } = await run("git", ["--version"]);      // "git version 2.39.5 …\n"

try {
  await run("ls", ["nope"]);
} catch (e) {
  console.log(e.code, e.stderr);                          // 1 "ls: nope: No such file or directory\n"
}

const sh = promisify(exec);
await sh("echo $HOME | wc -c");                           // 셸로 실행 — 파이프 · 변수가 된다

const child = spawn("npm", ["install"], { stdio: "inherit" });   // 출력을 그대로 내 터미널에
child.on("close", code => console.log("exit", code));
  • execFile 은 셸을 거치지 않아 인자에 공백 · 따옴표가 있어도 안전하다. 사용자 입력이 들어가면 exec 을 쓰지 않는다
  • 0 이 아닌 종료 코드는 reject 된다. e.code 가 종료 코드다
  • 출력이 크면(기본 1 MB 넘게) execFile 은 멈춘다. maxBuffer 를 늘리거나 spawn 을 쓴다
  • Windows 에서 npm · npx 같은 .cmd 를 spawn 하려면 { shell: true } 를 준다

OS 정보

import os from "node:os";

os.homedir();             // /Users/geon
os.platform();            // darwin · linux · win32
os.arch();                // arm64 · x64
os.cpus().length;         // 8
os.totalmem();            // 바이트
os.tmpdir();              // 임시 폴더
os.EOL;                   // 줄바꿈 — "\n" · Windows 는 "\r\n"

이벤트

EventEmitter 를 상속하면 on 으로 받고 emit 으로 낸다. Node 의 스트림 · 서버 · 프로세스가 모두 이것이다.

import { EventEmitter, once } from "node:events";

class Job extends EventEmitter {
  run() {
    this.emit("progress", 50);
    setTimeout(() => this.emit("done", { ok: true }), 10);
  }
}

const job = new Job();
job.on("progress", p => console.log("progress", p));      // 올 때마다
job.once("done", r => console.log("done", r));            // 한 번만
job.run();

const [result] = await once(job, "done");                 // 이벤트를 Promise 로 기다린다
  • "error" 이벤트를 받는 쪽이 없으면 emit("error", e) 가 예외를 던진다. 오류를 낼 수 있는 객체에는 on("error", …) 을 단다
  • 떼어 낼 때는 off(이름, 함수) 에 같은 함수를 준다

HTTP 요청

브라우저와 같은 fetch 가 전역에 있다.

const res = await fetch("https://api.github.com/repos/nodejs/node");
if (!res.ok) throw new Error(`HTTP ${res.status}`);       // 404 · 500 은 reject 되지 않는다
const repo = await res.json();

await fetch("https://example.com/api", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ a: 1 }),
  signal: AbortSignal.timeout(5000),                       // 5 초가 지나면 TimeoutError
});
  • 응답을 받았으면 상태 코드가 무엇이든 resolve 된다. res.ok(200–299) 를 꼭 본다
  • 연결하지 못하면 TypeError: fetch failed 로 reject 되고, 까닭은 e.cause.code 에 있다 (ECONNREFUSED · ENOTFOUND …)

큰 파일 흘려 보내기

파일을 통째로 읽지 않고 조금씩 읽어 바꾸고 쓴다. pipeline 이 끝날 때까지 기다리고, 중간에 오류가 나면 모두 닫는다.

import { createReadStream, createWriteStream } from "node:fs";
import { pipeline } from "node:stream/promises";
import { createGzip } from "node:zlib";
import { Readable } from "node:stream";

await pipeline(createReadStream("big.txt"), createGzip(), createWriteStream("big.txt.gz"));   // gzip

const res = await fetch("https://nodejs.org/dist/index.json");
await pipeline(Readable.fromWeb(res.body), createWriteStream("index.json"));                 // 내려받기
  • a.pipe(b) 는 오류가 나도 스트림을 닫지 않는다. pipeline 을 쓴다
