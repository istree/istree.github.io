노드 버전 매니저다. Node 를 여러 버전 설치하고, 터미널마다 쓸 버전을 바꾼다. 맥 · 리눅스용이고, 윈도우는 nvm-windows 를 쓴다.

Node 는 홈 폴더(~/.nvm/versions/node/) 에 설치된다. 전역 패키지(npm install -g) 도 버전마다 따로 설치되므로 sudo 가 필요 없다.

설치

설치 스크립트가 ~/.nvm 에 내려받고, ~/.zshrc 에 불러오는 줄을 더한다. 터미널을 새로 열면 nvm 명령이 생긴다.

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.41.0/install.sh | bash
  • 최신 버전 번호는 nvm-sh/nvm 의 README 에서 확인한다

Node 설치 · 바꾸기

nvm install --lts            # 최신 LTS 를 설치하고 쓴다
nvm install 26               # 26 의 최신을 설치
nvm install node             # 최신 버전 (LTS 가 아닐 수 있다)

nvm use 24                   # 이 터미널에서만 24 를 쓴다
nvm alias default 26         # 새 터미널의 기본 버전
nvm alias default lts/*      # 늘 최신 LTS 를 기본으로

nvm ls                       # 설치한 버전 · 기본값
nvm ls-remote --lts          # 설치할 수 있는 LTS
nvm current                  # 지금 쓰는 버전
nvm which 24                 # 그 버전의 node 경로
nvm uninstall 18
$ nvm ls
       v18.20.8 *
->     v24.13.0 *
       v26.13.0 *
default -> lts/* (-> v26.13.0 *)
  • nvm use 는 그 터미널에만 적용된다. 새 터미널은 default 로 시작한다
  • 버전을 확인할 때는 node -v && npm -v 를 실행한다

프로젝트마다 버전 정하기

프로젝트 맨 위에 .nvmrc 를 두면 그 폴더에서 nvm use · nvm install 이 그 버전을 쓴다.

echo "26" > .nvmrc
nvm use                      # Now using node v26.13.0 (npm v11.20.0)
  • package.json 의 engines 와 함께 둔다. .nvmrc 는 nvm 이, engines 는 npm 이 읽는다

업그레이드

nvm 자체를 새 버전으로 올릴 때는 설치 명령을 새 버전 번호로 다시 실행한다. 설치한 Node 는 그대로 남는다.

Node 를 새 버전으로 올리면서 전역 패키지를 옮긴다.

nvm install --lts --reinstall-packages-from=current

Apple Silicon 에서 x64 Node

Apple Silicon 용(arm64) Node 는 16 부터 있다. x64 용 네이티브 모듈만 있는 옛 패키지를 써야 할 때는 Rosetta 셸에서 x64 Node 를 설치한다.

arch -x86_64 zsh             # 이 셸을 x64 로
nvm install 20               # x64 Node 가 설치된다
node -p process.arch         # x64
exit                         # arm64 셸로 돌아온다
  • 16 아래는 arm64 판이 없다. nvm 은 14.17 아래와 15 를 알아서 x64 판으로 받고(Rosetta 가 있어야 한다), 14.17 이상의 14 는 소스에서 컴파일하므로 오래 걸린다. 14 는 위처럼 x64 셸에서 설치하는 편이 빠르다
  • 지금 쓰는 Node 의 아키텍처는 node -p process.arch 로 본다 (arm64 · x64)
  • 같은 버전 번호를 arm64 · x64 둘 다 설치할 수는 없다. 하나를 지우고 설치한다
