Node 의 패키지 매니저다. Node 로 개발한 프로그램(패키지) 을 내려받고, 버전을 맞추고, 배포한다.

Node 를 설치하면 함께 설치된다. nvm 으로 Node 를 설치하면 따로 설치할 필요가 없다.

설치

리눅스에서 nvm 없이 Node · npm 을 깔 때는 NodeSource 저장소를 쓴다. nodesource/distributions 에 배포판별 설명이 있다.

LTS 설치 예

# 우분투 · 데비안
curl -fsSL https://deb.nodesource.com/setup_lts.x -o nodesource_setup.sh
sudo -E bash nodesource_setup.sh
sudo apt-get install -y nodejs
  • 버전을 정하려면 setup_lts.x 대신 setup_22.x 처럼 쓴다

자주 쓰는 명령

npm init -y                  # package.json 만들기
npm install                  # package.json 의 의존성 설치 (npm i)
npm install lodash           # 의존성 추가 → dependencies
npm install -D vite          # 개발용 추가 → devDependencies
npm install -g serve         # 전역 설치
npm uninstall lodash
npm ci                       # package-lock.json 그대로 깨끗이 설치 (CI · 배포용)

npm run build                # package.json 의 scripts.build 실행
npm start                    # start · test 는 run 을 빼도 된다
npm test

npm outdated                 # 새 버전이 나온 패키지
npm update                   # 범위(^ · ~) 안에서 올리기
npm ls lodash                # 어디서 쓰는지 의존성 트리
npm audit fix                # 알려진 보안 문제 고치기
  • package-lock.json 은 저장소에 같이 올린다. 모두가 같은 버전을 설치한다
  • 버전 범위: ^1.2.3 은 1.x.x 안에서, ~1.2.3 은 1.2.x 안에서 올린다
  • npm run 은 pretest · posttest 처럼 앞뒤 스크립트도 돌린다. node --run test 는 그것 없이 바로 돌려 더 빨리 뜬다

package.json

npm init -y 가 만든 파일에 자주 더하는 필드다.

{
  "name": "my-lib",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "dev": "node --watch src/index.js",
    "build": "vite build",
    "test": "node --test"
  },
  "exports": {
    ".": { "import": "./dist/index.js", "require": "./dist/index.cjs" },
    "./utils": "./dist/utils.js"
  },
  "bin": { "my-lib": "./bin/cli.js" },
  "engines": { "node": ">=22" },
  "files": ["dist", "bin"]
}
필드 하는 일
type .js 를 ES 모듈(module) 로 읽을지 CommonJS(commonjs) 로 읽을지. npm init -y 는 "commonjs" 를 넣는다 — import 를 쓰면 "module" 로 바꾼다
scripts npm run 이름 으로 돌릴 명령. node_modules/.bin 의 명령(vite …) 을 npx 없이 쓴다
exports 가져갈 수 있는 경로. import · require 에 다른 파일을 준다. 적지 않은 경로는 막힌다
bin 설치하면 생기는 명령. npx my-lib · 전역 설치 뒤 my-lib 로 실행한다. 파일 첫 줄에 #!/usr/bin/env node 를 둔다
engines 필요한 Node 버전. 맞지 않으면 설치할 때 npm warn EBADENGINE Unsupported engine 이 나온다 (멈추지는 않는다)
files npm publish 로 올릴 파일
  • exports 가 있으면 my-lib/dist/secret.js 처럼 적지 않은 경로를 가져올 때 Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: Package subpath './dist/secret.js' is not defined by "exports" 가 난다
  • 옛 패키지의 main 은 exports 의 "." 과 같은 일을 한다. 둘 다 있으면 exports 를 따른다

git 저장소에 있는 모듈 설치

npm install git+https://github.com/your/repo.git
npm install github:your/repo#v1.0.0      # 태그 · 브랜치 지정

npmjs

npmjs.com 은 npm 의 저장소다. 공개 패키지는 무료이고, 비공개 패키지는 유료다.

npm에 패키지 배포 준비

npmjs 는 배포할 때 package.json 의 내용으로 패키지 페이지를 만든다. 최소한 다음 항목은 채우는 것이 좋다.

{
  "name": "my-package",
  "version": "1.0.0",
  "description": "my project",
  "author": "my name",
  "license": "MIT",
  "repository": {
    "type": "git",
    "url": "https://github.com/my/repo"
  },
  "keywords": ["any", "words"],
  "files": ["dist"]
}
  • files 에 적은 것만 올라간다. 빼면 .npmignore · .gitignore 에 없는 파일이 모두 올라간다. npm pack --dry-run 으로 미리 본다
  • README.md 에 패키지의 사용법 · 예제를 적는다. npmjs 패키지 페이지의 본문이 된다

npm에 패키지 배포

계정이 있어야 한다. npmjs.com 에서 가입한다.

배포할 패키지 디렉토리에서 로그인한다.

npm login

@scope/name 처럼 범위가 붙은 패키지는 기본이 비공개라서, 무료 사용자는 오류가 난다. 공개로 올린다.

npm publish --access=public

npm 패키지 갱신

내용을 고쳐 같은 버전으로 다시 npm publish 하면 오류가 난다. 다시 올릴 때는 늘 버전을 올린다.

npm version patch     # 1.0.0 → 1.0.1 (minor · major 도 있다). git 태그도 만든다
npm publish

pnpm · yarn

npm 대신 쓰는 패키지 매니저다. package.json 은 같고, 잠금 파일 · node_modules 모양이 다르다.

  • pnpm — 패키지를 컴퓨터에 한 벌만 두고 프로젝트에는 링크를 건다. 설치가 빠르고 디스크를 덜 쓴다. package.json 에 적지 않은 패키지는 가져오지 못한다(npm 은 우연히 된다)
  • yarn — 1.x(classic) 와 2 판 이후(berry) 가 다르다. 지금 판은 4 이고 node_modules 없이 설치하는 방식(Plug'n'Play) 이 기본이다
npm pnpm yarn
npm install pnpm install yarn
npm install lodash pnpm add lodash yarn add lodash
npm install -D vite pnpm add -D vite yarn add -D vite
npm uninstall lodash pnpm remove lodash yarn remove lodash
npm run build pnpm build yarn build
npx serve pnpm dlx serve yarn dlx serve
package-lock.json pnpm-lock.yaml yarn.lock 
npm install -g pnpm           # pnpm 설치
pnpm --version                # 12.18.0
  • 한 프로젝트에서는 하나만 쓴다. 잠금 파일이 둘 생기면 하나를 지운다
  • package.json 의 "packageManager": "pnpm@12.18.0" 에 쓰는 도구를 적어 둔다
  • Node 24 까지 들어 있던 Corepack(pnpm · yarn 을 버전에 맞춰 띄우는 도구) 은 Node 25 부터 빠졌다. 쓰려면 npm install -g corepack 으로 설치한다
