Node 로 명령줄 스크립트를 짤 때 쓰는 것을 모았다. 인자 · 환경 변수 · 입력 · 종료 코드는 모두 process 와 내장 모듈로 하고, 패키지를 설치하지 않는다. TypeScript 파일도 그대로 실행한다.

실행

node app.js                 # 파일 실행
node -e 'console.log(1+1)'  # 한 줄 실행
node -p 'process.arch'      # 실행하고 결과를 출력 — arm64
node                        # REPL. .exit 또는 Ctrl+D 로 나간다
  • 모듈은 ES 모듈(import) 로 쓴다. package.json 에 "type": "module" 을 두거나 확장자를 .mjs 로 한다. 둘 다 없어도 import 가 있으면 ES 모듈로 다시 읽지만 경고가 나온다
  • 파일 맨 위의 await 는 ES 모듈에서 그대로 된다. async 함수로 감싸지 않는다

shebang

첫 줄에 #!/usr/bin/env node 를 두고 실행 권한을 주면 node 없이 실행한다.

#!/usr/bin/env node
console.log("hello");
chmod +x greet.js
./greet.js
  • npm 패키지의 명령으로 내려면 package.json 의 bin 에 적는다

인자

process.argv 의 앞 둘은 node 와 스크립트 경로다. 옵션은 util.parseArgs 로 읽는다.

#!/usr/bin/env node
import { parseArgs } from "node:util";

const { values, positionals } = parseArgs({
  options: {
    name: { type: "string", short: "n", default: "world" },
    loud: { type: "boolean", short: "l" },
    tag:  { type: "string", multiple: true },        // --tag a --tag b
  },
  allowPositionals: true,                            // 옵션이 아닌 인자도 받는다
});

let msg = `Hello, ${values.name}!`;
if (values.loud) msg = msg.toUpperCase();
console.log(msg, values.tag ?? [], positionals);
$ ./greet.js -n geon --loud --tag a --tag b x y
HELLO, GEON! [ 'a', 'b' ] [ 'x', 'y' ]
  • 모르는 옵션이 오면 TypeError [ERR_PARSE_ARGS_UNKNOWN_OPTION]: Unknown option '--nope' 을 던진다. try 로 받아 e.message 를 보여 주고 process.exit(2) 로 끝낸다
  • strict: false 를 주면 모르는 옵션도 받아 values 에 넣는다
  • 하위 명령 · 도움말 출력까지 필요하면 commander 를 쓴다

환경 변수

process.env 에 있다. 값은 늘 문자열이다.

const port = Number(process.env.PORT ?? 3000);

.env 파일은 --env-file 로 읽는다. dotenv 패키지가 필요 없다.

# .env
API_URL=https://api.example.com
PORT=3000
QUOTED="a b"            # 따옴표 안의 공백도 된다
node --env-file=.env app.js
node --env-file=.env --env-file=.env.local app.js   # 뒤의 것이 앞의 것을 덮는다
node --env-file-if-exists=.env.local app.js         # 없어도 멈추지 않는다
  • 파일이 없으면 node: .env: not found 로 멈춘다. 없을 수 있는 파일은 --env-file-if-exists 로 읽는다
  • 이미 셸에 있는 변수는 덮지 않는다
  • 코드에서 읽으려면 process.loadEnvFile(".env"), 문자열을 나누기만 하려면 util.parseEnv("A=1\nB=2") 를 쓴다

입력

파이프로 들어온 내용을 통째로 읽는다.

import { text } from "node:stream/consumers";

const input = await text(process.stdin);
process.stdout.write(input.toUpperCase());
$ echo hello | node upper.js
HELLO

한 줄씩 읽을 때는 readline 을 쓴다. 큰 파일도 메모리에 다 올리지 않는다.

import { createInterface } from "node:readline";

let n = 0;
for await (const line of createInterface({ input: process.stdin })) n++;
console.log(`${n} lines`);

사용자에게 물을 때는 readline/promises 의 question 을 쓴다.

import { createInterface } from "node:readline/promises";

const rl = createInterface({ input: process.stdin, output: process.stdout });
const name = await rl.question("이름? ");
rl.close();                                     // 닫지 않으면 프로세스가 끝나지 않는다
console.log(`안녕, ${name}`);

종료 코드

할 일이 모두 끝나면 프로세스가 알아서 끝나고 0 을 돌려준다.

process.exitCode = 3;      // 끝날 때 3 — 남은 출력 · 일을 마치고 끝난다
process.exit(2);           // 바로 끝낸다 — 쓰는 중인 출력이 잘릴 수 있다
  • 잡지 않은 예외와 처리하지 않은 Promise 거부(reject) 는 오류를 출력하고 1 로 끝난다
  • 보통은 process.exitCode 를 쓰고, 더 진행하면 안 될 때만 process.exit() 를 부른다

Ctrl+C 를 받아 정리하고 끝낸다.

process.on("SIGINT", () => {
  console.log("bye");
  process.exit(130);       // 128 + 신호 번호(2) — 셸의 관례
});

고칠 때마다 다시 실행

node --watch app.js                   # app.js 와 import 한 파일이 바뀌면 다시 실행
node --watch-path=src app.js          # 이 폴더를 지켜본다
run 540
Completed running 'app.js'. Waiting for file changes before restarting...
Restarting 'app.js'
run 757
  • nodemon 이 하던 일이다. 서버를 띄우는 스크립트에 쓴다

TypeScript 실행

.ts 파일을 플래그 없이 실행한다. Node 는 타입 표기를 지우고(type stripping) 돌릴 뿐, 타입을 검사하지 않는다.

// util.ts
export interface User { name: string; age: number }
export function hello(u: User): string { return `${u.name} (${u.age})`; }

// main.ts — node main.ts
import { hello, type User } from "./util.ts";      // 확장자 .ts 까지 쓴다
console.log(hello({ name: "geon", age: 40 } satisfies User));
  • const n: number = "a" 도 그대로 실행된다. 검사는 tsc --noEmit 으로 따로 한다
  • 지워서 없어지는 문법만 된다. enum · namespace · 생성자의 private x 처럼 JavaScript 코드를 만들어야 하는 문법은 오류가 난다
  • 타입만 가져오는 import 는 import type · { type User } 로 쓴다
  • node_modules 안의 .ts 는 실행하지 않는다. 패키지는 빌드한 .js 로 낸다
  • 에디터 · tsc 가 같은 규칙을 지키게 tsconfig.json 에 둔다
{
  "compilerOptions": {
    "module": "nodenext",
    "erasableSyntaxOnly": true,
    "verbatimModuleSyntax": true,
    "allowImportingTsExtensions": true,
    "noEmit": true
  }
}

남의 파일 실행

모듈이 아닌 파일(브라우저용 <script> 파일처럼 전역에 함수 · 변수를 두는 것) 을 Node 에서 쓸 때는 읽어서 vm 으로 실행한다. 전역에 둔 것은 context 에 들어온다.

import fs from "node:fs";
import vm from "node:vm";

// prop.js — var title = "prop"; function hi(n) { return "hi " + n; }
const context = {};
vm.runInNewContext(fs.readFileSync("prop.js", "utf8"), context);
console.log(context.title, context.hi("geon"));    // prop hi geon
  • eval 은 지금 범위의 변수를 건드리므로 쓰지 않는다
  • 파일을 고칠 수 있으면 모듈로 바꾸는 편이 낫다
