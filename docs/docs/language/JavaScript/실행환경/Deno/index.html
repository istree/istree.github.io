Deno 는 V8 위에 Rust 로 만든 JavaScript · TypeScript 실행 환경이다. Node.js 를 만든 Ryan Dahl 이 Node 에서 아쉬웠던 점을 고치려고 새로 만들었다. 파일 · 네트워크 · 환경 변수는 허락한 것만 쓰고, fetch · Request · Response 같은 웹 표준 API 를 그대로 쓴다. 포매터 · 린터 · 테스트 · 실행 파일 만들기가 deno 명령 하나에 들어 있고, npm 패키지도 쓴다.

여기의 예제는 Deno 2.9 기준이다.

설치

curl -fsSL https://deno.land/install.sh | sh     # macOS · Linux — ~/.deno/bin
brew install deno                               # Homebrew
irm https://deno.land/install.ps1 | iex          # Windows PowerShell

deno --version
deno upgrade                                    # 새 판으로

실행

.ts 를 설정 없이 바로 실행한다. 타입 검사는 하지 않고, deno check 로 따로 한다.

// hello.ts
const name: string = Deno.args[0] ?? "world";
console.log(`Hello, ${name}!`);
deno run hello.ts geon          # Hello, geon!
deno hello.ts geon              # run 을 빼도 된다
deno run --watch hello.ts       # 고칠 때마다 다시
deno check hello.ts             # 타입 검사
deno                            # REPL
  • 명령줄 인자는 Deno.args, 환경 변수는 Deno.env.get("HOME") 이다. process 도 있어 Node 코드가 그대로 돈다

권한

아무 플래그 없이 실행하면 파일 · 네트워크 · 환경 변수 · 다른 프로그램 실행이 막혀 있다. 쓸 것만 열어 준다.

// read.ts
const text = await Deno.readTextFile("./data.txt");
const res = await fetch("https://example.com");
console.log(text.trim(), res.status);
$ deno run read.ts
error: Uncaught (in promise) NotCapable: Requires read access to "./data.txt", run again with the --allow-read flag

$ deno run --allow-read=. --allow-net=example.com read.ts
메모 200
플래그 여는 것
--allow-read[=경로] · --allow-write[=경로] 파일 읽기 · 쓰기
--allow-net[=호스트] 네트워크 (요청 · 서버)
--allow-env[=이름] 환경 변수
--allow-run[=프로그램] 다른 프로그램 실행
--allow-sys · --allow-ffi OS 정보 · 네이티브 라이브러리
-A (--allow-all) 모두
  • = 뒤에 범위를 주면 그것만 연다. 범위 없이 --allow-read 만 주면 모든 파일이다
  • 터미널에서 실행하면 막힌 자리에서 열지 물어 본다. CI 처럼 물을 수 없으면 바로 오류로 끝난다
  • npm 패키지도 같은 권한 아래에서 돈다. 색을 칠하는 패키지가 환경 변수를 읽으려다 NotCapable: Requires env access to "TF_BUILD" 로 멈추기도 한다. 그 패키지가 무엇을 읽는지 보고 --allow-env 를 준다

패키지

JSR(Deno 의 패키지 저장소) 은 jsr:, npm 은 npm: 을 붙여 가져온다. deno add 로 넣으면 deno.json 의 imports 에 이름이 생겨 짧게 쓴다.

deno add jsr:@std/path npm:chalk     # deno.json 에 적고 deno.lock 을 만든다
deno remove chalk
deno outdated                        # 새 판이 나온 것
import { join, extname } from "@std/path";          // deno.json 의 imports 로
import chalk from "chalk";
import { format } from "npm:date-fns@4";            // 적지 않고 바로
import { parseArgs } from "jsr:@std/cli/parse-args";

console.log(chalk.green(join("a", "b.ts")), extname("x.md"), format(new Date(2026, 10, 7), "yyyy-MM-dd"));
// a/b.ts .md 2026-11-07
  • node_modules 를 만들지 않고 전역 캐시에 받는다. package.json 이 있는 폴더에서는 deno install 이 node_modules 를 만든다
  • @std/… 는 Deno 팀이 내는 표준 라이브러리(path · fs · assert · cli …) 다

deno.json

{
  "tasks": {
    "dev": "deno run --watch --allow-net server.ts",
    "test": "deno test --allow-read"
  },
  "imports": {
    "@std/assert": "jsr:@std/assert@1",
    "chalk": "npm:chalk@^5.6.2"
  },
  "fmt": { "lineWidth": 100 },
  "lint": { "rules": { "exclude": ["no-unused-vars"] } }
}
  • deno task dev 로 tasks 의 명령을 돌린다. package.json 의 scripts 도 deno task 로 돈다
  • deno init 이 deno.json · main.ts · main_test.ts 를 만든다

내장 도구

deno fmt                    # 고쳐 쓴다 — --check 는 고치지 않고 검사만
deno lint                   # 린트
deno test                   # *_test.ts · *.test.ts 를 찾아 돈다
deno doc main.ts            # 주석에서 문서
deno compile -o greet hello.ts                                   # 실행 파일 하나로
deno compile --target x86_64-pc-windows-msvc -o greet.exe hello.ts   # 다른 OS 용
$ deno lint messy.ts
error[no-unused-vars]: `unused` is never used
 --> messy.ts:2:5
  = hint: If this is intentional, prefix it with an underscore like `_unused`

테스트는 Deno.test 로 쓰고, 단언은 @std/assert 에서 가져온다.

// slug_test.ts
import { assertEquals } from "@std/assert";
import { slug } from "./slug.ts";

Deno.test("공백을 - 로", () => {
  assertEquals(slug(" Hello World "), "hello-world");
});

Deno.test("묶음", async (t) => {
  await t.step("빈 문자열", () => assertEquals(slug(""), ""));
});
$ deno test
공백을 - 로 ... ok (533µs)
묶음 ...
  빈 문자열 ... ok (0ms)
묶음 ... ok (288µs)

ok | 2 passed (1 step) | 0 failed (2ms)
  • 테스트도 권한 아래에서 돈다. 테스트하는 코드가 파일 · 네트워크를 쓰면 deno test --allow-read 처럼 연다
  • deno compile 결과에는 Deno 런타임이 통째로 들어가 빈 스크립트도 70 MB 쯤 된다. 실행할 때 준 권한 플래그를 컴파일할 때 준다: deno compile --allow-net server.ts

서버

Deno.serve 에 Request 를 받아 Response 를 돌려주는 함수를 준다. 브라우저의 fetch 와 같은 객체다.

// server.ts — deno run --allow-net server.ts
const notes = [{ id: 1, text: "hello" }];

Deno.serve({ port: 8000 }, async (req) => {
  const url = new URL(req.url);
  if (url.pathname === "/api/notes" && req.method === "GET") return Response.json(notes);
  if (url.pathname === "/api/notes" && req.method === "POST") {
    const { text } = await req.json();
    const note = { id: notes.length + 1, text };
    notes.push(note);
    return Response.json(note, { status: 201 });
  }
  return new Response("not found", { status: 404 });
});
Listening on http://0.0.0.0:8000/ (http://localhost:8000/)

fetch 를 가진 객체를 내보내면 deno serve 가 띄운다. 권한(--allow-net) 을 알아서 준다.

// api.ts — deno serve --port 8001 api.ts
export default {
  fetch(req: Request): Response {
    return Response.json({ path: new URL(req.url).pathname });
  },
} satisfies Deno.ServeDefaultExport;

Node 프로젝트에서

package.json 이 있는 Node 프로젝트를 Deno 로 돌린다. node: 모듈 · require · process 가 있다.

deno install                  # package.json 의 의존성 → node_modules
deno run -A app.js            # node app.js 대신
deno task start               # npm run start 대신
  • Node 코드는 권한을 모르고 짜여 있어 보통 -A 로 돌린다
  • Express 같은 npm 서버도 npm:express 로 돈다. 처음부터 Deno 로 짜면 Deno.serve 가 짧다
