Bun 은 Zig 로 짜고 Safari 의 JavaScriptCore 엔진을 쓰는 JavaScript · TypeScript 실행 환경이다. Node.js 를 그대로 대신하는 것을 목표로, 실행기 · 패키지 매니저 · 테스트 · 번들러를 bun 실행 파일 하나에 넣었다. Node 의 node: 모듈 · require · package.json 을 그대로 읽고, 설치 · 시작이 빠르다. 파일 · 셸 · HTTP 서버는 Bun. 으로 시작하는 짧은 API 로도 쓴다.

여기의 예제는 Bun 1.4 기준이다.

설치

curl -fsSL https://bun.com/install | bash     # macOS · Linux — ~/.bun/bin, 셸 설정 파일에 PATH 를 더한다
brew install oven-sh/bun/bun                  # Homebrew
powershell -c "irm bun.sh/install.ps1 | iex"  # Windows

bun --version
bun upgrade

실행

.ts · .tsx · .jsx 를 설정 없이 실행한다. 타입 검사는 하지 않는다.

// hello.ts
const name: string = Bun.argv[2] ?? "world";
console.log(`Hello, ${name}!`);
bun hello.ts geon            # Hello, geon!
bun --watch hello.ts         # 고칠 때마다 다시 실행
bun --hot server.ts          # 프로세스를 두고 모듈만 바꿔 끼운다 (서버 연결이 끊기지 않는다)
bun init                     # package.json · tsconfig.json · index.ts
  • bun init 은 CLAUDE.md 도 만든다. AI 도구에게 Node 대신 Bun 명령을 쓰라고 적은 파일이다. 필요 없으면 지운다
  • process.argv · process.env 도 그대로 있다. Bun.argv · Bun.env 는 같은 값이다

패키지 매니저

npm 과 같은 package.json · node_modules 를 쓰고, 잠금 파일은 bun.lock 이다. npm 레지스트리에서 받으므로 npm 프로젝트에서 바로 쓴다.

npm bun
npm install bun install
npm install ms bun add ms
npm install -D @types/ms bun add -d @types/ms
npm uninstall ms bun remove ms
npm run build bun run build (bun build 은 번들러라 run 을 붙인다)
npx cowsay hi bunx cowsay hi
  • 캐시에 받아 둔 패키지는 다시 받지 않는다. 바뀐 것이 없으면 bun install 이 몇 ms 에 끝난다
  • 패키지의 postinstall 스크립트는 기본으로 돌리지 않는다. 돌려야 하는 패키지는 package.json 의 trustedDependencies 에 적는다
  • bun run start 가 "start": "node app.js" 를 돌리면 node 는 진짜 Node 다. Bun 으로 돌리려면 bun --bun run start 로 한다

서버

Bun.serve 의 routes 에 주소마다 처리 함수를 둔다. :id 같은 자리 값은 req.params 에 들어온다.

// server.ts — bun server.ts
const notes = [{ id: 1, text: "hello" }];

const server = Bun.serve({
  port: 3000,
  routes: {
    "/api/notes": {
      GET: () => Response.json(notes),
      POST: async req => {
        const { text } = await req.json();
        const note = { id: notes.length + 1, text };
        notes.push(note);
        return Response.json(note, { status: 201 });
      },
    },
    "/api/notes/:id": req => {
      const note = notes.find(n => n.id === Number(req.params.id));
      return note ? Response.json(note) : new Response("not found", { status: 404 });
    },
    "/": new Response("<h1>notes</h1>", { headers: { "Content-Type": "text/html" } }),   // 고정 응답
  },
  fetch() {                                    // routes 에 없는 주소
    return new Response("not found", { status: 404 });
  },
});

console.log(`http://localhost:${server.port}`);
  • Request · Response 는 브라우저의 fetch 와 같은 객체다
  • Express 같은 Node 서버 패키지도 그대로 돈다

파일 · 셸

import { $ } from "bun";

await Bun.write("out.txt", "hello\n");                 // 쓰기 — 문자열 · Blob · Response 도 된다
const file = Bun.file("out.txt");                     // 아직 읽지 않는다
await file.text();                                    // "hello\n"
file.size;                                            // 6
await Bun.file("data.json").json();                   // JSON 으로
await Bun.file("nope.txt").exists();                  // false

const out = await $`git branch --show-current`.text();   // 셸 명령 — 결과를 문자열로
for await (const line of $`ls *.ts`.lines()) console.log(line);

const name = "a b; rm -rf x";
await $`echo ${name}`;                                // a b; rm -rf x — 끼운 값은 글자 하나로 넘어간다

const r = await $`ls nope`.nothrow().quiet();         // 실패해도 던지지 않고, 출력도 숨긴다
r.exitCode;                                           // 1
  • $ 는 0 이 아닌 종료 코드면 ShellError 를 던진다. .nothrow() 를 붙이면 exitCode 로 본다
  • $ 의 명령은 Bun 이 직접 해석한다. macOS · Linux · Windows 에서 같은 문법으로 돈다
  • Bun.password.hash · Bun.password.verify(비밀번호 해시), Bun.sleep(ms) 같은 것도 들어 있다

테스트

bun test 가 *.test.ts · *.spec.ts 를 찾아 돌린다. Jest 와 같은 expect 를 쓴다.

// slug.test.ts
import { test, expect, describe, mock } from "bun:test";
import { slug } from "./slug";

describe("slug", () => {
  test("공백을 - 로", () => expect(slug(" Hello World ")).toBe("hello-world"));
  test("객체 비교", () => expect({ a: [1] }).toEqual({ a: [1] }));
});

test("mock", () => {
  const fn = mock((x: number) => x * 2);
  fn(2);
  expect(fn).toHaveBeenCalledTimes(1);
  expect(fn.mock.results[0].value).toBe(4);
});

test("스냅샷", () => expect(slug("A B C")).toMatchSnapshot());   // __snapshots__ 에 저장
$ bun test
 4 pass
 0 fail
snapshots: +1 added
Ran 4 tests across 1 file. [10.00ms]
  • bun test --watch · bun test --coverage 가 된다
  • Jest 테스트(describe · it · expect · jest.fn) 는 대부분 고치지 않고 돈다

번들 · 실행 파일

bun build app.ts --outdir dist --minify                 # 브라우저용으로 묶기
bun build app.ts --outdir dist --target node            # Node 용
bun build hello.ts --compile --outfile greet            # Bun 을 넣은 실행 파일 하나
bun build hello.ts --compile --target=bun-linux-x64 --outfile greet-linux   # 다른 OS 용
  • --compile 결과는 빈 스크립트도 90 MB 쯤 된다. Bun 런타임이 통째로 들어간다
  • --target 에는 bun-darwin-arm64 · bun-linux-x64 · bun-windows-x64 같은 이름을 준다

Node 와 다른 점

  • 엔진이 V8 이 아니라 JavaScriptCore 다. v8 모듈 같은 V8 전용 API 는 다르게 돌거나 없다
  • node: 모듈은 대부분 있지만 모두 같지는 않다. 공식 문서의 Node.js compatibility 에 모듈마다 적혀 있다
  • 한 파일에서 import 와 require 를 섞어 써도 된다
  • 네이티브 애드온(.node) 을 쓰는 패키지는 안 될 수 있다. 쓰기 전에 돌려 본다
