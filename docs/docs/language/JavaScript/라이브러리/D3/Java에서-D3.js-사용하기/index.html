D3.js(이하 D3) 는 JavaScript 로 작성되어 있기 때문에 JavaScript 엔진이 있으면 Java 에서도 돌릴 수 있다. 서버에서 차트를 SVG 문자열로 만들어 보고서 · PDF · 메일에 넣을 때 쓴다. 브라우저 없이 그리므로 마우스 이벤트 · 트랜지션은 쓰지 않는다.

필요한 것은 셋이다.

필요한 것 쓰는 것
JavaScript 엔진 GraalJS (javax.script 로 부른다)
DOM (document) domino — JavaScript 로 만든 DOM 구현
D3 d3.min.js (D3 7)

결과는 다음과 같다. 아래 코드가 만든 SVG 를 그대로 붙였다.

Java의 JavaScript 엔진

Java 버전마다 함께 들어 있는 엔진이 다르다.

Java 엔진 D3
6 · 7 Rhino 바탕 엔진 오래된 엔진이라 D3 3 무렵까지
8 ~ 14 Nashorn D3 5 까지 (ES5)
15 ~ 없음 — 따로 넣는다 GraalJS 를 넣으면 D3 7
  • D3 6 부터는 화살표 함수 · 클래스 같은 ES2015 문법으로 배포된다. ES5 까지만 읽는 Nashorn 에서는 D3 5 를 쓴다
  • Rhino 를 컴파일 모드로 돌리면 스크립트를 JVM 메서드로 바꾸는데, 메서드 하나가 64KB 를 넘을 수 없어서 d3.min.js(200KB 넘음) 같은 큰 파일이 실패한다. 인터프리터 모드(최적화 수준 -1) 로 돌리면 된다
  • 지금 쓰려면 Java 17 · 21 에 GraalJS 를 넣는다. 최신 ECMAScript 를 지원하고 javax.script 로도 부를 수 있다

의존성

Maven 에 GraalJS 와 ScriptEngine 연결을 넣는다.

<properties>
  <graal.version>25.5.5.0.3</graal.version>
</properties>
<dependencies>
  <dependency>
    <groupId>org.graalvm.polyglot</groupId>
    <artifactId>polyglot</artifactId>
    <version>${graal.version}</version>
  </dependency>
  <dependency>
    <groupId>org.graalvm.polyglot</groupId>
    <artifactId>js-community</artifactId>
    <version>${graal.version}</version>
    <type>pom</type>
  </dependency>
  <dependency>
    <groupId>org.graalvm.js</groupId>
    <artifactId>js-scriptengine</artifactId>
    <version>${graal.version}</version>
  </dependency>
</dependencies>
  • GraalVM 이 아닌 보통 JDK 에서 돌리면 "fallback runtime" 경고가 나온다. JIT 컴파일 없이 돌아 느려질 뿐이고 결과는 같다. 경고를 끄려면 -Dpolyglot.engine.WarnInterpreterOnly=false 를 준다

DOM

D3 는 DOM 을 다루는 라이브러리라서 document 객체가 필요하다. 웹 브라우저에는 window · document 가 들어 있지만 JavaScript 엔진은 말 그대로 엔진일 뿐이라 document 가 없다.

직접 만들기는 쉽지 않으므로 JavaScript 로 작성된 DOM 구현체인 domino 를 쓴다. domino 는 Mozilla 의 dom.js 를 바탕으로 한 서버용 DOM 구현이다.

domino 는 Node 용(CommonJS) 으로 작성되어 있어서 엔진에서 바로 읽을 수 없다. esbuild 로 파일 하나로 묶는다.

// entry.js
// 엔진에 타이머가 없으면 빈 함수로 채운다 (SVG 를 만드는 데는 쓰지 않는다)
for (const name of ["setTimeout", "clearTimeout", "setInterval", "clearInterval"])
  if (typeof globalThis[name] !== "function") globalThis[name] = function () {};

globalThis.domino = require("domino");
npm install domino d3@7 esbuild
npx esbuild entry.js --bundle --format=iife --platform=neutral --main-fields=main \
    --define:global=globalThis --outfile=domino.bundle.js
cp node_modules/d3/dist/d3.min.js .
  • --define:global=globalThis — domino 가 Node 의 global 을 쓴다. 엔진에는 globalThis 만 있다
  • 타이머를 채우지 않으면 setTimeout is not defined 오류가 난다
  • 두 파일을 src/main/resources/js/ 에 둔다

그리는 스크립트

JSON 문자열을 받아 SVG 문자열을 돌려주는 함수를 만든다. 브라우저에서 쓰는 D3 코드와 같고, 처음에 domino 로 document 를 만드는 것만 다르다.

// bar-chart.js
function barChart(json, width, height) {
  const data = JSON.parse(json);
  const margin = { top: 10, right: 10, bottom: 30, left: 40 };

  const window = domino.createWindow("<html><body></body></html>");
  globalThis.document = window.document;          // d3.create 가 전역 document 를 쓴다

  const x = d3.scaleBand()
    .domain(data.map(d => d.name))
    .range([margin.left, width - margin.right])
    .padding(0.2);
  const y = d3.scaleLinear()
    .domain([0, d3.max(data, d => d.value)]).nice()
    .range([height - margin.bottom, margin.top]);

  const svg = d3.create("svg")
    .attr("xmlns", "http://www.w3.org/2000/svg")    // 파일로 열 때 필요하다
    .attr("width", width)
    .attr("height", height);

  svg.append("g")
    .attr("fill", "steelblue")
    .selectAll("rect")
    .data(data)
    .join("rect")
      .attr("x", d => x(d.name))
      .attr("y", d => y(d.value))
      .attr("width", x.bandwidth())
      .attr("height", d => y(0) - y(d.value));

  svg.append("g")
    .attr("transform", `translate(0,${height - margin.bottom})`)
    .call(d3.axisBottom(x));
  svg.append("g")
    .attr("transform", `translate(${margin.left},0)`)
    .call(d3.axisLeft(y));

  return svg.node().outerHTML;
}

Java

엔진을 얻고, domino → D3 → 그리는 스크립트 순서로 읽은 뒤 함수를 부른다. 엔진 · 읽기는 한 번만 하고 차트마다 함수만 부른다.

public class D3Chart {
    private final ScriptEngine js;

    public D3Chart() throws Exception {
        js = new ScriptEngineManager().getEngineByName("js");
        if (js == null)
            throw new IllegalStateException("JavaScript 엔진이 없다");
        load("js/domino.bundle.js");   // DOM
        load("js/d3.min.js");          // D3 — 전역 d3
        load("js/bar-chart.js");       // 그리는 함수
    }

    private void load(String resource) throws Exception {
        try (Reader r = new InputStreamReader(
                D3Chart.class.getClassLoader().getResourceAsStream(resource), StandardCharsets.UTF_8)) {
            js.eval(r);
        }
    }

    public String barChart(String json, int width, int height) throws Exception {
        return (String) ((Invocable) js).invokeFunction("barChart", json, width, height);
    }
}
String json = """
    [{"name":"1월","value":30},{"name":"2월","value":80},{"name":"3월","value":45},{"name":"4월","value":60}]
    """;
String svg = new D3Chart().barChart(json, 400, 240);
Files.writeString(Path.of("chart.svg"), svg);
  • 데이터는 JSON 문자열로 넘긴다. Java 객체를 그대로 넘기면 엔진마다 다루는 법이 달라진다
  • ScriptEngine 하나는 여러 스레드에서 같이 쓰지 않는다. 서버에서는 스레드마다 하나씩 두거나 풀로 돌려 쓴다
  • PNG · PDF 가 필요하면 만든 SVG 를 Batik 같은 SVG 라이브러리로 바꾼다
