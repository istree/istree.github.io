C 프로그램은 main 함수에서 시작하고, 쓰는 함수의 헤더를 #include 로 가져온다. 값은 모두 정해진 크기의 타입을 갖고, 배열 · 구조체로 묶는다.

컴파일 · 실행

// hello.c
#include <stdio.h>

int main(void) {
    printf("Hello, %s!\n", "C");
    return 0;                   // 0 이면 성공
}
clang -std=c17 -Wall -Wextra -o hello hello.c    # gcc 도 옵션이 같다
./hello
  • -Wall -Wextra 는 늘 켠다. 쓰지 않는 변수 · 형식 문자열과 맞지 않는 인자 같은 실수를 경고로 알려 준다
  • Windows 의 Visual Studio 는 cl /W4 hello.c 로 컴파일한다

타입

#include <stdint.h>
#include <inttypes.h>

int a = 7, b = 2;
printf("%d %d %.2f\n", a / b, a % b, (double)a / b);    // 3 1 3.50 — 정수끼리 나누면 몫만

printf("%zu %zu %zu\n", sizeof(int), sizeof(long), sizeof(void *));   // 4 8 8 (64 비트 macOS)

int32_t count = INT32_MAX;          // 크기가 정해진 정수 — 파일 · 통신 형식에 쓴다
uint8_t byte = 255;
byte += 1;                          // 0 — 부호 없는 정수는 넘치면 0 부터 다시
printf("%" PRId32 "\n", count);     // int32_t 의 형식 문자열
타입 크기 (흔한 64 비트) 쓰는 곳
char 1 글자 한 바이트
int 4 보통 정수
long 8 (Windows 는 4) 크기가 OS 마다 다르다
long long 8 큰 정수
size_t 8 크기 · 개수 · 배열 인덱스 (sizeof 의 결과)
double 8 실수
int32_t · uint8_t … 이름 그대로 크기가 꼭 정해져야 할 때
  • int · long 의 크기는 표준이 정하지 않는다. 크기가 중요하면 stdint.h 의 타입을 쓴다
  • 부호 있는 정수가 넘치면 정의되지 않은 동작이다. 결과를 믿을 수 없고, 최적화가 엉뚱한 코드를 만든다. -fsanitize=undefined 로 컴파일하면 실행 중에 runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int' 로 알려 준다
  • 부호 없는 정수에서 빼기를 하면 0 아래로 내려가지 않고 아주 큰 수가 된다(0u - 1 은 4294967295). 개수끼리 빼서 비교할 때 조심한다

printf · scanf

printf("[%5d] [%-5d] [%05d]\n", 42, 42, 42);   // [   42] [42   ] [00042] — 폭 · 왼쪽 정렬 · 0 채우기
printf("[%x] [%o] [%e]\n", 255, 8, 12345.678);  // [ff] [10] [1.234568e+04]
printf("%s %c %p %%\n", "글자", 'A', (void *)&a);

int age;
if (scanf("%d", &age) == 1)        // 읽은 개수를 돌려준다 — 늘 확인한다
    printf("%d 살\n", age);
else
    puts("숫자가 아니다");
형식 타입
%d · %u · %ld · %lld int · unsigned · long · long long
%zu size_t
%f · %.2f · %e double (printf 에서는 float 도)
%s · %c · %p 문자열 · 글자 · 포인터
%x · %o 16 진수 · 8 진수
  • 형식과 인자 타입이 맞지 않으면 정의되지 않은 동작이다. -Wall 이 format specifies type 'int' but the argument has type 'long' 처럼 잡는다
  • scanf("%s", buf) 는 버퍼 크기를 모른다. 줄을 읽을 때는 fgets 를 쓴다

배열

int scores[5] = {90, 80};                        // 나머지는 0 — {90, 80, 0, 0, 0}
size_t n = sizeof scores / sizeof scores[0];     // 5 — 배열의 길이
for (size_t i = 0; i < n; i++) printf("%d ", scores[i]);

int grid[2][3] = {{1, 2, 3}, {4, 5, 6}};
grid[1][2];                                      // 6
  • 배열은 길이를 갖고 다니지 않는다. 함수에 넘기면 포인터가 되어 sizeof 로 길이를 알 수 없으므로 길이를 따로 넘긴다
  • 범위 밖을 읽고 써도 컴파일러가 막지 않는다. 다른 변수를 덮어쓰거나 프로그램이 죽는다

구조체 · enum

struct Item {
    char name[16];
    int qty;
    double price;
};

typedef struct {        // typedef 로 이름을 주면 struct 를 빼고 쓴다
    int x, y;
} Point;

enum Level { LOW, MID = 5, HIGH };    // 0, 5, 6

struct Item pen = {"펜", 2, 1.5};
struct Item note = {.qty = 3, .name = "공책"};   // 이름으로 — 빠진 price 는 0
Point p = {1, 2};
Point q = p;            // 통째로 복사된다
q.x = 9;                // p.x 는 1 그대로

제어문

switch (level) {
case LOW:  puts("low");  break;
case HIGH: puts("high"); break;      // break 가 없으면 다음 case 로 내려간다
default:   puts("?");
}

for (int i = 0; i < 3; i++) { … }
while (left > 0) { … }
do { … } while (retry());           // 한 번은 돈다
  • C 에는 bool 이 stdbool.h 에 있다(C17). 조건은 0 이 거짓, 나머지가 참이다

예전에는

C23 에서 C++ 과 비슷한 문법이 들어왔다. clang -std=c23 으로 쓴다.

int *p = nullptr;           // NULL 대신
constexpr int n = 3;        // 컴파일할 때 정해지는 상수
auto x = 2.5;               // 타입 추론 (double)
typeof(x) y = 1.5;          // 같은 타입
bool done = true;           // stdbool.h 없이 bool · true · false
int mask = 0b1010'0001;     // 2 진수 리터럴 · 자리 구분
[[maybe_unused]] int tmp;   // 속성
  • C89 에서는 변수를 블록 맨 앞에만 선언할 수 있었고 // 주석도 없었다. 지금은 쓰는 곳에서 선언한다
