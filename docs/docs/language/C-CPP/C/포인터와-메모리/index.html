포인터는 값이 있는 메모리 주소를 담는 변수다. 함수에 큰 값을 복사하지 않고 넘기거나, 함수가 호출한 쪽의 변수를 바꾸거나, 실행 중에 크기가 정해지는 메모리(힙) 를 다룰 때 쓴다. 메모리를 다 쓰면 직접 돌려줘야 하고, 잘못 다루면 컴파일러가 아니라 실행 중에 터진다.

포인터

int x = 10;
int *px = &x;          // & — x 의 주소
*px = 11;              // * — 그 주소의 값. x 가 11 이 된다

void swap(int *a, int *b) {     // 주소를 받으면 호출한 쪽의 변수를 바꾼다
    int t = *a;
    *a = *b;
    *b = t;
}
swap(&x, &y);
  • 아무것도 가리키지 않는 포인터는 NULL 이다. 쓰기 전에 확인한다
  • 값을 읽기만 하는 매개변수는 const int * 로 받는다. 함수가 바꾸지 않는다는 표시이고, 바꾸면 컴파일 오류다
  • void * 는 아무 타입이나 가리키는 포인터다. malloc · memcpy 가 이것을 주고받고, 쓸 때는 원래 타입의 포인터에 넣는다

배열과 포인터

배열 이름은 첫 원소의 주소로 바뀐다. 포인터에 정수를 더하면 원소 크기만큼 옮겨 간다.

int arr[] = {1, 2, 3, 4};
int *p = arr;                   // &arr[0]
*(p + 2);                       // 3
p[2];                           // 3 — 같은 뜻
&arr[3] - &arr[0];              // 3 — 원소 개수만큼 (ptrdiff_t, %td)

int sum(const int *arr, size_t n) {     // 배열을 넘길 때는 길이도 같이
    int s = 0;
    for (size_t i = 0; i < n; i++) s += arr[i];
    return s;
}
sum(arr, 4);                    // 10

구조체 포인터

struct Node {
    int value;
    struct Node *next;          // 자기 타입의 포인터 — 연결 리스트
};

struct Node c = {3, NULL}, b = {2, &c}, a = {1, &b};
for (struct Node *n = &a; n != NULL; n = n->next)
    printf("%d ", n->value);    // 1 2 3 — n->value 는 (*n).value

힙 메모리

malloc 은 실행 중에 메모리를 빌리고, free 는 돌려준다. 함수가 끝나도 남아 있으므로, 만든 함수 밖으로 돌려줄 수 있다.

#include <stdlib.h>

int *make_range(size_t n) {
    int *p = malloc(n * sizeof *p);     // sizeof *p — 타입이 바뀌어도 고칠 곳이 없다
    if (p == NULL) return NULL;         // 모자라면 NULL
    for (size_t i = 0; i < n; i++) p[i] = (int)i;
    return p;
}

int *r = make_range(5);
if (r == NULL) { perror("malloc"); return 1; }

int *bigger = realloc(r, 10 * sizeof *bigger);   // 크기 바꾸기 — 다른 곳으로 옮겨질 수 있다
if (bigger == NULL) { free(r); return 1; }        // 실패하면 r 은 그대로 남아 있다
r = bigger;

free(r);
r = NULL;                       // 돌려준 뒤 다시 쓰지 않게

int *zeros = calloc(3, sizeof *zeros);   // 0 으로 채운 메모리
  • malloc 한 것은 free 를 정확히 한 번 한다. 누가 돌려줄지(만든 함수 · 부른 쪽) 를 정해 두고 주석으로 적는다
  • r = realloc(r, …) 로 바로 덮으면 실패했을 때 원래 메모리를 잃는다. 다른 변수에 받는다
  • 지역 변수의 주소를 돌려주지 않는다. 함수가 끝나면 그 메모리는 없어진다

정의되지 않은 동작 · 검사 도구

아래는 모두 컴파일은 되지만 무엇이 일어날지 알 수 없는 코드다(정의되지 않은 동작). 바로 죽기도 하고, 한참 뒤에 엉뚱한 곳이 망가지기도 한다.

실수 예
범위 밖 쓰기 int *p = malloc(3 * sizeof *p); p[3] = 1;
돌려준 뒤 쓰기 free(p); printf("%d", p[0]);
두 번 돌려주기 free(p); free(p);
NULL 따라가기 int *p = NULL; *p = 1;
초기화하지 않은 값 읽기 int n; printf("%d", n);

AddressSanitizer 를 켜고 컴파일하면 이런 실수를 그 자리에서 잡고, 줄 번호까지 알려 준다.

clang -g -fsanitize=address,undefined -o app app.c
./app

==47903==ERROR: AddressSanitizer: heap-use-after-free on address 0x6020000000d0 …

  • 개발 · 테스트 빌드는 늘 sanitizer 를 켠다. 느려지므로 배포 빌드에서는 끈다
  • 돌려주지 않은 메모리(누수) 는 리눅스의 AddressSanitizer 가 끝날 때 알려 준다. macOS 에서는 지원하지 않아 leaks --atExit -- ./app 으로 본다: Process 47933: 1 leak for 48 total leaked bytes.
  • Valgrind(valgrind --leak-check=full ./app) 도 같은 일을 한다. 리눅스에서 쓴다
