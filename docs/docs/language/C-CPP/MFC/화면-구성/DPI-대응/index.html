Windows 디스플레이 배율(125% · 150% · 200%) 을 높인 화면에서 프로그램이 깨지지 않게 한다. 배율에 대응하지 않은 프로그램은 Windows 가 통째로 늘려 보여 주어 흐릿하고, 대응한다고 밝힌 프로그램은 선명하지만 크기를 스스로 맞춰야 한다.

대응하지 않기로 고정

96 DPI(100%) 기준 픽셀 좌표로 짜인 옛 화면은 배율이 높아지면 글자만 커지고 자리는 그대로라 겹친다. 고칠 곳이 많으면 매니페스트에 DPI 를 모른다고 밝혀, Windows 가 100% 로 그린 뒤 늘리게 한다. 조금 흐릿해지지만 겹치지 않는다.

<application xmlns="urn:schemas-microsoft-com:asm.v3">
  <windowsSettings>
    <dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">false</dpiAware>
  </windowsSettings>
</application>

옛 Visual Studio(2008) 의 매니페스트 도구(mt.exe) 는 dpiAware 를 모르고 버린다. 그때는 매니페스트 파일을 rc 로 직접 넣고, 링커의 매니페스트 생성을 끈다.

// dpiaware.rc
1 24 "app.manifest"     // 1 = 실행 파일 매니페스트, 24 = RT_MANIFEST

대응하기

픽셀로 박은 값은 DPI 로 늘린다. 96 이 100% 다.

CClientDC dc(this);
int dpi = dc.GetDeviceCaps(LOGPIXELSX);       // 96 · 120 · 144 …
int w   = MulDiv(180, dpi, 96);              // 100% 에서 180px 이던 폭

글자 크기(포인트) 는 72 포인트가 1 인치다.

int h = -MulDiv(10, dc.GetDeviceCaps(LOGPIXELSY), 72);   // 10pt 글꼴의 높이(px)
  • 대화상자 템플릿은 대화상자 단위(DLU) 라 저절로 커진다. 코드로 옮기는 자리 · 크기만 챙기면 된다
  • 그림은 큰 것을 준비해 두고 배율에 맞는 것을 고른다. 작은 그림을 늘리면 흐려진다

모니터마다 다른 배율

배율이 다른 모니터로 창을 옮기면 WM_DPICHANGED 가 온다(모니터별 대응, Windows 8.1 부터). 받은 자리로 창을 옮기고 크기를 다시 맞춘다.

LRESULT CMyDlg::OnDpiChanged(WPARAM wParam, LPARAM lParam)
{
    m_dpi = HIWORD(wParam);
    RECT* prc = (RECT*)lParam;               // Windows 가 권하는 새 자리
    SetWindowPos(NULL, prc->left, prc->top, prc->right - prc->left, prc->bottom - prc->top,
                 SWP_NOZORDER | SWP_NOACTIVATE);
    return 0;
}
