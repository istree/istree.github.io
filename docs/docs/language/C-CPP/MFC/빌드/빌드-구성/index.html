빌드 구성은 Debug · Release 와 플랫폼(Win32 · x64) 을 곱한 묶음이다. 구성마다 출력 이름과 폴더를 나눠 판이 섞이지 않게 한다.

구성 예

구성 · 플랫폼 출력 폴더 출력 파일 런타임 라이브러리
Debug · Win32 bin\Win32\Debug\ MyCtrld.dll /MDd
Release · Win32 bin\Win32\Release\ MyCtrl.dll /MD
Debug · x64 bin\x64\Debug\ MyCtrld.dll /MDd
Release · x64 bin\x64\Release\ MyCtrl.dll /MD 
출력 디렉터리   $(SolutionDir)bin\$(Platform)\$(Configuration)\
대상 이름      Debug: $(ProjectName)d     Release: $(ProjectName)
  • 디버그 DLL 은 이름 끝에 d 를 붙인다. MFC 도 mfc140u.dll · mfc140ud.dll 로 나눈다
  • C++ 프로젝트에서 x86 은 Win32 라는 이름으로 나온다

부르는 쪽

헤더에서 구성에 맞는 라이브러리를 고르면, 헤더만 포함해도 링크할 라이브러리가 따라온다.

// MyCtrl.h
#ifdef _DEBUG
    #pragma comment(lib, "MyCtrld.lib")
#else
    #pragma comment(lib, "MyCtrl.lib")
#endif

x64

  • 64 비트 프로그램은 64 비트 DLL · OCX 만 불러온다
  • 포인터를 담는 정수는 DWORD_PTR · LONG_PTR 로 쓰고, 창에 포인터를 달 때는 SetWindowLongPtr 를 쓴다
  • 플랫폼마다 코드를 나눌 때는 _WIN64 를 본다

런타임 라이브러리

  • /MD · /MDd — C 런타임 · MFC 를 DLL 로 쓴다. 여러 DLL 이 런타임 하나를 나눠 쓴다
  • /MT · /MTd — 런타임을 실행 파일 안에 넣는다

DLL 끼리 MFC 객체나 메모리를 주고받으면 모두 /MD 로 맞추고, 디버그 · 릴리스 판을 섞지 않는다. 섞으면 런타임과 MFC 가 두 벌 올라와 한쪽에서 만든 메모리를 다른 쪽에서 지우다 깨진다.
