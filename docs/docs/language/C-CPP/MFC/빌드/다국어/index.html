화면의 글자 · 대화상자를 언어마다 따로 두고, 실행할 때 고른다. 대화상자는 rc 에서 언어별로 나누고, 코드 속 글자는 메시지 클래스로 나눈다. 리소스를 통째로 언어별 DLL 로 나누는 방법도 있다.

한 rc 에 언어별로

같은 ID 의 리소스를 LANGUAGE 블록마다 둔다.

LANGUAGE LANG_KOREAN, SUBLANG_DEFAULT
IDD_FONT DIALOGEX 0, 0, 200, 120
// ...

LANGUAGE LANG_ENGLISH, SUBLANG_ENGLISH_US
IDD_FONT DIALOGEX 0, 0, 200, 120
// ...
  • 파일 하나로 끝난다. 어떤 언어를 쓸지는 스레드의 UI 언어(SetThreadUILanguage) 로 고른다
  • 언어가 늘수록 rc 가 커지고, 대화상자 하나를 고치면 언어 수만큼 고쳐야 한다

코드 속 글자 — 메시지 클래스

언어마다 클래스를 두고, 처음 한 번 언어를 정해 그 클래스를 쓴다.

enum MsgID { MSG_SERIES, MSG_GUIDELINE_N, /* ... */ };

struct IMessage {
    virtual LPCTSTR Get(MsgID id) = 0;
    virtual ~IMessage() {}
};
class CKorMessage : public IMessage { /* MSG_SERIES → _T("시리즈") */ };
class CEngMessage : public IMessage { /* MSG_SERIES → _T("Series") */ };

IMessage* Messages()
{
    static IMessage* p = CreateMessages();
    return p;
}

IMessage* CreateMessages()
{
    switch (ReadLanguage()) {   // 레지스트리의 언어 설정, 없으면 사용자 로캘
    case LANG_KOREAN: return new CKorMessage;
    default:          return new CEngMessage;
    }
}

쓰는 곳에는 원래 글자를 주석으로 남겨 두면 찾기 쉽다.

m_tab.InsertItem(0, Messages()->Get(MSG_SERIES) /* 시리즈 */);
str.Format(Messages()->Get(MSG_GUIDELINE_N) /* 가이드라인 %d */, nItem + 1);

언어마다 리소스 DLL

리소스만 담은 DLL 을 언어마다 만들고, 시작할 때 고른 DLL 을 리소스 핸들로 둔다.

HINSTANCE h = ::LoadLibrary(_T("MyAppENU.dll"));
if (h) AfxSetResourceHandle(h);
  • 언어를 더해도 본체를 다시 빌드하지 않는다. 대신 DLL 이 언어 수만큼 늘고, ID 가 본체와 맞아야 한다
  • MFC 는 실행 파일 이름 + 언어 약어 (MyAppENU.dll) 인 위성 DLL 을 스스로 찾아 올리기도 한다

DLL 안의 리소스를 쓸 때 리소스 핸들이 바뀌는 문제는 확장 DLL 에서 다룬다.
