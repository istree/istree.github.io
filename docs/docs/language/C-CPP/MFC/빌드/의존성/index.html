  • 라이브러리

여러 프로젝트로 나눈 솔루션에서 무엇이 무엇을 먼저 필요로 하는지 정해 둔다. 빌드할 때(프로젝트 · 라이브러리) 와 실행할 때(DLL · 런타임 · OCX) 둘 다 챙긴다.

프로젝트 의존성

솔루션 › 프로젝트 종속성에서 먼저 빌드돼야 할 프로젝트를 고른다. Visual Studio 는 이 그래프를 따라 빌드 순서를 정하고, 서로 상관없는 프로젝트는 동시에 빌드한다.

화살표는 먼저 빌드돼야 하는 쪽을 가리킨다. 빌드 순서는 MyCore → MyUI · MyData → MyApp 이다.

  • 의존성을 빠뜨리면 빌드 순서가 그때그때 달라져 가끔 .lib 를 못 찾는다 (LNK1104: cannot open file 'MyCore.lib'). 한 번 더 빌드하면 넘어가는 링크 오류는 대개 이것이다
  • 선언은 .sln 의 ProjectSection(ProjectDependencies) 에 남는다

시작 프로젝트

F5 로 실행 · 디버깅할 프로젝트다. 솔루션 탐색기에서 EXE 프로젝트를 오른쪽 클릭 › 시작 프로젝트로 설정한다.

  • 설정은 사용자 파일(.suo) 에 저장된다. 그 파일이 없으면 .sln 의 맨 앞 프로젝트가 시작 프로젝트가 된다
  • DLL 프로젝트를 시작 프로젝트로 두려면 디버깅 › 명령에 그 DLL 을 불러올 EXE 를 넣는다
명령            $(SolutionDir)bin\$(Platform)\$(Configuration)\MyApp.exe
작업 디렉터리    $(SolutionDir)bin\$(Platform)\$(Configuration)\

라이브러리 연결

C/C++ › 추가 포함 디렉터리        $(SolutionDir)MyCore\include
링커 › 추가 라이브러리 디렉터리     $(SolutionDir)lib\$(Platform)\$(Configuration)\
링커 › 추가 종속성                MyCore.lib
  • 경로는 $(SolutionDir) 같은 매크로로 쓴다. 절대 경로는 PC 마다 다시 맞춰야 한다
  • 디버그 · 릴리스 라이브러리를 헤더에서 고르는 방법은 빌드 구성 에 정리했다

실행할 때

  • VC · MFC 런타임 — /MD 로 빌드했으면 배포 PC 에 같은 버전의 재배포 패키지(vcredist) 가 있어야 한다
  • 매니페스트 — 쓰는 런타임 · 공용 컨트롤 버전을 적는다. 자동 생성을 끄고 직접 만든 매니페스트를 넣으면 빌드 환경(서비스 팩) 이 바뀌어도 경고 없이 그대로라서, 버전을 맞춰 고쳐 둔다
<dependency>
  <dependentAssembly>
    <assemblyIdentity type="win32" name="Microsoft.Windows.Common-Controls" version="6.0.0.0"
                      processorArchitecture="*" publicKeyToken="6595b64144ccf1df" language="*"/>
  </dependentAssembly>
</dependency>
  • OCX — 빌드할 때가 아니라 실행할 때 시스템에 등록된 CLSID 로 연결된다. 실제로 쓰이는 것은 배포 PC 에 등록된 버전이다
regsvr32 MyChart.ocx        (지우기: regsvr32 /u MyChart.ocx)

확인

EXE · DLL 이 불러오는 DLL 을 본다.

dumpbin /dependents MyApp.exe

화면으로 보려면 Dependencies(Dependency Walker 의 후속 도구) 로 빠진 DLL 을 찾는다.
