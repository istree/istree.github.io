  • 라이브러리

C++ 은 오류를 알리는 길이 여럿이다. 드물고 그 자리에서 고칠 수 없는 오류는 예외로 던지고, 자주 일어나는 실패(찾지 못함 · 잘못된 입력) 는 반환 값(std::optional · std::expected) 으로 돌려준다. 어느 쪽이든 RAII 로 자원을 쥐고 있으면 정리는 저절로 된다.

예외

#include <stdexcept>

class ConfigError : public std::runtime_error {          // 표준 예외를 물려받는다
public:
    explicit ConfigError(const std::string& key)
        : std::runtime_error("설정이 없다: " + key), key_{key} {}
    const std::string& key() const { return key_; }
private:
    std::string key_;
};

std::string read_config(const std::map<std::string, std::string>& m, const std::string& key) {
    auto it = m.find(key);
    if (it == m.end()) throw ConfigError{key};
    return it->second;
}

try {
    read_config(cfg, "host");
} catch (const ConfigError& e) {                // 구체적인 것부터
    std::println("{} ({})", e.what(), e.key()); // 설정이 없다: host (host)
} catch (const std::exception& e) {             // 나머지 표준 예외
    std::println("기타: {}", e.what());
}
  • 예외는 값으로 던지고 const& 로 잡는다. 포인터로 던지지 않는다
  • catch (...) 는 무엇이든 잡는다. 로그를 남기고 다시 던질(throw;) 때 쓴다
  • 잡는 곳이 없으면 프로그램이 끝난다: libc++abi: terminating due to uncaught exception of type std::runtime_error: 잡지 않음

표준 라이브러리가 던지는 것:

예외 던지는 곳
std::out_of_range vector::at · map::at · string::substr 범위 밖
std::invalid_argument std::stoi("abc") — stoi: no conversion
std::bad_alloc new 가 메모리를 얻지 못함
std::bad_optional_access · std::bad_expected_access 값이 없는데 .value()
std::system_error 스레드 · 파일 시스템 같은 OS 오류

noexcept

던지지 않는 함수에 붙인다. 컴파일러 · 표준 라이브러리가 그것을 믿고 더 빠른 길을 쓴다(이동 생성자 · 소멸자 · swap).

int safe_div(int a, int b) noexcept { return b == 0 ? 0 : a / b; }
noexcept(safe_div(1, 1));      // true — 컴파일할 때 확인

void f() noexcept { throw std::runtime_error("x"); }
// warning: 'f' has a non-throwing exception specification but can still throw
// 실행하면 잡을 기회 없이 끝난다: terminating due to uncaught exception of type std::runtime_error: x
  • 소멸자는 기본이 noexcept 다. 소멸자에서 던지지 않는다

optional — 없을 수 있는 값

#include <optional>

std::optional<int> find_age(const std::map<std::string, int>& ages, const std::string& name) {
    if (auto it = ages.find(name); it != ages.end()) return it->second;
    return std::nullopt;                          // 없음
}

auto a = find_age(ages, "lee");
a.has_value();                 // false
a.value_or(-1);                // -1
if (auto b = find_age(ages, "kim")) std::println("{}", *b);   // 30 — 있을 때만
  • "없음" 에 까닭이 필요 없을 때 쓴다. -1 · 빈 문자열 같은 특별한 값을 돌려주지 않는다

expected — 값 또는 오류

성공하면 값을, 실패하면 오류를 담는다(C++23). 실패를 타입에 드러내고, 예외 없이 부른 쪽이 처리하게 한다.

#include <expected>
#include <charconv>

enum class ParseError { Empty, NotNumber, OutOfRange };

std::expected<int, ParseError> parse_int(std::string_view s) {
    if (s.empty()) return std::unexpected(ParseError::Empty);
    int v{};
    auto [ptr, ec] = std::from_chars(s.data(), s.data() + s.size(), v);
    if (ec == std::errc::result_out_of_range) return std::unexpected(ParseError::OutOfRange);
    if (ec != std::errc{} || ptr != s.data() + s.size()) return std::unexpected(ParseError::NotNumber);
    return v;
}

auto r = parse_int("4x");
if (r) std::println("ok {}", *r);
else   std::println("err {}", static_cast<int>(r.error()));       // err 1 — NotNumber

parse_int("21").transform([](int v) { return v * 2; }).value();    // 42 — 성공했을 때만 바꾼다
parse_int("x").value_or(0);                                         // 0
  • .and_then · .or_else · .transform 으로 실패를 건너뛰며 단계를 잇는다
  • std::from_chars 는 예외도 로케일도 없이 숫자를 읽는다. 어디까지 읽었는지(ptr) 와 오류(ec) 를 돌려준다

고르는 법

상황 쓰는 것
그 자리에서 할 수 없고, 드물고, 위로 올려 처리할 오류 예외
자주 일어나는 실패, 부른 쪽이 바로 처리 std::expected
없을 수 있을 뿐 까닭은 필요 없음 std::optional
프로그래머의 실수(일어나면 안 되는 것) assert — 디버그 빌드에서 멈춘다
  • 게임 · 임베디드처럼 예외를 끄고(-fno-exceptions) 빌드하는 곳이 있다. 그런 곳에서는 expected · 오류 코드를 쓴다

예전에는

  • 오류를 int 반환 값 · 출력 매개변수 · 전역 errno 로 알렸다. 확인을 빠뜨리기 쉬웠다
  • 함수 선언에 throw(std::runtime_error) 처럼 던질 예외를 적었다(동적 예외 명세). C++17 에서 빠졌고 noexcept 만 남았다
  • std::expected 가 없던 때는 std::variant<T, Error> 나 라이브러리(tl::expected) 로 같은 일을 했다
