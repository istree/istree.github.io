지금 C++ 에서는 new · delete 를 직접 쓰지 않는다. 힙에 만든 객체는 스마트 포인터가 쥐고, 쥔 포인터가 사라질 때 함께 지운다. 큰 값은 복사하지 않고 옮기는(move) 방식으로 넘겨, 메모리를 새로 잡지 않고 속만 가져온다.

unique_ptr — 혼자 갖기

#include <memory>

struct Texture {
    std::string name;
    explicit Texture(std::string n) : name{std::move(n)} {}
    ~Texture() { std::println("free {}", name); }
};

std::unique_ptr<Texture> load(const std::string& n) {
    return std::make_unique<Texture>(n);          // 만들어 돌려준다 — 받은 쪽이 갖는다
}

void sink(std::unique_ptr<Texture> t) { /* … */ }  // 값으로 받으면 가진 것을 넘겨받는다

{
    auto t = std::make_unique<Texture>("grass");
    t->name;                                      // 포인터처럼 쓴다
    auto t2 = std::move(t);                       // 옮긴다 — t 는 nullptr
    sink(std::move(t2));                          // sink 가 끝날 때 지운다: free grass
}

auto u = load("sky");
u.reset();                                        // 지금 지운다

auto arr = std::make_unique<int[]>(3);            // 배열
  • unique_ptr 는 복사할 수 없다. auto q = p; 는 call to implicitly-deleted copy constructor of … unique_ptr<int> 로 컴파일되지 않는다. 넘길 때는 std::move(p) 로 옮긴다
  • 힙 객체가 필요하면 먼저 unique_ptr 를 쓴다. 크기 · 속도가 날 포인터와 같다
  • 가진 것을 넘기지 않고 쓰게만 하려면 Texture& 나 Texture* 로 넘긴다(t.get())

shared_ptr · weak_ptr — 같이 갖기

여러 곳이 같은 객체를 갖고, 마지막 하나가 사라질 때 지운다.

auto a = std::make_shared<Texture>("rock");
{
    auto b = a;                     // 같이 갖는다
    a.use_count();                  // 2
}
a.use_count();                      // 1 — b 가 사라졌다

서로를 shared_ptr 로 가리키면 수가 0 이 되지 않아 영영 지워지지 않는다(순환 참조). 거꾸로 가리키는 쪽은 weak_ptr 로 둔다.

struct Node {
    std::string name;
    std::vector<std::shared_ptr<Node>> children;   // 자식은 갖는다
    std::weak_ptr<Node> parent;                    // 부모는 가리키기만
};

child->parent = root;
root->children.push_back(child);
if (auto p = child->parent.lock())                 // 아직 살아 있으면 shared_ptr 를 얻는다
    std::println("parent {}", p->name);
  • 두 객체가 shared_ptr 로 서로를 가리키면 프로그램이 끝나도 소멸자가 불리지 않는다. 누가 누구를 갖는지 정하고, 갖지 않는 쪽은 weak_ptr 로 둔다
  • shared_ptr 는 수를 세느라 unique_ptr 보다 무겁다. 정말 주인이 여럿일 때만 쓴다

복사와 이동

이동은 다시 쓰지 않을 값의 속(힙 메모리 · 파일 핸들) 을 그대로 가져오는 것이다. 백만 개짜리 vector 도 포인터 몇 개만 옮긴다.

struct Big {
    std::vector<int> data;
    Big() : data(1'000'000, 1) {}
    Big(const Big& o) : data{o.data} { std::println("copy"); }
    Big(Big&& o) noexcept : data{std::move(o.data)} { std::println("move"); }   // 이동 생성자
};

Big x;
Big y = x;                  // copy — 백만 개를 새로 만든다
Big z = std::move(x);       // move — x 의 속을 가져온다
x.data.size();              // 0 — 옮긴 뒤의 x 는 비었다

std::vector<Big> v;
v.push_back(Big{});         // move — 임시 값은 알아서 옮긴다
v.emplace_back();           // 그 자리에서 만든다 — copy · move 없음
  • std::move 는 옮기지 않는다. "이 값은 다시 안 쓴다" 는 표시(rvalue 로 바꾸기) 일 뿐이고, 실제 이동은 받는 쪽의 이동 생성자가 한다
  • 옮긴 뒤의 객체는 지우거나 새 값을 넣는 것만 한다. 표준 타입은 "올바르지만 정해지지 않은" 상태다(string 은 보통 빈 문자열)
  • 이동 생성자에는 noexcept 를 붙인다. 없으면 vector 가 커질 때 안전하게 하려고 이동 대신 복사한다
  • 함수가 지역 변수를 돌려줄 때는 return std::move(x); 로 쓰지 않는다. 그냥 return x; 하면 컴파일러가 복사 없이 넘긴다

값으로 받기 · 전달 참조

받아서 저장할 값은 값으로 받고 안에서 옮기면, 부르는 쪽이 복사할지 옮길지 고른다.

class User {
public:
    explicit User(std::string name) : name_{std::move(name)} {}   // 받은 것을 옮겨 넣는다
private:
    std::string name_;
};

std::string n = "geon";
User a{n};                 // n 을 복사해 넘긴다 — n 은 그대로
User b{std::move(n)};      // 옮겨 넘긴다 — 복사 없음
User c{"kim"};             // 임시 값 — 복사 없음

템플릿에서 받은 값을 그대로 다른 함수에 넘길 때는 T&&(전달 참조) 로 받고 std::forward 로 넘긴다. 임시 값은 옮기고, 이름 있는 값은 복사한다.

template <typename T>
void store(std::vector<std::string>& out, T&& value) {
    out.push_back(std::forward<T>(value));
}

std::string s = "kept";
store(names, s);                     // 복사 — s 는 그대로
store(names, std::string("temp"));   // 이동
  • T&& 는 템플릿 매개변수일 때만 전달 참조다. std::string&& 처럼 정해진 타입이면 임시 값만 받는 rvalue 참조다

예전에는

  • new · delete 로 직접 만들고 지웠다. 예외 · 일찍 return 에서 delete 를 빠뜨려 누수가 났다. C++11 의 unique_ptr · shared_ptr, C++14 의 make_unique 로 바꾼다
  • std::auto_ptr 는 복사하면 몰래 옮겨지는 문제가 있어 C++17 에서 빠졌다
  • C++11 전에는 이동이 없어 큰 값을 돌려주지 않고 출력 매개변수(void get(std::vector<int>& out)) 로 받았다
