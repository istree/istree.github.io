  • 라이브러리

클래스는 데이터와 그것을 다루는 함수를 묶고, 바깥에서 고칠 수 있는 길을 정한다. C++ 클래스의 핵심은 생성자 · 소멸자다. 만들 때 자원을 얻고 사라질 때 돌려주게 하면(RAII), 예외가 나든 일찍 return 하든 정리가 저절로 된다.

클래스 만들기

#include <string>
#include <stdexcept>

class Account {
public:
    explicit Account(std::string owner, long balance = 0)
        : owner_{std::move(owner)}, balance_{balance} {}       // 초기화 목록

    void deposit(long amount) {
        if (amount <= 0) throw std::invalid_argument("0 보다 커야 한다");
        balance_ += amount;
    }
    long balance() const { return balance_; }                  // const — 객체를 바꾸지 않는다
    const std::string& owner() const { return owner_; }

private:
    std::string owner_;
    long balance_ = 0;                                         // 기본값
};

Account a{"geon"};
a.deposit(100);
a.balance();          // 100
  • 멤버는 생성자 본문이 아니라 초기화 목록(: owner_{…}) 에서 채운다. 본문에서 대입하면 한 번 만들고 다시 바꾸는 셈이다
  • 인자 하나인 생성자는 explicit 을 붙인다. 없으면 Account x = std::string("a"); · take("geon") 처럼 문자열이 몰래 Account 로 바뀐다. 붙이면 no viable conversion from 'std::string' … to 'Account' 로 막는다
  • 값을 읽기만 하는 멤버 함수는 const 를 붙인다. const 함수 안에서 멤버를 바꾸면 cannot assign to non-static data member within const member function 오류다
  • 데이터만 묶을 때는 struct 로 쓴다: struct Point { int x = 0; int y = 0; }; — struct 는 기본이 public 이라는 것만 다르다

RAII — 소멸자로 정리하기

#include <cstdio>

class File {
public:
    explicit File(const char* path) : f_{std::fopen(path, "w")} {
        if (!f_) throw std::runtime_error("열 수 없다");
    }
    ~File() { if (f_) std::fclose(f_); }          // 범위를 벗어나면 늘 불린다

    File(const File&) = delete;                    // 복사 금지 — 두 객체가 같은 파일을 닫으면 안 된다
    File& operator=(const File&) = delete;
    File(File&& other) noexcept : f_{other.f_} { other.f_ = nullptr; }   // 옮기기는 된다
    File& operator=(File&& other) noexcept {
        if (this != &other) {
            if (f_) std::fclose(f_);
            f_ = other.f_;
            other.f_ = nullptr;
        }
        return *this;
    }

    void write(const std::string& s) { std::fputs(s.c_str(), f_); }

private:
    std::FILE* f_;
};

{
    File f{"out.txt"};
    f.write("hello\n");
    File g = std::move(f);     // 파일은 g 가 갖는다. f 는 비었다
}                              // 여기서 g 의 소멸자가 한 번 닫는다
  • 파일 · 잠금 · 소켓 · 메모리처럼 돌려줘야 하는 것은 모두 이렇게 감싼다. 표준 라이브러리의 std::unique_ptr · std::lock_guard · std::fstream 이 그렇게 만들어져 있다
  • 복사를 지운 클래스를 복사하면 call to deleted constructor of 'File' 로 컴파일되지 않는다

0 · 3 · 5 규칙

규칙 뜻
0 의 규칙 멤버가 모두 스스로 정리하는 타입(string · vector · unique_ptr) 이면 소멸자 · 복사 · 이동을 하나도 쓰지 않는다. 컴파일러가 만든 것이 맞다
3 · 5 의 규칙 소멸자 · 복사 생성자 · 복사 대입 · 이동 생성자 · 이동 대입 중 하나를 직접 쓰면, 나머지도 모두 쓰거나 = delete · = default 로 정한다
  • 대부분의 클래스는 0 의 규칙으로 쓴다. 위의 Account 가 그렇다. 자원을 직접 쥐는 작은 클래스(File) 만 5 개를 쓴다

연산자

#include <compare>

struct Money {
    long won;
    Money operator+(Money other) const { return {won + other.won}; }
    auto operator<=>(const Money&) const = default;       // == != < <= > >= 를 한 번에 (C++20)
};

Money total = Money{1000} + Money{500};    // 1500
Money{1000} > Money{500};                  // true
  • 연산자는 원래 뜻과 맞을 때만 만든다. + 가 더하기 같지 않으면 이름 있는 함수로 쓴다

상속 · 가상 함수

#include <memory>
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;                   // 기반 클래스의 소멸자는 virtual 로
    virtual double area() const = 0;              // = 0 — 순수 가상 함수. 자식이 꼭 만든다
    virtual std::string name() const { return "도형"; }
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_{r} {}
    double area() const override { return 3.14159 * r_ * r_; }   // override — 부모의 것을 바꾼다
    std::string name() const override { return "원"; }
private:
    double r_;
};

class Rect final : public Shape {                 // final — 더 물려주지 않는다
public:
    Rect(double w, double h) : w_{w}, h_{h} {}
    double area() const override { return w_ * h_; }
private:
    double w_, h_;
};

std::vector<std::unique_ptr<Shape>> shapes;
shapes.push_back(std::make_unique<Circle>(1.0));
shapes.push_back(std::make_unique<Rect>(2, 3));
for (const auto& s : shapes)
    std::println("{} {:.2f}", s->name(), s->area());   // 원 3.14 · 도형 6.00
  • override 를 늘 붙인다. 부모와 모양이 다르면(const 를 빠뜨리는 등) non-virtual member function marked 'override' hides virtual member function 으로 알려 준다. 붙이지 않으면 새 함수가 하나 생길 뿐 조용히 지나간다
  • 순수 가상 함수가 있는 클래스는 만들 수 없다: variable type 'Shape' is an abstract class
  • 기반 클래스 포인터로 지울 객체는 기반 클래스의 소멸자가 virtual 이어야 자식의 소멸자까지 불린다
  • 다형성이 필요 없으면 상속보다 멤버로 갖기(합성) 를 먼저 생각한다

예전에는

  • C++11 전에는 복사를 막으려고 복사 생성자를 private 에 선언만 해 두었다. 지금은 = delete 로 쓴다
  • 비교 연산자 여섯 개를 하나씩 썼다. C++20 부터 operator<=> 를 = default 로 둔다
  • override · final 이 없던 때(C++03) 는 오타로 가상 함수를 잘못 바꿔도 알 수 없었다
