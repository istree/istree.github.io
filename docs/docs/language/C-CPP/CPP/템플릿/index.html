  • 라이브러리

템플릿은 타입을 매개변수로 받는 함수 · 클래스의 틀이다. 쓰는 타입마다 컴파일러가 실제 코드를 찍어 내므로, 같은 코드를 타입마다 적지 않고도 손으로 쓴 것만큼 빠르다. vector<T> · sort 같은 표준 라이브러리가 모두 템플릿이다. C++20 의 concepts 로 받을 수 있는 타입을 정하면 오류 메시지가 짧고 분명해진다.

함수 템플릿

template <typename T>
T max_of(T a, T b) {
    return a < b ? b : a;
}

max_of(3, 7);                     // T = int — 인자에서 추론한다
max_of(2.5, 1.5);                 // T = double
max_of<std::string>("a", "b");    // 직접 정한다 — 그냥 두면 const char* 로 추론된다
max_of(1, 2.5);
// error: no matching function for call to 'max_of'
// note: candidate template ignored: deduced conflicting types for parameter 'T' ('int' vs. 'double')

클래스 템플릿

template <typename T>
class Stack {
public:
    void push(T v) { items_.push_back(std::move(v)); }
    T pop() { T v = std::move(items_.back()); items_.pop_back(); return v; }
    bool empty() const { return items_.empty(); }
    std::size_t size() const { return items_.size(); }
private:
    std::vector<T> items_;
};

Stack<std::string> s;
s.push("a");
s.push("b");
s.pop();                          // "b"

template <typename T>
struct Pair { T first, second; };
Pair p{1, 2};                     // Pair<int> — 생성자 인자로 추론 (C++17)
std::vector v{1, 2, 3};           // std::vector<int>
  • 템플릿의 정의는 헤더에 둔다. 쓰는 곳에서 찍어 내야 하므로 .cpp 에 두면 다른 파일에서 링크 오류가 난다
  • 타입이 아닌 값도 매개변수가 된다: template <typename T, std::size_t N> constexpr std::size_t length(const T (&)[N]) { return N; } 은 배열 길이를 컴파일할 때 알아낸다

concepts

받을 타입의 조건을 이름으로 적는다. 조건에 맞지 않는 타입으로 부르면, 템플릿 안쪽 깊은 곳이 아니라 부른 자리에서 까닭과 함께 막는다.

#include <concepts>

template <std::integral T>                // 정수 타입만
T gcd(T a, T b) {
    while (b) { T t = a % b; a = b; b = t; }
    return a;
}

gcd(12, 18);      // 6
gcd(1.5, 2.0);
// error: no matching function for call to 'gcd'
// note: candidate template ignored: constraints not satisfied [with T = double]
// note: because 'double' does not satisfy 'integral'

직접 만들 때는 requires 로 "이런 식이 컴파일된다" 를 적는다.

template <typename T>
concept Shape = requires(const T& s) {
    { s.area() } -> std::convertible_to<double>;     // area() 가 있고 double 로 바뀐다
};

struct Sq { double side; double area() const { return side * side; } };
struct Circle { double r; double area() const { return 3.14159 * r * r; } };

double total_area(const Shape auto&... shapes) {      // Shape 인 것을 여러 개
    return (shapes.area() + ... + 0.0);               // 접기 식 (C++17)
}
total_area(Sq{2}, Circle{1});                         // 7.14
  • 표준 concepts: std::integral · std::floating_point · std::same_as<T> · std::convertible_to<T> · std::invocable<F, Args…> · std::ranges::range …
  • void f(std::integral auto x) 처럼 auto 매개변수에도 조건을 붙인다

if constexpr · 가변 인자

#include <type_traits>

template <typename T>
std::string describe(const T& v) {
    if constexpr (std::is_integral_v<T>) return "정수 " + std::to_string(v);   // 맞지 않는 갈래는 컴파일하지 않는다
    else if constexpr (std::is_floating_point_v<T>) return "실수";
    else return "그 밖";
}
describe(3);                       // "정수 3"
describe(std::string("x"));        // "그 밖" — to_string(string) 은 컴파일되지 않아도 된다

template <typename... Args>        // 인자 개수 · 타입이 제각각
void log_all(const Args&... args) {
    ((std::print("{} ", args)), ...);
    std::println("");
}
log_all(1, "two", 3.0);            // 1 two 3

타입 추론 규칙

auto 와 템플릿 매개변수는 같은 규칙으로 추론한다.

const int ci = 1;

template <typename T> void by_value(T x);   // by_value(ci) — T = int. 복사하므로 const 가 떨어진다
template <typename T> void by_ref(T& x);    // by_ref(ci)   — T = const int. 참조라 const 가 남는다

auto x = ci;         // int
auto& y = ci;        // const int&
  • 값으로 받으면 const · & 가 떨어지고, 참조로 받으면 남는다. "왜 이 타입이 나왔지" 싶으면 이 규칙을 떠올린다
  • 추론된 타입을 확인하려면 static_assert(std::is_same_v<decltype(x), int>); 로 컴파일러에게 물어본다

예전에는

  • 조건을 걸려고 std::enable_if_t<std::is_integral_v<T>, int> = 0 같은 SFINAE 를 썼다. 오류가 나면 수십 줄짜리 메시지가 나왔다. C++20 부터 concepts 로 쓴다
  • 가변 인자를 재귀로 하나씩 벗겨 처리했다. C++17 부터 접기 식((args + ...)) 으로 쓴다
  • std::vector<int> v{1, 2, 3} 처럼 늘 타입을 적었다. C++17 부터 생성자 인자로 추론한다
