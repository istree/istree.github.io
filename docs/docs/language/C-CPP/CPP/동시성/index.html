C++11 부터 스레드 · 잠금 · 원자 변수 · 비동기 작업이 표준 라이브러리에 있다. 여러 스레드가 같은 값을 건드리면 mutex 나 atomic 으로 지켜야 하고, 지키지 않으면 결과가 실행할 때마다 달라진다. 결과만 필요한 계산은 스레드를 직접 다루지 않고 std::async 로 맡긴다.

스레드

#include <thread>

{
    std::jthread t{[] { std::println("스레드에서"); }};
}   // 블록을 나갈 때 끝나기를 기다린다(join)

std::thread::hardware_concurrency();   // CPU 코어 수 (모르면 0)
  • std::jthread(C++20) 는 사라질 때 알아서 join 한다. std::thread 는 직접 join() · detach() 하지 않으면 소멸자에서 프로그램이 끝난다(std::terminate)
  • 스레드에 넘긴 인자는 복사된다. 참조를 넘기려면 std::ref(x) 로 감싸거나, 람다에서 참조로 잡는다(잡은 변수가 스레드보다 오래 살아야 한다)
  • macOS 의 clang 17(libc++) 은 jthread · stop_token 을 실험 기능으로 두어, -fexperimental-library 를 줘야 컴파일된다

데이터 경쟁

int count = 0;
{
    std::vector<std::jthread> ts;
    for (int i = 0; i < 4; ++i)
        ts.emplace_back([&count] { for (int k = 0; k < 100000; ++k) ++count; });
}
std::println("{}", count);    // 400000 이어야 하는데 115955 · 195149 · 205691 …

++count 는 읽기 · 더하기 · 쓰기 세 단계라, 두 스레드가 같은 값을 읽고 둘 다 1 만 더한다. 최적화를 켜면 우연히 맞게 나오기도 해서 더 찾기 어렵다. ThreadSanitizer 로 컴파일하면 그 자리를 알려 준다.

clang++ -std=c++23 -g -fsanitize=thread -o app app.cpp && ./app
WARNING: ThreadSanitizer: data race (pid=48882)
  Write of size 4 at 0x00016d98ee40 by thread T3:
  Previous write of size 4 at 0x00016d98ee40 by thread T2:
SUMMARY: ThreadSanitizer: data race conc.cpp:26 in main::$_1::operator()() const

mutex · atomic

#include <mutex>
#include <atomic>

int counter = 0;
std::mutex m;
auto work = [&] {
    for (int k = 0; k < 100000; ++k) {
        std::lock_guard lock{m};      // 블록 끝에서 풀린다 — 예외가 나도
        ++counter;
    }
};                                     // 스레드 넷 → 400000

std::atomic<int> hits{0};
hits.fetch_add(1);                     // 잠금 없이 한 번에 — 숫자 · 플래그 하나에 쓴다
hits.load();
  • m.lock() · m.unlock() 을 직접 부르지 않는다. 그 사이에서 예외가 나면 영영 풀리지 않는다. std::lock_guard · std::scoped_lock(여러 개를 한 번에) 을 쓴다
  • 잠금 둘을 스레드마다 다른 순서로 잡으면 서로 기다리다 멈춘다(교착). 여럿을 잡을 때는 std::scoped_lock lock{m1, m2}; 로 한 번에 잡는다
  • 값 하나는 atomic, 여러 값을 함께 맞춰야 하면 mutex 다

async · future

결과를 돌려주는 작업을 다른 스레드에 맡기고, 필요할 때 get() 으로 받는다.

#include <future>

long sum_range(long from, long to) { long s = 0; for (long i = from; i < to; ++i) s += i; return s; }

auto f1 = std::async(std::launch::async, sum_range, 0L, 50'000'000L);
auto f2 = std::async(std::launch::async, sum_range, 50'000'000L, 100'000'000L);
f1.get() + f2.get();                         // 4999999950000000 — 끝날 때까지 기다린다

auto fail = std::async(std::launch::async, []() -> int { throw std::runtime_error("작업 실패"); });
try { fail.get(); }                          // 작업에서 난 예외가 여기서 다시 던져진다
catch (const std::exception& e) { std::println("{}", e.what()); }
  • std::launch::async 를 꼭 준다. 빼면 get() 할 때까지 미뤘다가 그 스레드에서 돌릴 수도 있다
  • std::async 가 돌려준 future 를 받지 않으면 그 줄에서 끝나기를 기다린다. 비동기가 되지 않는다
  • 값을 다른 스레드에서 넘겨줄 때는 std::promise 로 set_value 하고 짝인 future 로 받는다

멈추기 · 기다리기

jthread 는 함수의 첫 매개변수로 std::stop_token 을 받아, 밖에서 멈추라는 요청을 확인한다.

std::jthread worker{[](std::stop_token st) {
    while (!st.stop_requested()) {
        poll();
        std::this_thread::sleep_for(10ms);
    }
}};
worker.request_stop();       // 소멸자도 request_stop 뒤에 join 한다

스레드끼리 일을 주고받는 큐는 condition_variable 로 "들어올 때까지 기다리기" 를 만든다.

#include <condition_variable>
#include <queue>

template <typename T>
class Queue {
public:
    void push(T v) {
        { std::lock_guard lock{m_}; q_.push(std::move(v)); }
        cv_.notify_one();                                   // 기다리는 쪽 하나를 깨운다
    }
    T pop() {
        std::unique_lock lock{m_};
        cv_.wait(lock, [this] { return !q_.empty(); });     // 조건이 맞을 때까지 잠금을 풀고 잔다
        T v = std::move(q_.front());
        q_.pop();
        return v;
    }
private:
    std::mutex m_;
    std::condition_variable cv_;
    std::queue<T> q_;
};
  • wait 에는 늘 조건을 준다. 아무 까닭 없이 깨어나는 일(spurious wakeup) 이 있다

예전에는

  • C++11 전에는 표준에 스레드가 없어 pthread · Windows CreateThread · Boost.Thread 를 썼다
  • 멈춤 요청을 std::atomic<bool> stop 플래그로 직접 만들었다. C++20 부터 jthread · stop_token 이다
  • 여러 잠금을 std::lock(m1, m2) 뒤에 lock_guard 를 adopt_lock 으로 만들었다. C++17 부터 scoped_lock 하나로 쓴다
