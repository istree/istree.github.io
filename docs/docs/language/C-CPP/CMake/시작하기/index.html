  • 라이브러리

CMake 를 설치하고, configure · build 명령으로 빌드한다. 빌드 결과는 소스 밖의 폴더에 둔다.

설치

brew install cmake ninja          # macOS
sudo apt install cmake ninja-build   # Ubuntu · Debian
winget install Kitware.CMake      # Windows — Visual Studio 의 "C++ CMake tools" 에도 들어 있다
cmake --version
  • Ninja 는 make 보다 빠른 빌드 도구다. 없으면 make(맥 · 리눅스) · MSBuild(Windows) 로 빌드한다

빌드 명령

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release   # configure — 소스(.) 를 읽어 build/ 에 만든다
cmake --build build                    # build
cmake --build build -j 8               # 8 개씩 함께 컴파일
cmake --build build --target apple     # 그 타깃만
cmake --build build --clean-first      # 지우고 다시
cmake -S . -B build --fresh            # 캐시를 버리고 configure 를 다시
ctest --test-dir build                 # 테스트
cmake --install build --prefix ~/apps  # 설치
  • 빌드 결과는 늘 소스 밖의 폴더(build/) 에 둔다. 지우고 다시 만들기 쉽고, .gitignore 에 한 줄이면 된다
  • -D이름=값 은 캐시 변수다. 한 번 주면 build/CMakeCache.txt 에 남아 다음 configure 에도 쓴다
  • CMAKE_BUILD_TYPE(Debug · Release · RelWithDebInfo · MinSizeRel) 은 Ninja · Makefile 처럼 설정이 하나인 생성기에 준다. Visual Studio · Xcode 는 한 폴더에 설정이 모두 있어, 빌드할 때 cmake --build build --config Release 로 고른다

예전에는

  • mkdir build && cd build && cmake .. && make 로 빌드했다. 지금은 -S · -B · --build 로 폴더를 옮기지 않고 한다
  • CMake 4 는 3.5 아래와 맞추는 호환 동작을 지웠다. cmake_minimum_required(VERSION 2.8) 같은 옛 프로젝트는 이 오류로 멈춘다. 3.10 아래면 지금도 경고가 나온다
CMake Error at CMakeLists.txt:1 (cmake_minimum_required):
  Compatibility with CMake < 3.5 has been removed from CMake.
  …
  Or, add -DCMAKE_POLICY_VERSION_MINIMUM=3.5 to try configuring anyway.
  • 내가 고칠 수 있으면 VERSION 을 올린다. 받아 쓰는 라이브러리라 고칠 수 없으면 configure 에 -DCMAKE_POLICY_VERSION_MINIMUM=3.5 를 준다
