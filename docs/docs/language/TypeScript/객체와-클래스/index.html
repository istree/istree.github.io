TypeScript 는 객체를 이름이 아니라 모양으로 견준다(구조적 타이핑). 필요한 속성이 모두 있으면 어떤 객체든 그 타입으로 통한다. 클래스에는 JavaScript 의 문법에 접근 제한 · 추상 클래스 · implements 를 더한다.

선택 · 읽기 전용 속성

type Settings = {
  theme: "light" | "dark";
  fontSize?: number;              // number | undefined
  readonly version: number;
};

const s: Settings = { theme: "dark", version: 1 };
s.fontSize.toFixed();             // TS18048: 's.fontSize' is possibly 'undefined'.
const size = s.fontSize ?? 14;    // 기본값을 주고 쓴다

인덱스 시그니처 · Record

키를 미리 모르는 객체(이름 → 점수 같은 표) 는 키의 타입과 값의 타입만 적는다.

type Scores = { [name: string]: number };
type Totals = Record<string, number>;          // 같은 뜻

const scores: Scores = { kim: 90 };
const lee = scores["lee"];                     // number | undefined (noUncheckedIndexedAccess)
lee.toFixed();                                 // TS18048: 'lee' is possibly 'undefined'.

type ByStatus = Record<"draft" | "published", string[]>;   // 키가 정해진 표 — 둘 다 있어야 한다
  • 키 · 값을 자주 넣고 빼면 객체 대신 Map<string, number> 을 쓴다. get 이 undefined 를 돌려주는 것도 타입에 드러난다

구조적 타이핑

type Point = { x: number; y: number };
function dist(p: Point) { return Math.hypot(p.x, p.y); }

const p3 = { x: 3, y: 4, z: 5 };
dist(p3);                       // 된다 — x · y 가 있으면 Point 다
dist({ x: 3, y: 4, z: 5 });     // TS2353: Object literal may only specify known properties, and 'z' does not exist in type 'Point'.
  • 바로 쓴 객체 리터럴만 남는 속성을 오류로 본다. 오타를 잡으려는 것이다
  • 이름이 같아도 모양이 다르면 다른 타입이고, 이름이 달라도 모양이 같으면 같은 타입이다. UserId · OrderId 를 모두 number 로 두면 서로 바꿔 넣어도 오류가 나지 않는다

keyof · typeof · 인덱스 접근

타입에서 키 목록 · 속성 타입을 꺼내고, 값에서 타입을 뽑는다.

type Keys = keyof Point;                  // "x" | "y"
const k: Keys = "z";                      // TS2322: Type '"z"' is not assignable to type 'keyof Point'.
type X = Point["x"];                      // number

const defaults = { theme: "light", fontSize: 14 };
type Defaults = typeof defaults;          // { theme: string; fontSize: number }

클래스

class Account {
  readonly owner: string;
  #balance = 0;                     // JavaScript 의 비공개 필드 — 실행 중에도 숨는다
  private log: string[] = [];       // TypeScript 의 비공개 — 검사에서만 막는다
  protected rate = 0;               // 자식 클래스에서는 쓴다
  static count = 0;

  constructor(owner: string) {
    this.owner = owner;
    Account.count++;
  }
  deposit(n: number): this {        // 이어서 부르기 — 자식에서도 자식 타입을 돌려준다
    this.#balance += n;
    this.log.push(`+${n}`);
    return this;
  }
  get balance() { return this.#balance; }
}

const acc = new Account("geon");
acc.deposit(100).deposit(50);
acc.log;          // TS2341: Property 'log' is private and only accessible within class 'Account'.
acc.rate;         // TS2445: Property 'rate' is protected and only accessible within class 'Account' and its subclasses.
acc.owner = "k";  // TS2540: Cannot assign to 'owner' because it is a read-only property.

class Savings extends Account {
  override deposit(n: number): this {      // override — 부모에 그 메서드가 없으면 오류
    return super.deposit(n);
  }
}
  • 비공개는 # 을 쓴다. private 은 빌드한 JavaScript 에서는 보통 속성이라 밖에서 읽힌다
  • 생성자 매개변수에 private · readonly 를 붙여 필드를 한 번에 만드는 문법(constructor(private name: string)) 이 있지만, 지워서 없어지는 문법이 아니라 Node 로 바로 돌리면 오류가 난다. 필드를 따로 적는다

추상 클래스 · implements

abstract class Shape {
  abstract area(): number;                       // 자식이 꼭 만든다
  describe() { return `넓이 ${this.area()}`; }
}
class Square extends Shape {
  side: number;
  constructor(side: number) { super(); this.side = side; }
  area() { return this.side ** 2; }
}
new Shape();      // TS2511: Cannot create an instance of an abstract class.

type Serializable = { toJSON(): string };
class Note implements Serializable {             // 이 모양을 갖췄는지 검사한다
  toJSON() { return "{}"; }
}
class Bad implements Serializable {}
// TS2420: Class 'Bad' incorrectly implements interface 'Serializable'.
//   Property 'toJSON' is missing in type 'Bad' but required in type 'Serializable'.
  • implements 는 검사만 한다. 메서드를 물려주지 않는다
  • 구조적 타이핑이라 implements 를 적지 않아도 모양이 맞으면 그 타입으로 통한다. 적어 두면 모양이 어긋날 때 클래스 쪽에서 바로 알려 준다
