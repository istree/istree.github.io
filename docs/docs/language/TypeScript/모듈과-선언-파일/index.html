TypeScript 의 모듈은 JavaScript 의 ES 모듈 그대로이고, 타입도 import · export 로 주고받는다. JavaScript 로 된 패키지의 타입은 선언 파일(.d.ts) 에 따로 적는다. 선언 파일에는 타입만 있고 코드는 없다.

타입 주고받기

// types.ts
export type Note = { id: number; text: string };
export const MAX_LENGTH = 500;

// app.ts
import type { Note } from "./types.js";             // 타입만 — 빌드하면 이 줄은 사라진다
import { MAX_LENGTH, type Note as N } from "./types.js";   // 값과 섞을 때는 그 이름에만 type
export type { Note } from "./types.js";              // 타입 다시 내보내기
  • verbatimModuleSyntax 를 켜면 타입을 type 없이 가져올 때 TS1484 오류가 난다. 무엇이 실행 중에 남는 import 인지 코드에서 보이게 하려는 것이다
  • 확장자는 module 설정을 따른다. nodenext 는 ./types.js, Node 로 .ts 를 바로 돌리면 ./types.ts, 번들러(preserve) 는 ./types

@types

타입을 들고 있지 않은 JavaScript 패키지는 DefinitelyTyped 저장소에서 따로 낸 @types/패키지이름 을 설치한다.

npm install express
npm install -D @types/express       # Express 는 JavaScript 로 짜여 있어 타입을 따로 받는다
npm install -D @types/node          # Node 의 내장 모듈 · process
  • npm 에서 패키지 이름 옆에 TS 표시가 있으면 타입이 들어 있고, DT 표시가 있으면 @types 로 따로 있다
  • @types/node 의 판은 쓰는 Node 판과 맞춘다(@types/node@26)

타입이 없는 패키지

@types 도 없는 패키지를 가져오면 오류가 난다.

error TS7016: Could not find a declaration file for module 'slugger'.
  '…/node_modules/slugger/index.js' implicitly has an 'any' type.
  Try `npm i --save-dev @types/slugger` if it exists or add a new declaration (.d.ts) file containing `declare module 'slugger';`

쓰는 만큼만 선언 파일에 적는다. tsconfig.json 의 include 안이면 어느 이름이든 읽는다.

// src/types/slugger.d.ts
declare module "slugger" {
  export default function slug(input: string): string;
}
import slug from "slugger";
slug("A B");      // string
slug(1);          // TS2345: Argument of type 'number' is not assignable to parameter of type 'string'.
  • 급하면 declare module "slugger"; 한 줄만 둔다. 그 패키지의 모든 것이 any 가 된다

이미지 · CSS 같은 파일

번들러가 처리하는 import logo from "./logo.svg" 는 TypeScript 가 모르는 파일이라 TS2307: Cannot find module './logo.svg' or its corresponding type declarations. 가 난다. 확장자마다 모양을 선언한다.

// src/types/assets.d.ts
declare module "*.svg" {
  const url: string;
  export default url;
}
declare module "*.module.css" {
  const classes: Record<string, string>;
  export default classes;
}
  • Vite 는 이것들을 vite/client 에 갖고 있다. tsconfig.json 의 types 에 "vite/client" 를 넣으면 따로 적지 않는다

전역에 더하기

window · 전역 변수에 속성을 더하면 TS2339: Property '__APP_VERSION__' does not exist on type 'Window & typeof globalThis'. 가 난다. declare global 로 넓힌다.

// src/types/global.d.ts
export {};                          // 이 파일을 모듈로 만든다 — declare global 은 모듈 안에서 쓴다

declare global {
  interface Window {
    __APP_VERSION__: string;        // 같은 이름의 interface 는 합쳐진다
  }
  const __BUILD_TIME__: string;     // 번들러가 define 으로 넣는 값
}

라이브러리 내기

declaration: true 로 빌드하면 .js 옆에 .d.ts 가 나온다. 주석(JSDoc) 도 그대로 옮겨져 쓰는 쪽 에디터에 보인다.

// src/index.ts
export type Options = { separator?: string };
/** 글자를 주소에 쓸 형식으로 바꾼다 */
export function slugify(text: string, options: Options = {}): string {
  return text.trim().toLowerCase().replace(/\s+/g, options.separator ?? "-");
}
// dist/index.d.ts — tsc 가 만든 것
export type Options = {
    separator?: string;
};
/** 글자를 주소에 쓸 형식으로 바꾼다 */
export declare function slugify(text: string, options?: Options): string;
{
  "name": "my-lib",
  "type": "module",
  "exports": {
    ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" }
  },
  "files": ["dist"]
}
  • exports 의 types 조건이 선언 파일 자리를 알려 준다. .d.ts 가 .js 바로 옆에 같은 이름으로 있으면 조건 없이도 찾는다
  • declarationMap: true 를 주면 쓰는 쪽에서 "정의로 가기" 가 .d.ts 가 아니라 원래 .ts 로 간다(소스를 같이 낸 경우)
  • 번들러로 묶는 라이브러리도 .d.ts 는 tsc --emitDeclarationOnly 로 따로 만든다
