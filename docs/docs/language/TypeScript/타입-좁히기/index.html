유니온 타입의 값은 모든 갈래에 있는 것만 쓸 수 있다. if · switch 로 갈래를 확인하면 그 안에서는 타입이 좁혀져(narrowing) 그 갈래의 것을 쓴다. TypeScript 가 JavaScript 의 확인 코드를 그대로 읽으므로, 따로 문법을 배우기보다 평소처럼 확인하면 된다.

typeof · in · instanceof

function format(value: string | number | Date) {
  if (typeof value === "string") return value.trim();       // string
  if (typeof value === "number") return value.toFixed(2);   // number
  return value.toISOString();                               // 남은 것 — Date
}

type Cat = { meow(): void };
type Dog = { bark(): void };
function speak(pet: Cat | Dog) {
  if ("meow" in pet) pet.meow();       // 속성이 있는지로 — Cat
  else pet.bark();                     // Dog
}

function toTime(x: Date | string) {
  return x instanceof Date ? x.getTime() : Date.parse(x);   // 클래스로
}
  • if (value) 처럼 참 · 거짓으로 확인하면 null · undefined 가 빠진다. 0 · "" 도 빠지므로 숫자 · 문자열은 != null 로 확인한다
  • return · throw 로 일찍 끝내면 그 아래는 남은 갈래로 좁혀진다

판별 유니온

갈래마다 같은 이름의 속성(status) 에 다른 리터럴 값을 두면, 그 값 하나로 갈래를 나눈다. 요청 상태 · 이벤트 · 메시지처럼 모양이 여럿인 데이터에 쓴다.

type Result =
  | { status: "ok"; data: string[] }
  | { status: "error"; message: string }
  | { status: "loading" };

function render(r: Result): string {
  switch (r.status) {
    case "ok":      return r.data.join(", ");        // data 가 있는 갈래
    case "error":   return `오류: ${r.message}`;
    case "loading": return "불러오는 중";
    default: {
      const unreachable: never = r;                   // 모든 갈래를 처리했는지 검사
      return unreachable;
    }
  }
}

나중에 갈래를 더하고 switch 를 고치지 않으면 default 의 never 대입에서 오류가 난다. 어디를 고쳐야 하는지 컴파일러가 찾아 준다.

type Result = /* … */ | { status: "empty" };
// TS2322: Type '{ status: "empty"; }' is not assignable to type 'never'.

타입 가드 함수

확인 코드를 함수로 뺄 때는 반환 타입을 x is 타입 으로 적는다. 이 함수가 true 를 돌려주면 그 값을 그 타입으로 본다.

function isNote(x: unknown): x is { id: number; text: string } {
  return typeof x === "object" && x !== null && "id" in x && "text" in x;
}

const data: unknown = JSON.parse(text);
if (isNote(data)) console.log(data.text);       // 좁혀진다

const mixed: unknown[] = ["a", 1, "b"];
const strings = mixed.filter(x => typeof x === "string");   // string[] — 간단한 것은 알아서 추론한다
  • 타입 가드가 거짓말을 해도(확인하는 것과 반환 타입이 달라도) 컴파일러는 믿는다. 밖에서 온 데이터는 Zod 같은 검증 라이브러리로 확인하는 편이 안전하다

검사에 실패하면 던지는 함수는 asserts 로 적는다. 부른 뒤로는 좁혀진다.

function assertDefined<T>(v: T | undefined, message: string): asserts v is T {
  if (v === undefined) throw new Error(message);
}

const port = process.env.PORT;          // string | undefined
assertDefined(port, "PORT 가 없다");
port.length;                            // string

satisfies

값이 어떤 타입에 맞는지 검사하되, 변수의 타입은 값 그대로 둔다. 타입을 적으면(: Config) 값의 자세한 타입을 잃고, as 로 우기면 검사를 하지 않는다.

type Config = { port: number; host: string };

const c1 = { port: 3000, host: "localhost", debug: true } satisfies Config;
// TS2353: Object literal may only specify known properties, and 'debug' does not exist in type 'Config'.
const c2 = { port: "3000", host: "x" } satisfies Config;
// TS2322: Type 'string' is not assignable to type 'number'.

const palette = { red: [255, 0, 0], green: "#00ff00" } satisfies Record<string, string | number[]>;
palette.green.toUpperCase();    // 된다 — green 은 string 으로 남는다
palette.red.map(n => n * 2);    // 된다 — red 는 number[]

const wide: Record<string, string | number[]> = { red: [255, 0, 0], green: "#00ff00" };
wide.green.toUpperCase();
// TS18048: 'wide.green' is possibly 'undefined'.
// TS2339: Property 'toUpperCase' does not exist on type 'string | number[]'.

as const

값을 리터럴 그대로 · 고칠 수 없는 것으로 고정한다. 설정 · 상수 표를 만들고 거기서 타입을 뽑을 때 쓴다.

const routes = { home: "/", about: "/about" } as const;
routes.home = "/x";               // TS2540: Cannot assign to 'home' because it is a read-only property.

type Route = (typeof routes)[keyof typeof routes];   // "/" | "/about"
const r: Route = "/blog";         // TS2322: Type '"/blog"' is not assignable to type 'Route'.

const sizes = ["S", "M", "L"] as const;
type Size = (typeof sizes)[number];                  // "S" | "M" | "L"
  • 값 목록에서 유니온 타입을 뽑으면 값과 타입을 한 곳에서 고친다. enum 대신 이렇게 쓴다
  • as const satisfies Config 처럼 둘을 함께 쓰면 고정하면서 모양도 검사한다

as

as 는 "이 값은 이 타입이다" 라고 우기는 것이다. 검사를 줄이므로 꼭 필요할 때만 쓴다.

const input = document.querySelector("#name") as HTMLInputElement;   // 무엇인지 아는 요소
input.value;

const n = "3" as number;
// TS2352: Conversion of type 'string' to type 'number' may be a mistake because neither type
//         sufficiently overlaps with the other. If this was intentional, convert the expression to 'unknown' first.
  • 오류가 시키는 대로 as unknown as number 로 쓰면 통과하지만, 값은 여전히 문자열이다. 바꿔야 하면 Number("3") 으로 바꾼다
