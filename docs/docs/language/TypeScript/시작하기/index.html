TypeScript 는 npm 패키지 typescript 로 설치하고, 그 안의 tsc 가 타입을 검사하고 .ts 를 .js 로 바꾼다. 프로젝트마다 tsconfig.json 에 설정을 둔다.

설치

npm init -y
npm install -D typescript @types/node      # @types/node — Node 의 타입 (fs · process …)
npx tsc -v                                 # Version 7.0.2
npx tsc --init                             # tsconfig.json 만들기
  • 프로젝트마다 -D 로 설치한다. 전역 설치(-g) 는 프로젝트마다 판이 달라 쓰지 않는다
  • tsc --init 이 만드는 tsconfig.json 은 strict · noUncheckedIndexedAccess 같은 엄격한 옵션을 켠 채로 나온다

검사와 빌드

// src/greet.ts
export function greet(name: string): string {
  return `Hello, ${name}!`;
}
console.log(greet("geon"));
npx tsc                     # tsconfig.json 대로 검사하고 outDir 에 .js 를 쓴다
npx tsc --noEmit            # 검사만 — 파일을 쓰지 않는다
npx tsc --watch             # 고칠 때마다 다시 검사
npx tsc -p tsconfig.build.json   # 다른 설정 파일로
// dist/greet.js — 타입만 지워진다
export function greet(name) {
    return `Hello, ${name}!`;
}
console.log(greet("geon"));
  • 오류가 있어도 기본으로는 .js 를 쓴다. 오류가 있으면 쓰지 않으려면 "noEmitOnError": true 를 준다
  • 오류는 src/greet.ts(3,1): error TS2322: Type 'string' is not assignable to type 'number'. 꼴로 나온다(터미널에서는 그 줄의 코드도 같이 보여 준다). TS2322 같은 번호로 찾으면 같은 오류의 설명이 많이 나온다

어디서 돌리나

타입 검사와 실행을 나눠서 생각한다. 검사는 늘 tsc 가 하고, 실행은 상황마다 다르다.

상황 실행 검사
Node 스크립트 · 서버 node app.ts — Node 가 타입을 지우고 돈다 tsc --noEmit
브라우저 앱 Vite · esbuild 가 .ts 를 바꿔 묶는다 tsc --noEmit (Vite 템플릿의 npm run build 에 들어 있다)
npm 라이브러리 tsc 가 .js · .d.ts 를 만든다 tsc
Deno · Bun 그대로 돈다 deno check · tsc --noEmit 
{
  "scripts": {
    "dev": "node --watch src/app.ts",
    "typecheck": "tsc --noEmit",
    "build": "tsc"
  }
}
  • 타입을 지우기만 하는 실행기(Node · esbuild · Vite) 는 타입 오류가 있어도 돈다. CI 에서 tsc --noEmit 을 따로 돌려 막는다
  • Node 로 바로 돌릴 때는 지워서 없어지는 문법만 쓴다. enum · namespace 는 쓰지 않는다 ("erasableSyntaxOnly": true 로 막는다)

TypeScript 6 과 7

TypeScript 7 은 컴파일러를 Go 로 새로 짠 판이다. 문법 · 검사 결과는 6 과 같고, 큰 프로젝트일수록 빌드 · 에디터가 훨씬 빠르다. 다만 컴파일러를 JavaScript 에서 부르는 API(ts.createProgram 같은 것) 가 없다.

TypeScript 6 TypeScript 7
컴파일러 JavaScript Go (네이티브 실행 파일)
tsc 명령 · tsconfig 같다 같다
JavaScript API 있다 없다
쓸 곳 API 를 쓰는 도구가 있을 때 그 밖 모두
  • @rollup/plugin-typescript · 일부 ESLint 플러그인 · 문서 생성기처럼 API 로 컴파일러를 부르는 도구는 TypeScript 7 에서 Cannot read properties of undefined 같은 오류로 멈춘다. 그 프로젝트는 npm install -D typescript@6 으로 6 을 쓴다
  • 6 은 JavaScript 로 짠 마지막 판이고, 7 에서 빠질 옵션을 미리 경고한다. 6 에서 경고 없이 빌드되면 7 로 옮기기 쉽다

예전에는

  • ts-node · tsx 로 .ts 를 바로 실행했다. 지금은 Node(22.18 이상) 가 직접 돌린다
  • tsc --init 이 거의 모든 옵션을 주석으로 단 긴 파일을 만들었다. 지금은 권하는 옵션만 담은 짧은 파일을 만든다
